# WIICUFS — 写"说人话"的技术课程文档

> **WIICUFS** = What If I Catch Up From Scratch
> 一套让"没学过的人"也能看懂的技术教程写作方法。

## 什么时候用

当你需要写一套**多讲次的技术教程**（如"从零学 X"系列），面向**没学过这个领域**的读者，要求他们能看懂、能练手、能信任内容正确性、能单纯凭借它通过正经的诸如考试，考核，科研等实际应用考验时。

典型场景：

- 给自己补一门没上过的课
- 给团队写技术入门系列
- 从零开始恶补一门甚至"不知道自己不知道什么"但又对当前极其重要的领域或课程
- 给社区写开源教程
- 期末考试(绝望)(绝对不能想当然，绝对不能漏或跳知识点)(不能口语和散装到完全用不了)(要前因后果但是不要像写小说一样卖关子讲口水话)(要系统地组织)

## 核心原则（违反即 bug）

1. **说人话**：不用官话、不堆砌不知所云的术语。能用大白话说清的概念不用学术黑话。
2. **严禁空降概念**：新术语第一次出现，当场给三样之一——① 完整解释；② 一句话"它是干啥的 + 现在只需知道这么多 + 第 N 讲细讲"；③ 明确标注"这个词现在可以跳过"。**写作时作者脑里有上下文会无意识跳过定义，读者第一次见没有这个上下文**——这是长篇教程最易违反的一条。之前出现过直接写c语言的`float`的一堆性质但是从来不说它是个什么。
3. **不藏着掖着或者无慈悲陈述**：列出的每样东西至少配"它长这样、这意味着什么、完整方法论心智模型、是否先记下来后面再说"。不要直接甩一堆没解释的东西让读者自己观察。不要因为后面会细讲就在前面故意藏着不说。不要把前面的知识点藏进作业，前面的知识点要完备，作业过饱和了是正常的。
4. **字典陷阱**：很多东西要在出现的时候，要出现方法论或者心智模型，什么时候怎么用，否则会退化成让人无所适从的字典。一个典型的例子就是python这种语义基础，但学生写起来瞎试拼凑就会组合爆炸，且不知道好坏与标准的情况。这个对知识的方向感有没有，如果有的话要怎么找。
5. **丰富具体例子**：倾向工程/数值计算方向，能跑的代码优先。抽象概念用数值实验坐实。
6. **每讲结尾留作业**：可自验证——数值题附答案和验算方法，代码题附能跑的验证。**两条硬约束**：① 答案只能用**已教过的概念**（答案里出现未教语法＝隐形空降，C++ 课程曾犯：第 05 讲答案用了第 07 讲才教的数组）；② 答案块**一律平铺**为“**参考答案**：”段写在题下（先独立做再对照），**禁用 `<details>`/HTML 折叠**——折叠答案在部分渲染环境会整体报错，且未闭合会吞掉后续内容；曾把线代课程 01–08 全部 70 个答案块从折叠改平铺。
7. **标明理解角度与深度**：每个概念不只说"是什么"，还要告诉读者"从什么角度理解它"和"理解到什么程度就够了"。哪些要能完全会用或者推导、哪些知道有这回事就行、哪些要会用了会查——明确区分，避免读者"不知道该怎么对待这个知识"。
   - **理解角度**：这个知识是"工具"（要会用）还是"清单"（遇到时打勾验证）还是"直觉"（建立感觉就行）？
   - **理解深度**：要能推导？要能复述？只要知道"有这回事 + 什么时候找它"？
   - **案例**：向量空间八条公理——不背，知道是"打勾清单"（遇到新集合时逐条验证），理解到"能加能缩放还在里面"的直觉就够；单纯形法——不手算，知道"顶点之间跳"的直觉 + 什么时候用它；SVD——知道"旋转-缩放-旋转"的几何直觉，不背公式。
8. **任务驱动、应用出发**（C++ 课程血泪教训）：每讲围绕一个**能跑的小任务**展开，概念只在“任务卡壳”的那一刻引入，**不上来罗列原理**。三个配套：① 每讲开头一张“本讲怎么走”脉络图 + 每节末尾一句“下一站”（读者看漏了随时能定位）；② 每讲一个可立即编译运行的成品程序开场（先看到“我能做出什么”再拆零件）；③ 同一课程的多讲尽量串成一条故事线（如 C++ 课程的“温度装置”：自检报告→存读数→超温报警）。**反面症状**：读者抱怨“先入为主背概念”“不知道学的哪里是哪里”“连要干啥都不知道就糊一脸概念”。
9. **解释的位置和解释本身同样重要**：概念的解释如果放在读者产生疑问的位置**之后**，效果等于空降——审查时要按“读者第一次遇到的顺序”走一遍，而不是按作者的知识组织顺序。读者自然产生的疑问（“分号干啥的”“main 干啥的”）必须在疑问产生的当页或前一页就有答案。
10. **地毯式覆盖优先于组织优雅**（C++ 课程 A36–A42 血泪教训）：写一个概念时，主线任务只决定了“必须讲什么”，但读者要的是“这个东西的**完整形态**”——标准形式之外每段能不能换、能不能嵌套、能不能被外部控制、重复了会怎样、好习惯坏习惯、和相邻概念的边界。**先地毯式列出完整形态再组织**，不许只写主线需要的部分，不许把规范/边界/习惯当“讲外内容”默认略去，更不许等读者问一个补一个。**判断“这里先理解即可后面会讲”的时机是写到具体那一讲的时候，不是现在**——现在只有“写全”和“不写”两个选项，没有“故意藏一半”。agent也要注意，一个反例是，之前出现过钻特别特性细的点，然后忽视主干和全面性。
11. **先定读者心智模型再动笔**：写作前先明确假想读者是谁（要简明手册的 / 完全踏入陌生领域、不知道自己不知道什么的 / 基本覆盖的技术入门 / 带旧语言经验来的），每一讲都要写一条该讲假想学生的**认知思维链条**——它是**学习者第一人称的自我梳理**（"我以为……等等，那岂不是……"），不是作者用第三人称替他做的总结。统一五段骨架：① 我带着什么来（旧心智模型+已有工具，写成"我以为 X 是……"式的旧直觉，不是作者视角的能力清单）；② 看到本讲任务时的第一反应（期待/误判/抗拒，常含一个**会错的直觉**，正文要有对应的破误段）；③ 我会**依次**卡住的疑问（**4–8 个、按遇到顺序排列、每个具体可答**——严禁只写一个约等于把讲题复读一遍的笼统问题；四类必含：**元问题迷失**（"我该往哪想"）、**旧直觉冲突**（"加法逐元素，乘法凭什么不是"）、**边界**（"只能这样吗"）、**防错**（"我会不会栽在 X"）），每个疑问标注由正文哪部分回答；④ 学完后我的新心智模型（学习者能自己说出口的一句话）；⑤ 还悬着的钩子（通往下讲）。每问一行，全条约 6–14 行，**具体而不嘴碎**。它们是参考，不因为迁就读者发散的思维就放弃系统化知识组织讲解，这会漏知识点。迁就混乱的结果是更多的混乱。但是也要照顾读者的思维，顺着一个健康的认知链条，这个链条不见得是“不知道自己不知道什么”的读者。
12. **因此** 格外留意不能漏掉知识点，不能因为说人话就漏掉知识点，所以要有前置PLAN疯狂穷举发散，留下的作为兜底，后文反复对照。
13. **问答/破误段不是教学容器**：任何新知识（定义、定理、记号、结论）必须**先由正文系统节完整教过**；“想当然/常见问法”类段落只做**对答案与校准表态**，首句须声明“本节零新知识”，且逐条锚定正文系统小节；问法数量**由内容决定**，禁止固定套路数字（如一律三个）。就地破误按原则 9 守在疑问自然产生的位置附近，不攒成一节逃避。写法与事故实录见 reference.md 1.11。
14. **口水话陷阱**：这意味着可能退化成博物馆导游。永远记住，永远要系统，永远要不啰嗦。能不卖关子就不卖关子。永远有清晰的主线意识。不一定要强行编一个故事来入戏，这让翻手册的时候很痛苦，但是也不能字典式地不符合认知规律。尝试做到简明扼要且全面，这里面的trade off你自己按需考虑，但不能走极端念字典念经或者极端口水稿。

## 写作流程：先 PLAN 后逐讲（两遍走）

```
第 0 步：建 PLAN.md（课程目录最前面，agent 自用，不给读者）
  → 明确目标 + 读者画像（哪一种学生，见原则 11）
  → 骨架大纲（每讲的任务/回答什么/成品）
  → 对照领域完整知识清单做地毯式覆盖检查（见下方“地毯式覆盖检查”）
  → 每讲的假想学生认知思维链条（按原则 11 的五段骨架，学习者第一人称）
第 1 遍：逐讲写作
  1. 预写讲义初稿（每讲先定“本讲的任务”再定内容；每个新机制按“完整形态六问”展开）
  2. 写验证脚本，实跑验证预写结论（不限 Python：C/C++ 课程用“生成源码→编译→运行→对照预期输出”同样成立）
  3. 对照预想 vs 实测：一致 → 嵌入实测数据；偏差 → 插入“我说过头了”段（偏差 + 实测 + 根因）
  4. 概念空降检查：逐段回查新术语首次出现处是否给了定义；按读者顺序查“解释位置是否在疑问产生之后”；检查作业答案是否用了未教概念
  5. 格式自检：`<details>` 残留计数为 0（答案一律平铺，不折叠）；引号风格一致；编号体系单一
  6. 重复内容检查：同一数据只允许一个权威出处，其他处指向它
  7. 归档验证脚本（移入课程脚本目录、加编号前缀，不删）、把本讲新概念/公式补进 AA_一览、回填 PLAN.md 状态、同步导览页
第 2 遍：交付前全课程回查
  1. 对照 PLAN.md 的地毯式覆盖清单逐项打勾，没写上的要么补、要么给出“不写”的理由
  2. 按读者顺序从头走一遍，查漏（尤其“规范/边界/习惯/被控形态”这类主线外内容）
  3. 对照每讲思维链条：链条上**每一个**疑问是否都能在正文找到答题小节、且答题位置不晚于该疑问自然产生处；骨架是否齐全（第一人称/4–8 问/五段）；AA_一览批量对账去重（见“多讲次课程的结构”）
```

## 地毯式覆盖检查（写任何机制前必过）

**每个新机制（语法/概念/工具）第一次教时，按“完整形态六问”逐项回答**——这是 C++ 课程被读者连环追问后总结的清单，每问对应一类真实被漏：

| 问                                      | 内容                                                     | C++ 课程被漏的实例                                    |
| --------------------------------------- | -------------------------------------------------------- | ----------------------------------------------------- |
| ① 标准形态 +**每一部分的自由度** | 标准写法是什么；每一段/每个位置能不能换成别的、空着      | for 三段全是自由位（i+=2/多条件/for(;;)）             |
| ②**嵌套与组合**                  | 能不能嵌套自己；能不能和别的结构混着套；什么绝对不能嵌套 | if/for/while 可随意嵌套，唯独函数定义不能             |
| ③**被控与外部打断**              | 能不能被外部逻辑控制；谁让它变假/停；被控形态叫什么      | while 的标志驱动/忙等，循环体不自己前进               |
| ④**重复与共存**                  | 重复写会怎样；能不能改名复用；听谁的                     | 声明/定义/赋值三件套、遮蔽、重载、ODR                 |
| ⑤**规范：好习惯/坏习惯**         | 怎么用是对的；怎么用会埋坑                               | 循环/函数的习惯表、垃圾值纪律                         |
| ⑥**相邻边界与对比**              | 和相邻概念的区分；和读者旧语言（如 Python）的行为差异    | 函数不能嵌套 vs 控制流可嵌套；Python 参数也改不动外面 |

**执行纪律**：六问的答案不一定都进正文（有些可以标“认识即可”），但**必须在写作时逐问过并做出决定**——“决定不写”和“没想到”是两回事。决定记录在 PLAN.md。

## 心智模型对账（防漏的根）

- **作者易犯**：“主线任务 = 本讲内容”——任务跑通需要的才写，规范/边界/习惯被自动归为“讲外”；专家视角默认过滤“显然的东西”（for 三段可换、能嵌套、惯例是 int）——但读者问的恰恰是“就这些吗？只能这样吗？”。
- **读者真实**：学习者不知道边界，每个机制都想问“完整形态”——标准形式之外能不能变、能不能套、能不能被外面打断、重复了会怎样。且**不知  道自己不知道什么**——没写出来的地方他问不出来，只能靠地毯式覆盖兜底。很可能会问一些“没有概念”的，“天马行空的”的，“额话其实不是这么讲的”的问题，这很正常，且要做好准备。
- **纪律**：每写完一个机制，默念“读者会问：只有这一种形态吗？”——凡回答不了“它的完整形态是什么”的机制，就是漏了。

## 数值验证闭环

**每一讲含数值实验的，必须跑脚本验证**——不能只靠"我觉得这个结论对"。

```
写 _verify_lecXX.py（建在课程目录内）
  → uv run --with numpy python _verify_lecXX.py（或 --with scipy）
  → 实测数据回填讲义
  → 归档脚本：移入课程目录的脚本文件夹，重命名为"讲次-序号_原名"（不删）
  → 清理中间产物（__pycache__、编译输出等，照旧删除）
  → 同步进度文件（导览页状态 + 总览文件）
```

**脚本规范**：

- 开头写"规模纪律"注释（目标 < X 秒）
- 纯 numpy/scipy，不依赖重型框架
- 每个实验有 print 标题 + 实测数据 + "→ 结论"一句话总结
- **跑完不删，编号归档**：移入课程目录下的脚本文件夹（如 `scripts/`），文件名加"第几讲-第几个"编号前缀、原名完整保留在前缀之后（不许只剩编号），如 `lec03-01_verify_gd_loss.py`；同一讲内按编写顺序编号，保证按序排列、可回溯复跑——讲义里每个实测数字都对应一个归档脚本
- **中间产物照旧清理**：`__pycache__`、编译输出、临时日志这类不算脚本的中间文件，跑完即删，不进归档

## 预写偏差修正

**预写结论 ≠ 实测结果时**，不要偷偷改掉——**诚实记录**：

在讲义中插入"我说过头了"或"一个诚实的修正"段落，包含三要素：

1. **偏差描述**：预想什么、实测什么
2. **实测数据**：具体数字
3. **根本原因**：为什么预想错了

**透明化偏差是教学可信度的核心**——读者看到"作者也会错、错了会纠正"，比看到"永远正确"更可信。

## 概念首次出现即定义

**写的时候**每个新术语首次出现就给定义，以及括号内英文专有名词，不要等"后面再补"。

**易空降的高危类型**（写完务必回查）：

- **缩写首次出现没展开**：如 LP、BFS、DAG、DFS、RMSE、NP-hard
- **公式符号密集没说各代表什么**：如 $c^Tx$ 里的 $c/x$、$Ax\le b$ 里的 $A/b$
- **术语只给名字没给动机**：如"为什么要标准形""为什么要松弛变量"
- **抽象结构概念**：如"地面集""独立集族""超平面支撑"
- **记号没注音**：如 $\lfloor v\rfloor$（向下取整）、$\epsilon$（读 epsilon）

**跨讲引用要回追根**：第 03 讲用了第 01 讲没定义的缩写 → 回第 01 讲补定义。
**不要因为它解释起来复杂就直接避开不讲，不然会漏知识点**

## 多讲次课程的结构

```
课程目录/
├── PLAN.md             agent 自用的写作计划（目标/读者画像/大纲/地毯覆盖清单/每讲思维链条），不给读者，但必须先于一切存在
├── 00_导览.md          课程大纲、讲次列表、前置、学完能做什么、达标判据
├── 01_xxx.md           第一讲
├── 02_xxx.md           第二讲
├── ...
├── scripts/            验证脚本归档：文件名 = 讲次-序号_原名（如 lec03-01_verify_gd_loss.py），见"数值验证闭环"
├── NN_与X的接口.md     固定的最后一讲：和后续/应用的连接点
└── AA_一览.md          全课程附录：关键概念/公式/中英对照的严谨字典（编号用 AA，永不重排，见下）
```

**`AA_一览`——附录：关键概念、公式、中英对照的严谨字典**：它是**附录、字典，不是速查清单**——不必像正文那样循循善诱从头讲（不重复铺垫、动机、推导过程），但**必须和正文同样严谨：每条都要说清"是什么"**——完整的、自足的定义，读者忘了翻回来能重新明白这东西到底是什么；**只说"怎么样/怎么用"不说"是什么"是鬼话，禁止**。收两类东西：① 关键概念/术语/缩写：中文名 + 英文名/缩写 + **说清"是什么"的定义**（不是用法提示） + 首次出现的讲次 + 理解层次（对应原则 7 的三档）；② 关键公式：符号各指什么 + 适用条件 + 出处讲次。**编号固定用 `AA_` 不用数字**——无论后续加多少讲，这个文件永不需要重排编号或换位置。**与正文的分工**：首次出现的叙述性教学（动机、例子、推导）仍在对应讲正文里（原则 2 不空降），AA 提供措辞严谨的字典形态；原则 4"字典陷阱"约束的是正文不许退化成甩条目，不约束 AA，但 AA 同样不许退化成只甩名字。**维护纪律**：每讲交付后把本讲新概念/公式补进 AA；第 2 遍回查时批量对账去重（每条的"首次出现讲次"与正文交叉核对）。

**每一讲的固定结构**：

```
# 第 N 讲：讲名
> 前置：第几讲 ｜ 预计时间 ｜ 本讲回答什么问题
> 本讲目标（学完你能）：行为化目标 2–3 条 + “目标达成 = 掌握度自测全打勾”
> 怎么学这一讲：成品→拆解→实验→作业→自测的固定循环

正文（任务驱动的成品开场，说人话，概念不空降，例子偏工程/数值）

## 本讲小结        一页纸能说清的骨架
## 掌握度自测      行为化 checklist（与本讲目标一一对应）
## 作业            可自验证：数值题附答案，代码题附能跑的验证
```

**目标行不是可选项**：每讲开头必须让读者一眼看到“这讲结束我能做出什么、怎么判断我达标了”（指向末尾自测），否则课程退化成手册——读者拿到不知道干嘛、从哪学。目标用行为动词（能写出/能说出/能跑出），不用“理解/了解”。

## 多课程并行时的文件边界

同时推进多门课时：

- **所有操作限定在当前课程目录内**
- **严禁修改全局 README.md 或 JOURNAL.md**（其他并行任务在维护）
- **只改课程专属文档**（课程 00_导览.md + 系列总览.md）
- **验证脚本建在课程目录内**，不污染工作区根目录；跑完归档进课程的脚本文件夹（编号规则见"数值验证闭环"）

## 常见踩坑

| 坑                                                                                                                           | 症状                                                                                 | 解法                                                                              |
| ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| GBK 编码                                                                                                                     | 控制台报`UnicodeEncodeError: 'gbk' codec`                                          | 脚本 print 里不用 ✓、²、³ 等 Unicode 符号，改`[OK]`、`^2`、`^3`          |
| numpy API 变动                                                                                                               | `np.trapz` 报 `AttributeError`                                                   | 改用`np.trapezoid` 或手动梯形积分                                               |
| 数据太容易                                                                                                                   | 实验看不出效果（如过拟合没复现）                                                     | 换更难的数据（如两类重叠的高斯团）                                                |
| 网络太小                                                                                                                     | MLP 训练后准确率不够                                                                 | 加宽隐藏层（如 2-2-1 → 2-4-1）                                                   |
| 卷积核选错                                                                                                                   | 输出全 0（正确但教学效果差）                                                         | 换匹配图像特征的核（竖线用竖直边缘核）                                            |
| 单次实验看不出趋势                                                                                                           | 结论不稳定                                                                           | 重复多次（如 50 次）取平均看趋势                                                  |
| 预写结论与实测不符                                                                                                           | loss 不降/准确率不够/反常                                                            | 诚实记录"我说过头了"，分析根因                                                    |
| 答案用`<details>` 折叠                                                                                                     | 部分渲染环境整体报错；未闭合还吞后续内容                                             | 一律平铺为“**参考答案：**”块；交付前 grep `<details>` 计数 = 0          |
| grep 模式假阴性                                                                                                              | 搜编码形式（如`&lt;/details&gt;`）得 0 匹配，误判“全缺失”并批量误改              | 用字面量模式；批量改前用两种模式双向验证，改完再 grep 确认无重复                  |
| 文件快照失效                                                                                                                 | 用户/并行任务重新排版过文件，凭记忆 SearchReplace 匹配失败或改错                     | **改前必 Read 当前版本**，不信任会话内的旧印象                              |
| 解释在错误位置                                                                                                               | 解释存在但在读者需要它的位置之后，读感等同空降                                       | 按"读者第一次遇到的顺序"审查，不按作者知识组织顺序                                |
| 作业答案用未教概念                                                                                                           | 答案代码用了后面讲才教的语法                                                         | 对照"已教清单"逐句检查答案代码                                                    |
| 同一数据多处重复                                                                                                             | 表格/实测值散落多处，改一处漏其他                                                    | 数据收拢到唯一权威出处，其余处写指向                                              |
| PowerShell 剥引号                                                                                                            | `wsl -e bash -lc "..."` 嵌套引号/heredoc 被毁，`unexpected EOF`                  | 复杂命令写成脚本文件再执行；测试源文件用 Write 工具生成，不内联 heredoc           |
| `$?` 被外层 shell 截胡 | 跨层取退出码输出 `True` 等错误值          | 把含 `$?` 的整条命令用单引号包进 bash，或拆成两步 |                                                                                      |                                                                                   |
| Windows linter 误报                                                                                                          | `'iostream' file not found` 等                                                     | Windows 端 IntelliSense 找不到 Linux 头文件，以 WSL 编译为准，忽略                |
| 批量长文错别字                                                                                                               | “佳在”“铺垂”“甪”等同音/形近字                                                  | 大量写作后专项自查一轮；交付前 diff 里扫一遍新增文本                              |
| 只写主线、漏周边（挤牙膏）                                                                                                   | 读者连环追问补漏（C++ 课程 A36–A42 七连）：声明/嵌套/自由度/被控/规范全是被问出来的 | 每个新机制过“完整形态六问”；先有 PLAN.md 地毯清单再动笔；交付前对照清单逐项打勾 |

## 不该做什么

- **不该跳过验证**：只靠"我觉得对"就交付，数值结论可能错
- **不该删验证脚本**：跑完即删会断掉"实测数字怎么来的"证据链；脚本必须编号归档进课程脚本目录，讲义里每个实测数据都能靠它复跑回溯
- **不该偷偷改掉偏差**：把预写错的结论直接改成对的，不记录——读者看不出哪里可能踩坑
- **不该空降概念**：直接不眨眼地写陈述句然后以为读者认识其中每一个专有名词以及意义。"LP 是什么""为什么要有标准形"
- **不该罗列原理开场**：上来就摆零件清单/概念表，不先展示"学完能做出什么"——这是 C++ 课程被读者投诉后全量重写三讲的根源
- **不该只写主线、挤牙膏**：主线任务跑通就交付，规范/边界/习惯/被控形态等读者问了才补——每个机制必须先过完整形态六问，先地毯式覆盖再谈组织
- **不该没有 PLAN 就动笔**：没有目标/读者画像/大纲/覆盖清单就开写，漏是必然不是意外
- **不该让答疑卡片替代正文**：问答笔记（如 QnAnExperience）里解释过的内容，如果正文有漏，必须回填正文；卡片是索引，不是正文的替身
- **不忘记正式定义概念**：讲的很投入但是读者抓不到边界从而不敢学进去，退化成模式识别，理解不深入。
- **不该把思维链条写成许愿**：每讲只问一个笼统问题（约等于把讲题复读一遍）、用作者第三人称替读者做总结——思维链条必须是学习者第一人称的自我梳理、按遇到顺序排列的 4–8 个具体疑问、五段骨架齐全（线性代数课程 PLAN 曾犯，被读者退回重写）
- **不吝啬给出心智模型以及总结：**   很多时候可以总结提炼心智模型，总结干货，那就做，不因为前文讲过了就不给，也不因为要给心智模型所有前文故意不讲。在讲内写，和那个AA_一览不矛盾，且因为是讲内，写的要比它细和全。
- **不该把问答/破误段当教学容器**：新知识必须先由正文系统节完整教过（曾犯：线性代数第 06 讲把反序律/幂/自逆/除法首讲塞进“想当然三连击”节被退回，第 05 讲同病改名）——问答段只对答案、首句声明零新知识、逐条锚定系统节；问法数量由内容决定
- **该用 ML 的地方用了 ML 但规则已知**：在教程里用 ML 学已知公式，白费力气还加误差——用物理/公式更精确
