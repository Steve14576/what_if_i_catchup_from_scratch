# WHATIFICATCHUPFROMSCRATCH

> **What if I catch up from scratch?**——"如果我从零开始，把它补起来呢？"

一个关于**自学**的开源共享仓库，关心这件事的两个面：

- **把它讲明白** → [`wiicufs/`](wiicufs/)：一套让"从零学"的教程真的能教会人的写作方法（Agent Skill）
- **把它记下来** → [`tutorials/`](tutorials/)：自学途中问答与经验的沉淀（按科目组织的卡片笔记）

两者共享同一个朴素的前提：**清晰、完整、说人话。**

## WIICUFS：写"说人话"的教程

**WIICUFS** = **W**hat **I**f **I** **C**atch **U**p **F**rom **S**cratch。

它是一套**多讲次技术教程的写作方法**：面向没学过这个领域的读者，目标是他们**看得懂、能练手、能信任内容正确性、能单纯凭借这套教程通过考试、考核、科研等实际应用考验**。

典型场景：

- 给自己补一门没上过的课
- 给团队写技术入门系列
- 从零恶补一门"不知道自己不知道什么"、但对当前极其重要的领域
- 期末考试（绝望）——绝对不能想当然、不能漏知识点、不能散装到用不了

### 它偏执的地方

这套方法的每一条都是被真实翻车教出来的。几个能感受它风格的例子（完整 12 条原则在 [`SKILL.md`](wiicufs/SKILL.md)）：

- **空降概念是 bug**：新术语第一次出现，必须当场给定义，或至少给一句"它是干啥的 + 现在只需知道这么多 + 第 N 讲细讲"。作者脑里有上下文，读者第一次见没有——这是长篇教程最常翻车的地方。
- **挤牙膏是 bug**：读者最终会问"只有这一种形态吗？能嵌套吗？重复了会怎样？"——这些问题要在写的时候先自己问完，不必等读者催一点、补一点。
- **没实测过的数字不进讲义**：写进讲义的每个结论都对应一个可复跑的验证脚本，编号归档，证据链不断。
- **预写错了不许偷偷改**：预测与实测不符时，要在讲义里留一段"一个诚实的记录"：预期什么、实测什么、根因是什么。

### 文件构成

| 文件 | 内容 |
|---|---|
| [`SKILL.md`](wiicufs/SKILL.md) | 主文件。12 条核心原则、写作流程（先写 PLAN、两遍回查）、各类检查清单 |
| [`reference.md`](wiicufs/reference.md) | 展开补充。每条原则的具体做法、完整案例与踩坑实录 |

### 怎么用

**方式一：作为 Agent Skill 安装。** 把 `wiicufs/` 整个目录复制进你所用 agent 的 skills 目录，例如 Qoder 的 `~/.qoder/skills/`、Claude Code 的 `~/.claude/skills/`，之后按工具约定唤起（如输入 `/wiicufs`）。这个 skill 被设计成**只在被显式点名时才加载**——你不点名，它不会主动搅进你的其他任务。

**方式二：当文章直接读。** 两份文档是完整、自包含的，不需要任何 agent 环境——人直接读，就是一篇"怎么写好教程"的长文。

## tutorials：学习资料

按科目组织的自学笔记区，目前四门：

| 目录 | 科目 |
|---|---|
| `advanced_math_I/` | 高等数学 I |
| `advanced_math_II/` | 高等数学 II |
| `linear_algebra/` | 线性代数 |
| `probs_n_stats/` | 概率与统计 |

每个科目目录里住着一份 **`QnAnExperience.md`**——"问答与经验"的卡片笔记，分两节：

- **A. 从 sessions 中沉淀的**：学习过程中真实问过的问题、答疑与经验，追加式记录，怎么清楚怎么讲；
- **B. "不知道应不应该问"的**：没有直接问、但迟早会撞上的问题，主动点破——专门对付"不知道自己不知道什么"的那种迷失感。

> **诚实说明**：这些笔记刚刚起步。目前各科目目录里是就位的空白模板，内容会随着学习推进陆续沉淀。
