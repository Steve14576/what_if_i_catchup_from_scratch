## 0. 这一讲要解决的具体麻烦

同学发给你一个项目文件夹，说："进到项目目录，运行 `python main.py`。"

你在桌面打开终端，照着敲：

```powershell
python main.py
```

得到：

```text
python: can't open file 'main.py': [Errno 2] No such file or directory
```

可是 `main.py` 明明就在那个文件夹里。你没打错字，文件也存在，问题出在**你站的位置**：终端并不知道你在资源管理器里用鼠标点开了哪个文件夹。它有自己的"当前目录"，`main.py` 这个相对路径是从那个目录算起的。

这一讲解决的就是这类问题：文件系统长什么样、终端站在哪、路径怎么算、命令为什么找不到。

## 1. 四个词先分清：终端、控制台、shell、命令行

这四个词经常被混着用，但它们指的不是同一个东西。分清了，你看教程和报错时才知道自己在哪一层。

| 词 | 是什么 | 例子 | 你会在哪遇到 |
|---|---|---|---|
| 终端 | 一个窗口程序，负责显示文字、把你的键盘输入交给某个程序，再把结果画出来 | Windows Terminal、VS Code 里的终端面板、macOS 的"终端" | "打开一个终端" |
| shell | 真正读你输入的那一行、解释并执行它的程序 | PowerShell、cmd、bash、zsh | 提示符的样子由它决定 |
| 命令行 | 你敲的那一整行字，包括命令名和参数 | `python hello.py` | "运行这条命令行" |
| 控制台 | 早先指连接机器的物理控制台，现在多半只是"终端窗口"的另一种叫法 | 报错里出现的 "console" | 一般不影响操作 |

一句话：**终端是窗口，shell 是窗口里那个解释你命令的程序，命令行是你敲的那一行字。** 你写 Python 时不用关心它们的区别，但看到教程说"在 bash 里跑"、"在 PowerShell 里跑"时，要知道那是两种不同的 shell，某些语法（比如设置环境变量）不通用。

### 1.1 怎么打开终端

- **Windows**：按 `Win + R`，输入 `powershell`，回车；或者在文件资源管理器的地址栏里直接输入 `powershell` 回车（这样打开时当前目录就是那个文件夹，很实用）；或者用 VS Code 的"终端 → 新建终端"。
- **macOS**：启动台里搜"终端"（Terminal）。
- **Linux**：多数桌面环境按 `Ctrl + Alt + T`。

打开后你会看到一个窗口，里面有一行字，末尾在闪。那行字叫**提示符**，它在告诉你"我准备好了，你说吧"。

## 2. 提示符在告诉你什么

PowerShell 的提示符长这样：

```text
PS C:\Users\Administrator>
```

三段，逐段拆：

- `PS`：当前 shell 是 PowerShell。它不是命令，是标签。cmd 的提示符没有这一段，只有 `C:\Users\Administrator>`。
- `C:\Users\Administrator`：**当前工作目录**，也就是你现在"站"的位置。这一讲后面大半内容都在讲它。
- `>`：提示符和你的输入之间的分界。你敲的字出现在它右边，回车才执行。

bash 的提示符长得不一样，例如：

```text
me@laptop:~/lab$
```

`me` 是用户名，`laptop` 是机器名，`~/lab` 是当前目录（`~` 是"我的用户主目录"的简写），`$` 表示普通用户（如果是 `#`，表示管理员/root）。

提示符本身只是一串由 shell 打印出来的文字，可以自定义成任何样子。所以不要把 `PS` 当成命令的一部分去背，也不要看到别人的提示符不一样就以为走错了地方。

另外两条通用操作值得先记住：

- **`Ctrl + C`**：打断正在运行的程序。程序卡住或进入死循环时用它（第 14 讲讲循环时会再遇到）。
- **上箭头**：调出上一条命令。命令行不是只能一条条重敲。

## 3. 文件系统是一棵树

### 3.1 树、目录、根

硬盘上的文件组织成一棵树：最上面是**根**，根下面挂着一层层**目录**（directory，就是文件夹，两个词同义，命令里习惯叫 directory），目录里可以再放目录或文件。

Windows 和 macOS / Linux 在"根"这一层不一样：

- Windows：每个盘符各是一棵树的根，`C:\`、`D:\` 是两棵独立的树；
- macOS / Linux：只有一棵树，根写作 `/`，其他磁盘挂载到这棵树的某个目录下。

这个差别会影响路径怎么写，但不影响"相对路径从当前目录算起"这条规则。

### 3.2 路径就是从某处走到某个文件的步骤

**绝对路径**从根开始写，不依赖你现在在哪：

```text
C:\lab\data\raw\a.csv
/home/me/lab/data/raw/a.csv
```

**相对路径**从当前目录开始写：

```text
data\raw\a.csv
.\data\raw\a.csv
..\raw\a.csv
```

其中两个特殊名字必须记住：

- `.` 表示"当前目录"；
- `..` 表示"上一级目录"。

它们不是装饰，是真的路径成分。实测（脚本 `scripts/lec02-01_demo_paths.py`，临时目录里造了一棵 `root/data/reports/2026/a.csv`）：

```text
  基准目录      = C:\Users\...\Temp\tmppn55p9dj\data\reports
  base / '.'    = C:\Users\...\Temp\tmppn55p9dj\data\reports
  解析后        = C:\Users\...\Temp\tmppn55p9dj\data\reports
  base / '..'   = C:\Users\...\Temp\tmppn55p9dj\data\reports\..
  解析后        = C:\Users\...\Temp\tmppn55p9dj\data
```

注意第二行：`base / '..'` 打印出来时那个 `..` 还在，它没有被"化简"；只有真正解析（`resolve`）时才算出上级目录。这说明 `..` 是一个**指向**，不是字符串替换——`a\..\a` 和 `a` 指的是同一个地方，但写法不同。第 19 讲用 `pathlib` 处理路径时会再遇到这件事。

### 3.3 当前工作目录：相对路径的起点

每个正在运行的程序都有一个**当前工作目录**（current working directory，简称 cwd）。相对路径全部从它算起，`python 脚本.py` 里的脚本名也按它解析。

这不是一个抽象概念，可以实测。准备一个脚本 `show.py`：

```python
from pathlib import Path

target = Path("data/reports/2026/a.csv")
print("  子进程当前目录 =", Path.cwd())
print("  相对路径 target =", target)
print("  这个文件存在吗 =", target.exists())
try:
    with open(target, encoding="utf-8") as f:
        print("  第一行 =", f.readline().strip())
except FileNotFoundError as exc:
    print("  FileNotFoundError:", exc)
```

在树根 `root` 下运行：

```text
  子进程当前目录 = C:\Users\...\Temp\tmppn55p9dj
  相对路径 target = data\reports\2026\a.csv
  这个文件存在吗 = True
  第一行 = name,score
```

切到 `root\data` 下运行同一个脚本、同一句相对路径：

```text
  子进程当前目录 = C:\Users\...\Temp\tmppn55p9dj\data
  相对路径 target = data\reports\2026\a.csv
  这个文件存在吗 = False
  FileNotFoundError: [Errno 2] No such file or directory: 'data\\reports\\2026\\a.csv'
```

同一个脚本、同一个文件、同一行代码，结果一个成功一个失败，唯一的差别是 cwd。

三条结论：

1. 报错里给出的路径（`'data\\reports\\2026\\a.csv'`）是**相对 cwd 解析后的结果**，不是你写的那个字符串的错。
2. 你启动的 `python` 是 shell 的子进程，它**继承 shell 的当前目录**。所以"终端站在哪"决定了"脚本从哪找文件"。
3. 写脚本时，凡是读写文件的地方，都要问自己一句："这个相对路径是相对于谁的？"第 19 讲会给一套不依赖 cwd 的写法。

### 3.4 分隔符与大小写：Windows 宽松，Unix 严格

先看实测（同一台 Windows 机器，`sys.platform = win32`）：

```text
  全大写路径存在吗 = True
  正斜杠写法的 Path  = C:/Users/.../data/reports/2026/a.csv
```

两件事：`DATA\REPORTS\2026\A.CSV` 和 `data\reports\2026\a.csv` 在 Windows 上是**同一个文件**（大小写不敏感）；正斜杠 `/` 也能当分隔符用。

在 Linux 上这两条都不成立：`A.CSV` 和 `a.csv` 是两个不同的文件，分隔符只能是 `/`。

实践建议只有一条：**代码里统一写正斜杠 `/`**。Windows 的 Python 和绝大多数工具都接受它，Linux 也只认它，写一套在哪都能跑。

### 3.5 路径里的三个坑

**坑一：空格。** 路径里有空格时，shell 会把空格当成"参数分隔符"，把你的一个路径拆成两半。实测（PowerShell）：

```text
Get-Content .\my project\hello.py
```

```text
Get-Content : 找不到接受实际参数"project\hello.py"的位置形式参数。
```

shell 把 `.\my` 当成第一个参数，把 `project\hello.py` 当成多余的第二个参数，于是报"位置形式参数"错误。加上引号就好：

```powershell
Get-Content '.\my project\hello.py'
```

```text
print("hi")
```

同一个文件，Python 层面反而没有这个问题：用参数列表启动子进程时，`my project\hello.py` 是一个完整参数，实测退出码 `0`、正常输出。**空格只对 shell 的"分词"有影响**，对文件系统本身没有影响。第 01 讲那个 `C:\Program Files\...` 也是同理，凡是在终端里写带空格的路径，一律加引号。

**坑二：中文路径。** 中文目录名在现代 Windows + Python 3 上通常没问题，但老工具、某些命令行程序、某些打包工具会在编码上翻车。稳妥做法：**代码项目的路径用纯 ASCII**（英文、数字、下划线），数据文件里的中文内容不受影响。

**坑三：隐藏的扩展名。** 第 01 讲提过 `hello.py.txt`。资源管理器默认隐藏"已知类型的扩展名"，所以一个叫 `hello.py.txt` 的文件会显示成 `hello.py`。验证办法：资源管理器"查看"选项卡里勾上"文件扩展名"，或者用命令行 `dir` 看真实文件名。

## 4. 日常八件事，六件必须会

下面这张表按"要做的事"列，同一件事给三种 shell 的写法。PowerShell 与 cmd 的写法在 Windows 上都能用（但不要混着敲，一条命令只属于一种 shell），macOS / Linux 看最后一列。

| 要做的事 | PowerShell（Windows） | cmd（Windows） | macOS / Linux（bash） |
|---|---|---|---|
| 看我在哪 | `pwd` 或 `Get-Location` | `cd`（不带参数） | `pwd` |
| 看目录里有什么 | `ls` 或 `Get-ChildItem` | `dir` | `ls` |
| 进入某个目录 | `cd 路径` | `cd 路径`（换盘要 `cd /d 路径`） | `cd 路径` |
| 建目录 | `mkdir 名字` | `mkdir 名字` | `mkdir -p 名字` |
| 复制 | `Copy-Item 源 目标` | `copy 源 目标` | `cp 源 目标` |
| 移动 / 改名 | `Move-Item 源 目标` | `move 源 目标` | `mv 源 目标` |
| 看文件内容 | `Get-Content 文件` | `type 文件` | `cat 文件` |
| 删除 | `Remove-Item 路径` | `del 文件` / `rmdir 目录` | `rm 路径` |

前六件（看自己在哪、看目录、进目录、建目录、复制、移动改名）加上"看文件内容"，是必须会的。删除单独放在第 7 节讲，因为它是唯一一个"做错了没法撤回"的操作。

几条实测片段，用来对上表里的输出长相。

列出整棵树（`Get-ChildItem -Recurse -Name`，等价于"递归列出、只显示名字"）：

```text
data
data\reports
data\reports\2026
data\reports\2026\a.csv
```

看文件内容：

```powershell
Get-Content "$p\data\reports\2026\a.csv"
```

```text
name,score
li,90
```

建目录、复制、改名，然后确认结果：

```powershell
New-Item -ItemType Directory -Path .\backup | Out-Null
Copy-Item .\data\reports\2026\a.csv .\backup\a_copy.csv
Rename-Item .\backup\a_copy.csv a_final.csv
Get-ChildItem .\backup -Name
```

```text
a_final.csv
```

`Out-Null` 的意思是"别把这条命令的输出打印出来"，只是让屏幕干净，不影响命令本身做了什么。

还有一个 cmd 特有的坑要单独说：**cmd 里换盘符要带 `/d`**。在 cmd 里敲 `cd D:\work`，它只改变了 D 盘记住的当前目录，人还站在 C 盘，此时敲 `cd` 会显示 `C:\...`。要真正过去，得用 `cd /d D:\work` 或者先敲 `D:`。PowerShell 没有这个毛病，`cd D:\work` 直接过去。

## 5. 为什么"命令找不到"

### 5.1 敲下一条命令，系统做了什么

以 `python hello.py` 为例，shell 的动作分三步：

1. **先看是不是自己内置的**。`cd`、`dir`、`pwd` 这类命令由 shell 自己实现，不去磁盘上找。
2. **否则在 `PATH` 列出的目录里按顺序找同名可执行文件**。Windows 上会按扩展名清单（`.exe`、`.bat`、`.cmd` 等）逐个试。
3. **都找不到就报错**。Windows 说"不是内部或外部命令，也不是可运行的程序"，或 PowerShell 的"无法将……项识别为 cmdlet、函数、脚本文件或可运行程序的名称"；Unix 说 `command not found`。

所以"命令找不到"几乎从来不是"你没装"，而是"装在了 `PATH` 没列出来的地方"，或者"装了但当前这个 shell 看不到"。

### 5.2 PATH 是什么

`PATH` 是一个**环境变量**：操作系统保存的一串"名字 = 值"的配置，程序启动时可以读。`PATH` 的值是**一串目录**，Windows 用分号 `;` 分隔，macOS / Linux 用冒号 `:` 分隔。

查看它的内容：

```powershell
$env:PATH -split ';'
```

```bash
echo $PATH        # 在 bash 里，输出是一整行，目录之间用冒号
```

数量取决于你装了什么。实测结果：普通 PowerShell 窗口里是 45 条；在 `uv run` 启动的环境里是 46 条——多出来那一条的原因下面马上讲。

### 5.3 两条真实的"找不到"

先查"这个命令有没有、在哪"：

```text
where.exe python
信息: 用提供的模式无法找到文件。
```

退出码 `1`。换一个命令：

```text
where.exe git
C:\Program Files\Git\cmd\git.exe
```

退出码 `0`。再直接敲：

```text
python --version
python : 无法将"python"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
请检查名称的拼写，如果包括路径，请确保路径正确，然后再试一次。
```

注意它**没有**说"你没装 Python"，它说的是"我不认识 `python` 这个词"。这两件事完全不同：解释器可能装得好好的，只是所在的目录不在 `PATH` 里。

### 5.4 同一个命令，换个环境就找得到了

第 01 讲我们用 `uv run python ...` 跑脚本，那台机器上直接敲 `python` 却是"无法识别"。同一个程序，为什么一会儿有一会儿没有？

因为 `uv run` 在启动你的脚本之前，**临时把项目虚拟环境的目录排到了 `PATH` 最前面**。实测按名字查的结果：

```text
  which('python') = E:\E_Vault\CC_Formed_Projs2\WHATIFICATCHUPFROMSCRATCH\.venv\Scripts\python.EXE
  which('git')    = C:\Program Files\Git\cmd\git.EXE
  which('uv')     = C:\Users\Administrator\.local\bin\uv.EXE
  which('pip')    = None
```

两件事值得看清：

- `python` 找到了，但它指向的是**项目里的 `.venv`**，不是某个全局安装的 Python。这就是"换到另一个项目，`python` 可能是另一个版本"的原因。
- `pip` 是 `None`：这个虚拟环境里根本没装 `pip`（`uv` 建的环境默认不装它）。所以"装完 Python 就有 `pip`"这句话，在虚拟环境里不一定成立。第 03 讲专门处理这件事。

`PATH` 是"进程启动时从环境里读进来的一份清单"，所以**临时改它对当前进程立刻生效，对已经开着的其他窗口不生效**。下面这段实测证明查找机制本身很朴素：

```text
  把 faketools 加进 PATH 之前: which('mytool') = None
  加进 PATH 之后:            which('mytool') = C:\Users\...\Temp\tmppn55p9dj\faketools\mytool.BAT
```

它不会去"猜"文件在哪，只是拿着名字在清单里挨个目录找。找不到就是找不到。

### 5.5 怎么修

按从省事到麻烦的顺序，三条路：

1. **重装时勾选**。Windows 安装器第一屏有一个 "Add python.exe to PATH" 复选框，勾上，装完新开一个终端就有效。这是最省事的办法。
2. **手动加进用户 `PATH`**。打开"编辑系统环境变量"→"环境变量"，在**用户变量**里找到 `Path`，新建两条：解释器目录（例如 `C:\Users\你\AppData\Local\Programs\Python\Python312\`）和它下面的 `Scripts\`（`pip` 等命令在这里）。改完必须**新开终端**。
3. **只在当前窗口临时加**。PowerShell：

```powershell
$env:PATH += ";C:\Users\你\AppData\Local\Programs\Python\Python312"
python --version
```

这只影响当前这个窗口，关掉就没了；适合"我就试一下"。bash 里对应的是 `export PATH="$PATH:/usr/local/bin/python3"`。

macOS / Linux 上通常不用管：系统自带的 `python3` 已经在 `PATH` 里，用 `python3` 和 `pip3` 即可。

### 5.6 PATH 的边界，以及一个常见的怪现象

关于 `PATH`，只要记住四条：

- 它只管"按名字找程序"，**不影响你读写文件**。文件找不到是路径问题，不是 `PATH` 问题。
- **顺序决定赢家**：清单里靠前的目录先被查，所以同时装了两个 Python 时，`PATH` 里排在前面的那个生效。
- 改了环境变量，**已经打开的窗口不会更新**，新开的才会。
- 程序内部的查找（比如 `pip` 装包、`python` 找模块）用的是另外的规则，不是 `PATH`，第 03、14 讲分别处理。

还有一个 Windows 上常见、但和你装没装 Python 无关的现象：敲 `python` 却弹出了微软商店。这是因为"应用执行别名"里给 `python.exe` 留了一个占位入口，它指向一个打开商店的小程序。处理办法是在系统设置的"应用 → 高级应用设置 → 应用执行别名"里，把 `python.exe` / `python3.exe` 的开关关掉。本机没有触发这个现象，所以这里只作为"如果你的机器出现"来登记，不当成事实陈述。

## 6. 三个够用就好的东西

下面三样不属于"必须会"，但知道了能省很多力气。知道它们存在，遇到时再来查具体写法。

- **通配符 `*`**：`Get-ChildItem *.py` 列出所有 `.py` 文件，`ls *.csv` 同理。`*` 由 shell 展开成一批文件名。
- **重定向 `>` 与 `>>`**：`python main.py > out.txt` 把程序的标准输出写进文件（`>` 覆盖，`>>` 追加）。这和第 19 讲用 `open` 写文件是两条不同的路：重定向由 shell 完成，`open` 由你的程序完成。
- **管道 `|`**：把前一个命令的输出交给后一个命令当输入。`Get-ChildItem | Select-String py` 相当于"列出文件，再在里面筛出含 py 的行"。

再补三个用起来很舒服的操作习惯：`Tab` 键补全路径（少打很多字、也不会打错）、上箭头调历史命令、`Ctrl + C` 打断卡住的程序。

## 7. 删除为什么单独说

其他命令做错了，最多重来一次；删除做错了，东西就没了。三个事实：

1. **命令行删除不进回收站**。资源管理器里删文件是"移到回收站"，命令行是直接抹掉。
2. **递归删除会一次带走整棵子树**。"删这个目录"和"删这个目录以及里面所有东西"，在命令里只差一个参数。
3. **相对路径在不确定 cwd 时最危险**。同一句删除命令，站在不同目录下删的是不同的东西。

三条安全习惯，成本很低：

- 删之前先 `pwd` 看自己在哪，再 `Get-ChildItem`（或 `ls`）看要删的东西到底有哪些；
- 不熟的东西不删，先改名放到一边；
- 关键目录要么有备份，要么已经进 git（第 04 讲），要么两者都有。

本讲不给可直接复制的递归删除命令，理由很简单：这种命令的正确用法只有"你完全清楚自己在删什么"这一种，而照抄的人通常不清楚。

## 8. 这一讲留下的东西

- **cwd 是相对路径的起点**。你启动的 Python 继承 shell 的 cwd，所以"文件找不到"先查自己在哪。
- **`PATH` 是命令的查找清单**。找不到命令先 `where`（Windows）或 `which`（Unix），再想是不是没进 `PATH`。
- **路径三种写法**：绝对、相对、带 `.` / `..`。代码里统一用 `/`，带空格的路径在终端里加引号。

这三条会在后面反复出现：第 03 讲装环境时 `PATH` 会再出现一次；第 19 讲处理文件路径时会正式用 `pathlib`；第 04 讲讲 git 时会用到"当前目录"这个概念（仓库就是"当前目录及其子目录"）。

## 小结

- 终端是窗口，shell 是解释命令的程序，命令行是你敲的那一行；提示符由 shell 打印，里面通常包含当前目录。
- 文件系统是一棵树，Windows 每个盘符一棵，Unix 只有一棵（根是 `/`）。
- 绝对路径从根写起，相对路径从**当前工作目录**写起；`.` 是当前目录，`..` 是上一级。
- 同一个脚本、同一行相对路径，cwd 不同就可能一个成功一个失败；`FileNotFoundError` 里给的是解析后的路径。
- Windows 大小写不敏感、两种分隔符都认；Unix 大小写敏感、只认 `/`。代码里统一写 `/`。
- 带空格的路径在终端里必须加引号，否则 shell 会把一个路径拆成两个参数。
- 命令找不到，多半是它所在目录不在 `PATH` 里，或者当前 shell 看不到；`PATH` 顺序决定哪个版本先被找到。
- 命令行删除不进回收站，递归删除会带走整棵子树；删之前先确认 cwd 和待删清单。

## 作业

**Q1.** 磁盘上有这样一棵树：`C:\lab\data\raw\a.csv`。你现在的当前目录是 `C:\lab\data`。写出 `a.csv` 的一个相对路径和一个绝对路径。

**参考答案：** 相对路径 `raw\a.csv`（也可以写 `.\raw\a.csv`，`.\\` 表示当前目录，等价）；绝对路径 `C:\lab\data\raw\a.csv`。

如果当前目录是 `C:\lab`，同一个文件的相对路径就变成 `data\raw\a.csv`——相对路径永远相对"你现在在哪"，所以每次写之前都要先确认 cwd。

**Q2.** 提示符显示 `PS D:\work\proj>`。请说出三件事：当前 shell 是什么、当前目录是什么、`>` 是什么。

**参考答案：** 当前 shell 是 PowerShell（`PS` 前缀）；当前工作目录是 `D:\work\proj`；`>` 是提示符与本行输入的分界，说明它在等你输入命令。

补充：这说明你已经不在 C 盘，接下来敲的相对路径都从 `D:\work\proj` 算起。

**Q3.** 运行 `python main.py` 得到：

```text
python: can't open file 'main.py': [Errno 2] No such file or directory
```

`main.py` 确实存在于某个文件夹里。请给出两个可能原因，以及两条排查命令。

**参考答案：** 两个可能原因：(1) 当前工作目录不是 `main.py` 所在的那一层，相对路径 `main.py` 从别处找；(2) 文件名其实不是你看到的样子，比如真实名字是 `main.py.txt`（扩展名被隐藏），或者拼写、大小写在某个区分大小写的系统上不一致。

排查：先 `pwd`（PowerShell 里 `Get-Location`）确认当前目录；再 `Get-ChildItem`（或 `ls`）看这一层到底有哪些文件，必要时用 `Get-ChildItem -Recurse -Filter main.py` 在子目录里找。

**Q4.** 在 Windows 上，`where.exe python` 输出"信息: 用提供的模式无法找到文件。"，而 `where.exe git` 能正常输出路径。这两条结果分别说明什么？至少给两条修复路线。

**参考答案：** 说明 `git` 所在的目录在 `PATH` 里，而 `python` 这个名字在 `PATH` 的任何目录下都找不到对应可执行文件——可能是没装、装的时候没勾选加入 `PATH`、或者装了但当前窗口的环境变量还是旧的。

修复路线：(1) 重新运行安装器，勾选 "Add python.exe to PATH"；(2) 在用户环境变量 `Path` 里手动加上解释器目录与其下的 `Scripts\` 目录，然后**新开**终端；(3) 临时在当前窗口用 `$env:PATH += ";C:\...\Python312"` 试一次，确认能用了再做永久配置。

**Q5.** 动手做一遍（在 PowerShell 里）：在桌面上建一个 `lab` 目录，在它下面建 `notes` 子目录，把一个已有文件复制进 `notes` 并改名为 `memo.txt`，最后打印它的内容。写出你用的命令。

**参考答案：** 在 PowerShell 里依次执行下面六行（`win.ini` 只是一个现成的文件，换成你手头任何文件都可以）：

```powershell
cd $HOME\Desktop
mkdir lab
cd lab
mkdir notes
Copy-Item C:\Windows\win.ini .\notes\memo.txt
Get-Content .\notes\memo.txt
```

要点：`mkdir` 在 PowerShell 里是 `New-Item -ItemType Directory` 的别名；`Copy-Item` 的第二个参数是"目标路径"，如果目标以文件名结尾，就是"复制并改名"；`Get-Content` 打印文件内容。

在 macOS / Linux 上等价写法是 `mkdir -p lab/notes`、`cp 源 lab/notes/memo.txt`、`cat lab/notes/memo.txt`。

**Q6.** 为什么命令行删除比在资源管理器里删除更危险？给出两条具体的安全习惯。

**参考答案：** 因为命令行删除通常不进回收站，删掉就没了；而且递归删除会在一条命令里带走整棵子树，打错一个字符的代价远大于点鼠标。

两条习惯：(1) 删之前先 `pwd` 确认当前目录、再用 `Get-ChildItem` 或 `ls` 列出准备删除的东西，看清了再删；(2) 不确定就先改名挪到一边，或者确保项目已经在 git 里（第 04 讲），这样至少能恢复到上一次提交。
