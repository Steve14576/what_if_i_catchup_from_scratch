## 0. 场景：三件需要"一串东西"的事

- 一个班的成绩要排序、算平均、取前三名；
- 一张二维表（行与列）要逐格填数；
- 一个坐标 `(x, y)` 从函数里返回，既要取出两个值，又不能被人误改。

前两件用列表，第三件用元组。它们看起来都是"一串东西"，但一个能改、一个不能改——这个差别决定了后面所有行为。

下一节先看列表的基本形态：有顺序、可修改、可混装。

## 1. 列表：有顺序、可修改、可混装

### 1.1 创建与访问

```python
xs = [3, 1, 2]
```

方括号、逗号分隔。实测：

```text
  xs = [3, 1, 2]   len = 3   第一个 = 3   最后一个 = 2
  切片 xs[:2] = [3, 1]
```

索引与切片的规则和第 11 讲的字符串**完全一样**：从 0 开始、负索引从尾部数、切片含起点不含终点、越界切片自动截断。

列表还允许混装不同类型：

```text
  可混装不同类型: [1, 'two', 3.0, True, None]
```

这不是"随便"：很多时候一个记录就是"名字、分数、是否及格"三样不同类型的东西。但混装会让代码难读，工程上更常用元组或字典来表示一条记录（第 13 讲）。

### 1.2 增删改查

```text
  append(9)        -> [3, 1, 2, 9]
  extend([7, 8])   -> [3, 1, 2, 9, 7, 8]
  insert(0, 100)   -> [100, 3, 1, 2, 9, 7, 8]
  pop()            -> 返回 8，剩下 [100, 3, 1, 2, 9, 7]
  remove(100)      -> [3, 1, 2, 9, 7]
  index(1) = 1   count(1) = 1
```

几个必须分清的点：

- `append(x)` 在**末尾加一个元素**；`extend([...])` 把另一个序列的**每个元素**依次加进来；`append([7, 8])` 会把整个列表当成**一个元素**塞进去，得到 `[..., [7, 8]]`。
- `insert(位置, 值)` 在下标处插入，后面的元素顺延。
- `pop()` 默认删末尾并**返回**被删的元素；`pop(0)` 删第一个。`remove(值)` 删除**第一个匹配的值**，不返回值。
- `index(值)` 返回第一个匹配的下标，找不到抛 `ValueError`；`count(值)` 数出现次数。

### 1.3 与字符串方法的关键区别

先记一句总纲：列表方法是"就地修改"，字符串方法是"返回新对象"。

实测里 `append`、`insert`、`remove` 都没有返回值（返回 `None`），你只能看列表本身的变化。而第 11 讲的 `strip()`、`replace()` 都返回新字符串、原字符串不变。

这个区别的后果：写 `xs = xs.append(9)` 会把列表换成 `None`。凡是"方法名是动词且对象可变"的，先想一下它到底改谁。

列表本身清楚了，下一节看排序：`sort` 与 `sorted` 的分工。

## 2. 排序：`sort` 与 `sorted`

### 2.1 `sort()` 返回 `None`

```text
  xs.sort() 的返回值 = None；sort 之后 xs = [1, 2, 3]
  sorted([3,1,2]) = [1, 2, 3]
```

这是全 Python 最经典的坑之一：

```python
xs = [3, 1, 2]
xs = xs.sort()      # 错：xs 现在变成 None
```

`sort()` 原地排序、返回 `None`；`sorted()` 返回一个新列表、原列表不动。

### 2.2 怎么选

| 你的需求 | 用哪个 | 结果 |
|---|---|---|
| 原列表可以改，就要排好的它 | `xs.sort()` | 原列表被排序，返回 `None` |
| 原列表要保留原顺序 | `ys = sorted(xs)` | 新列表，原列表不变 |
| 排序结果直接用一次 | 直接 `sorted(xs)` | 不必起名字 |
| 对元组/字符串排序 | 只能 `sorted(x)` | 元组没有 `sort` 方法（不可变） |

一句话：**要保留原件用 `sorted`，要就地改就用 `sort` 并且别接收返回值。**

### 2.3 `key` 参数（第 16 讲展开）

排序时经常要"按某个字段排"或"忽略大小写排"，那要用 `key=`：

```python
words = ["Banana", "apple", "Cherry"]
print(sorted(words, key=str.lower))
```

`key` 收一个函数，排序时对每个元素先调用它、按返回值比较。函数作为参数是第 16 讲的内容，这里知道有这条路即可。

排序定了，下一节进本讲最值钱的一节：别名、切片、拷贝三组对照。

## 3. 别名、切片、拷贝：三组必须分清的操作

这一节是全课最容易出错的地方。三组写法看起来差不多，效果完全不同。

### 3.1 `b = a`：别名（同一个对象，两张标签）

```text
  a = [1,2,3]; c = a; c.append(4)
  -> a = [1, 2, 3, 4]   c = [1, 2, 3, 4]   是同一个对象吗 = True
```

`c = a` 没有复制任何东西，只是多了一张标签。改 `c` 就是改 `a`——第 09 讲的标签模型在这里第一次产生实际后果。

### 3.2 `b = a[:]`：浅拷贝（新对象，但只复制第一层）

```text
  a = [1, 2, 3]   b = a[:] 后 b.append(4) -> b = [1, 2, 3, 4]
  a 变了吗 = [1, 2, 3]   是同一个对象吗 = False
```

`a[:]`、`list(a)`、`a.copy()` 三种写法都是浅拷贝：造一个新列表，把原列表里的元素**引用**逐个放进去。

对"元素都是数字/字符串"的列表，浅拷贝就等于完全独立。但对嵌套列表就不成立了：

```text
  nested = [[1, 2, 99], [3, 4]]
  shallow = nested[:] 后 shallow[0].append(99)
  外层是同一个对象吗 = False；内层是同一个对象吗 = True
```

外层确实是新列表，但两个列表的**第二层元素指向同一批内层列表**。所以 `shallow[0].append(99)` 改的是那个共享的内层列表，`nested[0]` 自然跟着变。

### 3.3 `copy.deepcopy`：连内层一起复制

```text
  deepcopy 之后改 deep[0] -> nested = [[1, 2, 99], [3, 4]]   deep = [[1, 2, 99, 1000], [3, 4]]
```

`copy.deepcopy(nested)` 递归复制所有层级，改副本完全不影响原件。代价是慢，而且如果对象里有"不该复制的东西"（比如文件句柄），会出问题。日常原则：**能用浅拷贝就用浅拷贝，只有确实嵌套了可变对象才上 deepcopy。**

| 写法 | 结果 | 适用 |
|---|---|---|
| `b = a` | 同一个对象（别名） | 只想要另一个名字 |
| `b = a[:]` / `a.copy()` / `list(a)` | 新列表，元素引用共享 | 列表元素不可变（数字、字符串） |
| `b = copy.deepcopy(a)` | 完全独立的新对象树 | 嵌套列表、嵌套字典 |

### 3.4 经典坑：`[[0] * 2] * 3` 共享内层

```text
  grid = [[0]*2]*3; grid[0][0] = 1
  -> [[1, 0], [1, 0], [1, 0]]
  三行是同一个内层吗 = True
  用推导式重建: [[1, 0], [0, 0], [0, 0]]
```

`[[0] * 2] * 3` 的意思是"把一个内层列表的引用复制三份"，所以三行其实是同一个列表。改一格，三行都变。

正确写法是**逐行新建**：`[[0] * 2 for _ in range(3)]`（列表推导式，第 14 讲正式讲）。这条坑在初始化矩阵、游戏棋盘时几乎人人踩过一次。

三种"复制"分清了，下一节看元组：不可变序列怎么用。

## 4. 元组：不可变的有序序列

### 4.1 创建与解包

```text
  point = (3, 5)   point[0] = 3   len = 2
  解包: x = 3, y = 5
```

元组用圆括号（其实逗号才是关键），支持索引与切片，但**不能修改**：

```text
  point[0] = 9 -> TypeError: 'tuple' object does not support item assignment
```

解包是元组最有用的特性：`x, y = point` 一行取出两个值。函数返回多个值时，实际上返回的就是一个元组（第 15 讲）。

### 4.2 单元素元组必须带逗号

```text
  单元素元组 (7,) 的类型 = tuple；写 (7) 的类型 = int
```

`(7)` 只是"加了括号的 7"，类型还是 `int`。要表示"只有一个元素的元组"，必须写 `(7,)`。这个逗号不是装饰，是语法。

### 4.3 元组里放列表，还算不可变吗

```text
  元组里放列表，改列表是允许的: ([1, 2, 3], 'tag')
```

"元组不可变"指的是**元组这一层的元素绑定不能换**：你不能写 `t[0] = 别的列表`。但如果元素本身是可变对象（列表），改它的内容是可以的——因为那没有替换元组里的引用。

所以准确说法是：**元组保证"指向不变"，不保证"内容绝对冻结"。** 想要真正冻结，里面的元素也必须是不可变的（数字、字符串、元组）。

### 4.4 什么时候用元组

| 场景 | 推荐 | 理由 |
|---|---|---|
| 一组会增删的数据（成绩、待办） | 列表 | 需要修改 |
| 固定结构的一条记录（坐标、RGB、日期） | 元组 | 语义上"这几样是一体的、不该被改" |
| 函数返回多个值 | 元组 | 调用方解包即可 |
| 想当字典的键 | 元组 | 列表不能（见下一节） |
| 需要排序 / 追加 | 列表 | 元组没有 `sort` / `append` |

判据一句话：**"这些元素以后还要不要改"，要改就用列表。**

元组规则清楚了，下一节回答一个顺带的问题：为什么元组能当字典键、列表不能。

## 5. 可哈希：为什么元组能当键、列表不能

```text
  hash((1, 2)) = -3550055125485641917
  hash([1, 2]) -> TypeError: unhashable type: 'list'
```

`hash(x)` 算出一个整数"指纹"。只有**可哈希**的对象才能当字典的键或放进集合（第 13 讲）。规则是：**可变对象不可哈希**——因为它的内容会变，指纹就不稳定了。

所以：

- 元组可以当键（只要里面的元素也都可哈希）；
- 列表不能当键；
- 字符串、数字可以当键（不可变）。

一个容易忽略的推论：`(1, [2])` 这个元组**不能**当键，因为它里面含列表，同样不可哈希。这里的 `hash` 只是用来演示规则，第 13 讲会正式用字典与集合。

可哈希讲完，下一节补序列的通用操作。

## 6. 通用序列操作

```text
  nums = [4, 1, 7]   len=3   sum=12   max=7   min=1
  7 in nums = True   9 in nums = False
  [1, 2] + [3] = [1, 2, 3]   [0] * 3 = [0, 0, 0]
```

这些操作字符串与元组也支持（`sum` 除外，它要数字）。两条实践提醒：

- `in` 在列表里是**逐个比较**，列表很长时慢；要频繁判断"在不在"，该用集合（第 13 讲）。
- `+` 产生新列表，`*` 复制引用。第 3.4 节那个坑就是 `*` 的后果：`[0] * 3` 没问题（0 不可变），`[[0]] * 3` 就有问题（内层可变）。

通用操作会用了，下一节把本讲收起来。

## 7. 这一讲留下的东西

- 列表可变、元组不可变；方法上"列表就地改、字符串返回新对象"。
- `sort()` 原地排序返回 `None`；`sorted()` 返回新列表；元组只能 `sorted`。
- 三种"复制"：`=` 是别名、`[:]` 是浅拷贝、`deepcopy` 是深拷贝。
- 浅拷贝只复制第一层，嵌套可变对象仍共享；`[[0]*2]*3` 三行是同一个列表。
- 元组不可变指"指向不变"，元素本身可变则内部仍可改；单元素元组要写 `(7,)`。
- 可哈希 = 能当字典键；可变对象不可哈希。

下一讲处理"按键查值"的数据结构：字典与集合。你会看到"为什么列表不能当键""遍历时删元素会怎样""`get` 与 `[]` 该怎么选""统计词频为什么不用列表"。

## 本讲小结

- 列表用方括号、可混装，索引切片规则与字符串一致（`xs[:2]` 得 `[3, 1]`）。
- 变列表的方法就地修改：实测 `append`/`extend`/`insert`/`pop`/`remove` 后列表变化，返回值是 `None` 或弹出元素。
- `xs.sort()` 返回 `None`（实测），`sorted([3,1,2])` 返回新列表；`xs = xs.sort()` 会把列表变成 `None`。
- `b = a` 是别名（`a is c` 为 `True`，改一个两个都变）；`b = a[:]` 是新列表（`is` 为 `False`）。
- 浅拷贝只复制第一层：实测 `nested[:]` 后外层 `is` 为 `False`、内层 `is` 为 `True`；`deepcopy` 才能完全独立。
- `[[0]*2]*3` 三行是同一个内层（实测 `grid[0] is grid[1] is grid[2]` 为 `True`），要用推导式逐行新建。
- 元组不可改：`point[0] = 9` 抛 `TypeError`；`(7,)` 是元组、`(7)` 是 `int`；元组里的列表仍可改内容。
- `hash((1,2))` 可以，`hash([1,2])` 抛 `TypeError: unhashable type: 'list'`。

## 作业

**Q1.** 下面代码想给成绩排序并保存，但运行后 `scores` 变成了 `None`。为什么？给出两种正确写法。

```python
scores = [88, 72, 95]
scores = scores.sort()
```

**参考答案：** `sort()` 是就地排序，返回值是 `None`，所以赋值把 `scores` 换成了 `None`。

两种写法：

```python
scores = [88, 72, 95]
scores.sort()              # 就地排序，不接收返回值
```

```python
scores = sorted([88, 72, 95])   # 返回新列表
```

判据：想保留原列表就用 `sorted`；想就地改就只写 `scores.sort()`，别写等号。

**Q2.** `a = [1, 2, 3]`，分别执行下面三行后，`a` 与 `b` 的关系是什么？

```python
b = a
b = a[:]
b = a.copy()
```

**参考答案：** 三种写法分别对应三种关系：

- `b = a`：`b` 与 `a` 是同一个对象（`a is b` 为 `True`），改任意一个另一个都变。
- `b = a[:]`：`b` 是新列表，元素引用相同；对"元素都是数字"的列表，效果等同于完全独立。
- `b = a.copy()`：与 `a[:]` 完全等价，同样是浅拷贝。

三者都是"浅"的：如果 `a` 里装着列表，后两种写法下内层仍共享。

**Q3.** 你要初始化一个 3 行 2 列的表格，全部填 0。下面写法有什么问题？给出正确写法。

```python
grid = [[0] * 2] * 3
grid[0][0] = 1
print(grid)
```

**参考答案：** 输出是 `[[1, 0], [1, 0], [1, 0]]`——改一格，三行都变了。原因是 `* 3` 复制的是**内层列表的引用**，三行指向同一个列表（实测 `grid[0] is grid[1] is grid[2]` 为 `True`）。

正确写法是逐行新建：

```python
grid = [[0] * 2 for _ in range(3)]
grid[0][0] = 1
print(grid)      # [[1, 0], [0, 0], [0, 0]]
```

（列表推导式第 14 讲正式讲；现在可以先理解为"循环三次、每次都新建一个内层列表"。）

**Q4.** 下面的元组，能不能修改？分别说明哪一行能改、哪一行不能。

```python
t = (1, [2, 3])
t[1].append(4)
t[0] = 9
```

**参考答案：** `t[1].append(4)` 可以执行：元组里的引用没变，变的是那个列表的内容，执行后 `t` 是 `(1, [2, 3, 4])`。

`t[0] = 9` 会抛 `TypeError: 'tuple' object does not support item assignment`：这要替换元组里的元素绑定，被禁止。

所以"元组不可变"准确说是"元组这一层的指向不可变"，不是"里面所有东西冻结"。

**Q5.** 为什么 `d[[1, 2]] = "x"` 会报错，而 `d[(1, 2)] = "x"` 可以？（`d` 是字典）

**参考答案：** 字典用键的**哈希值**定位存储位置，所以键必须可哈希。列表可变，内容一变哈希就变，找不到原来的位置，因此不可哈希——实测 `hash([1, 2])` 抛 `TypeError: unhashable type: 'list'`。元组不可变，可以哈希（前提是里面元素也都可哈希），所以能当键。

顺带：`(1, [2])` 这个元组同样不能当键，因为它含列表。

**Q6.** 函数返回两个值，用元组还是列表？给出理由，并写出调用方取值的代码。

**参考答案：** 用元组。理由：返回值在语义上是"一条固定结构的记录"，调用方不需要（也不应该）去追加或删除元素；元组还省一点内存、能当字典键。列表适合"会增删的一组数据"。

```python
def min_max(nums):
    return min(nums), max(nums)      # 逗号分隔，实际返回一个元组

low, high = min_max([3, 1, 7])       # 解包
print(low, high)                     # 1 7
```

（函数定义 `def` 是第 15 讲内容，这里只看返回值的形态与解包。）
