## 0. 场景：三个账户共用一个余额

你要处理三个账户：开户、存钱、取钱、查流水。用列表或字典也能做：

```python
accounts = {
    "张三": {"balance": 100, "history": []},
    "李四": {"balance": 200, "history": []},
}

def withdraw(name, amount):
    acc = accounts[name]
    if amount > acc["balance"]:
        raise ValueError("余额不足")
    acc["balance"] -= amount
    acc["history"].append(("withdraw", amount))
```

问题不在能不能跑，而在三件事：

1. 键名是字符串，写错 `"ballance"` 不会报错，只会静默建一个新键；
2. "余额不足"这条规则散在函数里，谁都可以绕过它直接改 `acc["balance"]`；
3. 数据与操作它的函数之间没有任何约束，别人可以传进一个形状不对的字典。

类解决的是这三件事：**给状态一个固定的形状，把改动它的规则收进方法里，让调用方只能通过方法改**。

下一节先看 `class` 语句执行时到底造出了什么。

## 1. `class` 创建了什么

先看一个最小类跑出来的东西：

```text
  type(Account)             = <class 'type'>
  Account 的公开名字        = ['rate', 'tags', 'deposit', 'withdraw', 'statement']
  type(a)                   = <class '__main__.Account'>
  a.__dict__                = {'owner': '张三', 'balance': 100, '_history': [], '_Account__secret': 'pin-1234'}
  isinstance(a, Account)    = True
```

逐条读：

- `class Account:` 这一段代码执行时，Python 建了一个**类对象**，名字叫 `Account`。它的类型是 `type`——也就是说"类"本身也是对象，和函数、列表没有本质区别。
- `Account.__dict__` 里放着类自己的东西：类属性 `rate` / `tags` 和方法。上面那行我把双下划线开头的名字过滤掉了，所以看不到 `__init__`、`__module__` 这些；它们确实在里面。
- `Account("张三", 100)` 调用类是**创建实例**：它会新建一个对象，然后调用 `__init__` 把属性填进去。`type(a)` 显示 `__main__.Account`，`__main__` 是"脚本顶层"的模块名（第 17 讲讲过的 `__name__`）。
- 实例的 `__dict__` 只装**这个实例自己的**属性：`owner`、`balance`、`_history`、`_Account__secret`。方法不在里面——方法在类上。

对照一下"字典 + 函数"的写法：`Account` 相当于把"每个账户该有哪些键"固定下来；`a.__dict__` 相当于那份字典；区别是键名写错会立刻 `AttributeError`，而不是静默加一个键。

下一节回答最常见的一个疑问：方法里那个 `self` 到底是谁传进去的。

## 2. `self` 是谁

同一个方法，两种访问方式拿到的东西不一样：

```text
  Account.deposit           = <function Account.deposit at 0x...>
  a.deposit                 = <bound method Account.deposit of <__main__.Account object at 0x...>>
  a.deposit.__self__ is a   = True
  type(a.deposit)           = <class 'method'>
  用 Account.deposit(a, 50) 直接调后 a.balance = 150
```

三件事：

1. **定义在类里的是一个普通函数**，`Account.deposit` 是 function 类型，它需要一个 `self` 参数才完整。
2. **通过实例访问时才绑定**：`a.deposit` 返回一个"绑定方法"，它已经把 `a` 记住了（`__self__ is a` 为真）。你调用 `a.deposit(50)`，实际执行的是 `Account.deposit(a, 50)`。
3. 所以 `self` 不是关键字，只是一个**约定俗成的参数名**。上面第四行我故意写成 `Account.deposit(a, 50)`，效果与 `a.deposit(50)` 一样——这就是"绑定"在同层语言里的意思。

由此可以推出两个常见报错：

- 方法定义忘了写 `self`：调用时参数个数对不上，报 `TypeError: deposit() takes 1 positional argument but 2 were given`。
- 用 `Account.deposit(50)` 这样调：`50` 被当成 `self`，等用到 `self.balance` 时报 `AttributeError: 'int' object has no attribute 'balance'`。

`self` 这个名字可以换成别的（比如 `this`），但没有人这么做：全世界的 Python 代码都默认第一个参数叫 `self`，换名字只会让读代码的人多花时间。

下一节看属性到底从哪里取。

## 3. 实例属性与类属性

`rate` 定义在类里，`balance` 定义在 `__init__` 里（也就是实例上）。两者读起来一样，行为不同。实测三步：

```text
  a.rate（读类属性）        = 0.02
  a.rate = 0.05 之后        = 0.05，b.rate = 0.02，Account.rate = 0.02
  'rate' in a.__dict__      = True
  Account.rate 改为 0.03 后：a.rate = 0.05（被自己遮蔽），b.rate = 0.03
  del a.rate 之后           = 0.03  ← 又去看类属性
```

规则两条：

- **读**：先在实例的 `__dict__` 里找，找不到去类里找，再找不到去父类（第 21 讲展开）。这叫属性查找。
- **赋值**：`a.rate = 0.05` 只在 `a.__dict__` 里新建一个 `rate`，**不碰类**。所以 `b.rate` 和 `Account.rate` 都没变，`a.rate` 从此"遮蔽"了类上的那个。

`del a.rate` 把实例上的那个删掉，查找又落到类上，所以读回 `0.03`。

| 放哪 | 适合放什么 | 读写的后果 |
|---|---|---|
| 类属性 | 所有实例共享的常量、默认值、计数器 | 改类属性会影响所有"没遮蔽"的实例 |
| 实例属性（`__init__` 里赋值） | 每个实例各自的状态 | 各改各的，互不影响 |

判断标准很简单：**这个值每个实例一样吗？** 一样就放类上（比如利率默认值），不一样就放实例上（比如余额、户名）。

下一节看一个反例：类属性本身可变时会发生什么。

## 4. 可变类属性的坑

`tags = []` 写在类里，效果：

```text
  c.tags = ['vip']
  d.tags = ['vip']  ← 被连带改了
  c.tags is d.tags = True
```

原因和第 15 讲"可变默认参数"是同一个机制：`class` 语句只执行一次，`tags = []` 只建了**一个**列表；所有实例通过属性查找拿到的都是这同一个对象。`c.tags.append(...)` 是修改这个共享对象，不是给 `c` 新建属性。

修法也只有一条：**可变的东西在 `__init__` 里初始化**。

```python
class Account:
    def __init__(self, owner: str, balance: int = 0) -> None:
        self.owner = owner
        self.balance = balance
        self.tags = []      # 每个实例各建一个
```

`__init__` 每创建一个实例就执行一次，所以每个实例拿到的是各自的新列表。

顺带说清一个容易混的点：`balance: int = 0` 这种默认值放在 `__init__` 的参数上，是**每次调用时求值**的（第 15 讲：默认参数在函数定义时求值一次——`0` 不可变所以无所谓；如果写成 `self.tags=[]` 当默认参数，就会复现同样的坑）。

下一节回到方法：实例属性还能把方法挡住。

## 5. 方法也是查找出来的

```text
  e.deposit 可调用          = True
  给 e.deposit 赋 5 之后    = 5
  再调用抛                  = TypeError: 'int' object is not callable
  其它实例不受影响            = True
```

`deposit` 是类上的方法，但属性查找先看实例。你在实例上放一个同名属性，就把方法挡住了——而且挡得很彻底：调用时拿到的是 `5`，`5(...)` 当然不行。

查找顺序可以写成一张表：

| 顺序 | 位置 | 本讲例子 |
|---|---|---|
| 1 | 实例 `__dict__` | `e.deposit = 5` 后命中 5 |
| 2 | 类 `__dict__` | `c.deposit` 命中类上的函数并绑定 |
| 3 | 父类（第 21 讲） | `__init__`、`__repr__` 等来自 `object` |
| 4 | 都没有 | 抛 `AttributeError: 'Account' object has no attribute 'nonexistent'` |

这条规则解释了很多"莫名其妙"的现象：为什么给实例赋一个和类属性同名的值就"覆盖"了默认值；为什么改类属性会影响那些没被覆盖的实例；为什么方法不能被"删除"——它根本不在实例上。

下一节处理"私有"。

## 6. 私有只是约定

```text
  f.__dict__ 的键            = ['owner', 'balance', '_history', '_Account__secret']
  访问 _Account__secret      = pin-1234
  访问 _history（约定内部）   = []
  访问不存在的属性            = AttributeError: 'Account' object has no attribute 'nonexistent'
```

两套写法，两种效果：

- **单下划线 `_history`**：完全没变，就是个普通名字。它表达的是"这是内部实现，调用方别碰"，仅此而已。
- **双下划线 `__secret`**：被**改名**了。类里的 `self.__secret` 实际存成 `self._Account__secret`（前面加 `_类名`）。改名的目的是避免子类里同名属性互相覆盖（第 21 讲会看到），**不是为了安全**——你照样能写 `f._Account__secret` 读出来。

所以 Python 里没有真正的私有。想要"别人别乱改"，靠的是两样：单下划线表达意图，方法维护不变量（下一节）。如果确实需要拦截赋值，要用 `@property`，那是第 21 讲的内容。

另外那个 `AttributeError` 消息值得记住：`'Account' object has no attribute 'nonexistent'`。看到它，先想"名字拼错了"还是"这个属性根本没在 `__init__` 里创建"。

下一节把前面所有零件拼成一个能用的类。

## 7. 多实例验证：一个能用的 Account

```python
class Account:
    def __init__(self, owner: str, balance: int = 0) -> None:
        self.owner = owner
        self.balance = balance
        self._history = []

    def deposit(self, amount: int) -> None:
        if amount <= 0:
            raise ValueError(f"存款必须为正: {amount}")
        self.balance += amount
        self._history.append(("deposit", amount))

    def withdraw(self, amount: int) -> None:
        if amount > self.balance:
            raise ValueError(f"余额不足: {self.balance} < {amount}")
        self.balance -= amount
        self._history.append(("withdraw", amount))

    def statement(self) -> list[tuple[str, int]]:
        return list(self._history)
```

实测两个实例各自操作：

```text
  p: balance=120 statement=[('deposit', 50), ('withdraw', 30)]
  q: balance=180 statement=[('withdraw', 20)]
  超额取款                    = ValueError: 余额不足: 120 < 10000
  失败后 p.balance 仍为       = 120
```

四个设计要点，每一条都对应前面某节：

1. **状态在实例上**：`balance` / `_history` 都在 `__init__` 里建，所以 `p` 与 `q` 互不干扰（第 3、4 节）。
2. **不变量由方法维护**："余额不能为负"这条规则只在 `withdraw` 里检查一次。调用方没法绕过它改余额——除非直接写 `p.balance = -100`，这是约定层面的问题（第 6 节）。
3. **失败不改状态**：超额取款抛异常，`p.balance` 仍是 120。检查放在修改之前，这一点和第 18 讲"先挡再做事"是同一个思路。
4. **`statement` 返回副本**：`list(self._history)` 复制一份，调用方改返回值不会污染内部记录。这是第 12 讲"别名"的直接应用。

下一节说反话：什么时候不该写类。

## 8. 什么时候不该写类

类不是"高级写法"，它是一个取舍。三种常见的不该：

| 情形 | 更合适的写法 | 理由 |
|---|---|---|
| 只有一个动作，没有跨调用保留的状态 | 普通函数 | 类会多出 `self` 与实例化的负担 |
| 只是把几个字段打包传递 | `dict` / `tuple` / 第 21 讲的 `dataclass` | 没有行为要维护，类只是更啰嗦的字典 |
| 状态要跨多个模块共享且只有一份 | 模块级变量（第 17 讲） | "单例"用模块天然就有 |

判据一句话：**有没有"必须由某个方法维护的不变量"？** 有，就写类（比如余额不能为负）；没有，就写函数或容器。

反例：把 `read_rows` / `write_rows` 包进一个 `DataIO` 类，里面没有一个 `self` 属性被用到——这不是面向对象，这是给函数套了一层壳。

第 21 讲会补上"类与类之间"的关系（继承、多态）以及更省事的写数据类的方式（`dataclass`）。

四类现象到这里都说完了，下一节把本讲结论收起来。

## 9. 这一讲留下的东西

- `class` 语句造出一个类对象（`type(Account)` 是 `type`）；实例是另一批对象，`__dict__` 只装实例属性。
- `Account.deposit` 是函数，`a.deposit` 是绑定了 `a` 的方法；`self` 就是被绑进去的那个实例，不是关键字。
- 读属性逐层查找：实例 → 类 → 父类；赋值只在实例上新建，不影响类与其他实例。
- 类属性只在类定义时建一次；可变类属性（列表、字典）被所有实例共享，必须在 `__init__` 里建。
- 实例属性会遮蔽类上的同名方法，遮蔽后调用报 `'int' object is not callable`。
- 单下划线是约定，双下划线是改名（`_类名__属性`），两者都拦不住访问。
- 多实例互不干扰靠"状态在 `__init__` 里建"；不变量靠方法维护；返回内部容器时给副本。
- 只有当"存在必须由方法维护的不变量"时才值得写类；否则函数或字典更简单。

下一讲处理类与类之间的关系：继承到底继承了什么、`super()` 与 MRO 怎么走、`__repr__` / `__eq__` / `__len__` 什么时候被自动调用、以及用 `dataclass` 把数据类写到十几行。

## 作业

**Q1.** 下面代码想给每个账户一个空的流水列表，但运行后发现两个账户共用一份流水。为什么？给出修法。

```python
class Account:
    history = []

    def __init__(self, owner):
        self.owner = owner

a = Account("张三")
b = Account("李四")
a.history.append(("deposit", 100))
print(b.history)
```

**参考答案：** `history = []` 是类属性，只在 `class` 语句执行时创建一次；`a.history` 与 `b.history` 通过属性查找拿到的是同一个列表，`a.history.append(...)` 修改的是这个共享对象。本讲实测 `c.tags is d.tags` 为 `True`。

修法是把可变对象放进 `__init__`：

```python
class Account:
    def __init__(self, owner):
        self.owner = owner
        self.history = []
```

这样每个实例创建时各建一个新列表。

**Q2.** 下面两行分别输出什么？为什么？

```python
print(a.balance)
print(Account.balance)
```

其中 `a = Account("张三", 100)`，`Account` 只有 `__init__` 里设置了 `self.balance`，类上没有 `balance`。

**参考答案：** 第一行输出 `100`：`a.balance` 在实例 `__dict__` 里找到。第二行抛 `AttributeError: type object 'Account' has no attribute 'balance'`：`balance` 是实例属性，类上根本没有这个名字。

这说明"实例属性"和"类属性"是两套存储：`__init__` 里的 `self.balance` 写进的是实例的 `__dict__`，不是类的。

**Q3.** 下面代码为什么在第一次调用时就报 `TypeError`？给出两种修法。

```python
class Counter:
    def __init__():
        self.n = 0
```

**参考答案：** `__init__` 的定义少写了 `self`。创建实例时 Python 调用 `Account.__init__(新实例)`，于是那个实例被当成第一个位置参数、而函数不接受参数，报 `TypeError: __init__() takes 0 positional arguments but 1 was given`。

两种修法：把 `self` 加回去（唯一正确做法）；或者改用 `@staticmethod` / `@classmethod`——但初始化器必须是普通方法，所以实际只有第一种。这里列出第二种是为了说明"参数个数对不上"是这类报错的共同原因。

**Q4.** 有人写了 `withdraw` 之后，又直接在外部写 `p.balance = -50`。类的作者说"这破坏了封装"。从本讲的内容出发，说明这句话在 Python 里意味着什么，以及有什么办法减少这种事。

**参考答案：** Python 没有强制封装：`p.balance = -50` 一定成功，因为属性赋值不经过任何检查（第 6 节：私有只是约定）。所谓"破坏"是指绕过了 `withdraw` 里那条"余额不能为负"的检查，对象进入了不该有的状态。

减少办法有三层，强度递增：

1. 命名约定：内部字段用 `_balance`，并在文档字符串里写清"请通过 `deposit` / `withdraw` 修改"；
2. 只读属性：用 `@property` 暴露 `balance` 的读，不提供 setter（第 21 讲）；
3. 真正的管控：把值存在内部字段里、由方法统一维护，调用方拿不到可写入口。

第一层是多数项目的做法；后两层在需要保证不变量时使用。

**Q5.** 判断对错并说明理由：
(a) `self` 是 Python 的关键字；
(b) 类属性对所有实例是只读的；
(c) 在实例上赋值同名的属性，会覆盖类属性；
(d) 双下划线属性在类外部无法访问。

**参考答案：** 四条逐一看：

- (a) 错。`self` 只是第一个参数的约定名，换成 `this` 也能跑；它不是关键字。
- (b) 错。类属性可写（`Account.rate = 0.03` 本讲实测生效），影响所有"没有被实例遮蔽"的实例。
- (c) 对，但要精确：它**遮蔽**了类属性，不是修改它。`a.rate = 0.05` 后 `Account.rate` 仍是 0.02（本讲实测），`del a.rate` 后又能读到类上的值。
- (d) 错。它被改名为 `_类名__属性`，直接写 `f._Account__secret` 就能访问（本讲实测打印出 `pin-1234`）。

**Q6.** 把一个"字典 + 函数"的账户管理改写成类，至少要保留哪三样东西？各对应本讲哪一节？

**参考答案：** 三样：

1. **每个账户独立的状态**：余额与流水在 `__init__` 里建，对应第 3、4 节（实例属性 vs 类属性）；
2. **只能通过方法修改余额**：`deposit` / `withdraw` 里检查不变量（正数、不透支），对应第 7 节；
3. **可查询但不暴露内部容器**：`statement()` 返回副本，对应第 7 节第 4 点（以及第 12 讲的别名）。

可选加分项：用 `_history` 表达"内部"，对应第 6 节的命名约定。做到这三样，"字典 + 函数"那三个问题（键名拼错、规则可绕过、形状不受约束）就都解决了。
