# Python 程序设计 PLAN（作者自用，不给读者）

## 一、目标，读者画像与要求

- **课程目标（行为化）**：学完能独立完成这些事，而不是"认得语法"。
  1. 拿到一个空目录，能配置出可运行的环境（建虚拟环境、装包、选定解释器、在终端里跑脚本），并能解释自己刚才每一条命令改动了什么。
  2. 用 Python 写 50–300 行的单文件脚本：读文件、清洗文本、用字典/列表做统计、把结果写回文件或打印成表。
  3. 遇到报错时能读 traceback 定位到具体一行，而不是重跑或猜；能自己造最小复现。
  4. 能把手写逻辑封装成函数与类，说清"什么时候该用类、什么时候用 dict 就够"。
  5. 能用 git 保管自己的代码：每改一小步就提交，改坏了能退回上一版，并把项目推送到远程。
  6. 能读别人的代码与第三方库文档，知道去哪儿找标准库的现成工具，而不是自己重写。
  7. 能用 AI 编码工具完成上述工作中的一部分，并且有能力审查它给出的 diff、判断它是否在编造，知道什么任务不该交给它。
  8. 应付国内大学《Python 程序设计》期末试卷与计算机二级 Python 语言部分（公共基础模块除外，见下）。

- **读者画像**：零基础，没写过任何程序；理工科在读，期末前有一段时间但不宽裕；能接受在终端里敲命令，但对"终端为什么存在"完全没有概念；对 git、虚拟环境、AI 编码工具都只听过名字。默认阅读状态是"时间不长不短但有点小急"，要求知识点密集可检索、同时能被讲通。

- **旧经验误会清单**（每条都要在未来正文中有对应的破误段，不默认读者会自己纠正）：
  - **变量是盒子**：数学里 $x$ 是一个待求的数，所以"变量里装着数"。实际是名字贴在对象上，两个名字可以贴同一对象。
  - **电脑懂人话**：以为写 `打开文件` 这种中文或半英文就能跑；以为报错是因为"它不理解我"。
  - **报错 = 我笨**：把 traceback 当判决书而不是线索，第一反应是删掉重写。
  - **会语法 = 会编程**：以为背完 `for`、`if` 的语法就能写程序，不知道"数据结构选择"才是真正的分水岭。
  - **虚拟环境是花架子**：以为那是大项目才用的仪式，`pip install` 到全局也能跑，所以跳过。
  - **git 是网盘/备份**：以为 git 就是"把文件夹传上去"，不知道它保存的是可回退的快照历史。
  - **AI 写完就是对的**：以为 agent 说"已修复"就等于修好了，从不看 diff。
  - **程序必须一次写对**：不知道正常开发是"写一点、跑一点、错一点、改一点"，把调试当失败。
  - **Python 慢所以不适合干正事**：不知道瓶颈通常在算法与数据结构选择，而不是语言（本课程在性能一节用测量说话）。

- **借鉴材料**：无指定教材。范围按国内大学《Python 程序设计》通用教学大纲 + 计算机二级 Python 语言程序设计（不含公共基础知识：数据结构与算法、程序设计基础、软件工程、数据库、计算机系统，那属于考试的另一半，本课程不承担，末讲给一句交代）。标准库覆盖面参照 Python 3.12 官方文档的教程与标准库索引。

  - 语言基线：Python 3.12（机房若是 3.8–3.10，凡涉及差异处（`match`、`tomllib`、f-string 嵌套引号、`int.bit_count` 等）就地标注最低版本）。

  - 图策略：以下必须有图，不许只写文字——名字与对象的绑定关系（箭头图）、浅拷贝/深拷贝的嵌套结构、列表的索引与切片边界、字典哈希表的分桶示意、git 三区与提交链、异常继承树的最小版、for 循环背后的迭代协议（iter/next）、模块搜索路径顺序、类与实例的属性查找。图内文字只用 matplotlib mathtext 能渲染的写法（`\le` 写成 `≤`）。

### 02 把你的机器配成能干活的工位

> 本讲定位：见面熟。目标是"知道有这么几样东西、以后卡住时知道去哪儿找"，不是背命令。

1. `PATH` 与环境变量：为什么系统"找不到"你的命令
   ① 敲一个命令 → shell 在 `PATH` 列出的目录里按顺序找同名可执行文件 → 找到就运行，找不到就报 `command not found` → 所以"装了但用不了"通常是没进 `PATH`
   ② 边界：会看 `PATH`、会临时改、会判断"哪个 python 在生效"（`where python`）；系统级持久化改动不教（有风险，且多数场景不需要）
   ③ 接：为什么我装了 Python 却提示不是内部或外部命令；`where python` 出来好几个，用哪个
   ④ 例题 1 道：用 `where python` 找出机器上所有解释器，逐个 `--version` 对照
   ⑤ 易错：Microsoft Store 的 `python` 别名指向一个空壳；改了环境变量不重开终端

2. Python 从哪来：安装来源、多版本与 `py` 启动器
   ① 三种来源（官网安装包、Store 别名、uv 托管）→ 各自装到不同目录、注册不同入口 → 多版本共存时需要一个"选版本"的入口（Windows 的 `py -3.12`、类 Unix 的 `python3.12`）
   ② 边界：会装、会切、会确认当前版本；编译安装与源码构建不讲
   ③ 接：机房是 3.8，我本机是 3.12，代码会不会跑不了；怎么同时留两个版本
   ④ 例题 1 道：用 `py -0` 列出已装版本，用一个指定版本跑同一脚本
   ⑤ 易错：`python` 与 `python3` 在不同系统指向不同版本；把 3.13 的新语法写进要交到 3.8 机房的作业

3. 虚拟环境：一个项目一套依赖
   ① 全局 `site-packages` 只有一份 → 两个项目要不同版本的同一个包就会互相踩 → `venv` 在项目目录里造出一个独立目录（含解释器链接 + 独立 `site-packages` + 激活脚本）→ 激活后 `python`/`pip` 指向这一份
   ② 边界：会建、会激活、会退出、会删（删目录即可）；会解释"激活改的只是当前终端的环境变量"；不激活也能用的写法（`\.venv\Scripts\python.exe xxx.py`）要会给
   ③ 接：虚拟环境里装的东西为什么在别的终端里不见了；`.venv` 要不要提交到 git；删了会不会弄坏系统 Python
   ④ 例题 1 道：同一个包在两个 venv 里装不同版本，分别打印版本号，证明互不干扰
   ⑤ 易错：激活失败（执行策略限制）就以为 venv 坏了；在 IDE 里选错解释器导致"明明装了却 import 不到"

4. `pip` 与包索引：装一个包到底发生了什么
   ① `pip install 名字` → 去包索引（默认 PyPI，国内可换镜像）查元数据 → 解析依赖图、下载 wheel → 解压到当前解释器的 `site-packages` → `import` 时按 `sys.path` 找到它
   ② 边界：会 `install`/`uninstall`/`list`/`freeze`/`show`、会用 `-i` 换源；会读"版本冲突"的报错大意；不讲依赖解析算法
   ③ 接：为什么装完还是 `ModuleNotFoundError`（装到了另一个解释器）；为什么 `pip freeze` 出来的东西一大堆；`-i` 换源安全吗
   ④ 例题 1 道：在 venv 里装一个纯 Python 包，用 `pip show` 找到它的安装位置，再用 `python -c "import 包; print(包.__file__)"` 对照
   ⑤ 易错：`pip` 与 `python -m pip` 不是一回事；用系统 `pip` 装包然后困惑于项目里没有

5. `uv`：它快在哪，和 `pip` 是什么关系
   ① `uv` 是一个用 Rust 写的 Python 工具链（管解释器、环境、依赖、运行）→ 它兼容 `pip` 的命令形态（`uv pip install`）但自己维护锁文件 `uv.lock` 与项目元数据 `pyproject.toml` → `uv run` 会先确保环境与锁文件一致再运行脚本
   ② 边界：会 `uv venv`/`uv pip install`/`uv run --with X python a.py`/`uv sync`；不需要会它的全部子命令；说明"它不替代 Python 本身"
   ③ 接：既然有 pip 为什么还要 uv；`uv run --with numpy` 和我自己建环境装 numpy 有什么区别；锁文件要不要入库
   ④ 例题 1 道：用 `uv run --with` 在没有任何预装环境的目录里跑一个需要第三方包的脚本，对照 `python 脚本` 的失败
   ⑤ 易错：把 `uv pip install` 当成全局安装（它默认作用于当前环境/项目）；离线环境下 `uv run --with` 需要缓存命中

6. `conda`、`poetry`、`pipx`：它们各自想解决什么
   ① `conda` 管的是"整个软件栈"（含非 Python 的二进制依赖与 CUDA 这类东西）→ `poetry` 管的是"项目依赖 + 打包发布"→ `pipx` 管的是"把命令行工具装成全局可执行"；三者与 venv+pip 不是替代关系，而是不同粒度的封装
   ② 边界：知道什么时候会遇到它们（科研/数据环境、要发布库、要装 CLI 工具）；不要求会操作（认识层）
   ③ 接：学校机房为什么用 conda；我该选哪个（给出决策：先 venv+pip，想要快与锁用 uv，要非 Python 依赖再考虑 conda）
   ④ 例题 0 道（本讲认识层，不设操作题；作业里给一个判断场景题）
   ⑤ 易错：在 conda 环境里用系统 pip 装包把环境搞乱；以为装了 conda 就不需要 venv

7. 编辑器、IDE 与"运行按钮"背后

   ② 边界：会选解释器、会开集成终端、会打断点单步；插件生态与快捷键不穷举
   ③ 接：为什么同一个脚本在 IDE 里能跑、在终端里报 `ModuleNotFoundError`；断点和 `print` 该用哪个
   ④ 例题 1 道：在 IDE 里把解释器切成另一个 venv，观察 `sys.executable` 的变化，证明"按钮改了命令"
   ⑤ 易错：把 IDE 的"运行"当成程序的一部分；在 IDE 的工作目录假设下写相对路径

8. 编码、换行与控制台：乱码的三个来源
   ① 字符 → 码点（Unicode 负责）→ 字节（UTF-8/GBK 负责）→ 终端按自己的码页解码并找字形 → 任一环节不匹配就乱码；Windows 控制台历史默认 GBK 码页是其主因
   ② 边界：会 `chcp` 看/改码页、会在 `open()` 里显式写 `encoding="utf-8"`、会处理 BOM；字体缺字形属于显示层，讲清现象即可
   ③ 接：为什么我的中文在 VS Code 里正常、在 cmd 里是问号；`UnicodeDecodeError: 'gbk' codec can't decode` 怎么办；Excel 打开 CSV 全是乱码怎么救
   ④ 例题 1 道：同一个 UTF-8 文件，分别在 GBK 与 UTF-8 码页的控制台下打印，对照现象并解释
   ⑤ 易错：把"改文件编码"和"改终端码页"当成一回事；用 `errors="ignore"` 掩盖问题

9. 卡住时的自检顺序（本讲收束）
   ① 现象 → 先分四类：命令找不到（PATH）→ 模块找不到（解释器/环境）→ 打不开文件（路径/cwd/权限）→ 乱码（编码/码页）→ 每一类都有一条最短定位命令
   ② 边界：给四类各一条检查命令与一句"怎么修"；不追求覆盖全部环境故障
   ③ 接：我怎么知道是哪一类；报错信息哪一句才是关键
   ④ 例题 1 道：给四个故障现象，逐个判断类别并写出第一条该敲的命令
   ⑤ 易错：遇到任何错误先重装 Python；把"我改了很多东西"当成解决问题的方法

### 03 版本控制与敢改的底气：git 与 AI 结对

> 本讲定位：git 讲成"可回退"，AI 讲成"会编、要审"。两条都要落到日常动作上，不追求覆盖全部命令。

1. git 解决的是"回退"，不是"备份"
   ① 手写 `final_v2_真正最终版.py` → 版本爆炸、无法比较、无法知道改了什么 → git 把每次提交存成一个完整快照并串成历史 → 任何一次提交都能取回、任意两次能比较
   ② 边界：只讲本地单人用法；协作流程（PR、review、分支策略）认识层
   ③ 接：git 和网盘/OneDrive 有什么区别；我只是自己写作业需要 git 吗
   ④ 例题 1 道：同一份文件手工造三个"最终版"与 git 三个提交，分别回答"上周三那版第 12 行是什么"
   ⑤ 易错：把 git 当自动备份（不 commit 就没有历史）；以为提交就等于上传

2. 三个区域与一次提交的完整路径
   ① 工作区（磁盘上的文件）→ `git add` 把改动放进暂存区（一张"这次要提交什么"的清单）→ `git commit` 把暂存区固化为一个快照并移动 `HEAD` → `git log` 从 `HEAD` 往回走历史
   ② 边界：要能画出三区图并说出每条命令移动的是哪一格；分支与合并只到"分支是指向提交的可移动标签"（认识层）
   ③ 接：为什么我 `commit` 了但同事看不到（没 push）；`add` 和 `commit` 为什么要分开；`git status` 里那些颜色分别是什么意思
   ④ 例题 1 道：新建仓库 → 改文件 → 分两次 `add`+`commit` → 用 `log --stat` 与 `diff` 证明"每次提交只含一件事"
   ⑤ 易错：`git add .` 一把梭把 `.venv` 与数据文件都加进去

3. 回退的决策表：改坏了到底该敲哪条
   ① 问三个问题：改动是否已提交？是否已推送？是要"撤销这次改动"还是"保留历史再补一次反向改动"？→ 未提交用 `restore`；已提交未推送可 `reset --hard`（危险，丢历史）；已推送只能 `revert`（新增一次反向提交）
   ② 边界：给四行决策表；`reset --hard` 必须标注"会永久丢弃未提交改动"，并要求先 `git status` 确认
   ③ 接：`reset --hard` 到底丢了什么；删掉的提交还能救回来吗（`reflog` 认识层）；`checkout` 和 `restore` 的混乱关系
   ④ 例题 1 道：给三种"改坏了"的场景，各写出应按的命令与事前检查动作
   ⑤ 易错：在有未提交改动时 `reset --hard`；把 `revert` 当成"删除提交"

4. `.gitignore` 与"什么东西绝不该进仓库"
   ① 仓库该存"人和工具都能重造出来的东西"（源码、配置模板、说明）→ 不该存"能重造的"（`.venv`、`__pycache__`、`.pyc`）与"不能公开的"（密钥、token、个人数据）→ `.gitignore` 是这份名单的机器可读形式
   ② 边界：会写常见模式（`*.log`、`/data/`、`!.gitkeep`）；已误提交后怎么清（`git rm --cached` 认识层）
   ③ 接：为什么 `.venv` 不能提交；我提交了密钥怎么办（改密码 + 清历史，一句交代）；空目录 git 为什么不跟踪
   ④ 例题 1 道：给一个真实项目目录结构，写出 `.gitignore`，并用 `git status` 验证该忽略的都灰了
   ⑤ 易错：把 `data/` 大文件提交导致仓库膨胀；先 commit 再补 `.gitignore`（列表对已跟踪文件无效）

5. 远程仓库：`clone` / `pull` / `push`
   ① 远程仓库是另一份完整历史 → `clone` 复制过来（含全部提交）→ `push` 把自己新增的提交送过去 → `pull` 把对方新增的取回并合并 → 冲突发生在"同一处被两边改过"时
   ② 边界：会 clone/pull/push 与读冲突标记（`<<<<<<<`）；不展开 PR 流程与团队规范
   ③ 接：为什么 push 被拒绝（对方有新提交）；冲突的那几行我该删哪些；能不能强制推送（危险）
   ④ 例题 1 道：两个本地目录模拟"两台机器"，制造一次冲突并按正确顺序解决
   ⑤ 易错：`push -f` 覆盖别人提交；在冲突未解决时继续提交

6. AI 编码工具在做什么：一次请求背后的循环
   ① 你的话 + 项目里的文件片段被塞进上下文 → 模型逐 token 预测出"下一步动作"（读文件/改文件/跑命令）→ 工具执行并把结果塞回上下文 → 循环直到它认为完成 → 所以它的能力边界由"上下文里有什么"和"它能不能验证"决定
   ② 边界：讲清机制即可；不比较具体产品、不讲训练与微调
   ③ 接：为什么它改了我没让它改的文件；为什么它信誓旦旦说某个函数存在其实没有；为什么同一句话两次结果不同
   ④ 例题 1 道：让 AI 改一个脚本，要求它先说明要改哪几行；对照它实际 diff，找出"多改的"或"没改到的"
   ⑤ 易错：把"它说改好了"当验收；一次让它改十个文件

7. 幻觉的三种可识别信号与验证办法
   ① 幻觉来源：模型在补"最像的下一个 token"，而不是在查证 → 三类信号：编造 API（函数/参数/字段不存在）→ 编造文件与路径 → 编造"我已经运行并验证" → 验证办法统一是"跑一遍 + 查文档 + 看 diff"
   ② 边界：给三类信号与三条验证动作；不承诺穷举
   ③ 接：它给的代码看着很合理为什么一跑就错；它说跑过了但明明没跑；它引用的文档章节是真的吗
   ④ 例题 1 道：让它调用一个不存在的库函数，观察它如何"补全"出一个看似合理的用法，再用 `help()`/官方文档证伪
   ⑤ 易错：因为代码能跑就认为逻辑对；把 AI 的自信当证据

8. 与 AI 协作的动作纪律（可直接照做）
   ① 先 `git commit` 建立可回退点 → 把任务写成"目标 + 约束 + 验收标准 + 不许动的东西" → 要求先给计划再动手 → 只看 diff 决定接受与否 → 跑测试/跑脚本验证 → 小步提交
   ② 边界：这六步是默认姿势；学习期与涉及密钥时的禁用清单单独列
   ③ 接：我该怎么描述任务它才不乱改；它一次改了太多我怎么审；什么情况下干脆别用
   ④ 例题 1 道：给同一个需求写两版描述（模糊版 / 带验收标准版），对照两次产出与两次 diff 的可审查性
   ⑤ 易错：不提交就让 AI 大改；接受"顺手优化"带来的无关改动；把自己的密钥贴进对话

### 04 第一个程序与变量：名字、对象、类型

1. 写、存、跑：一个脚本的最小生命周期
   ① 新建 `hello.py` → 写入 `print("hello")` → 终端执行 `python hello.py` → 输出出现在终端；改一行再跑，输出随之改变
   ② 边界：只要求会"存盘 → 跑 → 看输出"；编辑器细节回呼 02 讲
   ③ 接：为什么改了没生效（没存盘/跑的是另一个文件）；为什么双击 py 文件窗口一闪而过
   ④ 例题 1 道：写三行脚本，故意在第 2 行留一个语法错误，观察报错位置与行号
   ⑤ 易错：把 `>>>` 提示符写进文件；在 REPL 里编辑长程序

2. `print` 与 `input`：最小的输入输出闭环
   ① `print` 把对象转成字符串写到标准输出（`sep` 管多个参数之间、`end` 管结尾）→ `input("提示")` 打印提示并等一行输入 → 读回来的**永远是 `str`** → 要算数必须 `int()`/`float()` 转换
   ② 边界：`print` 的格式化留到 05 讲（f-string）；`input` 在无终端环境（IDE 控制台/管道）会阻塞或读到 EOF，需知道现象
   ③ 接：为什么 `input()` 拿到 `"12"` 加 1 会报错；为什么程序"卡住不动"（其实在等输入）；`end=""` 什么时候用
   ④ 例题 1 道：读两个数求和，先写错版（不转换）跑一次看报错，再写对版
   ⑤ 易错：`int(input())` 遇到空行/空格崩溃；以为 `print` 有返回值

3. 变量不是盒子：名字绑定到对象
   ① `a = [1, 2]` 造出一个列表对象、把名字 `a` 绑到它 → `b = a` 只是把 `b` 也绑到同一对象 → `b.append(3)` 改的是那个对象 → `print(a)` 看到 `[1, 2, 3]`
   ② 边界：绑定不等于赋值拷贝；`=` 右侧先求值；同一名字可以改绑到新对象（`a = a + [3]` 与 `a.append(3)` 结果不同）
   ③ 接：为什么改了 `b` 结果 `a` 也变了；`a = a + [3]` 和 `a += [3]` 有区别吗（有，一个新建一个原地）
   ④ 例题 2 道：别名实验（上面那条链）；`+=` 与 `+` 在列表上的差别实验
   ⑤ 易错：把变量当容器，以为赋值会复制内容

4. 一切皆对象：`id`、`type` 与值
   ① 每个值都是一个对象 → 有身份（`id`，生命周期内唯一）、类型（`type`，决定能做什么）、值（`==` 比较的内容）→ 三者互不蕴含：`id` 相同必 `==`，`==` 相同 `id` 未必同
   ② 边界：`id` 的具体数值是实现细节，不可依赖；小整数 `-5..256` 与部分字符串会被复用（驻留），会造成 `is` 偶真的假象
   ③ 接：`==` 和 `is` 到底什么时候用哪个；为什么 `a = 256; b = 256; a is b` 是 True 而 257 可能不是
   ④ 例题 1 道：对同一段代码分别打印 `id`/`type`/`==`/`is`，把四列的结论写成一句规则
   ⑤ 易错：用 `is` 比较数值与字符串（应只在和 `None`/`True`/`False` 比较时用 `is`）

5. 动态类型 + 强类型：Python 的两条线
   ① 类型属于对象而不属于名字 → 同一个名字可以先绑 `int` 再绑 `str`（动态）→ 但运算要求类型相容，`1 + "1"` 直接报 `TypeError`（强）→ 两条线合起来：自由改绑，不容忍隐式瞎转
   ② 边界：与 C/Java 的"静态弱/强"对照只在表格里说清，不做语言评测
   ③ 接：那为什么 `1 + 1.0` 可以（数值类型有隐式提升）；`True + True` 为什么是 2
   ④ 例题 1 道：给六个表达式判断报错还是出结果，再实跑对照
   ⑤ 易错：以为动态类型等于可以随便加；`"1" + 1` 与 `int("1") + 1` 混为一谈

6. 内置标量类型速览：`int`/`float`/`bool`/`None`/`str`
   ① `int` 任意精度（没有溢出）→ `float` 是 IEEE754 双精度（有精度上限与误差）→ `bool` 是 `int` 的子类（`True == 1`）→ `None` 是单例，表示"没有值"→ `str` 是文本序列（05 讲展开）
   ② 边界：`bytes`/`complex`/`Decimal`/`Fraction` 只点名；不讲位宽与机器表示
   ③ 接：`2**100` 为什么能算出来；为什么 `0.1 + 0.2 != 0.3`；`None` 和 `0`/`""` 有什么区别
   ④ 例题 1 道：算 `2**100`、`2**1000`，打印位数与耗时，说明"没有溢出但有代价"
   ⑤ 易错：拿 `float` 做金额；用 `if x == None` 而不是 `if x is None`

7. 数值运算的完整形态：整除、取余、幂、舍入
   ① `/` 永远返回 float → `//` 向下取整（负数方向是朝负无穷，`-7 // 2 == -4`）→ `%` 与 `//` 满足 `a == (a // b) * b + a % b`（所以 `-7 % 2 == 1`）→ `round` 是"四舍六入五成双"（`round(2.5) == 2`、`round(3.5) == 4`）
   ② 边界：金额与精确小数用 `Decimal` 或整数分单位；`round` 不是"四舍五入"这件事必须说死；`math.isclose` 用于浮点比较
   ③ 接：`-7 // 2` 为什么不是 `-3`；`round(0.5)` 为什么是 0；怎么判断两个浮点"差不多相等"
   ④ 例题 1 道：用 `a == (a//b)*b + a%b` 验证四个正负组合；用 `math.isclose` 判断 `0.1+0.2` 与 `0.3`
   ⑤ 易错：用 `==` 比较浮点；以为 `//` 是截断（对负数是向下取整）

8. 可变与不可变：一张清单决定后面所有坑
   ① 不可变：`int`/`float`/`bool`/`str`/`tuple`/`frozenset`/`None`；可变：`list`/`dict`/`set`/自定义对象 → 不可变对象"改"其实是造新对象并改绑 → 由此推出：可变对象作函数参数会被改到外面、作默认参数会跨调用累积、作字典键不行
   ② 边界：这里只建立清单与三条推论，具体坑在 09（默认参数）、07（可哈希）、06（浅拷贝）各讲落地
   ③ 接：`s += "a"` 在字符串上是原地改吗（不是，新建）；为什么 `tuple` 里放 `list` 之后 `tuple` 也算"变了"
   ④ 例题 1 道：对六种类型做"改一下看原对象变没变"的实验，填一张表
   ⑤ 易错：以为 `tuple` 完全不可变（它只是不能换元素引用）

9. 注释与文档字符串：写给人看的那部分
   ① 注释 `#` 是给读代码的人的解释，Python 不执行 → 模块/函数/类开头的三引号字符串是 docstring，会被存进 `__doc__` 并能被 `help()` 打印 → 二者用途不同：注释解释"为什么"，docstring 说明"这是什么、怎么用"
   ② 边界：docstring 的风格规范（Google/NumPy/Sphinx）只点名；17 讲再谈文档与 README
   ③ 接：三引号字符串和注释有什么区别；`help(函数)` 打印的是哪来的
   ④ 例题 1 道：给一个函数加 docstring，用 `help()` 与 `函数.__doc__` 两种方式取出
   ⑤ 易错：用 docstring 写"临时注释掉的一段代码"；注释写"i += 1  # i 加 1"

### 05 字符串：文本从哪儿来，到哪儿去

1. `str` 是什么：码点序列，不是字节序列
   ① 字符 → Unicode 码点（`ord()` 给出整数）→ `str` 是码点的序列 → `len()` 数的是码点个数 → 存成字节时按某种编码（UTF-8 用 1–4 字节）→ 所以 `len("中文") == 2` 而 `len("中文".encode()) == 6`
   ② 边界：组合字符与 emoji（一个"字"可能是多个码点）只点名；不做 Unicode 规范展开
   ③ 接：为什么 `len` 和"看起来几个字"有时不一致；`str` 和 `bytes` 什么时候会撞上
   ④ 例题 1 道：对 `"a"`、`"中"`、`"🙂"` 分别打印 `ord`/`len`/`len(encode())`，做成表
   ⑤ 易错：把字节长度当字符长度做截断（切出半个 UTF-8 序列导致乱码）

2. 字面量的完整写法
   ① 单引号与双引号等价（选一种坚持用）→ 转义序列 `\n`/`\t`/`\\`/`\'` → 原始字符串 `r"..."` 关掉转义（写正则与 Windows 路径时用）→ 三引号可跨行且保留换行 → 相邻字面量自动拼接（`"ab" "cd"`）
   ② 边界：`\x41`/`\u4e2d`/`\N{...}` 只点名；`r` 字符串不能以奇数个反斜杠结尾
   ③ 接：Windows 路径为什么建议写 `r"C:\new"`；三引号写 SQL/JSON 时缩进会带进去怎么办
   ④ 例题 1 道：用五种写法表达同一个含引号与反斜杠的字符串，打印 `len` 与内容对照
   ⑤ 易错：把 `\t` 当两个字符；用 `r` 前缀后又想在里面写转义

3. 索引、切片与步长：全都从 0 开始、切片不报错
   ① 索引从 0 开始、负数从末尾数 → 切片 `s[start:stop:step]` 取"左闭右开"→ 越界的**切片**会静默截断，越界的**索引**才报 `IndexError` → `step` 为负表示反向
   ② 边界：切片永远是浅拷贝（新字符串）；`s[::-1]` 反转是最常用特例
   ③ 接：为什么 `s[100]` 报错而 `s[100:200]` 返回空串；`s[-3:]` 取的是哪三位；怎么反转字符串
   ④ 例题 1 道：对 `"abcdef"` 写出 8 个切片表达式的结果，先手算再跑脚本对照
   ⑤ 易错：把 `stop` 当闭区间；忘记切片是拷贝而以为"改动切片会改原串"

4. 方法族：文本处理的日常工具
   ① 查询：`find`/`index`/`count`/`startswith`/`endswith`/`in` → 切分与拼接：`split`/`rsplit`/`splitlines`/`join`（`join` 是"用分隔符连接列表"，不是反过来）→ 清理：`strip`/`lstrip`/`rstrip`（只去两端，不去中间）→ 替换与大小写：`replace`/`lower`/`upper`/`title`/`capitalize`
   ② 边界：这些方法都返回新字符串（不可变）；`str` 上的方法不会原地改；正则留给 `re`（认识层）
   ③ 接：`split()` 不带参数与带 `" "` 有什么区别；`join` 为什么写成 `"-".join(lst)` 而不是 `lst.join("-")`；`strip` 为什么去不掉中间的空格
   ④ 例题 1 道：给一行日志 `2026-11-14 09:03:12 WARN disk usage 91%`，拆出时间、级别、消息三部分
   ⑤ 易错：`s.strip("abc")` 以为去掉子串（其实是去掉两端任意这些字符）；用 `+` 在循环里拼大量字符串

5. 格式化：把变量塞进文本的三种方式
   ① `%` 老式（`"%s-%d" % (a, b)`）→ `str.format`（`"{}".format(x)`）→ f-string（`f"{x}"`，3.6+，可嵌表达式、可加格式说明符）→ f-string 是默认选择，前两种只要求读得懂
   ② 边界：格式说明符 `{x:>8.2f}`/`{n:,}`/`{p:.1%}`/`{x=}`（3.8+ 调试用）；嵌套引号在 3.12 前有限制
   ③ 接：`{:.2f}` 是四舍五入吗（沿用浮点舍入规则，见 04 讲）；怎么把表格对齐；`f"{x=}"` 打印出什么
   ④ 例题 1 道：把一份 `(姓名, 分数)` 列表排成宽度对齐的表，中英混排各一行对照
   ⑤ 易错：把 f-string 写在 3.5 环境里；用 `%` 格式化时参数个数与占位符不匹配

6. 编码与解码：`encode`/`decode` 与三类乱码
   ① `str.encode("utf-8")` 得到 `bytes` → `bytes.decode("utf-8")` 回到 `str` → 用错编码就出现 `UnicodeDecodeError`（解码）或 `UnicodeEncodeError`（编码）→ 乱码（`锟斤拷`/`???`）是"编解码不对称"的表现，不报错的那种最难查
   ② 边界：`errors="replace"/"ignore"` 只作为最后手段并说明代价；BOM 与 `utf-8-sig`
   ③ 接：文件明明能打开却有 `\ufeff`；读 GBK 文件为什么要写 `encoding="gbk"`；写文件给 Excel 打开该用什么编码
   ④ 例题 1 道：同一段中文分别用 UTF-8/GBK 编码再解码，构造出"用错编码"的报错与"不报错的乱码"两种现象
   ⑤ 易错：在 `open` 里不写 `encoding`（默认值随平台变）；把 `errors="ignore"` 当解决方案

7. 字符串比较与排序
   ① 比较按码点逐位进行（`"apple" < "banana"`、`"Z" < "a"`）→ 因此大小写混排排序结果不符合人的直觉 → 需要时统一 `lower()` 或用 `key=str.lower`
   ② 边界：中文按什么排（拼音需要额外库）只点名
   ③ 接：为什么 `sorted(["b", "A"])` 是 `['A', 'b']`；数字字符串排序为什么 `"10" < "9"`
   ④ 例题 1 道：对一组含大小写的名字排序，给出"默认"与"忽略大小写"两种结果
   ⑤ 易错：用字符串排序代替数值排序（读进来的数字忘了转 `int`）

8. 文本处理的一段完整走查（本讲收束）
   ① 读入多行文本 → `splitlines()` 拆行 → 每行 `strip()` 去两端空白 → 跳过空行与 `#` 注释 → `split()` 取字段 → 用 f-string 重新排版输出；整条链只用本讲的方法
   ② 边界：数据量很大时要流式处理（13 讲）
   ③ 接：为什么处理完少了几行（空行被跳过）；`split()` 与 `split(" ")` 在多个连续空格上的差别
   ④ 例题 1 道：把一段不规整的配置文本解析成"键 = 值"并整齐打印
   ⑤ 易错：在循环里对整串反复 `split` 造成重复计算

### 06 列表与元组：有序容器的完整形态

1. `list` 是什么：可变的动态数组
   ① 内存里是一段连续的引用 → `append` 在尾部放，满了就扩容（摊还 $O(1)$）→ `insert(0, x)`/`pop(0)` 要整体挪动（$O(n)$）→ 由此推出"尾部快、头部慢"
   ② 边界：不讲扩容倍数与内存对齐；只要求能判断"这个操作大概贵不贵"
   ③ 接：为什么往列表头部插入十万次会很慢；`in` 为什么在列表上慢而在集合上快（07 讲）
   ④ 例题 1 道：对比 `append` 与 `insert(0, ·)` 各做 10 万次的耗时，两个数量级以上的差距要实测出来
   ⑤ 易错：在循环里 `list.pop(0)` 当队列用（该用 `collections.deque`，认识层）

2. 索引、切片、切片赋值
   ① 索引与切片规则同 05 讲字符串 → 但列表切片是"新的列表对象"（浅拷贝）→ 切片赋值 `lst[1:3] = [...]` 可以改变长度（与字符串不同）
   ② 边界：步长不为 1 时切片赋值要求长度一致；`del lst[1:3]`
   ③ 接：`b = a[:]` 与 `b = a` 有什么区别；为什么 `a[::2] = [1,2]` 会报错
   ④ 例题 1 道：用一个列表演示切片、切片赋值、`del` 三者对原列表的影响
   ⑤ 易错：以为 `b = a[:]` 是深拷贝（嵌套元素仍共享）

3. 增删改查的完整方法表
   ① 增：`append`（一个）/`extend`（多个）/`insert`（指定位置）→ 删：`pop`（按下标，返回元素）/`remove`（按值，找不到报错）/`del`（按位置）/`clear` → 查：`index`/`count`/`in` → 改：下标赋值
   ② 边界：`remove` 只删第一个匹配；`pop` 不传参删末尾；`extend` 与 `+` 的区别（原地 vs 新建）
   ③ 接：`remove` 找不到为什么报错而不是什么都不做；`a += b` 与 `a = a + b` 在列表上的差异
   ④ 例题 1 道：给一个待办列表，按"添加/完成/删除/清空"四个动作写出对应方法调用，并打印每步后的列表
   ⑤ 易错：边遍历边 `remove` 导致漏删

4. 排序：`sort` 与 `sorted` 的完整形态
   ① `sorted(可迭代)` 返回新列表且不挑类型 → `list.sort()` 原地排且返回 `None` → 两者都接受 `key=`（对每个元素先求一个"排序依据"）与 `reverse=` → Python 排序稳定：相等元素保持原相对顺序
   ② 边界：`key` 必须是"一次算一个值"的函数；多关键字用元组做 key；逆序的某一列用 `-x` 只对数值有效（字符串不能取负）
   ③ 接：为什么 `a = a.sort()` 会让 `a` 变成 `None`；怎么"按成绩降序、同分按名字升序"；`key=lambda x: x[1]` 里的 `x` 是什么
   ④ 例题 2 道：对 `(姓名, 分数)` 列表按分数降序+姓名升序排；对字典列表按多字段排
   ⑤ 易错：把 `sort()` 的返回值赋回原变量；用 `reverse=True` 做多关键字排序（会把所有关键字一起反转）

5. 列表推导式与它的边界
   ① `[f(x) for x in 可迭代 if 条件]` 等价于"建空列表 → 循环 → 条件过滤 → append"→ 语法上更短、语义上更接近"生成一个列表"而不是"做一堆事"
   ② 边界：嵌套推导式（`for` 两个）只在简单映射时用；带副作用（写文件、改外部变量）的循环不该写成推导式；生成器表达式 `(...)` 只在认识层
   ③ 接：推导式里能不能写 `if/else`（能，位置不同含义不同）；推导式和普通循环性能差多少（差不多，省的是行数不是时间）
   ④ 例题 1 道：把一段"循环 + append + if"改写成推导式，再改回循环，比较可读性
   ⑤ 易错：把推导式写成三层嵌套；在推导式里调用有副作用的函数

6. 浅拷贝与深拷贝：嵌套结构的陷阱
   ① `b = a`（同一对象）→ `b = a[:]`/`a.copy()`/`list(a)`（新外层，元素引用相同 = 浅拷贝）→ `copy.deepcopy(a)`（递归复制）→ 所以"二维列表"用浅拷贝会共享内层行
   ② 边界：`deepcopy` 有成本且对不可变对象不必要；自定义对象也能被 `deepcopy`（认识层）
   ③ 接：为什么 `grid = [[0]*3]*3` 改一格三格都变；`[row[:] for row in grid]` 为什么能救
   ④ 例题 1 道：构造 3×3 的"乘法表式陷阱"，用四种拷贝方式各改一格，打印对照
   ⑤ 易错：用 `*` 复制嵌套结构；以为切片是深拷贝

7. `tuple`：不可变带来的三个好处
   ① 不能改元素引用 → 可哈希（能当 `dict` 键与 `set` 元素）→ 表达"这条记录不该变"的意图 → 解包语法统一（`a, b = b, a` 就是元组打包解包）
   ② 边界：`tuple` 里放可变对象时"整体"仍然可变（`t[0].append(1)` 合法）；`namedtuple` 只在认识层
   ③ 接：函数返回多个值其实是返回元组吗（是）；为什么 `(1)` 不是元组而 `(1,)` 是；星号解包 `a, *rest = lst`
   ④ 例题 1 道：用元组做"坐标 → 值"的字典键，再用列表做同样的键触发 `TypeError` 并读懂报错
   ⑤ 易错：`(1)` 当元组；以为元组里的列表也不能改

8. 遍历时修改容器：为什么结果不对
   ① `for x in lst` 背后是按下标递增取元素 → 循环体里删除元素会让后面的元素前移 → 于是"跳过"某些元素 → 正确做法：生成新列表（推导式过滤）或倒序遍历或先收集再删
   ② 边界：`dict` 在遍历中增删键会直接抛 `RuntimeError`（更严格）；集合同理
   ③ 接：为什么我只删了一半；为什么改字典时报 `dictionary changed size during iteration`
   ④ 例题 1 道：删除列表中所有偶数，先写错版（漏删）再写对版（推导式 / 倒序）
   ⑤ 易错：在 `for` 里 `del`；用 `lst[:]` 遍历副本却忘了副本是浅拷贝

### 07 字典与集合：按"键"找东西

1. `dict` 是什么：哈希表带来的 $O(1)$
   ① 键 → 计算哈希值 → 映射到桶位 → 冲突时在桶内比较 `==` → 平均 $O(1)$ 查找；列表要逐个比（$O(n)$）→ 所以"按名字查"该用字典
   ② 边界：不讲哈希函数细节与扩容策略；只要求知道"平均快、最坏会退化、键要可哈希"
   ③ 接：为什么 `10 万条数据里查一个`用字典几乎瞬间、用列表要等；哈希冲突会发生什么
   ④ 例题 1 道：同一个查找任务分别用列表 `in` 与字典 `in` 做 10 万次，实测耗时差
   ⑤ 易错：用"两个平行列表按下标对齐"当字典用

2. 增删改查的完整方法表
   ① `d[k] = v` 增/改 → `d[k]` 取（键不存在抛 `KeyError`）→ `d.get(k, 默认)` 安全取 → `d.setdefault(k, 默认)` 取或建 → `del d[k]`/`d.pop(k, 默认)` 删 → `k in d` 判断
   ② 边界：`get` 与 `setdefault` 的区别（后者会写入）；`pop` 不传默认值且键不存在时抛 `KeyError`
   ③ 接：`get` 和 `setdefault` 什么时候用哪个；为什么 `d["没有的键"]` 要报错而不是返回 `None`
   ④ 例题 1 道：用字典做"单词 → 次数"计数，分别用 `get`、`setdefault`、`Counter` 三种写法
   ⑤ 易错：用 `d[k] += 1` 给新键计数（先 `KeyError`）

3. 键必须可哈希：这条规则从哪来
   ① 哈希表要先用哈希值定位 → 所以键必须"哈希值不变" → 可变对象（`list`/`dict`/`set`）不能保证这点 → 因此被禁止；`tuple` 与 `frozenset` 可以（前提是里面装的也都可哈希）
   ② 边界：`__hash__` 与 `__eq__` 必须一致（相等则哈希相同）——15 讲自定义类时再落地
   ③ 接：为什么列表不能当键；自定义对象默认能不能当键（能，按身份）；为什么元组里放列表就不能当键
   ④ 例题 1 道：分别用 `str`/`int`/`tuple`/`list` 做键，记录哪些成功哪些报什么错
   ⑤ 易错：把"能当键"和"能当值"混为一谈（值随便）

4. 遍历与顺序：3.7 之后字典记住了插入顺序
   ① `d.keys()`/`d.values()`/`d.items()` 返回的是视图（不是列表），可迭代 → 迭代顺序 = 插入顺序（3.7+ 的语言保证）→ 要排序需显式 `sorted(d.items(), key=...)`
   ② 边界：视图会随字典改变而变；遍历中改字典大小会抛错（06 讲第 8 条）
   ③ 接：为什么我不能 `d.items()[0]`（视图不支持下标）；怎么按值排序
   ④ 例题 1 道：对词频字典按次数降序输出前 3 名
   ⑤ 易错：把 `keys()` 当列表用（`list(d.keys())` 才能下标）

5. 字典推导式与嵌套字典
   ① `{k: v for k, v in 可迭代 if 条件}` 与列表推导式同构 → 嵌套字典 `d[a][b]` 访问时容易 `KeyError` → 用 `d.get(a, {}).get(b)` 或 `defaultdict(dict)`
   ② 边界：深层的自动创建用 `defaultdict` 递归工厂（认识层）；`json` 里的嵌套结构在 13 讲处理
   ③ 接：怎么安全读三层嵌套的配置；`defaultdict(dict)` 与 `setdefault` 的取舍
   ④ 例题 1 道：把"学生 → 科目 → 分数"的三元组列表聚合成嵌套字典，再安全读取不存在的路径
   ⑤ 易错：`d["不存在"]["键"]` 直接崩；在推导式里改外部字典

6. `Counter` 与 `defaultdict`：两类重复劳动
   ① 计数 → `Counter(可迭代)` 直接给出"元素 → 次数"，`most_common(n)` 取前 n → 分组 → `defaultdict(list)` 让 `d[k].append(v)` 不用先判空
   ② 边界：`Counter` 是 `dict` 的子类，缺键返回 0 而不是 `KeyError`；`defaultdict` 缺键时会写入（会污染字典）
   ③ 接：既然 `Counter` 这么好，为什么还要讲 `get`/`setdefault`（要懂原理，且不是所有场景都值得引入）；`defaultdict` 打印出来为什么多了键
   ④ 例题 1 道：统计一段文本的词频并输出前 5；按首字母分组单词
   ⑤ 易错：用 `dict.get` 计数时忘了把结果写回

7. `set`：去重与集合运算
   ① `set` 是"只有键的哈希表" → 成员测试平均 $O(1)$、自动去重、无序 → `|`/`&`/`-`/`^` 对应并/交/差/对称差；`frozenset` 是不可变版本（可当键）
   ② 边界：集合无序（不能下标）；元素必须可哈希；`set()` 是空集，`{}` 是空字典
   ③ 接：去重后怎么保持原顺序（用 `dict.fromkeys`）；`{}` 为什么不是集合；两个列表找共同元素怎么写最快
   ④ 例题 1 道：两批用户 id 求共同/仅在 A/仅在 B，并对照列表实现的耗时
   ⑤ 易错：`{}` 当空集合；对集合用 `[0]` 取元素

8. 选哪个容器：一张决策表（本讲收束）
   ① 需要顺序且频繁尾部增删 → `list` → 需要按名字/编号查 → `dict` → 只关心"在不在"/去重 → `set` → 一条不许改的记录 → `tuple` → 四问下来选择就唯一了
   ② 边界：决策表只覆盖Python 内置容器；`deque`/`heapq` 只点名
   ③ 接：为什么不能所有东西都用列表；我现在的代码该不该换结构
   ④ 例题 1 道：给四个需求场景各选容器并说明理由
   ⑤ 易错：用列表存"键值对"再写查找函数；用字典当"有序列表"

### 08 控制流：让程序自己走

1. 缩进即语法
   ① Python 用缩进表示语句块 → 同一块必须同缩进 → 常用 4 空格 → 混用 Tab 与空格会报 `IndentationError`/`TabError` → 所以"看起来对齐"不等于"语法上同块"
   ② 边界：空块用 `pass` 占位；续行用括号或 `\`
   ③ 接：为什么我复制来的代码报 `IndentationError`；`if x:` 后面能不能直接跟语句（能，但没人这么写）
   ④ 例题 1 道：写一个"看起来对齐但 Tab/空格混用"的片段，跑出报错再修好
   ⑤ 易错：用 Tab 缩进后又在别处补空格

2. `if`：条件、链式比较与真值
   ① `if 条件:` 求值 → 非零/非空/非 `None` 为真 → `elif` 顺序匹配，命中即跳出 → 链式比较 `0 < x < 10` 等价于 `0 < x and x < 10`
   ② 边界：假值清单必须给全（`0`/`0.0`/`""`/`[]`/`{}`/`set()`/`None`/`False`）；`== True` 是多余的
   ③ 接：`if x:` 和 `if x is not None:` 有什么区别（`0` 会被前者判假）；为什么 `1 < 2 < 3` 能写到一起
   ④ 例题 1 道：给八个值分别用 `if x:` 与 `if x is not None:` 判断，做成对照表
   ⑤ 易错：用 `if x == None`；把 `=` 写成 `==`（或反过来）导致逻辑反了

3. `for` 背后是迭代协议
   ① `for x in obj:` → 先 `iter(obj)` 拿到迭代器 → 循环里反复 `next()` → 拿到 `StopIteration` 时结束 → 所以"能被 `for` 的东西"是实现了 `__iter__` 的对象
   ② 边界：`range` 是"按需算下一个数"的对象，不是列表；自己写迭代器只到认识层
   ③ 接：为什么 `for i in 10` 报错而 `for i in range(10)` 可以；`range(10)` 占多少内存；循环里能改 `x` 吗（改的是名字，不影响下一轮）
   ④ 例题 1 道：用 `iter()`/`next()` 手工推一遍 `for i in [10, 20]` 的内部三步，把观察打印出来
   ⑤ 易错：以为 `for` 遍历的是下标；在循环里改被遍历的对象

4. `while` 与三种退出方式
   ① `while 条件:` 每轮先判条件 → `break` 立即退出整个循环 → `continue` 跳过本轮剩余部分 → `else` 在"循环正常结束（没被 `break`）"时执行
   ② 边界：`for ... else` 同样存在（很多人不知道）；`while True` + `break` 是"至少执行一次"的常用写法
   ③ 接：`for ... else` 什么时候执行；我该用 `while` 还是 `for`；死循环怎么停（`Ctrl+C`）
   ④ 例题 1 道：写"读输入直到输入 `quit`"，用 `while True` + `break` 与 `while 条件` 两个版本
   ⑤ 易错：`while` 里忘了更新条件变量；用 `continue` 时跳过了更新语句导致死循环

5. 循环里的标准工具：`enumerate`/`zip`/`reversed`
   ① 需要下标与元素 → `enumerate(可迭代, start=0)` → 需要并行遍历多个序列 → `zip`（按最短截断）→ 需要反向 → `reversed`（要求序列或实现 `__reversed__`）
   ② 边界：`zip` 在长度不等时静默截断（3.10+ 可用 `strict=True` 报错）；`enumerate` 的 `start` 只影响编号不影响元素
   ③ 接：为什么不要写 `for i in range(len(lst))`（除非真要改 `lst[i]`）；`zip` 长度不等会怎样；怎么同时遍历字典的键和值
   ④ 例题 1 道：把"按下标遍历两个列表"改写成 `enumerate` + `zip` 版本
   ⑤ 易错：`zip` 返回的是迭代器，遍历一次就空了

6. 嵌套循环与提前退出
   ① 两层循环 + 找到就停 → `break` 只能跳出最内层 → 所以要"跳出外层"必须用标志位或把逻辑抽成函数 `return`
   ② 边界：`itertools.product` 可替代纯笛卡尔积（认识层）；`for ... else` 可以省掉标志位
   ③ 接：为什么我 `break` 了还在继续打印；嵌套三层循环正常吗（常常说明该抽函数或换数据结构）
   ④ 例题 1 道：在二维网格里找第一个满足条件的格子，先用标志位写，再改成函数 `return`
   ⑤ 易错：以为 `break` 能跳出两层；用异常来控制流程

7. `any`/`all` 与三元表达式
   ① `any(可迭代)` 遇到第一个真值就返回 `True`（短路）→ `all` 遇到第一个假值就返回 `False` → 三元 `A if 条件 else B` 是表达式（有值），不是语句
   ② 边界：`any([])` 是 `False`、`all([])` 是 `True`（空集的约定）；三元表达式嵌套超过一层就该改 `if`
   ③ 接：`any` 和"写个循环 + 标志位"哪个好；为什么 `all([])` 是 `True`；三元能不能不放 else
   ④ 例题 1 道：判断列表中是否存在偶数、是否全为正数，各用 `any`/`all` 一行写完
   ⑤ 易错：把三元表达式当语句用（`x if c else y` 单独一行没有意义）

8. 一段控制流的完整走查（本讲收束）
   ① 读入一批数字（可能含非法输入）→ 逐个 `try` 转换（`try` 在 11 讲，此处只写"先跳过坏行"的 `if` 版）→ 过滤 → 累加与计数 → 输出统计 → 用 `for ... else` 判断"是否一个有效数据都没有"
   ② 边界：`try` 版本在 11 讲替换 `if` 版；本节只要求结构完整
   ③ 接：为什么我算出的平均值分母不对（计数没同步）；为什么最后一行空数据也能进循环
   ④ 例题 1 道：完整走一遍并打印中间量，人为制造一个坏数据验证跳过逻辑
   ⑤ 易错：用 `sum/len` 时把无效项算进分母；在循环里反复 `print` 调试后忘了删

### 09 函数 I：把一段逻辑封起来

1. `def`、调用与 `return`
   ① 定义函数只是"把一段代码绑定到一个名字"（不执行）→ 调用时才执行 → `return` 把值交回调用处并立即结束函数 → 没有 `return` 或只有 `return` 时返回 `None`
   ② 边界：`return` 与 `print` 完全不同（一个有值、一个只有输出）；函数可以返回多个值（其实是元组）
   ③ 接：为什么我的函数"什么都没返回"（只 `print` 了）；`return` 后面的代码为什么不执行；函数名不加括号会怎样（得到函数对象）
   ④ 例题 1 道：把 04 讲的"读两个数求和"改写为函数，并在调用处用返回值参与后续计算
   ⑤ 易错：在函数里 `print` 结果然后在外面等它返回值；`return` 写成 `print`

2. 参数传递：传的到底是什么
   ① 实参求值后把**对象引用**交给形参 → 形参是新的名字，指向同一对象 → 函数里 `修改对象内容`（`append`）会影响外面，`重新绑定名字`（`=`）不会
   ② 边界：这就是"传对象引用"（不是"传值"也不是"传引用"）；不可变对象看起来像"传值"是因为它没法被原地改
   ③ 接：为什么函数里 `lst.append(1)` 外面能看到、`lst = [1]` 外面看不到；我想在函数里改外面的变量怎么办（返回新值，或明确用可变容器）
   ④ 例题 1 道：写四个函数分别对 `list` 做"append/重新绑定/切片赋值/`+=`"，对照调用后的原列表
   ⑤ 易错：以为所有参数都是"复制一份进去"

3. 三类参数与默认值的求值时机
   ① 位置参数按顺序匹配 → 关键字参数按名字匹配 → 默认值在**函数定义时**求值一次并保存在函数对象上 → 所以可变默认值（`def f(x, acc=[])`）会在多次调用间累积
   ② 边界：`def f(x, acc=None): acc = [] if acc is None else acc` 是标准修法；默认值不能引用后面的参数；`/`（仅位置）与 `*`（仅关键字）只点名
   ③ 接：为什么我的默认参数"记住"了上次的结果；关键字参数能不能写在位置参数前面（不能）；参数顺序怎么设计
   ④ 例题 1 道：复现可变默认值累积，再用 `None` 修法修好，打印每次调用的结果
   ⑤ 易错：用 `[]`/`{}` 当默认值；调用时把关键字参数写成字符串（`f("x"=1)`）

4. 作用域：`LEGB` 与两条边界
   ① 名字查找顺序：局部 → 外层函数（闭包）→ 全局 → 内置 → 函数内对名字赋值会让它在整个函数内是局部的（不管赋值在第几行）→ 想改外层用 `global`/`nonlocal`
   ② 边界：`global` 应尽量避免（隐式依赖）；`nonlocal` 只用于嵌套函数（10 讲闭包）
   ③ 接：为什么我在函数里读全局变量可以、改就报 `UnboundLocalError`；`global` 什么时候必须用；模块级变量算不算"全局"
   ④ 例题 1 道：构造"函数里先读后赋值"的 `UnboundLocalError`，再用 `global` 修好并说明代价
   ⑤ 易错：在函数内部 `x += 1` 却不声明 `global`；以为 `global` 能跨模块

5. 命名、文档与"纯函数"的取舍
   ① 好函数名是动词短语（`parse_line`/`load_config`）→ 函数做一件事，输入从参数来、输出从 `return` 走 → 不读全局、不打印、不写文件 = 纯函数：好测、好组合
   ② 边界：工程里不可能全是纯函数（`print`/写文件/读时间都有副作用），关键是"副作用集中到少数地方"
   ③ 接：函数里该不该 `print`；函数多长算长；为什么"能返回就别打印"
   ④ 例题 1 道：把一个"边算边打印"的函数改成"返回结果"，由调用方决定怎么显示
   ⑤ 易错：函数名用 `f`/`do`/`process`；一个函数既读文件又算又写文件

6. 把脚本重构成函数（本讲收束）
   ① 一段 30 行的脚本 → 找出"输入 → 处理 → 输出"三段 → 各抽成函数 → 主流程只剩三行调用 → 这样才可能被测试与复用（16 讲）
   ② 边界：抽函数的标准是"能单独描述用途"，不是"行数超过 N"
   ③ 接：拆到什么粒度才算好；拆完之后变量怎么传
   ④ 例题 1 道：把 08 讲第 8 条的统计脚本重构成三个函数，行为完全不变（跑通前后输出一致）
   ⑤ 易错：拆完之后用一堆全局变量传数据

### 10 函数 II：可变参数、闭包与"函数是值"

1. `*args` 与 `**kwargs`
   ① 形参 `*args` 把多余位置参数收集成元组 → `**kwargs` 把多余关键字参数收集成字典 → 调用侧的 `*`/`**` 反向：把序列/字典拆成参数
   ② 边界：`*args` 之后仍可跟仅关键字参数；参数顺序固定为"位置 → 默认 → `*args` → 仅关键字 → `**kwargs`"
   ③ 接：`f(*lst)` 和 `f(lst)` 的区别；为什么要用 `**kwargs` 转发参数；`args`/`kwargs` 这两个名字是强制的吗（不是，是惯例）
   ④ 例题 1 道：写一个 `log(*args, **kwargs)` 转发给 `print`，并演示调用侧解包
   ⑤ 易错：把 `*args` 写成 `args*`；在函数体内把 `args` 当列表修改（它是元组）

2. 函数是对象：把行为当数据
   ① `def` 造出一个函数对象并绑定名字 → 函数可以被赋值、放进列表/字典、作为参数传入、作为返回值传出 → 于是"按名字选函数"可以用字典做分派
   ② 边界：`map`/`filter` 返回迭代器（要看结果得 `list()`）；`sorted(key=...)` 是最常用的"传函数"场景
   ③ 接：为什么 `sorted(key=f)` 里的 `f` 不加括号；`map` 和列表推导式哪个好（推导式更 Pythonic，`map` 在已有函数名时更短）；字典分派比 `if/elif` 好在哪
   ④ 例题 1 道：用字典把 `"add"/"mul"` 映射到两个函数，替代 `if/elif` 链
   ⑤ 易错：把函数调用结果当函数传（`key=f()`）

3. `lambda`：只在"当场用一次"时用
   ① `lambda 参数: 表达式` 是一个匿名函数对象，函数体只能是一个表达式（有隐式 `return`）→ 它和 `def` 造出来的东西本质同类，只是没名字
   ② 边界：复杂逻辑不该用 `lambda`（可读性差且不能写语句）；赋值给变量再用，不如直接 `def`
   ③ 接：`lambda x: x[1]` 和 `def f(x): return x[1]` 有区别吗（只有名字）；`lambda` 里能写 `if` 吗（能，用三元表达式）
   ④ 例题 1 道：用 `lambda` 与 `def` 各写一遍"按第二个字段排序"，比较可读性并给出选用建议
   ⑤ 易错：在 `lambda` 里写语句；为了省行数把三行逻辑塞进 `lambda`

4. 闭包：内层函数记住外层变量
   ① 外层函数执行时创建局部变量 → 内层函数定义时捕获这些名字（不是值）→ 外层返回内层函数后，被捕获的名字仍然活着 → 这就是闭包；要改它需 `nonlocal`
   ② 边界：捕获的是"变量"而不是"当时的值"，所以循环里建闭包会全部指向最后一次的值（晚期绑定）；用默认参数 `lambda x=i: ...` 冻结
   ③ 接：为什么我 `for` 里建的三个 `lambda` 都输出同一个值；闭包和全局变量比好在哪（不污染、可造多个独立实例）；`nonlocal` 什么时候必须写
   ④ 例题 1 道：用闭包写一个计数器（两个实例互不干扰），再复现"循环里建闭包"的晚期绑定陷阱并修好
   ⑤ 易错：以为闭包捕获的是值；在闭包里改外层变量却忘写 `nonlocal`

5. 装饰器：函数进、函数出（认识层 + 一个例子）
   ① 装饰器是一个"接收函数、返回新函数"的函数 → `@deco` 等价于 `f = deco(f)` → 因为上一条的闭包，新函数能"包住"原函数并在前后插入动作（计时、重试、日志）
   ② 边界：只要求读懂与写一个不带参数的装饰器；带参数装饰器、`functools.wraps` 的作用点名即可
   ③ 接：`@` 这一行到底做了什么；为什么被装饰后 `f.__name__` 变了（`wraps` 能救）；什么时候真的需要装饰器（横切关注点，如计时/重试）
   ④ 例题 1 道：写一个计时装饰器，套在 06 讲第 1 条的插入耗时函数上，对照手写计时
   ⑤ 易错：以为装饰器只对类有效；忘了 `return` 新函数导致调用变成 `None`

6. 递归：基线、栈与改写
   ① 递归函数必须有两个部分：基线条件（能直接返回）→ 递归步（把问题变小并调用自己）→ 每次调用在内存里压一帧 → 帧太多会 `RecursionError`（默认上限约 1000）
   ② 边界：Python 没有尾递归优化；能改成循环就改（更省内存）；递归适合"结构本身是递归的"（目录树、JSON、分治）
   ③ 接：为什么我忘了基线会崩；递归和循环哪个快；`sys.setrecursionlimit` 能随便调大吗（不能，可能真把栈撑爆）
   ④ 例题 2 道：用递归算阶乘与斐波那契（含"重复计算"的性能对照），再用循环重写
   ⑤ 易错：基线写错导致无限递归；用递归处理上万条数据

7. 函数设计的三条纪律（本讲收束）
   ① 参数超过 4 个时考虑"打包成一个配置对象/数据类" → 布尔参数（`f(x, True)`）应改成两个函数或关键字参数 → 返回 `None` 与返回值的函数不要混着用（同族函数保持同一约定）
   ② 边界：这是工程惯例而非语法规则；竞赛/脚本场景可以放松
   ③ 接：我的函数要传 8 个参数该怎么办；`f(data, True)` 这种调用半年后还看得懂吗
   ④ 例题 1 道：把一个"6 个参数 + 1 个布尔开关"的函数重构为 `dataclass` + 两个函数
   ⑤ 易错：靠位置传一堆布尔值；用返回 `None` 表示"失败"和"成功"两种含义

### 11 错误与异常：出错时到底发生了什么

1. traceback 逐行读法
   ① 报错输出分三段：`Traceback` 调用链（从最外层到出错处）→ 最后一行 `文件, 行号, 函数` → 最底一行 `异常类型: 消息`；真正的原因在最后一行，位置在最后一个 `File` 帧
   ② 边界：只看最后一行会对"在哪出错"判断错（要在最后一个 `File` 里找行号）；`During handling of the above exception` 表示"处理异常时又出错"
   ③ 接：报错里好几个 `File`，哪个是我的代码；`ModuleNotFoundError` 和 `ImportError` 有什么区别；报错信息读不懂时先看什么（行号 + 类型）
   ④ 例题 1 道：给一段三层函数调用的代码制造 `ZeroDivisionError`，逐帧标注"这一帧在干什么"
   ⑤ 易错：只看第一行 `Traceback (most recent call last)` 就开始改

2. 异常是对象：层次与常见类型
   ① 所有异常都继承自 `BaseException` → 业务代码关心的是 `Exception` 这一支（`SystemExit`/`KeyboardInterrupt` 不该被吞）→ 常见叶子类型各自表示一类错误原因
   ② 边界：清单给 9 个高频类型（`ValueError`/`TypeError`/`KeyError`/`IndexError`/`NameError`/`AttributeError`/`FileNotFoundError`/`ZeroDivisionError`/`UnicodeDecodeError`）各一句"什么时候出现"
   ③ 接：`TypeError` 和 `ValueError` 差在哪；为什么捕获 `Exception` 不捕获 `BaseException`；`KeyboardInterrupt` 为什么不能被裸 `except` 吞掉
   ④ 例题 1 道：写出六段各触发一种异常的代码，跑一遍把"异常类型 → 触发原因"做成表
   ⑤ 易错：`except` 的顺序写反（父类在前会吞掉子类）

3. `try`/`except`/`else`/`finally` 的完整语义
   ① `try` 里第一句出错 → 跳到匹配的 `except`（按书写顺序匹配，第一个匹配的赢）→ 没有异常则执行 `else` → 无论是否异常都执行 `finally`（清理、关闭资源）
   ② 边界：`finally` 里 `return` 会吞掉异常（危险，要说明）；`else` 的意义是"只在没出错时做的事"
   ③ 接：`else` 有什么用（把"不该被 `try` 保护的代码"移出去）；`finally` 与 `return` 谁先执行；`with` 和 `finally` 什么关系（13 讲）
   ④ 例题 1 道：写一个"读文件 → 解析 → 打印"的函数，四个分支各打印一句，证明执行顺序
   ⑤ 易错：把大段逻辑塞进 `try`（掩盖真正的 bug）；以为 `finally` 一定在 `return` 之后

4. 捕获的粒度与 `raise`
   ① 只捕获"你知道怎么处理"的异常类型 → `except ValueError as e:` 拿到对象（能打印消息、能检查）→ 处理不了就 `raise` 继续抛（可 `raise ... from e` 保留原因链）
   ② 边界：裸 `except:` 会连 `KeyboardInterrupt` 一起吞；`except Exception: pass` 是"静默失败"，本讲明确列为反模式
   ③ 接：为什么我的程序"什么都没发生"（被 `pass` 吞了）；`raise` 与 `raise e` 的区别；什么时候该包一层自己的异常
   ④ 例题 1 道：把裸 `except` 改成精确捕获，并给"解析失败"包一层自定义异常
   ⑤ 易错：`except:` 一把梭；捕获后什么都不做

5. 自定义异常与 EAFP
   ① 业务错误用自定义异常类表达（`class ConfigError(Exception): pass`）→ 调用方能按类型分别处理 → EAFP（先做、出错再处理）与 LBYL（先检查、再做）各有适用：输入来自用户/文件时 EAFP 更稳，因为"检查通过"与"真正使用"之间仍有窗口
   ② 边界：自定义异常要放在模块顶层（12 讲）；异常消息要写"发生了什么 + 期望什么"
   ③ 接：什么时候该自定义异常而不是 `ValueError`；EAFP 是不是"用异常控制流程"；`assert` 能不能替代异常（不能，见下条）
   ④ 例题 1 道：定义一个 `ScoreError`，在解析成绩的函数里抛出、在调用处分别处理
   ⑤ 易错：为每种小错误都建一个异常类（层级爆炸）；用异常做普通的 if 分支

6. `assert` 的边界
   ① `assert 条件, "消息"` 在条件为假时抛 `AssertionError` → 但它会被 `python -O` 整体移除 → 所以只能用于"开发期自检/测试"，不能用于校验用户输入或做安全检查
   ② 边界：测试里的 `assert`（16 讲 `pytest`）是同一机制；生产代码里的输入校验必须用 `if + raise`
   ③ 接：既然 `assert` 这么方便为什么不都用它；`-O` 之后我的检查全没了会怎样
   ④ 例题 1 道：写一个用 `assert` 校验参数的函数，用 `python -O` 跑一次证明校验消失
   ⑤ 易错：用 `assert` 校验用户输入；`assert` 里写有副作用的表达式

7. 调试：从"重跑碰运气"到"最小复现"
   ① 出 bug → 先稳定复现（固定随机种子、固定输入）→ 二分定位（注释一半 / 打印中间量 / 用 `breakpoint()`）→ 找到那一行后再问"我以为它是什么、实际它是什么"（用 `repr()` 看真身）
   ② 边界：`breakpoint()` 进 `pdb`，本讲只用 `n`/`s`/`p`/`q` 四个命令；`logging` 留到 16 讲
   ③ 接：为什么加了几十个 `print` 还是没找到；程序没输出是卡住了还是崩了；`breakpoint()` 在 IDE 里和在终端里有什么不同
   ④ 例题 1 道：给一个"结果不对但不报错"的函数，用二分 + `repr` 定位到一个类型错误（本该 `int` 实际是 `str`）
   ⑤ 易错：靠改代码碰运气；只看输出不看中间量

8. 一个健壮脚本的完整形态（本讲收束）
   ① 主流程 → 分层处理错误：可预期的（文件不存在、格式错）就地处理并给用户可读提示 → 不可预期的让它带着 traceback 崩出来 → 最外层只在"命令行工具"场景做一次兜底，并把异常记进日志
   ② 边界：本节不引入 `logging`（16 讲），用 `print` 到 `stderr` 占位
   ③ 接：什么时候该让程序崩（早崩比带病跑好）；用户看到的报错该长什么样
   ④ 例题 1 道：给 08 讲第 8 条的统计脚本加"文件不存在/格式错误/空文件"三种处理，逐一制造场景验证
   ⑤ 易错：所有异常都兜底成"出错了"；把 traceback 直接甩给最终用户

### 12 模块、包与导入：代码怎么组织起来

1. `import` 到底做了什么
   ① `import m` → 在 `sys.path` 列出的目录里按顺序找 `m.py`（或包）→ 找到就**执行一次**该文件并把它的全局命名空间存进 `sys.modules["m"]` → 把 `m` 这个名字绑到当前命名空间
   ② 边界：同一进程里第二次 `import` 直接取缓存（所以改了文件不重启不生效）；`sys.path[0]` 通常是"被运行脚本所在目录"
   ③ 接：为什么改了模块内容重跑交互式解释器才生效；为什么我的脚本能 import 同目录文件、换个目录跑就不行；同名模块到底导的是哪个
   ④ 例题 1 道：造两个同名 `utils.py`（不同目录），分别从两个 cwd 运行，用 `print(utils.__file__)` 对照
   ⑤ 易错：把模块名和标准库同名（如 `random.py`）导致自己写的被导到

2. `sys.path`、搜索顺序与遮蔽
   ① `sys.path` 是一个字符串列表 → 顺序即优先级 → 脚本所在目录排最前 → 所以本地文件可以遮蔽标准库/第三方包
   ② 边界：`PYTHONPATH` 环境变量能插路径（认识层）；不要靠 `sys.path.append` 解决结构问题
   ③ 接：为什么 `import` 到了错的东西；`pip install` 的包装在哪个目录（用 `pip show -f`）；为什么在 IDE 里能跑在终端里不能（cwd 不同）
   ④ 例题 1 道：打印 `sys.path` 前三项，并解释"为什么脚本目录排第一"
   ⑤ 易错：写 `sys.path.append("..")` 当万能药；依赖 cwd 的相对导入

3. `import x` 与 `from x import y`
   ① `import x` 只把模块名绑进来（用 `x.f()`）→ `from x import y` 把 `y` 直接绑进当前命名空间（用 `f()`）→ `from x import *` 把除下划线开头之外的名字全倒进来（污染、不可追踪）
   ② 边界：`import x as y` 起别名（长名字与避免冲突时用）；`from . import z` 是相对导入（下条）
   ③ 接：为什么 `from math import *` 之后 `sqrt` 能直接用、但别人看不出它从哪来；两种写法我该用哪种（默认 `import`，名字很长时 `as`）
   ④ 例题 1 道：同一段代码用三种导入写法各写一遍，比较可读性与命名空间内容（`dir()`）
   ⑤ 易错：`from x import *` 遮蔽同名变量；循环导入

4. `__name__ == "__main__"` 与 `python -m`
   ① 一个文件被直接运行时 `__name__` 是 `"__main__"` → 被 import 时 `__name__` 是模块名 → 所以把"只在直接运行时做的事"放进这个 `if` 块 → `python -m 包.模块` 也是以 `__main__` 运行，且 `sys.path[0]` 是当前目录（这就是包内脚本的标准姿势）
   ② 边界：`if __name__ == "__main__":` 块里不该有业务逻辑（应调用 `main()`）
   ③ 接：为什么我的模块一 import 就开始跑；`python -m` 和 `python 文件名` 有什么区别；`main()` 函数有必要吗
   ④ 例题 1 道：写一个既能在命令行跑又能被 import 的模块，两种方式各跑一次对照输出
   ⑤ 易错：把脚本逻辑写在模块顶层；文件名与包名冲突导致 `-m` 失效

5. 包：目录 + `__init__.py`
   ① 目录下有 `__init__.py` 就构成包（3.3+ 命名空间包可省略，但建议写）→ 包可以嵌套 → `from 包.子模块 import 函数` → `__init__.py` 里做"对外接口的收口"（导入常用名字）
   ② 边界：绝对导入优先；相对导入（`from . import x`）只要求读懂现象；`__all__` 点名
   ③ 接：我的项目什么时候该拆成包（有"库"的意图时）；`__init__.py` 里该写什么；为什么相对导入在直接运行时会报错
   ④ 例题 1 道：把 09 讲重构出的三个函数拆成 `mytool/` 包（`__init__.py` + 两个模块），从包外导入使用
   ⑤ 易错：包目录名与模块名同名；在 `__init__.py` 里写有副作用的代码

6. 标准库巡览：什么时候该去哪里找
   ① 按用途分类给一句话 + 一句"什么时候找它"：路径与文件（`os`/`pathlib`/`shutil`/`glob`）→ 系统与运行（`sys`/`time`/`subprocess`）→ 数学与随机（`math`/`random`/`statistics`）→ 时间日期（`datetime`）→ 数据格式（`json`/`csv`）→ 容器与迭代（`collections`/`itertools`）→ 文本模式（`re`）→ 命令行参数（`argparse`）
   ② 边界：只到"知道有它、知道大概管什么"；`re` 给一个 `\d+` 例子，不展开语法
   ③ 接：我怎么知道标准库里有没有现成的（`help("modules")` + 官方文档索引）；`os.path` 和 `pathlib` 该用哪个（新代码用 `pathlib`）
   ④ 例题 1 道：用 `datetime` 算两个日期差、用 `random` 做不放回抽样、用 `itertools.chain` 拼三个序列
   ⑤ 易错：自己手写日期加减；用 `random` 做加密（要用 `secrets`，认识层）

7. 第三方包与依赖
   ① `pip install 包` 装进当前解释器的 `site-packages` → `import` 靠 `sys.path` 找到它 → 依赖冲突来自"两个包要求同一个包的互斥版本" → `requirements.txt` 记录精确版本才能复现
   ② 边界：`pip freeze > requirements.txt` 与手写清单的差别；`uv.lock` 的作用（认识层细节，02 讲已讲）
   ③ 接：为什么装了还是 `ModuleNotFoundError`（装到别的解释器/别的 venv）；同事的电脑上跑不起来怎么排查；版本号 `~=`/`>=` 什么意思
   ④ 例题 1 道：在一个干净 venv 里按 `requirements.txt` 装依赖并跑通脚本，中途故意漏一个包复现 `ModuleNotFoundError`
   ⑤ 易错：在全局环境装包然后提交代码；不锁版本

8. 一个多文件小项目的完整走查（本讲收束）
   ① 需求 → 拆成"入口脚本 + 包 + 数据文件 + `requirements.txt`"→ 入口只做参数解析与调度 → 业务在包里 → 数据用相对路径（相对项目根，13 讲详谈）
   ② 边界：本节不引入测试与打包（16 讲测试、17 讲打包）
   ③ 接：目录结构该怎么长；入口脚本放哪；数据文件放哪
   ④ 例题 1 道：搭出这个骨架并跑通（三个文件 + 一个包）
   ⑤ 易错：所有代码塞一个 800 行文件；数据文件用绝对路径

### 13 文件与数据：读写、路径与格式

1. `open` 的完整参数与 `with`
   ① `open(路径, mode, encoding, newline)` 返回文件对象 → `mode` 决定读/写/追加与文本/二进制 → 文本模式必须显式给 `encoding`（否则跟平台默认走）→ `with` 保证离开代码块时关闭（即使中途异常）
   ② 边界：`mode` 全集 `r`/`w`/`a`/`x`/`b`/`+` 的组合意义；`x` 是"不存在才创建"；`w` 会清空
   ③ 接：为什么不用手动 `close()`（异常时会漏掉）；`w` 和 `a` 差在哪；`rb` 读出来的为什么是 `bytes`
   ④ 例题 1 道：用六种 `mode` 对同一个文件做实验，记录"文件不存在时"与"文件存在时"的结果
   ⑤ 易错：`open("w")` 把数据清空；不写 `encoding` 在别人机器上乱码

2. 读：四种方式与它们的适用
   ① `f.read()` 一次读全部（小文件）→ `f.readline()` 一行 → `f.readlines()` 全部行成列表 → `for line in f` 逐行迭代（大文件首选，内存友好）
   ② 边界：`read(n)` 按字符读；行尾带 `\n` 需要 `strip()`；空行是 `"\n"` 不是 `""`
   ③ 接：为什么读大文件会卡死/爆内存；为什么我读出来的每行末尾多了空行；`readlines()` 和 `list(f)` 有区别吗
   ④ 例题 1 道：对一个 10 万行文件分别用 `read`/`readlines`/迭代，打印耗时与内存占用量级（`sys.getsizeof` 只作示意）
   ⑤ 易错：对大文件用 `read()`；忘了 `strip()` 导致比较失败

3. 写：覆盖、追加与写不进去的三类原因
   ① `w` 清空后写 → `a` 追加 → 写的内容必须是 `str`（文本模式）→ 写完不 `flush` 也可能丢（进程崩溃时）→ `with` 退出时自动 `flush` + `close`
   ② 边界：`print(..., file=f)` 也可写文件；原子写（临时文件 + `os.replace`）只在认识层
   ③ 接：为什么我写完文件是空的（没进 `with`/没 `flush`）；`Permission denied` 是权限还是被 Excel 占用；中文写进去乱码怎么办
   ④ 例题 1 道：同一段数据分别用 `w` 和 `a` 写两次，对照文件内容；再故意让另一个句柄占用文件复现 `PermissionError`
   ⑤ 易错：在 `with` 外写文件；用 `w` 追加

4. `pathlib`：路径不再是字符串拼接
   ① `Path("data") / "x.csv"` 用 `/` 拼路径 → `.exists()`/`.is_file()`/`.suffix`/`.stem`/`.parent`/`.name` → `.mkdir(parents=True, exist_ok=True)` → `.glob("*.csv")` → `.read_text()`/`.write_text()` 一步读写
   ② 边界：`os.path` 仍会遇到（老代码），要能读懂 `os.path.join`；路径对象可以直接传给 `open`
   ③ 接：`Path` 和字符串有什么区别；`glob` 与 `rglob` 差在哪；相对路径相对于谁（下条）
   ④ 例题 1 道：用 `pathlib` 实现"遍历目录下所有 `*.csv` 并打印相对路径"
   ⑤ 易错：用字符串 `+` 拼路径（漏分隔符）；`Path("a")/"b"` 写成 `Path("a")+"b"`

5. 相对路径相对于谁：cwd 陷阱
   ① 相对路径由**当前工作目录**解析，不是脚本所在目录 → `python 脚本.py` 时 cwd 是"你在哪个目录敲的命令" → 所以同一脚本在不同目录跑会找不同文件
   ② 边界：要让相对路径稳定，基于 `__file__` 或 `Path(__file__).parent` 构造绝对路径；`Path.cwd()` 可查看
   ③ 接：为什么我在 IDE 里能跑、双击就找不到文件；`__file__` 在交互式环境里为什么不存在
   ④ 例题 1 道：同一个脚本从两个不同 cwd 运行，分别打印 `Path.cwd()` 与打开结果，对照失败现象
   ⑤ 易错：假设 cwd 就是脚本目录；在 `pyproject.toml`/IDE 配置里隐含设置 cwd 却不自知

6. CSV：逗号、引号、BOM 与 Excel
   ① CSV 不是"按逗号 split"：字段里可能含逗号与换行，靠引号包裹 → `csv` 模块负责这些规则 → `csv.reader` 给列表、`csv.DictReader` 给字典 → 写用 `csv.writer`/`DictWriter`，Windows 下用 `newline=""` 避免空行
   ② 边界：方言（分隔符、引号字符）参数点名；BOM 用 `encoding="utf-8-sig"`
   ③ 接：为什么我的 CSV 用 Excel 打开乱码/所有内容挤在一列（编码与分隔符）；字段里有逗号怎么办；写完多出一个空行
   ④ 例题 1 道：读写一个含"带逗号的字段 + 中文"的 CSV，Excel 能正常打开，再读回来验证往返一致
   ⑤ 易错：手写 `line.split(",")`；写文件不加 `newline=""`

7. JSON：结构化数据的通用格式
   ① JSON 的基本类型映射到 Python：对象→`dict`、数组→`list`、字符串→`str`、数字→`int`/`float`、`true/false`→`bool`、`null`→`None` → `json.dumps/loads` 处理字符串，`dump/load` 处理文件对象 → 中文要 `ensure_ascii=False` 才不转成 `\uXXXX`
   ② 边界：JSON 没有元组/集合/日期，序列化自定义对象要 `default=`；`pickle` 只在认识层且需安全警告
   ③ 接：为什么我的元组读回来变成了列表；`dumps` 的 `indent` 有什么用；为什么不能直接把 `datetime` 塞进 `json`
   ④ 例题 1 道：把一个含中文与嵌套结构的配置写成 JSON、读回、改一项再写回，全程保持可读
   ⑤ 易错：`ensure_ascii` 忘了关导致中文不可读；用 `json` 存二进制

8. 批量处理一个目录（本讲收束）
   ① 需求：遍历目录 → 过滤扩展名 → 逐个读取 → 汇总统计 → 写出结果 → 关键纪律是"幂等"（重跑不产生重复数据）与"先算后写"（别边读边覆盖原文件）
   ② 边界：本节不引入并行；错误处理用 11 讲的"单个文件失败不中断整批"
   ③ 接：跑一半崩了怎么办（重跑幂等）；要不要备份原文件；文件很多时怎么显示进度
   ④ 例题 1 道：统计一个目录下所有 `*.csv` 的行数并写出汇总表，中途放一个坏文件验证不中断
   ⑤ 易错：就地覆盖源文件；把结果写成相对路径落到 cwd 而不是项目里

### 14 面向对象 I：把"数据 + 行为"放在一起

1. 为什么需要类：一堆平行字典的痛
   ① 用字典表示"一个学生"（`{"name": ..., "score": ...}`）→ 多个函数各自约定字段名 → 字段改名要全项目搜 → 行为（算等级）散落在各处 → 类把"字段约定 + 行为"绑在一个类型上，改一处即可
   ② 边界：类不是唯一解（`dataclass`、`namedtuple`、纯函数 + 字典都行），14–15 两讲最后会给决策
   ③ 接：用字典也能跑，为什么要引入类；类是不是"高级语法"（不是，是组织手段）
   ④ 例题 1 道：先用字典 + 三个函数实现"学生成绩"，再用类实现同一功能，对照"字段名出现在几处"
   ⑤ 易错：为了用类而用类（一个类只有一个方法）

2. `class`、实例与 `self`
   ① `class Student:` 定义类型 → `Student("张三", 90)` 造出实例并自动把实例作为第一个参数传给 `__init__` → 所以 `self` 就是"这个实例本身" → `a.method(x)` 等价于 `A.method(a, x)`
   ② 边界：`self` 是约定名不是关键字；方法定义在类里、调用在实例上；`Student.method` 不加实例调用会缺参
   ③ 接：`self` 从哪来、为什么要写；忘写 `self` 报什么错；什么时候用 `Student.method(a)` 这种写法
   ④ 例题 1 道：用两种调用形式调用同一个方法，打印 `self is a` 证明是同一对象
   ⑤ 易错：漏写 `self` 参数；在方法里用类名而不是 `self`

3. `__init__`、实例属性与类属性
   ① `__init__` 在实例创建后立即被调用，用来**设置实例属性**（`self.x = x`）→ 实例属性存在 `实例.__dict__` 里，各实例独立 → 类属性存在类上，所有实例共享（除非实例自己覆盖）
   ② 边界：可变类属性（`class A: items = []`）是陷阱：所有实例共享同一个列表；`__init__` 不负责"分配内存"（那是 `__new__`，认识层）
   ③ 接：为什么我改了 `a.items` 结果 `b.items` 也变了；类属性和实例属性该用哪个；`__init__` 里能不能 `return`
   ④ 例题 1 道：复现"可变类属性共享"的 bug，再改成在 `__init__` 里创建实例属性修好
   ⑤ 易错：把可变容器写成类属性；在 `__init__` 里写业务逻辑（重）

4. 方法、`@property`、`@staticmethod`、`@classmethod`
   ① 实例方法（默认，第一个参数 `self`）→ `@property` 把方法伪装成属性访问（做计算属性或校验）→ `@staticmethod` 不需要实例（纯工具函数）→ `@classmethod` 第一个参数是类（常用作"另一个构造函数"）
   ② 边界：`@property` 的 setter 只要求读懂；`@staticmethod` 在模块级函数能替代时不必放类里
   ③ 接：什么时候该用 `@property` 而不是普通属性；`@classmethod` 造实例有什么用（从不同输入格式构造）；`staticmethod` 和模块函数有什么区别
   ④ 例题 2 道：给 `Student` 加 `@property` 的 `level`；用 `@classmethod` 写 `from_string("张三,90")`
   ⑤ 易错：给不需要校验的属性也套 `@property`；`@property` 上再写 `@staticmethod`

5. 封装是惯例，不是强制
   ① `_x` 表示"内部使用，别碰"（约定）→ `__x` 会被名称改写为 `_类名__x`（不是真私有，只是防误用与继承冲突）→ 真正的封装靠"公开接口稳定、内部随便改"
   ② 边界：Python 没有 `private` 关键字；`__slots__` 只在认识层
   ③ 接：`_x` 和 `__x` 有什么区别；为什么从外部还能访问 `__x`；我要不要给所有属性加下划线
   ④ 例题 1 道：写一个含 `_x` 与 `__y` 的类，从外部尝试访问并打印实际属性名对照
   ⑤ 易错：以为 `__x` 是私有；对"要被外部读"的属性也加双下划线

6. 什么时候该用类（本讲收束）
   ① 三个信号：同一组数据被多个函数反复传递 → 需要维护"状态"（多次操作之间有累积）→ 需要多个实现同一接口、可替换 → 三者至少中一个，才考虑类；否则用函数 + 字典/`dataclass` 更轻
   ② 边界：这是工程判断而非语法；15 讲会给出"组合优于继承"的进一步约束
   ③ 接：我的脚本只有 80 行，需要类吗；一个类该有多少方法；类太大怎么拆
   ④ 例题 1 道：给四个场景（纯计算、一次性脚本、要维护连接状态、要多种可替换实现）判断该不该用类
   ⑤ 易错：把所有函数塞进一个 `class App`；用类当命名空间

### 15 面向对象 II：继承、多态与魔术方法

1. 继承做了什么与 `super()`
   ① `class B(A)` 让 `B` 的实例在查找属性时先看自己、再沿继承链往上找（`B` → `A` → `object`）→ `super().__init__(...)` 调用父类实现 → 于是"共用部分写在父类、差异写在子类"
   ② 边界：`MRO`（方法解析顺序）只讲现象（多继承时按一条确定的顺序找），不讲 C3 算法；深继承树是反模式
   ③ 接：为什么我改了父类结果子类也变了行为；`super()` 里能不能不传参数（3 里可以）；多继承要不要用（能不用就不用）
   ④ 例题 1 道：`Animal` → `Dog`/`Cat` 两个子类，`super().__init__` 传递公共字段，打印各自的属性
   ⑤ 易错：忘了调 `super().__init__` 导致父类字段缺失；为复用代码而建三层继承

2. 多态与鸭子类型
   ① 多态 = 同一个调用在不同实例上得到不同行为 → Python 靠"有没有这个方法"而不是"是不是这个类型"来决定（鸭子类型）→ 于是"可替换"靠接口一致，不靠继承
   ② 边界：`isinstance` 该在"确实需要区分类型"时用；`Protocol`/`abc` 只在认识层
   ③ 接：不继承能不能实现多态（能，只要方法名一样）；那继承还有什么用（复用实现 + 表达"是一种"）；`isinstance` 会不会破坏多态
   ④ 例题 1 道：两个无共同父类的类各实现 `area()`，放进同一列表循环调用，证明鸭子类型生效
   ⑤ 易错：用 `type(x) == A` 判断（漏掉子类）；为多态强行造一个共同父类

3. 魔术方法：让对象像内置类型
   ① `__str__` 给人看（`print`）→ `__repr__` 给开发者看（交互式回显、容器打印）→ `__eq__` 决定 `==` → `__lt__` 让对象可排序 → `__len__` 让 `len()` 可用 → `__iter__` 让 `for` 可用
   ② 边界：只给最常用的六个；`__hash__` 与 `__eq__` 联动（定义了 `__eq__` 的对象默认不可哈希）
   ③ 接：为什么 `print(对象)` 打出一串 `<__main__.X object at 0x...>`；`__repr__` 和 `__str__` 该写哪个（两个都写，`__repr__` 优先）；为什么我定义了 `__eq__` 之后不能当字典键了
   ④ 例题 2 道：给 `Point` 实现 `__repr__`/`__eq__`/`__lt__` 并排序；实现 `__len__`/`__iter__` 让自定义容器能 `for`
   ⑤ 易错：`__eq__` 忘了返回 `NotImplemented`（跨类型比较）；只写 `__str__` 不写 `__repr__`

4. `dataclass`：省掉样板
   ① `@dataclass` 按字段声明自动生成 `__init__`/`__repr__`/`__eq__` → `field(default_factory=list)` 解决"可变默认值" → `frozen=True` 得到不可变版本
   ② 边界：`dataclass` 只适合"主要是数据"的类；带复杂行为的类仍手写
   ③ 接：`dataclass` 和普通类怎么选；为什么默认值不能直接写 `[]`（与 09 讲默认参数同因）；`frozen=True` 和 `tuple` 有什么区别
   ④ 例题 1 道：把 15 讲第 3 条的 `Point` 用 `dataclass` 重写，对照行数与行为
   ⑤ 易错：在 `dataclass` 里写可变默认值；以为 `dataclass` 会自动校验类型（注解只是标注）

5. 组合优于继承
   ① 继承表达"是一种"且强耦合（父类改，子类可能坏）→ 组合表达"有一个"，通过持有对象并调用它的方法复用 → 大多数"想复用代码"的场景其实是组合
   ② 边界：真正需要多态的接口一致时继承仍合适；"组合 + 委托"要多写几个转发方法
   ③ 接：我需要复用三个方法，该继承还是组合；组合之后调用链变长怎么办
   ④ 例题 1 道：把"继承 `Logger` 的 `Service`"改成"持有一个 `logger` 对象"，对照改动面
   ⑤ 易错：为复用代码而继承；继承后重写父类大部分方法

6. 常见误用清单（本讲收束）
   ① 一个类只有一个方法且无状态 → 应该是函数 → 类只当命名空间（全 `@staticmethod`）→ 深继承树（>2 层）→ 用类属性存共享可变状态 → `__init__` 里做重 I/O
   ② 边界：这是清单不是禁令，遇到具体场景要说明理由
   ③ 接：我的 `class Config` 全是类属性算不算滥用；什么时候该拆类
   ④ 例题 1 道：给一段"滥用类"的代码逐条指出问题并改写
   ⑤ 易错：把所有工具函数塞进一个 `Utils` 类

### 16 验证与可读：风格、测试、断点与日志

1. 代码风格：让改动在 diff 里看得见
   ① PEP 8 是社区约定而非语法 → 命名（`snake_case` 变量与函数 / `CamelCase` 类 / `UPPER_CASE` 常量）→ 行宽与空行 → import 分三组（标准库/第三方/本地）→ 统一风格的效果是"diff 里只剩真实改动"，而不是混着格式化噪音
   ② 边界：只要求会跑 `ruff check` 与 `ruff format`（或 `black`）；不争论行长 79 还是 88；风格不改变行为，也不替代测试
   ③ 接：风格真的重要吗（三个月后的自己与别人）；有没有自动工具；为什么 import 要分三组；机房没装 ruff 怎么办
   ④ 例题 1 道：对一段命名混乱、import 乱序的脚本跑 `ruff format`，对照格式化前后的 diff，指出哪些行只是格式、哪些行是语义
   ⑤ 易错：手工逐行调格式；同一文件混用 `camelCase` 与 `snake_case`；把格式化 diff 与真实改动混在一次提交里

2. 测试的最小闭环：不装任何东西也能测
   ① 写一个函数 → 另写一个脚本调用它 → 用 `assert 函数(输入) == 期望` 钉住结论 → 跑脚本：全过则静默，任一失败则抛 `AssertionError` 并显示两边的值 → 于是"我试过了"变成"这一步可重复地证明了"
   ② 边界：这一条刻意只用标准库、不依赖 pytest；测试是代码不是文档，跑不起来就没有价值
   ③ 接：这和 11 讲第 6 条的 `assert` 校验参数有什么区别（一个钉住行为、一个拦输入）；要写多少条测试；测试里的 `print` 有什么用（基本没用）
   ④ 例题 1 道：给 09 讲重构出的函数写一个 `assert` 测试脚本，先跑绿；再把实现改错一位跑红，读错误输出里的期望值与实际值
   ⑤ 易错：测试里靠 `print` 用眼睛比对；只测正常路径，不测空列表、零、负数这些边界

3. `pytest`：命名约定、`raises` 与失败输出怎么读
   ① `pip install pytest` → 测试放进 `test_*.py`、函数名 `test_*` → 在项目根目录跑 `pytest` → 它自动发现并执行、最后给出通过/失败数 → 失败时打印"哪个文件哪一行、左边实际值、右边期望值"
   ② 边界：只讲函数级测试、`pytest.raises` 断言异常、`-k` 只跑指定测试；不讲 fixture、mock、覆盖率、参数化
   ③ 接：为什么函数名必须以 `test_` 开头；为什么我写的测试没被发现（文件名、目录、cwd）；失败输出里该看哪一行；`pytest` 与第 2 条的 assert 脚本是什么关系（同一机制，多了收集与汇总）
   ④ 例题 2 道：把第 2 条的脚本改造成 pytest 测试文件并跑出"3 passed"；给一个会抛 `ValueError` 的函数写 `pytest.raises(ValueError)`
   ⑤ 易错：测试文件与源码同名导致 import 到错的东西；断言写成 `assert f(x)` 不给期望值（失败时看不出差多少）；测试之间共享全局状态导致顺序依赖

4. 改代码之前先钉住现状
   ① 要重构一个函数 → 先为它现有行为写测试并跑绿 → 再改内部实现 → 再跑 → 全绿说明行为未变；变红说明这处改动破坏了某条既有约定 → 于是重构的风险从"凭感觉"变成"有对照"
   ② 边界：这是纪律不是教条；不要求先写测试再写功能（TDD），只要求在动别人（或三个月前的自己）的代码前先有对照
   ③ 接：我改自己的脚本也要这样吗；测试写多了维护成本高不高；重构时测试要不要跟着改（只改测试里对实现细节的假设，不改被钉住的行为）
   ④ 例题 1 道：给 13 讲批量统计函数先写三条测试钉住输出，再把内部实现从"循环累加"改成 `Counter`，测试全绿
   ⑤ 易错：改实现时顺手把测试也改了（等于没测）；测试依赖随机数却没固定种子

5. 断点与 `pdb`：让程序停在你想看的那一行
   ① 在代码里写 `breakpoint()` → 运行到该行暂停并进入调试器 → `n` 执行下一行、`s` 进入函数内部、`p 表达式` 求值、`q` 退出 → 于是"猜哪个变量不对"变成"当场问它现在是多少"
   ② 边界：只要求这四个命令；IDE 会接管 `breakpoint()`（变成图形断点），两者是同一个钩子而非两套东西；在调试器里改变量值（`!` 前缀）只点名
   ③ 接：为什么我在 IDE 里点的断点与终端里 `breakpoint()` 表现不一样；断点为什么没停（没走到 / 被跳过 / 跑的不是这份文件）；调试与 `print` 该怎么分工
   ④ 例题 1 道：在一个累积求和的循环第 3 轮 `breakpoint()` 停下，用 `p` 分别查看总和、当前元素、下标，再 `n` 走一行看变化
   ⑤ 易错：不知道要看什么就一直按 `n`；调试完忘了删断点；在要循环一万次的地方下断点导致反复停

6. `logging` 与 `print` 的分工
   ① `print` 只会输出、无级别、不能整体关掉、不带时间与位置 → `logging` 有级别（`DEBUG`/`INFO`/`WARNING`/`ERROR`）、可配置目标（控制台/文件）与格式、可按级别开关 → 于是调试信息留在代码里也不再妨碍正常使用
   ② 边界：`logging.basicConfig(level=..., format=...)` 最小配置即可；日志轮转、多 handler、结构化日志只点名
   ③ 接：什么时候用 `print` 什么时候用 `logging`；怎么让日志同时进文件和控制台；为什么生产代码不该留 `print`；日志该记什么（输入、关键决策、失败原因，不含密钥）
   ④ 例题 1 道：给 13 讲批量脚本换成 `logging`，用命令行开关控制级别，对照原来的 `print` 版本在关闭调试信息后的输出差异
   ⑤ 易错：日志里打印密钥、密码、身份证号；只写"失败"不写哪个文件、什么原因；`print` 与 `logging` 混用导致输出重复

7. 一次改动的完整验证流程（本讲收束）
   ① 读懂需求 → 写/补测试并跑绿（钉住现状）→ 改实现 → 跑测试 → 红了用断点定位到具体一行 → 修 → 全绿 → 提交（`git commit`，回呼 03 讲）→ 关键决策写进注释或日志
   ② 边界：这是单人最小流程，不是团队 CI；"跑绿"必须有输出记录，不能凭印象
   ③ 接：哪一步可以省（一步都不该省，但小脚本可把"写测试"缩成三条断言行）；会不会太慢（比起改坏了找不到原因，这是最快的路）
   ④ 例题 1 道：把第 4 条的重构完整走一遍，留下 `pytest` 输出与 `git log` 作为证据
   ⑤ 易错：改完不跑测试就提交；红了先去改测试

### 17 交付质量：性能、可复现、文档与打包

1. 性能：先测量，再动手
   ① 直觉对性能的判断经常错 → 用 `time.perf_counter()` 包住可疑的那一段，测出毫秒数 → 按"算法层 → 数据结构层 → 重复计算层 → I/O 层"的顺序找原因 → 只改最贵的那一处
   ② 边界：只讲"测量 + 换数据结构 + 消除重复计算"；`cProfile` 认识层；不讲 C 扩展、并发、JIT
   ③ 接：Python 慢是语言问题还是我的问题；优化前怎么知道瓶颈在哪；几毫秒的优化值不值得做
   ④ 例题 1 道：同一个"两列表求交集"的任务写三种实现（双层循环 / 列表 `in` / 集合 `&`），实测三者耗时并给出比值
   ⑤ 易错：凭感觉优化；没测就下结论；优化后不重测

2. 复杂度直觉：数循环层数与容器操作的代价
   ① 循环里套循环 → 次数是 $n \times n$ → 内层若是"在列表里查找"（$O(n)$）则整体 $O(n^2)$ → 把查找对象换成集合或字典，内层变 $O(1)$ → 整体降到 $O(n)$ → 一万条数据从秒级降到毫秒级
   ② 边界：不给复杂度证明，只给"数循环层数 + 看每个容器操作的代价"这条判据；数据结构本体的实现不讲
   ③ 接：我怎么一眼看出这段是 $O(n^2)$；`in` 在列表、集合、字典上代价为什么不同（回呼 06、07 讲）；嵌套三层是不是一定慢
   ④ 例题 1 道：给出"两两比较"与"建集合再取交集"两个版本的实测耗时表（$n = 1000 / 10000 / 100000$ 三个规模）
   ⑤ 易错：只看代码行数不看循环结构；在循环里重复读文件、重复求 `len()`、重复构造不变的对象

3. 可复现：别人拿到你的项目能不能跑
   ① 能跑 = 代码 + 依赖清单（含版本）+ Python 版本 → 清单写成 `requirements.txt`（pip）或 `pyproject.toml` 加 `uv.lock`（uv），Python 版本固定用 `.python-version` → 在干净环境里按清单装一遍并跑通，才算验证过
   ② 边界：版本约束 `==`（精确）/`>=`（下限）/`~=`（兼容到次版本）各自含义；`.venv` 不入库（回呼 03 讲 `.gitignore`），锁文件入库
   ③ 接：为什么同事跑不起来；该不该把 `.venv` 压缩发过去（不该）；`pip freeze` 出来几百行正常吗（正常，但会带上间接依赖）
   ④ 例题 1 道：在全新的 venv 里按清单复现 12 讲的多文件项目，中途故意漏一个包复现 `ModuleNotFoundError`，再补上跑通
   ⑤ 易错：清单里只写包名不写版本；把本机绝对路径写进配置；用全局环境验证"能跑"

4. 项目结构、README 与注释
   ① 结构按"能一眼找到东西"分层：入口脚本 + 包 + `data/` + `tests/` + `README.md` → README 回答四问（这是什么、怎么装、怎么跑、输入输出长什么样）→ 注释解释"为什么这么写"，docstring 说明"这是什么、怎么调用"
   ② 边界：不规定唯一目录模板；不要求写长文档，只要求别人（或三个月后的你）照 README 能跑起来
   ③ 接：我 300 行的单文件要不要拆；README 写多长才够；注释多少算合适
   ④ 例题 1 道：给 13 讲的批量脚本补目录、README 与 docstring，然后只拿着这个仓库照 README 走一遍，记录卡住处并修
   ⑤ 易错：README 写了 `pip install -r requirements.txt` 但文件不存在；注释在复述代码（`i += 1  # i 加 1`）

5. 打包与本地安装（认识层）
   ① `pyproject.toml` 声明项目名、版本、依赖 → `pip install -e .` 把当前目录以"可编辑"方式装进当前环境 → `[project.scripts]` 声明命令行入口 → 于是 `python 脚本.py` 变成"在任意目录敲一个命令"
   ② 边界：只到"本地能装、能作为命令运行"；发布到 PyPI、构建 wheel、语义化版本号只点名
   ③ 接：我只是交作业需要打包吗（多数不需要）；`-e` 是什么意思（改代码不用重装）；装了之后原来的 `import` 会怎样
   ④ 例题 1 道：给 12 讲的包加 `pyproject.toml`，`pip install -e .` 后在项目目录之外用命令名调用并跑通
   ⑤ 易错：把 `.venv` 与 `__pycache__` 打进包；版本号写成 `0.0.0` 或随手递增

6. 交付前自查清单（本讲收束）
   ① 六问：干净环境能跑吗 → 测试全绿吗 → 输入文件缺失时给的是可读错误还是 traceback → 输出与日志里有没有密钥与隐私 → README 与实际命令是否一致 → `git status` 里有没有 `.venv`、`__pycache__`、数据大文件
   ② 边界：清单是给自己用的拦网，不是仪式；每条都要能给出证据（命令 + 输出），不接受"我记得"
   ③ 接：这套检查该在什么时候跑；哪条最容易漏（干净环境，因为它要求你离开自己机器的状态）
   ④ 例题 1 道：对 12–13 讲的项目逐条自查，把六条证据写成一段记录
   ⑤ 易错：只在自己机器上验证；把"我装过"当证据；`git status` 里塞满临时文件还照常提交
