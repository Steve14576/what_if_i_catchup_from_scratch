## 0. 场景：三件天天要做的事

- 日志一行是 `2026-11-14 09:30:12 ERROR 连接超时`，你要把日期、时刻、级别分开统计；
- 用户输入的姓名前后带空格、大小写混乱，你要规整成 `Zhang San` 这种形式；
- 终端里输出一张表，列要对齐，不然读起来像乱码。

这三件事全部落在字符串上。字符串是 Python 里最常用的类型，没有之一。

## 1. 四种写法与转义

### 1.1 引号：单双都行

```python
print("他说\"你好\"")
print('他说"你好"')
```

两种写法输出一样（实测都是 `他说"你好"`）。规则很简单：**字符串用哪种引号开头，就得用同种引号结尾**；里面要出现同种引号时，要么用反斜杠转义，要么换另一种引号。

实践建议：**外层用双引号，内层需要引号时用单引号**。这样最不容易出转义错误。

### 1.2 转义：反斜杠 + 一个字符

| 写法 | 含义 | 实测 |
|---|---|---|
| `\n` | 换行 | `"第一行\n第二行"` 打印成两行 |
| `\t` | 制表符（Tab） | `'a\tb'` 的 `repr` 显示为 `'a\tb'` |
| `\\` | 一个反斜杠本身 | 写路径时常用 |
| `\"` / `\'` | 引号本身 | 见上一节 |

`repr()` 是一个很有用的函数：它把字符串"能看见的样子"打出来——换行会显示成 `\n`，而不是真的换行。调试时看 `repr` 比看 `print` 更准确。

### 1.3 raw 字符串：反斜杠不转义

在引号前加 `r`：

```python
print(repr(r"a\nb"))
```

```text
'a\\nb'
```

`r"a\nb"` 里有两个字符 `a`、`n` 中间的反斜杠？不对——它是四个字符：`a`、`\`、`n`、`b`。加 `r` 之后，`\n` 不再被解释成换行。

什么时候用：写 Windows 路径（`r"C:\Users\me"`）、写正则表达式（第 22 讲）。注意 raw 字符串**不能以单个反斜杠结尾**（`r"abc\"` 是语法错误），因为结尾的反斜杠会把结束引号转义掉。

### 1.4 三引号：跨行文本

```python
multi = """第一行
第二行"""
```

实测打印出两行。三引号保留换行，适合写多行文本块；函数体第一句三引号字符串就是文档字符串（第 09 讲见过）。

## 2. 索引：一个字符的位置

### 2.1 正索引与负索引

```text
  s = 'python'   len(s) = 6
  s[0] = 'p'   s[3] = 'h'   s[-1] = 'n'   s[-2] = 'o'
```

- 正索引从 `0` 开始，最后一个字符是 `len(s) - 1`；
- 负索引从尾部数：`-1` 是最后一个，`-2` 是倒数第二个；最小可用是 `-len(s)`。

为什么从 0 开始？因为索引的含义是"偏移量"：`s[0]` 表示"从开头偏移 0 个字符"。这个惯例在几乎所有语言里都一样。

### 2.2 单点索引越界：报错

```text
  s[100] -> IndexError: string index out of range
```

单点索引越界会直接抛 `IndexError`。这是好事：它让你立刻知道"我算错了位置"，而不是悄悄给你一个空字符串、让错误往下游传。

## 3. 切片：一次取一段

### 3.1 三个数字

切片写法是 `s[起点:终点:步长]`，三个都可以省略：

- 起点默认 `0`；
- 终点默认到末尾（**不含**终点）；
- 步长默认 `1`；步长为负表示反向。

关键记忆点：**含起点、不含终点**。所以 `s[0:3]` 是前三个字符。

### 3.2 九个实测

```text
  s = '0123456789'
  s[2:5]       = '234'
  s[:3]        = '012'
  s[7:]        = '789'
  s[:]         = '0123456789'
  s[::2]       = '02468'
  s[::-1]      = '9876543210'
  s[1:100]     = '123456789'
  s[100:200]   = ''
  s[5:2]       = ''
```

逐条读：

- `s[2:5]`：从 2 开始，到 5 之前，得到 `234`；
- `s[:3]`：省略起点，等价 `s[0:3]`；
- `s[7:]`：省略终点，一直取到结尾；
- `s[:]`：整份拷贝（第 4 节会说为什么强调"拷贝"）；
- `s[::2]`：每隔一个取一个；
- `s[::-1]`：反向取，最常用的反转字符串写法；
- `s[1:100]`：终点超界，不报错，截到末尾为止；
- `s[100:200]`：起点也超界，得到空字符串；
- `s[5:2]`：起点大于终点且步长为正，得到空字符串。

### 3.3 为什么切片越界不报错

这不是疏漏，是设计选择：切片表达的是"我想要这一段"，而"这一段不存在"是一个合法结果（空）。这样你写 `line[:10]` 取前十个字符时，不必先判断长度够不够。

对比第 2.2 节：`s[100]` 要的是"第 100 个字符"，它不存在，所以必须报错。

把这两条合起来记：单点索引越界报错，切片越界得到空或截断。

### 3.4 切片产生新对象

`t = s[:]` 看起来像"给自己"，实际上创造了一个新字符串对象。这一点现在不重要，但到第 12 讲讲列表切片时会变成关键区别（列表切片也是新对象，而 numpy 的切片是视图，第 23 讲会对比）。

## 4. 不可变：字符串改不了

### 4.1 实测

```text
  s[0] = 'P' -> TypeError: 'str' object does not support item assignment
```

字符串一旦创建，里面的字符就不能替换。想要 `Python`，只能新建：

```python
s = "python"
t = "P" + s[1:]
```

实测 `t` 是 `'Python'`，而原来的 `s` 仍然是 `'python'`——因为 `+` 产生了新对象，`s` 还贴在旧对象上（第 09 讲的标签模型）。

### 4.2 所有"修改"方法都返回新对象

`strip()`、`replace()`、`upper()` 这些方法**都不改原字符串**，而是返回一个新的：

```python
raw = "  Alice, Bob , Carol  "
print(raw.strip())    # 'Alice, Bob , Carol'
print(raw)            # 仍然是 '  Alice, Bob , Carol  '
```

忘了接收返回值，是新手最常见的"我明明调用了怎么没变"。

### 4.3 一个性能预告

因为不可变，循环里反复拼接会不断产生新对象：

```python
result = ""
for x in items:
    result = result + x     # 每次都新建一个字符串
```

元素多的时候这很慢。正确做法是用列表收集、最后 `"".join(...)` 一次拼好。这里只需要记住结论，第 23 讲会用实测对比两种写法的耗时。

## 5. 常用方法

### 5.1 去空白与切分

```text
  raw = '  Alice, Bob , Carol  '
  strip()          -> 'Alice, Bob , Carol'
  split(',')       -> ['Alice', ' Bob ', ' Carol']
  split(',') 后再 strip 每项 -> ['Alice', 'Bob', 'Carol']
```

- `strip()` 去掉两端空白；`lstrip()` / `rstrip()` 只去左 / 右；
- `split(分隔符)` 按分隔符切成一个**列表**（第 12 讲正式讲列表，这里只需要知道它是一串元素）；
- 注意 `split` 之后每一项**各自还带着空格**，所以还要对每项 `strip`——这就是上面第三行的写法。

`split()` 不带参数时按任意空白切分，并自动丢弃空项，处理"多个空格分隔"的文本时更方便。

### 5.2 查找、替换、判断

```text
  'abcabc'.replace('a','X') -> 'XbcXbc'
  'abcabc'.find('ca')       -> 2
  'abcabc'.count('a')       -> 2
  'log.txt'.endswith('.txt') -> True
```

- `find(子串)` 返回第一次出现的**下标**，找不到返回 `-1`；`index` 与它一样但找不到会抛 `ValueError`；
- `replace(旧, 新)` 默认替换全部；第三个参数可以限制次数；
- `count(子串)` 数出现次数；
- `startswith` / `endswith` 判断前缀后缀，常用于"这个文件是不是 `.csv`"。

### 5.3 大小写

`upper()` 全大写、`lower()` 全小写、`title()` 每个词首字母大写、`capitalize()` 只有首字母大写。这些同样返回新字符串。

### 5.4 `split` 与 `join` 的对称性

```text
  ','.join('a,b,c'.split(',')) == 'a,b,c' ? True
```

`split` 把字符串拆成列表，`join` 用分隔符把列表拼回去。记住这个对称性，解析与重组就都有了方向：

- 解析：`line.split(",")`；
- 重组：`",".join(parts)`。

一个容易写反的地方：`join` 是**分隔符**的方法，不是列表的方法。写 `",".join(parts)`，不是 `parts.join(",")`。

### 5.5 方法一览

| 想做的事 | 方法 | 返回值 |
|---|---|---|
| 去两端空白 | `strip()` / `lstrip()` / `rstrip()` | 新字符串 |
| 按分隔符切开 | `split(sep)` / `split(sep, maxsplit)` / `splitlines()` | 列表 |
| 拼起来 | `sep.join(列表)` | 新字符串 |
| 替换 | `replace(旧, 新)` | 新字符串 |
| 找位置 | `find()`（找不到 -1）/ `index()`（找不到报错） | 整数 |
| 计数 | `count(子串)` | 整数 |
| 前后缀判断 | `startswith()` / `endswith()` | 布尔值 |
| 大小写 | `upper()` / `lower()` / `title()` / `capitalize()` | 新字符串 |

## 6. f-string：把值与格式一起写清楚

### 6.1 基本用法

```python
name = "小明"
print(f"你好，{name}")
```

`f"..."` 前面的 `f` 表示"这个字符串里 `{}` 会被求值替换"。花括号里可以写任意表达式：`{a + b}`、`{len(s)}`、`{d["key"]}`，不只是变量名。

### 6.2 格式说明符：冒号后面那一串

```text
  两位小数: 87.46
  宽度 8 右对齐:       小明|
  宽度 10 居中:     小明    |
  千分位: 1,234,567
  百分比一位: 87.3%
  调试写法 score=: score=87.456
```

对应写法：

| 想要的效果 | 写法 | 说明 |
|---|---|---|
| 保留两位小数 | `{x:.2f}` | `f` 是定点小数；`.2` 是小数位数 |
| 宽度 8、右对齐 | `{s:>8}` | `>` 右、`<` 左、`^` 居中 |
| 宽度 8、补零 | `{n:08d}` | `0` 是填充字符，`d` 是整数 |
| 千分位 | `{n:,}` | 只影响显示，不影响值 |
| 百分比 | `{r:.1%}` | 自动乘 100 并加 `%` |
| 调试输出 | `{expr=}` | 连同表达式文本一起打印 |

两条实践建议：

- **输出表格一律用宽度对齐**（`{:>8}` / `{:^10}`），比手工加空格可靠；
- 调试时用 `{score=}`，不用手写 `"score=" + str(score)`。

注意中文的对齐宽度：一个汉字的终端显示宽度通常是 2，但 f-string 的宽度按**字符数**算，所以中英混排的表格不一定能对齐。这是显示层的问题，不是 f-string 的错；真要严格对齐，得用能识别宽度的库（本课程不展开）。

### 6.3 引号嵌套

f-string 里如果还要用引号（比如 `{d["key"]}`），**外层用单引号、内层用双引号**最稳：

```python
print(f'值是 {d["key"]}')
```

外层双引号、内层也双引号在不同 Python 版本上的支持不一样，换一种引号可以避开所有版本差异。

## 7. 编码：字符与字节不是一回事

### 7.1 `len` 数的是字符

```text
  text = '中文a'   len(text) = 3（字符数）
```

`len("中文a")` 是 3——两个汉字加一个字母，按**字符**数。你在编辑器里看到几个字，`len` 就是几（除了 emoji 这类复合字符，暂时不用管）。

### 7.2 字节：存到文件、发到网络时才出现

```text
  utf-8 字节 = b'\xe4\xb8\xad\xe6\x96\x87a'   长度 = 7
  gbk   字节 = b'\xd6\xd0\xce\xc4a'   长度 = 5
```

同一个 `'中文a'`：

- 用 UTF-8 编码占 7 个字节（每个汉字 3 个字节，字母 1 个）；
- 用 GBK 编码占 5 个字节（每个汉字 2 个字节，字母 1 个）。

`encode(编码)` 把字符串变成字节串（`bytes`，显示时带 `b'...'` 前缀）；`decode(编码)` 反过来。

### 7.3 乱码与解码错误

```text
  utf-8 解回来 -> '中文a'
  用错编码解码 -> UnicodeDecodeError: 'gbk' codec can't decode byte 0xad in position 2 ...
```

用错编码解码会得到两种结果：

- **报错**（`UnicodeDecodeError`）：这算幸运，至少你知道错了；
- **乱码**：读出来了，但内容全是奇怪的符号，程序继续跑，错误传到很远的地方才暴露。

这就是第 01 讲说"本课程所有 `.py` 都存 UTF-8"的原因。第 19 讲讲文件读写时会定一条纪律：**每次 `open` 都显式写 `encoding="utf-8"`**，不依赖系统默认值（Windows 的默认值曾经是 GBK，换台机器就乱）。

## 8. 实战：把一行日志切成四个字段

```python
line = "2026-11-14 09:30:12 ERROR 连接超时"
```

先看一种**错**切法：

```text
  先看一种错切法 split(' ', 2): ['2026-11-14', '09:30:12', 'ERROR 连接超时']
```

`split(" ", 2)` 的意思是"最多切两刀"，所以得到三段：日期、时刻、以及**粘在一起的**级别和消息。字段数数错，后面的统计就全乱。

正确切法：

```text
  正确切法 split(' ', 3): ['2026-11-14', '09:30:12', 'ERROR', '连接超时']
  日期 = '2026-11-14'  时刻 = '09:30:12'
  级别 = 'ERROR'    消息 = '连接超时'
  取小时: time_part[:2] = '09'
```

三条经验：

1. `maxsplit` 要比字段数少 1（四个字段切三刀）；
2. 字段数拿不准时，先 `print(line.split(" "))` 数一数，再决定切几刀；
3. 切完的最后一段通常用于"消息"，用 `maxsplit` 正好保住消息里的空格——所以这类日志切分常常写 `split(" ", 3)` 而不是 `split()`。

## 9. 这一讲留下的东西

- 字符串不可变：所有"修改"都是新建；忘了接收返回值就等于什么都没做。
- 索引单点越界报 `IndexError`；切片越界是截断或空，不报错。
- 切片 `s[起:终:步]`：含起点不含终点，步长可负，`s[::-1]` 反转。
- `split` 与 `join` 互为逆操作；`join` 是分隔符的方法。
- f-string 用 `{}` 嵌值、用 `:` 加格式；对齐、补零、千分位、百分比都有现成写法。
- `len` 数字符，`encode` 出字节；同一段文本在不同编码下字节数不同，乱码就发生在"用错编码解码"这一步。

下一讲进入列表与元组：有序、可改、能排序的一串东西。你会看到"切片到底是拷贝还是视图""`sort()` 为什么返回 `None`""改了一个列表另一个为什么也变了"。

## 小结

- 引号单双等价；转义 `\n` / `\t` / `\\`；`r"..."` 不转义；三引号保留换行。
- 正索引从 0 起，负索引从 -1 起；`s[100]` 抛 `IndexError: string index out of range`。
- 切片含起点不含终点：实测 `s[2:5]='234'`、`s[::2]='02468'`、`s[::-1]='9876543210'`、`s[1:100]` 截断、`s[100:200]=''`、`s[5:2]=''`。
- 字符串不可变：`s[0]='P'` 抛 `TypeError: 'str' object does not support item assignment`；拼接产生新对象。
- `strip` / `split` / `join` / `replace` / `find` / `count` / `startswith` 都返回新对象；`",".join("a,b,c".split(","))` 还原原串。
- f-string：`{x:.2f}`、`{s:>8}`、`{n:,}`、`{r:.1%}`、`{expr=}`。
- `len('中文a')=3`，UTF-8 占 7 字节、GBK 占 5 字节；编码用错会报 `UnicodeDecodeError` 或产生乱码。
- 日志切分：`split(" ", 3)` 得四个字段；`maxsplit` 比字段数少 1。

## 作业

**Q1.** 给定 `s = "  Hello, World  "`，写出得到下列结果的最短写法：`"Hello, World"`、`"HELLO, WORLD"`、`"Hello"`、`"World"`。

**参考答案：** 四次链式调用如下：

```python
s = "  Hello, World  "
s.strip()                 # 'Hello, World'
s.strip().upper()         # 'HELLO, WORLD'
s.strip().split(",")[0]   # 'Hello'（先切出 'Hello' 与 ' World'）
s.strip().split(",")[1].strip()   # 'World'（第二段还带前导空格，要再 strip）
```

要点：`strip()` 只去两端空白，不会去掉中间的空格；第二段开头的空格属于"中间"，得单独处理。

**Q2.** 用切片写出：取 `"0123456789"` 的后三位、去掉首尾各一位、每两个取一个、反转。

**参考答案：** 四个切片表达式：

```python
s = "0123456789"
s[-3:]      # '789'
s[1:-1]     # '12345678'
s[::2]      # '02468'
s[::-1]     # '9876543210'
```

注意 `s[1:-1]` 用的是负索引作终点，`-1` 表示"最后一个字符之前"，所以去掉了首尾各一位。

**Q3.** 下面的代码想统计每行日志的级别，但结果不对。指出问题并修正。

```python
line = "2026-11-14 09:30:12 ERROR 连接超时"
parts = line.split(" ", 2)
print(parts[2])
```

**参考答案：** `split(" ", 2)` 只切两刀，得到三段，`parts[2]` 是 `'ERROR 连接超时'`——级别与消息粘在一起。

改成切三刀：

```python
parts = line.split(" ", 3)
print(parts[2])   # 'ERROR'
```

或者用解包让结构更清楚：

```python
date_part, time_part, level, message = line.split(" ", 3)
print(level)
```

解包还有个好处：字段数对不上时会直接报错（`ValueError: not enough values to unpack`），比默默取错下标更早暴露问题。

**Q4.** 用 f-string 输出一行：姓名左对齐宽度 6、分数右对齐宽度 6 保留一位小数。给定 `name="Li"`、`score=93.5`。

**参考答案：** 一条 f-string 就够：

```python
name = "Li"
score = 93.5
print(f"{name:<6}{score:>6.1f}")
```

输出是 `Li      93.5`（`Li` 后面 4 个空格，凑满 6；`93.5` 前面 2 个空格，凑满 6）。

要点：宽度与对齐都写在冒号后面，顺序是"填充/对齐 + 宽度 + 精度 + 类型"，例如 `>6.1f`。

**Q5.** 解释为什么 `len("中文") == 2`，但把这段文本存成 UTF-8 文件时占 6 个字节。

**参考答案：** `len` 数的是**字符**：`中`、`文` 是两个字符，所以是 2。存文件时要把字符编码成**字节**，UTF-8 里一个常用汉字占 3 个字节，所以 `"中文".encode("utf-8")` 得到 6 个字节。

两个数都对，只是量的对象不同：一个是"屏幕上几个字"，一个是"磁盘上几个字节"。同理，GBK 下这两个字只占 4 个字节。

**Q6.** 你从文件里读出一行 `"a, b ,c"`，想得到列表 `["a", "b", "c"]`。写出代码，并说明为什么直接 `split(",")` 不够。

**参考答案：** 先切、再对每一项去空白：

```python
line = "a, b ,c"
parts = [x.strip() for x in line.split(",")]
print(parts)   # ['a', 'b', 'c']
```

直接 `split(",")` 得到的是 `['a', ' b ', 'c']`——第二项前后都有空格。`split` 只按分隔符切开，不会顺手去掉每项两端的空白，所以要对每一项再 `strip()`。

（这里的 `[... for x in ...]` 是列表推导式，第 14 讲讲控制流时会正式讲；现在也可以写成先 `split` 再循环处理。）
