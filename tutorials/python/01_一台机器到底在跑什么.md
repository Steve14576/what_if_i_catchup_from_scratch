# 第 01 讲 一台机器到底在跑什么

> **前置**：会用鼠标和键盘，能在文件夹里新建、保存、找到文件。不需要任何编程经验，也不需要会用命令行。
> **预计时间**：约 1.5 小时（含作业；第 3 节的三个角色读懂即可，不需要背）。
> **本讲回答**：我写的那几行英文，凭什么能被机器执行？"装 Python"到底在我电脑上放了什么？为什么同一句代码在黑色窗口里敲就出结果，写成文件却什么都不发生？报错是不是说明我把它弄坏了？
> **本讲结束你能做到**：写出一个 `.py` 文件并用解释器运行它；说清源代码、解释器、内存、磁盘各自扮演什么角色；把一条报错拆成"位置 / 类型 / 消息"三段，并说出它大概意味着什么。

## 0. 这一讲要求你做到什么程度

这是素养卷的第一讲。它属于"先见个面、混个脸熟"的范畴：看不懂的地方可以直接跳过，去翻第 09 讲开始写 Python；等你第一次真正被"文件找不到""命令不存在"卡住时，再回来看这八讲，会比现在顺。

但"允许跳过"不等于"这一讲可以写得含糊"。本讲仍然会把该说清的说清，只是不要求你记住细节。读完这一讲，你只需要牢牢记住三句人话：

1. 你写的 `.py` 文件**只是一段文本**，它本身不会执行。
2. 真正执行它的是**解释器**，解释器也是一个普通程序，装在硬盘上，运行时被读进内存、由 CPU 一条条执行。
3. 报错不是"你把电脑弄坏了"，而是解释器在告诉你：它在哪一步、因为什么、停下了。

## 1. 先做一个最小实验

### 1.1 写一个两行的文件

在桌面上新建一个文件夹，叫 `py-learn`。用记事本（或任何纯文本编辑器）新建文件，输入下面这一行：

```python
print("hello, python")
```

保存到 `py-learn` 文件夹里，文件名写 `hello.py`。

这里有一个新手几乎都会踩的坑：Windows 记事本的"保存类型"默认是"文本文档 (\*.txt)"，如果你只在文件名里写 `hello.py` 而不把"保存类型"改成"所有文件"，最终得到的文件名其实是 `hello.py.txt`。它在资源管理器里可能只显示成 `hello.py`（因为系统默认隐藏已知扩展名），但解释器看到的仍然是 `.txt`。判断办法很简单：打开"查看 → 文件扩展名"，或者看这个文件的类型描述。第 02 讲讲路径时会再回来看这个问题。

### 1.2 用解释器运行它

打开终端，进入这个文件夹，然后让解释器去跑这个文件：

```powershell
cd C:\Users\你的用户名\Desktop\py-learn
python hello.py
```

屏幕上出现：

```text
hello, python
```

`cd` 是"切换当前目录"（change directory），`python hello.py` 的意思是"启动 Python 解释器，让它执行 `hello.py` 这个文件"。这一行里没有任何魔法：`python` 是命令名，`hello.py` 是交给它的参数。第 02 讲会把 `cd` 和路径讲清楚。

### 1.3 换一种跑法：不带文件名

只敲 `python`，回车：

```powershell
python
```

你会看到类似这样的提示（版本号可能不同）：

```text
Python 3.12.13 (main, ...) [MSC v.1944 64 bit (AMD64)] on win32
Type "help", "copyright", "credits" or "license" for more information.
>>>
```

`>>>` 是提示符，表示"我在等你输入一行代码"。现在直接敲：

```text
>>> print("hello, python")
hello, python
>>> 1 + 1
2
>>> exit()
```

三行输入、三种结果：第一行打印了文本，第二行直接显示了 `2`，第三行退出了这个环境。这种"你敲一行、它算一行、立刻给你看结果"的模式，叫**交互式解释器**，也常被叫做 **REPL**（Read-Eval-Print Loop，读入—求值—打印—循环）。

### 1.4 两次结果一样，说明什么

同一句话，在 `>>>` 后面敲和在文件里写，输出完全一样。原因是同一个：**执行它的都是同一个解释器**。两次的区别只在"解释器从哪里拿到这段代码"——一次是你现场敲的，一次是从文件里读的。

这个观察很小，但它是理解后面所有内容的地基：Python 没有"文件里的代码"和"终端里的代码"两套规则，只有一套规则，只是入口不同。

## 2. 源代码只是文本

你刚才写进 `hello.py` 的那段文字，叫**源代码**（source code）：用某种编程语言的语法写出来、供人或程序阅读的文本。这一段要说清的是它到底"是什么东西"——它和你硬盘里的一张图片、一份 Word 文档，在存储层面完全是同一类东西。

### 2.1 后缀名不决定它是不是程序

把 `hello.py` 复制一份，改名为 `hello.txt`，内容一个字都不改，再让解释器跑它：

```powershell
python hello.txt
```

实际运行结果如下（本讲所有"实测"都来自 `scripts/lec01-01_demo.py`，你可以自己跑一遍）：

```text
[hello.py] 退出码=0  stdout='hello, python'
[hello.txt] 退出码=0  stdout='hello, python'
```

两个文件的输出一模一样。解释器打开文件、读到的是 `print("hello, python")` 这段文本，它就照做，根本不去看文件名末尾是 `.py` 还是 `.txt`。

反过来也成立：如果文件里放的不是合法的 Python 文本（比如把一个图片改名成 `.py`），解释器会在读完它之后报 `SyntaxError`（语法错误）。决定"能不能跑"的是**里面的内容**，不是扩展名。

### 2.2 那后缀名有什么用

它对人有用，对工具也有用，只是对"解不解释"没有决定权：

- 编辑器和 IDE 靠它决定用哪套语法高亮；
- 资源管理器靠它决定双击时用哪个程序打开；
- 团队约定靠它一眼认出"这是 Python 源码"。

所以 `.py` 是一个**约定**，不是开关。把 `.py` 当开关，会得到两个后果：一是不知道为什么改名还能跑，二是遇到 `hello.py.txt` 这种"看起来对、其实不对"的文件时完全懵掉。

### 2.3 文本要先能被正确读出来：编码

还有一层：文件在硬盘上存的是一串**字节**（byte，八个二进制位一组，计算机存数据的基本单位），解释器要把它还原成字符，就必须知道用哪套对应规则，这套规则叫**编码**（encoding）。同一串字节用不同编码去读，可能读出完全不同的字符，甚至读不出来——这就是"乱码"的来源。

现在你只需要记住一条操作纪律：**本课程所有的 `.py` 文件都存成 UTF-8**。现代编辑器默认就是 UTF-8，记事本在"另存为"里也能选。编码的完整规则放在第 11 讲（字符串）与第 19 讲（文件读写），现在深究没有收益。

### 2.4 顺带说清：编译型与解释型

你以后会听到"编译型语言"和"解释型语言"这两个说法。粗线是这样：

- C、C++ 这类语言，源码要先经过一个叫**编译器**的程序，翻译成机器能直接执行的 `.exe`，之后运行时不再需要源码；
- Python 属于解释型：源码交给解释器，由解释器负责翻译并执行。解释器内部其实也会先编译成一种中间形式（字节码），但这一步对使用者是透明的，你不需要手动做。

这两种路线的差别会引出很多工程问题（分发方式、启动速度、跨平台），本课程不展开。现在只要知道：**Python 的源码要跑，必须有解释器在场**。这也是为什么"把 `.py` 发给同学，他那边打不开"——他缺的不是文件，是解释器。

## 3. 解释器是一个程序

### 3.1 "装 Python"到底装了什么

严格说，"装 Python"装的是三样东西：

| 装的东西 | 是什么 | 在哪 | 你怎么感知到它 |
|---|---|---|---|
| 解释器 | 一个可执行文件（Windows 上是 `python.exe`） | 安装目录，例如 `...\Python312\` | 敲 `python --version` 能打印版本号 |
| 标准库 | 几百个写好的 `.py` 文件，`print`、`open` 之外的很多能力都来自它 | 解释器安装目录下的 `Lib\`（虚拟环境的情况第 03 讲） | `import math` 能直接用，不用额外安装 |
| `pip` | 一个包管理程序，负责从网上装第三方包 | 解释器或当前虚拟环境下的 `Scripts\` 目录 | `pip --version` 能打印版本 |

这里出现两个新词，都只要求"知道是什么"：

- **包**（package）：别人写好的一堆 Python 代码，打包发布出来，你装上就能 `import`。第 03 讲讲怎么装，第 17 讲讲 `import` 到底做了什么。
- **标准库**：Python 自带的包，装完解释器就有，不需要联网。

想确认自己机器上正在用的是哪个解释器，可以这样问它：

```powershell
python -c "import sys; print(sys.executable)"
```

`-c` 的意思是"不要文件，我直接把一行代码交给你执行"——这是第三种运行方式，和交互式、脚本并列。上面这行输出的是解释器的完整路径，例如：

```text
E:\E_Vault\CC_Formed_Projs2\WHATIFICATCHUPFROMSCRATCH\.venv\Scripts\python.exe
```

你机器上的路径会不一样。**记住这个命令**，它是排查"我装的包到底装到哪去了"的第一把钥匙（第 03 讲会反复用到）。

### 3.2 一条 `python hello.py` 背后发生了什么

按顺序是五步：

1. 终端在 `PATH` 里找到名为 `python` 的程序（`PATH` 是什么，第 02 讲）；
2. 解释器打开 `hello.py`，把里面的字节按编码读成文本；
3. 解释器检查这段文本是否符合 Python 语法，并把它编译成字节码；语法不合法就在这里停下，报 `SyntaxError`，此时**一行都还没执行**；
4. 解释器按顺序执行这些字节码，执行过程中产生的数据放在内存里；
5. 程序结束，解释器把一个**退出码**交还给终端：正常结束是 `0`，因异常中止是 `1`（下一节会实测）。

第 3 步和第 4 步的区分很重要，它是理解"为什么有的报错一行都没跑，有的报错跑到一半才炸"的关键。

### 3.3 磁盘、内存、CPU 各干什么

一台电脑跑程序，主要涉及三个角色：

| 角色 | 类比的位置 | 特点 | 程序运行时在干什么 |
|---|---|---|---|
| 硬盘 / 固态盘 | 仓库 | 容量大、速度慢、断电不丢 | 存放 `.py` 文件、解释器本身、你读写的文件 |
| 内存 | 工作台 | 容量小、速度快、断电即丢 | 存放正在运行的程序和它处理的数据 |
| CPU | 干活的人 | 只会执行极其简单的指令，速度极快 | 一条条执行解释器翻译出来的指令 |

几个日常现象可以这样解释：

- 打开一个几百 MB 的表格文件会卡：要把数据从硬盘搬进内存，硬盘慢；
- 程序跑到一半提示内存不足：工作台放不下了；
- 关掉终端窗口，正在跑的程序就没了：它是终端启动的一个**进程**（运行中的程序），终端关掉，它也跟着被终止。

这三个角色各自会在后面引出一个具体问题：磁盘慢，所以要学会分块读大文件（第 19 讲）；内存有限，所以不能把几百万行数据一次装进列表（第 19、23 讲）；CPU 是执行者，所以纯 Python 的循环在数值计算上比不过专门的数组库（第 23 讲会用实测对比）。

现在不要求你深究这些，只要建立"文件在硬盘上、数据在内存里、计算在 CPU 上"这三层印象，后面讲到具体问题时你会立刻知道该往哪想。

## 4. 两种运行方式的确切差别

### 4.1 交互式（REPL）

特点有四条：

- **一行一行来**：敲一行，回车，立刻执行；
- **立刻显示结果**：表达式算出来的值会直接打印在屏幕上；
- **状态会保留**：上一行定义的变量，下一行还能用；
- **有专门的退出方式**：输入 `exit()` 回车；Windows 上也可以按 `Ctrl+Z` 再回车，macOS / Linux 上是 `Ctrl+D`。

它适合：算一个式子、试一个函数怎么用、看看某个对象长什么样。它不适合写超过十几行的东西——你要改中间某一行，得把后面全部重敲。

### 4.2 脚本

把代码写进 `.py` 文件，用 `python 文件名.py` 一次执行完。特点正好相反：改起来方便、能保存、能发给别人、能进版本管理。

这是本课程的主战场。后面每一讲的示例都是脚本，只有讲某个函数"现场试一下"时才会用 REPL。

### 4.3 最关键的一条差异：表达式的结果会被丢掉

这是新手第一个大坑，必须用实测说清。准备两个文件。

`expr_only.py`，两行，只有表达式：

```python
1 + 1
"abc".upper()
```

`expr_print.py`，同样两行，但套上 `print`：

```python
print(1 + 1)
print("abc".upper())
```

分别运行，抓回标准输出（`stdout`，也就是程序正常打印的内容）：

```text
[expr_only.py] 退出码=0  stdout=''
[expr_print.py] 退出码=0  stdout='2\nABC\n'
```

`expr_only.py` 的输出是**空字符串**：两行表达式都算出来了，但结果显示给谁看？没有人。脚本模式只执行，不回显。

而在 REPL 里，同样三行输入的输出是：

```text
[模拟 REPL 输出] "2\n'PYTHON'\n"
```

`1 + 1` 的值 `2` 被自动打印了，`name.upper()` 的值被自动打印了（带引号，因为它是字符串，这一点第 09 讲会解释），而 `name = "python"` 这行赋值没有任何输出——赋值不是表达式结果，没有"值"可显示。

所以两种环境的真实差别是：

| 对比项 | 交互式（REPL） | 脚本 |
|---|---|---|
| 代码来源 | 你现场敲的 | 文件里的 |
| 执行方式 | 一行一行，敲完立刻执行 | 从头到尾一次执行 |
| 表达式结果 | 自动显示 | 丢掉，除非你 `print` |
| 改一行代码 | 重新敲 | 改文件，重新运行 |
| 适合 | 试算、试探 API | 写程序、交付、版本管理 |

把 `1 + 1` 从 REPL 抄进文件、运行后"什么都没发生"，不是程序坏了，是**脚本不会替你回显**。这一条会一直跟着你，直到你习惯"想看见什么，就 `print` 什么"。

### 4.4 什么时候用哪个

判断标准只有一条：这段代码你还要不要再跑第二次。

- 只是现在想知道 `2 ** 10` 是多少、`"abc".upper()` 返回什么 → REPL；
- 这段逻辑明天还要用、要交给别人、要改 → 写进文件。

REPL 里试出来的写法，确认可用之后再抄进脚本，是很快的工作方式。反过来，在 REPL 里维护几十行逻辑，是自找麻烦。

## 5. 报错不是失败，是信息

### 5.1 四种真实报错

下面四段报错都是在 Windows + Python 3.12 上实跑得到的，文件放在临时目录里，所以路径里有一串随机字符。

**第一种：括号没闭合。** 下面这段代码少了一个右括号：

```python
print("hello"
```

```text
  File "C:\Users\...\Temp\tmp90m5vm7i\err_syntax.py", line 1
    print("hello"
         ^
SyntaxError: '(' was never closed
```

读法：`SyntaxError`（语法错误），消息是"小括号从来没有被闭合"。解释器在编译阶段就发现了，所以这个文件**一行都没执行**。

**第二种：名字没定义。** 下面这段代码里的 `total` 从来没有被赋值过：

```python
print(total)
```

```text
  File "C:\Users\...\Temp\tmp90m5vm7i\err_name.py", line 1, in <module>
    print(total)
          ^^^^^
NameError: name 'total' is not defined
```

读法：`NameError`（名字错误），消息是"名字 `total` 没有定义"。`^` 指着的正是出问题的那个名字。它属于运行时错误：解释器执行到这一句，去查"`total` 是谁"，查不到，停下。

**第三种：该缩进的地方没缩进。** 下面这段 `if` 的语句体没有缩进：

```python
if True:
print("x")
```

```text
  File "C:\Users\...\Temp\tmp90m5vm7i\err_indent.py", line 2
    print("x")
    ^^^^^
IndentationError: expected an indented block after 'if' statement on line 1
```

读法：`IndentationError`（缩进错误），消息是"第 1 行的 `if` 语句后面应该有一个缩进块"。Python 用缩进表示"这几行属于同一个块"，所以缩进是语法的一部分，不是排版好看。这一点第 09 讲会正式讲。

**第四种：文件不存在。** 下面这段代码想打开一个并不存在的文件：

```python
open("no_such_file.txt", encoding="utf-8")
```

```text
Traceback (most recent call last):
  File "C:\Users\...\Temp\tmp90m5vm7i\err_missing.py", line 1, in <module>
    open("no_such_file.txt", encoding="utf-8")
FileNotFoundError: [Errno 2] No such file or directory: 'no_such_file.txt'
```

读法：`FileNotFoundError`（文件未找到错误），消息里直接给出了找不到的文件名。`open` 是"打开文件"的函数，第 19 讲才正式讲，这里只是借用它制造一个典型的运行时错误。

四段的退出码都是 `1`。

### 5.2 一条报错怎么读：从最后一行往上

一条报错的信息量集中在三个位置，按重要性排序：

1. **最后一行**：错误类型 + 一句消息。这一行决定你往哪个方向查。
2. **倒数第二、三行**：出错位置——哪个文件、第几行、那一行代码长什么样，`^` 指向具体出问题的字符。
3. **再往上**：调用链（call stack，也叫调用栈）。现在只有一层（`in <module>`，意思是"在模块顶层"），等程序里函数一层层调用起来，这里会变成一叠，第 18 讲和第 24 讲专门讲怎么从上往下读。

注意一个细节：前三种报错**没有** `Traceback (most recent call last):` 这一行，第四种有。区别在于发生时机——语法错误、缩进错误在编译阶段就被发现，程序还没开始执行，所以没有"调用栈"可回溯；`FileNotFoundError` 是执行到那一句才发生的，所以有完整的调用栈。

### 5.3 两类错误的区别：发生时机

| 对比项 | 语法 / 缩进错误 | 运行时错误 |
|---|---|---|
| 什么时候被发现 | 编译阶段，执行前 | 执行到出问题的那一句时 |
| 已经执行的语句 | 一条都没有 | 前面的语句**已经生效** |
| 典型例子 | `SyntaxError`、`IndentationError` | `NameError`、`FileNotFoundError`、`ZeroDivisionError` |
| 常见原因 | 少括号、少冒号、缩进不齐 | 名字拼错、文件不存在、除以零 |

第二条值得单独验证。执行下面这一行：

```powershell
python -c "print('A'); open('no_such_file.txt')"
```

实测输出是：

```text
A
Traceback (most recent call last):
  File "<string>", line 1, in <module>
FileNotFoundError: [Errno 2] No such file or directory: 'no_such_file.txt'
```

`A` 先被打印出来，然后才报错——说明"前面的语句已经执行了"。这条差别在真实项目里很重要：程序跑到一半崩溃时，前面已经写出去的文件、已经发出的请求，都不会自动撤销。第 18 讲讲异常处理时会正式处理这个问题。

### 5.4 退出码：没有输出不等于成功

上面的实测里，还有一个容易忽略的信号：每次运行结束，解释器都会给终端一个**退出码**（exit code）。

```text
脚本                退出码    stdout 长度
expr_only.py       0        0
expr_print.py      0        6
hello.py           0        14
ok.py              0        5
quiet.py           0        0
```

前四个都是正常结束，退出码 `0`。`expr_only.py` 和 `quiet.py` 一个字都没输出，退出码同样是 `0`。而前面四种报错，退出码都是 `1`。

所以：

- **没有输出，不代表成功**——可能只是你忘了 `print`；
- **没有输出，也不代表失败**；
- 判断成功与否，看的是退出码：`0` 表示正常结束，非 `0` 表示出了问题。

这条规则不光 Python 有，几乎所有命令行程序都遵守。以后写自动化脚本、跑测试、配持续集成，判断"这一步到底成没成"靠的就是退出码，而不是肉眼看屏幕。第 26 讲会把这条规则用到项目入口上。

## 6. 这一讲留下的三件事

本讲没有教任何 Python 语法，但留下了三件后面会反复用到的事：

1. **文件是文本**。你写的程序本质是一段文字，编码决定它怎么被读出来。落到第 11 讲（字符串与编码）和第 19 讲（文件读写）。
2. **解释器是一个程序，环境 = 解释器 + 已装的包**。所以"我这边能跑、你那边不能跑"通常不是代码问题，而是环境不同。落到第 03 讲（配环境）与第 17 讲（模块与包）。
3. **报错有结构**，最后一行告诉你类型，往上告诉你位置。落到第 18 讲（异常）与第 24 讲（调试）。

下一讲解决一个更具体的问题：你怎么让解释器准确找到你写的那个文件？——路径、当前目录、终端命令。

## 小结

- `.py` 文件只是一段文本，执行它的是解释器；后缀 `.py` 是约定，不是开关，改名为 `.txt` 照样能被解释器执行。
- 装 Python 装了三样：解释器、标准库、`pip`。`python -c "import sys; print(sys.executable)"` 能告诉你正在用的是哪个解释器。
- 三种运行方式：交互式（REPL）、脚本、`-c` 一行。REPL 会自动显示表达式结果，脚本不会——这是新手第一个大坑。
- 磁盘存文件、内存放运行中的数据、CPU 执行指令；程序运行时是一个进程，关掉终端它就停了。
- 报错分两类：语法 / 缩进错误在执行前发现，一行都没跑；运行时错误在执行到那一句时发生，前面的语句已经生效。
- 退出码 `0` 表示正常结束，非 `0` 表示出问题；"没有输出"既不能证明成功，也不能证明失败。

## 作业

**Q1.** 下面这个脚本运行后，屏幕上会显示什么？为什么？

```python
1 + 1
x = 2
print(x)
```

**参考答案：** 只显示 `2`，来自第三行的 `print(x)`。

第一行 `1 + 1` 是一个表达式，值是 `2`，但脚本模式不会自动显示表达式的值，所以这个结果被丢掉；第二行 `x = 2` 是赋值，也没有输出；第三行显式调用了 `print`，把 `x` 的值送到屏幕上。如果把这三行逐行敲进 REPL，第一行会显示 `2`，第二行没有输出，第三行显示 `2`。

**Q2.** 把 `hello.py` 改名为 `hello.txt`，再用 `python hello.txt` 运行，会发生什么？这说明"是不是程序"由什么决定？

**参考答案：** 照样输出 `hello, python`，退出码 `0`。解释器只读文件内容，不看扩展名。决定一段文本能不能作为 Python 程序运行的，是它的内容是否符合 Python 语法；扩展名只影响编辑器高亮、双击时的默认打开方式这类"约定"。

**Q3.** 下面这段代码运行后报什么错？是执行前发现还是执行到一半发现？屏幕上有输出吗？

```python
print("start")
print(undefined_name)
print("end")
```

**参考答案：** 报 `NameError: name 'undefined_name' is not defined`，属于运行时错误，执行到第二行才发现。屏幕上会先输出 `start`，然后中止，`end` 不会输出，退出码为 `1`。

判断依据：这是运行时错误，前面的语句已经生效；解释器不会跳到后面继续执行，所以第三行不会运行。

**Q4.** 一个脚本运行结束后，终端里一个字都没显示。能不能断定它失败了？应该看什么？

**参考答案：** 不能。没有输出可能只是没有写 `print`（例如 `quiet.py` 只做了 `x = 1 + 1`），此时退出码仍然是 `0`。判断成败要看退出码：`0` 是正常结束，非 `0` 是出了异常或其他错误。

**Q5.** 亲手做一遍：在 `py-learn` 文件夹里新建 `area.py`，内容为 `print("面积 =", 3 * 4)`，用 `python area.py` 运行，记下输出和退出码。然后把文件名改成 `area.txt` 再运行一次，比较两次结果。

**参考答案：** 两次输出都是 `面积 = 12`，退出码都是 `0`（在 PowerShell 里可以用 `$LASTEXITCODE` 查看上一条命令的退出码）。第二次能成功，说明扩展名不影响解释器是否执行它。

如果第一次运行报"不是内部或外部命令"，问题不在文件，而在 `python` 这个命令没有出现在 `PATH` 里——第 02、03 讲会处理。如果报"系统找不到指定的文件"，说明当前目录不对或者文件名不是你以为的那个（很可能是 `area.py.txt`）。

**Q6.** 用一句话回答：为什么"把 `.py` 文件发给同学，他那边打不开"通常不是你代码的问题？

**参考答案：** 因为 `.py` 只是文本，真正执行它的是解释器；对方机器上没有装 Python（或没把它加入 `PATH`），就没有程序来读这段文本。缺的是环境，不是代码。
