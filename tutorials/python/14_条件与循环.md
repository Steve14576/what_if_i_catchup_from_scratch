## 0. 场景：三件需要"按条件决定"的事

- 把分数分成"不及格 / 及格 / 良好 / 优秀"，每档规则不同；
- 猜数字：最多猜五次，每次告诉大了还是小了，可以中途退出；
- 在一份名单里找某个名字，找到就停下，找不到要提示。

前两件是"条件"，第三件是"循环 + 提前退出"。它们合起来构成程序的控制流。

## 1. 真值判断：什么算真、什么算假

`if` 后面放的不是"必须布尔值"，任何对象都能被判真假。规则是：

规则一句话：零值、空容器、空字符串、`None`、`False` 为假；其余为真。

实测：

```text
  判为假的值：
    0          bool -> False
    0.0        bool -> False
    ''         bool -> False
    []         bool -> False
    {}         bool -> False
    set()      bool -> False
    None       bool -> False
    False      bool -> False
  判为真的值：
    1          bool -> True
    -1         bool -> True
    '0'        bool -> True
    ' '        bool -> True
    [0]        bool -> True
    {'a': 1}   bool -> True
    True       bool -> True
```

### 1.1 三个最容易误判的

| 值 | 真假 | 为什么 |
|---|---|---|
| `"0"` | 真 | 它是长度 1 的字符串，非空即真；不是数字 0 |
| `" "` | 真 | 一个空格也是字符，非空即真 |
| `[0]` | 真 | 列表里有一个元素（哪怕那个元素是 0），非空即真 |

所以"用户什么都没输入"和"用户输入了 0"是两件事：

```python
text = input("请输入一个数: ")   # 直接回车得到 ''
if not text:
    print("你没输入")
elif int(text) == 0:
    print("你输入了 0")
```

先判"空不空"，再判"值是多少"——顺序反了就会把空字符串送进 `int()`，得到第 09 讲那个 `ValueError`。

### 1.2 `if x:` 与 `if x is not None:` 的区别

- `if x:`：判"真假"。`0`、`""`、`[]` 都算假；
- `if x is not None:`：只判"是不是 `None`"，`0` 和 `""` 都会通过。

选哪个取决于语义：

- 如果 `0` 是一个合法值（比如"温度 0 度"），必须用 `is not None`，否则 0 会被当成"没有值"；
- 如果空集合和"没有"是同一件事（比如"找到的匹配项列表"），用 `if xs:` 更简洁。

## 2. `if` / `elif` / `else`

### 2.1 互斥匹配：命中一个就跳出整条链

```text
    classify( -3) = 负数
    classify(  0) = 零
    classify(  7) = 个位数
    classify( 42) = 两位数及以上
```

`if` / `elif` / `else` 是一条**互斥链**：从上往下判断，第一个为真的分支执行完，整条链就结束了，后面的 `elif` 不会再判断。

由此得到一条实践规则：**互相排斥的条件，顺序要从特殊到一般。** 如果把 `n < 10` 放在 `n == 0` 前面，0 会先命中"个位数"，`elif n == 0` 永远轮不到。

`else` 是可选的，但"所有情况都该有归宿"时建议写上——它让读者知道"剩下那些走这里"，而不是猜。

### 2.2 条件表达式：一行版

```text
    n = 0 -> 零点
    n = 5 -> 非零
```

写法是 `A if 条件 else B`，它本身是一个**表达式**（有值），所以可以直接赋值或塞进函数调用。

适合"二选一且都很短"的场合。三层以上就别用了，写成正常的 `if` 更好读。

### 2.3 提前返回：把嵌套压平

新手常写很深的嵌套：

```python
if 条件A:
    if 条件B:
        if 条件C:
            做正事
        else:
            报错3
    else:
        报错2
else:
    报错1
```

更清楚的做法是"先处理异常情况、提前退出"：

```python
if not 条件A:
    return 报错1
if not 条件B:
    return 报错2
if not 条件C:
    return 报错3
做正事
```

`return` 是函数里的东西（第 15 讲），但思路现在就能用：**把"不符合"的情况一个个挡掉，正事的代码就留在最外层。** 这个写法叫"卫语句"。

## 3. 循环：`for` 与 `while` 的分工

### 3.1 `while`：直到条件不成立

```text
    while 里: count = 3
    while 里: count = 2
    while 里: count = 1
    循环结束: count = 0
```

每轮开始前判断一次条件，为真就执行循环体。三个必须检查的点：

1. **循环体里必须有东西让条件最终变假**（这里是 `count -= 1`），否则死循环；
2. 死循环时用 `Ctrl+C` 停（第 02 讲）；
3. 条件里的变量在循环体里被改，改的是同一份数据——不要以为每次循环都重新初始化。

### 3.2 `for`：逐个处理

```text
    list(range(5))      = [0, 1, 2, 3, 4]
    list(range(1, 6))   = [1, 2, 3, 4, 5]
    list(range(1, 10, 3)) = [1, 4, 7]
    list(range(5, 0, -1)) = [5, 4, 3, 2, 1]
```

`for x in 某个可迭代对象:` 的含义是"把这个对象里的元素一个个取出来"。它不负责计数，也不负责结束条件——那些是 `range` 与 `while` 的事。

`range` 三个参数：

| 写法 | 结果 | 说明 |
|---|---|---|
| `range(5)` | `0,1,2,3,4` | 起点默认 0，**不含 5** |
| `range(1, 6)` | `1,2,3,4,5` | 含起点、不含终点 |
| `range(1, 10, 3)` | `1,4,7` | 步长 3 |
| `range(5, 0, -1)` | `5,4,3,2,1` | 步长为负时递减 |

"含头不含尾"这条和第 11 讲的切片是同一个规则，记住一次两边都通用。它的好处是：`range(len(xs))` 正好覆盖全部合法下标，不会越界。

### 3.3 该用哪个

| 你要表达的意思 | 用哪个 | 例子 |
|---|---|---|
| "对每一个元素做点事" | `for` | 遍历名单、遍历文件的每一行 |
| "重复到某个条件不成立" | `while` | 猜数字、读输入直到用户说停 |
| "跑固定次数" | `for` + `range` | 重复 10 次 |
| "不知道要跑几次，但知道什么时候停" | `while` | 直到结果足够精确、直到队列空 |

判据一句话：**能说清"对谁"就用 `for`，只能说出"什么时候停"就用 `while`。**

## 4. 循环控制：`break`、`continue`、`else`

### 4.1 `break`：整个循环结束

```text
    x == 3 时 break   -> 收集到 [1, 2]
```

跑到 `break`，立刻跳出**当前这一层**循环，后面的元素不再处理。

### 4.2 `continue`：只跳过本轮

```text
    x == 3 时 continue -> 收集到 [1, 2, 4, 5]
```

`continue` 跳过本轮剩余的语句，直接进入下一轮。

两者的区别只有一句话：**`break` 结束循环，`continue` 结束这一轮。**

### 4.3 循环 `else`：没被 `break` 打断才执行

这是 Python 独有、也最容易被误解的语法。实测两种：

```text
    自然结束（n=3）-> else 执行了
```

```text
    找到了 7，break
    没找到 5 -> else 执行
```

第一段是 `while`：循环条件自然变假、正常结束，`else` 执行；第二段里第一次找到 7 就 `break` 了，`else` 不执行；第二次没找到（循环跑完），`else` 执行并提示。

所以 `else` 的语义不是"否则"，而是**"循环没有被 `break` 提前结束"**。它最自然的用途就是"找东西，找不到才提示"：

```python
for name in names:
    if name == target:
        print("找到了")
        break
else:
    print("名单里没有")
```

用标志位也能实现同样的逻辑（`found = False` … 循环后 `if not found:`），效果一样，只是多一个变量。循环 `else` 更紧凑，但读的人必须知道这条语法——团队里如果不熟，就用标志位。

### 4.4 一个常见误解

`while ... else` 里的 `else` **不会**在 `while` 条件一开始就是假时"跳过"——它照样执行。因为那时循环也是"正常结束"：

```python
while False:
    pass
else:
    print("会打印")     # 打印
```

只有 `break` 能阻止 `else`。这条同样是"按定义推导"，不需要额外记忆。

## 5. 常用配套：`enumerate` 与 `zip`

```text
    enumerate: 1 -> alice
    enumerate: 2 -> bob
    zip: alice = 90
    zip: bob = 75
```

- `enumerate(序列, start=1)`：同时给出"序号"和"元素"。别再手写 `i = 0; i += 1`——那个计数器容易漏加，而且 `for i in range(len(xs))` 也不如 `enumerate` 直接。
- `zip(序列1, 序列2)`：把两个序列按位置配对。**以最短的为准**，长出来的部分被丢弃——两个序列长度不一致时，这是个安静的 bug，值得警惕。

## 6. 遍历时修改容器

### 6.1 列表：跳过元素，而且症状有欺骗性

先看一个"看起来没问题"的例子——删掉列表里的偶数：

```text
    删偶数: 实际删掉 [2, 4]，剩下 [1, 3]
```

结果正确。但这不代表写法对，只代表**被跳过的那个元素（3）本来就不该删**，所以错误被掩盖了。

换成"删掉小于 3 的数"，问题立刻露出来：

```text
    删小于 3 的: 实际删掉 [1]，剩下 [2, 3, 4]
```

2 也是小于 3 的，却没被删。原因是 `for` 内部按**下标**推进：删掉下标 0 的 1 之后，2 滑到下标 0、3 滑到下标 1，而循环的下标已经加到了 1，于是 2 被跳过。

这就是这个坑最阴的地方：它不报错，只在某些数据下出错。

### 6.2 字典：直接报错（第 13 讲）

```text
  边遍历边删 -> RuntimeError: dictionary changed size during iteration
```

字典更"诚实"：改变大小立刻抛异常。列表则默默跳过。所以"字典会报错，列表不会"不代表列表更安全，恰恰相反。

### 6.3 正确写法

写法一：先收集要删的，循环结束后统一删。

```python
to_remove = []
for x in xs:
    if x < 3:
        to_remove.append(x)
for x in to_remove:
    xs.remove(x)
```

写法二：用推导式重建（推荐）。

```text
    用列表推导式重建: [3, 4]（原列表 [1, 2, 3, 4] 不变，需要时再赋值回去）
```

```python
xs = [x for x in xs if x >= 3]
```

一行表达"留下满足条件的"，既不碰遍历中的列表，也不会跳元素。列表推导式是第 14 讲顺带引入的语法，下一讲重构函数时会大量用到。

## 7. `for` 背后：迭代协议

```text
    iter([10,20]) -> <list_iterator object at 0x...>
    next(it) = 10
    next(it) = 20
    再 next -> StopIteration（for 就是靠它知道结束）
```

`for x in 某东西` 的执行过程其实是三步：

1. 调 `iter(某东西)`，拿到一个**迭代器**；
2. 反复调 `next(迭代器)`，每次拿一个元素；
3. 遇到 `StopIteration` 异常就结束循环（这个异常由 `for` 自己吞掉，不会让你看到）。

两个术语：

- **可迭代对象**（iterable）：能被 `for` 遍历的东西，如列表、字符串、字典、`range`；
- **迭代器**（iterator）：真正记录"当前走到哪"的对象，`iter()` 从可迭代对象造出来。

为什么要知道这个？因为它解释了后面几件事：

- 为什么同一个列表能被 `for` 两遍、而生成器只能遍历一遍（第 16 讲）；
- 为什么 `for` 里改动容器会出问题（迭代器记着"下一个取哪"，而容器已经变了）；
- 为什么自定义对象只要实现 `__iter__` 就能被 `for` 遍历（第 21 讲）。

## 8. 嵌套循环：`break` 只跳一层

```text
    内层 j==1 时 break -> [(0, 0), (1, 0), (2, 0)]
```

`break` 只结束**它所在的那一层**循环。外层照样跑完三轮，每轮内层都在 `j == 1` 时退出。

要跳出两层，三种做法：

- 用标志位：内层 `break` 后设 `found = True`，外层每轮开头检查；
- 把循环包进函数，用 `return` 直接返回（第 15 讲，最干净）；
- 用 `itertools.product` 之类的工具改写（第 22 讲）。

## 9. 这一讲留下的东西

- 真值判断：零、空、`None`、`False` 为假；`"0"`、`" "`、`[0]` 都是真。
- `if` / `elif` 是互斥链，顺序从特殊到一般；`else` 兜底所有剩余情况。
- `for` 表达"对谁"，`while` 表达"直到什么时候"；`range` 含头不含尾。
- `break` 结束循环，`continue` 结束本轮；循环 `else` 只在"没有被 `break`"时执行。
- `enumerate` 替代手写计数器，`zip` 并行遍历（以最短为准）。
- 遍历时修改列表会**静默跳过**元素，改字典会抛 `RuntimeError`；正确做法是收集后删或用推导式重建。
- `for` 背后是 `iter()` + `next()` + `StopIteration`。

下一讲把这一讲的两个脚本重构成函数：你会看到参数怎么传、`return` 与 `None` 的分工、作用域规则，以及"可变默认参数"这个几乎人人踩过的坑。

## 小结

- 实测：`0`/`0.0`/`""`/`[]`/`{}`/`set()`/`None`/`False` 全为假；`1`/`-1`/`"0"`/`" "`/`[0]` 全为真。
- `if` 链命中即跳出；把宽条件放前面会吃掉后面的窄条件。
- 条件表达式 `A if 条件 else B` 有值，可直接赋值。
- `while` 每轮重判条件；`count` 不变就是死循环。
- `range(5)` 是 0–4；`range(1,10,3)` 是 `[1,4,7]`；`range(5,0,-1)` 是 `[5,4,3,2,1]`。
- `while ... else` 正常结束执行 else；`while False` 也执行 else；只有 `break` 会阻止。
- `for ... else` 实测：找到 7 后 `break`，else 不执行；找不到 5 时 else 执行。
- `break` 收集到 `[1,2]`，`continue` 收集到 `[1,2,4,5]`。
- 遍历时删列表：删偶数"看起来对"（被跳过的是奇数 3），删小于 3 则漏掉 2；正确写法是推导式重建。
- 迭代协议：`iter` → `next` → `StopIteration`。

## 作业

**Q1.** 把下面的分数分级改成互斥且正确的形式：90 以上优秀、80–89 良好、60–79 及格、60 以下不及格。说明为什么顺序重要。

```python
score = 85
if score >= 60:
    print("及格")
elif score >= 80:
    print("良好")
elif score >= 90:
    print("优秀")
else:
    print("不及格")
```

**参考答案：** 现在的写法只会打印"及格"：85 先命中 `>= 60`，整条链就结束了，后面两个 `elif` 永远不会轮到。

正确顺序是从严到宽：

```python
score = 85
if score >= 90:
    print("优秀")
elif score >= 80:
    print("良好")
elif score >= 60:
    print("及格")
else:
    print("不及格")
```

判据：`elif` 是互斥链，先命中的赢；所以宽条件必须放在窄条件后面。

**Q2.** 用 `while` 写一个猜数字游戏：答案是 7，最多猜 5 次，每次提示"大了/小了"，猜中或次数用完就结束。

**参考答案：** 循环 + `while ... else` 正好完成这个结构：

```python
answer = 7
tries = 0
while tries < 5:
    guess = int(input("猜一个数: "))
    tries += 1
    if guess == answer:
        print("猜中了，用了", tries, "次")
        break
    elif guess > answer:
        print("大了")
    else:
        print("小了")
else:
    print("次数用完，答案是", answer)
```

三个要点：`tries` 必须在循环里自增；猜中就 `break`；`while ... else` 正好表达"没猜中就提示答案"——`else` 不会在 `break` 之后执行。

注意 `int(input(...))` 遇到非数字会抛 `ValueError`，这里没有处理，第 18 讲会补上。

**Q3.** 下面代码想求 1 到 5 的和，但结果不对。指出问题并修正。

```python
total = 0
i = 1
while i < 5:
    total += i
    i += 1
print(total)
```

**参考答案：** 输出 `10`（1+2+3+4），少了 5。条件 `i < 5` 在 `i == 5` 时就不成立了，所以 5 没被加进去。

两种改法：

```python
while i <= 5:      # 改成 <=
```

```python
for i in range(1, 6):   # 或直接用 for + range（含头不含尾，所以写 6）
    total += i
```

第二种更不容易错：`range` 的"含头不含尾"是固定规则，而手写 `<` / `<=` 每次都要想一下。

**Q4.** 用循环 `else` 改写：在名单 `["alice", "bob"]` 里找 `"carol"`，找不到就打印"不在名单里"。

**参考答案：** 循环跑完没碰到 `break`，`else` 就会执行：

```python
names = ["alice", "bob"]
for name in names:
    if name == "carol":
        print("找到了")
        break
else:
    print("不在名单里")
```

执行过程：循环跑完两次都没命中，没有 `break`，于是 `else` 执行，打印"不在名单里"。

如果名单里有 `"carol"`，会打印"找到了"并 `break`，`else` 被跳过。

**Q5.** 下面代码想把列表里的 0 全部删掉，但结果不对。说明原因并给出正确写法。

```python
xs = [0, 1, 0, 2, 0]
for x in xs:
    if x == 0:
        xs.remove(x)
print(xs)
```

**参考答案：** 结果是 `[1, 0, 2, 0]`——只删掉了第一个 0。删掉下标 0 的 0 之后，1 滑到下标 0、第二个 0 滑到下标 1，而循环的下标已加 1，正好跳到那个 0 上，于是它被跳过。

正确写法用推导式重建：

```python
xs = [x for x in xs if x != 0]
```

或者先收集要删的、循环结束后再删。判据：**只要循环体里会改变容器的大小，就一定不能用 `for x in 容器`。**

**Q6.** `range` 与 `enumerate` 各解决什么问题？为什么说 `for i in range(len(xs))` 不如 `enumerate(xs)`？

**参考答案：** 两者分工不同：

- `range` 生成一串整数，用于"跑固定次数"或"按下标访问"；
- `enumerate` 在遍历的同时给出"序号 + 元素"，用于"既要下标又要值"。

`for i in range(len(xs))` 也能拿到下标，但每次都要 `xs[i]` 去取值，多了一步、也多一个出错机会（比如 `len` 与循环里改动列表配合时会越界）。`enumerate(xs)` 直接给 `(i, x)` 两样，还支持 `start=1` 从 1 开始编号，读起来就是"第几个、是什么"。

顺带：`zip` 解决的是另一种需求——同时遍历两个序列并按位置配对，与下标无关。
