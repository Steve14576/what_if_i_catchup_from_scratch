## 0. 场景：三件"顺序不重要、按条件找"的事

- 学号 → 姓名：给你学号，要立刻拿到姓名；
- 一段文本里每个词出现了几次：词是条件，次数是值；
- 一份名单里有重复，要去重并找出"两个班都报名的人"。

这三件事用列表也能做，但会很别扭：列表只能按位置找，你为了找"学号 2023001"得从头扫。字典与集合解决的就是"按条件直接定位"。

下一节先看字典的基本动作：按键取值、增删改。

## 1. 字典：按键定位

### 1.1 创建与取值

```text
  scores = {'alice': 90, 'bob': 75}
  scores['alice'] = 90
  scores['carol'] -> KeyError: 'carol'
  scores.get('carol')      = None
  scores.get('carol', 0)   = 0
```

字典用花括号，一行一个"键: 值"。两条取值路线：

- `scores['carol']`：键不存在就抛 `KeyError`；
- `scores.get('carol')`：键不存在返回 `None`；`get('carol', 0)` 返回你给的默认值。

怎么选：**这次缺键是"错误"还是"正常情况"？**

- 如果缺了说明程序状态不对（比如配置里必须有这个字段），用 `[]`，让它早点炸；
- 如果缺了很正常（比如查一个可能不存在的学生），用 `get`，并给一个合理的默认值。

### 1.2 增删改

```text
  scores['carol'] = 88  -> {'alice': 90, 'bob': 75, 'carol': 88}
  scores['bob'] = 80    -> {'alice': 90, 'bob': 80, 'carol': 88}（覆盖旧值）
  scores.pop('bob')     -> 返回 80，剩下 {'alice': 90, 'carol': 88}
  update({...})         -> {'alice': 95, 'carol': 88, 'dave': 60}
```

要点：

- **赋值就是新增或覆盖**，没有"先判断存在再插入"这一套；
- `pop(键)` 删除并返回值；`pop(键, 默认值)` 可以避免缺键报错；
- `update(另一个字典)` 批量合并，同键被覆盖；
- `del d[键]` 只删不返回。

### 1.3 `in` 查的是键，不是值

```text
  'alice' in scores = True   'bob' in scores = False
```

想查"某个分数存不存在"，得用 `90 in scores.values()`。`values()` 返回的是值的视图，判断是逐个比较，慢；如果你经常要按值查，说明数据结构选错了（应该反过来建一个"分数 → 人"的字典）。

基本动作会了，下一节看遍历：三种视图与"边遍历边改"的报错。

## 2. 遍历

### 2.1 三种视图与顺序

```text
  keys()   -> ['alice', 'bob', 'carol']
  values() -> [90, 75, 88]
  items()  -> [('alice', 90), ('bob', 75), ('carol', 88)]
```

- `keys()` / `values()` / `items()` 返回的是**视图**，不是列表；要用列表就 `list(...)`；
- 遍历顺序是**插入顺序**（Python 3.7 起的语言保证），不是字母序；
- 要按大小或字母排，用 `sorted(scores.items(), key=...)`（第 12、16 讲）。

最常用的遍历写法是 `for name, score in scores.items():`——`items()` 每次给一个"键值对"元组，直接解包成两个名字（第 12 讲的解包）。

### 2.2 遍历时修改：直接报错

```text
  边遍历边删 -> RuntimeError: dictionary changed size during iteration
```

这不是 Python 脾气差，而是"边遍历边改"本来就没有明确语义：删掉当前元素后，下一个该是谁？解释器选择直接拦下来。

正确做法是**遍历键的副本**：

```text
  先 list(d) 复制键再删 -> {'a': 1, 'c': 3}
```

`for key in list(d):` 里遍历的是复制出来的键列表，`del d[key]` 改的是原字典，两者互不干扰。列表也有同样的坑（第 12 讲提过），解决思路一样。

遍历的坑清楚了，下一节看四种"给缺失键设默认值"的写法。

## 3. 默认值：四种做词频的写法

同一个需求——数一数 `["a", "b", "a", "c", "a"]` 里每个词出现几次——有四种写法，各有适用场景。

```text
  用 get 计数      -> {'a': 3, 'b': 1, 'c': 1}
  用 setdefault    -> {'a': 3, 'b': 1, 'c': 1}
  defaultdict(list) -> {'a': [1, 3], 'b': [2]}
  Counter           -> {'a': 3, 'b': 1, 'c': 1}   most_common(1) = [('a', 3)]
```

### 3.1 `get` 写法（最好懂）

```python
counts = {}
for word in words:
    counts[word] = counts.get(word, 0) + 1
```

读起来就是"取当前值，没有就当 0，加一放回去"。缺点是每次都要先 `get` 再赋值，查了两遍。

### 3.2 `setdefault` 写法（少一次查表）

```python
counts.setdefault(word, 0)
counts[word] += 1
```

`setdefault(键, 默认值)`：键不存在就插入默认值，然后返回该键的值。它和 `get` 的区别是**会顺手把键写进去**。

### 3.3 `defaultdict`（值是容器时最省事）

```python
from collections import defaultdict
groups = defaultdict(list)
for word, line in pairs:
    groups[word].append(line)
```

`defaultdict(list)` 的意思是"访问不存在的键时，自动创建一个空列表"。它适合"值是列表/字典，要往里累加"的场景——不用先判断键在不在，直接 `append`。

注意 `defaultdict` 访问任意不存在的键都会创建它，所以别拿它当普通字典乱查，会把字典撑大。

### 3.4 `Counter`（专门做计数）

```python
from collections import Counter
c = Counter(words)
c.most_common(1)     # [('a', 3)]
```

一行搞定计数，还自带"最常见的 N 个"。做词频统计优先用它，其余情况再考虑前三种。

| 场景 | 推荐 | 理由 |
|---|---|---|
| 只取值、缺了给默认值 | `get(键, 默认)` | 不改变字典 |
| 计数 | `Counter` | 一行、自带排行 |
| 值是列表/字典，要累加 | `defaultdict(list/dict)` | 不用判空 |
| 想显式控制"不存在就插入" | `setdefault` | 语义清楚，且只查一次 |

四种写法分清了，下一节看集合：只有"在不在"的容器。

## 4. 集合：只有"在不在"的容器

### 4.1 去重与无序

```text
  set([3,1,3,2,1]) = {1, 2, 3}（无序，打印顺序不保证）
```

集合用花括号（但没有冒号），自动去重。**无序**是指"不保证按插入顺序"，打印出来的顺序可能变；所以不要写依赖顺序的代码，要顺序就 `sorted(集合)`。

### 4.2 集合运算

```text
  a = {1, 2, 3, 4}   b = {3, 4, 5}
  a | b（并） = {1, 2, 3, 4, 5}
  a & b（交） = {3, 4}
  a - b（差） = {1, 2}
  a ^ b（对称差） = {1, 2, 5}
```

| 运算 | 写法 | 含义 |
|---|---|---|
| 并集 | `a \| b` 或 `a.union(b)` | 两边的全部元素 |
| 交集 | `a & b` 或 `a.intersection(b)` | 两边都有的元素 |
| 差集 | `a - b` | 在 a 不在 b |
| 对称差 | `a ^ b` | 只在一边出现的元素 |
| 子集判断 | `a <= b` 或 `a.issubset(b)` | a 的元素都在 b 里 |

`a - b` 与 `b - a` 不同，这是最容易写反的一处：问"我们班多出来的人"要写 `我们的 - 他们的`。

### 4.3 增删与不可变集合

`add(x)` 加一个、`discard(x)` 删一个（不存在也不报错，`remove` 会报错）、`clear()` 清空。

还有 `frozenset`：不可变的集合，能当字典键。用得少，知道存在即可。

集合会用了，下一节用实测回答"字典与集合到底快多少"。

## 5. 为什么字典与集合"快"

### 5.1 先看数字

三种容器里各放同一批数字，然后判断"某个数在不在"（挑的是最坏情况：目标在末尾）。实测（脚本 `lec13-01_demo_mapping.py` 第 7 节，单次判断的微秒数）：

```text
      规模      列表 in (us)      集合 in (us)      字典 in (us)
      1000           9.940           0.046           0.043
     10000          67.250           0.035           0.030
    100000         486.850           0.150           0.100
```

读法：

- 列表：规模从 1 千到 10 万，单次判断从约 10 微秒涨到约 490 微秒，**随规模线性增长**；
- 集合与字典：始终在 0.03–0.15 微秒量级，**基本不随规模变化**；
- 10 万条时，列表比集合慢大约 **3000 倍**。

绝对数字会随机器、负载、缓存波动（同一脚本两次跑，1000 那一行可能从 4 微秒到 10 微秒），但**比例关系稳定**：一个是线性，一个是常数。

### 5.2 快的原理：一次算出位置

列表找元素要逐个比较，最坏看完全部 n 个。

字典与集合先对键算一个**哈希值**，再对表长取余，直接得到"该去哪个格子找"。所以平均只需一次比较，与 n 无关。这叫**均摊 O(1)**：平均常数时间，偶尔因为扩容而慢一下。

两个必须知道的边界：

- **最坏情况仍是 O(n)**：如果所有键的哈希都落到同一个格子（冲突），就退化成长链表的逐个比较。正常数据（字符串、数字）不会这样，但"故意构造的键"可以，所以别把外部输入直接当键做安全相关的判断；
- **代价是内存**：哈希表要留空位、要扩容，比列表占更多内存。数据量小（几十个）时，用列表完全没问题。

### 5.3 集合的另一半价值：去重

```python
unique = list(set(items))
```

一行去重。注意这会**打乱顺序**；要"去重但保留首次出现的顺序"，得用循环 + 集合辅助记录（`seen = set()`），或者用字典的键（3.7 起字典有序）：

```python
unique = list(dict.fromkeys(items))
```

这条写法的意思是"用这些元素当键建字典、再取回键"——字典的键唯一且保序，正好完成"去重且保序"。它用到了第 13 讲的两个性质，不需要额外记忆。

速度差异看清了，下一节补一条硬约束：键必须可哈希。

## 6. 键必须可哈希

```text
  {(0,0): '原点'} 可以，取值 = 原点
  用列表当键 -> TypeError: unhashable type: 'list'
```

第 12 讲已经给出规则：**可变对象不可哈希**，所以列表不能当键、元组可以。补两点：

- 元组里如果含列表（`(1, [2])`），同样不可哈希；
- 自定义对象默认可哈希（按身份），但你重写 `__eq__` 之后要一起处理 `__hash__`，这是第 21 讲数据模型的事。

键的资格定了，下一节看合并与嵌套取值。

## 7. 合并与嵌套取值

```text
  d1 | d2 = {'a': 1, 'b': 20, 'c': 30}（右边覆盖左边）
  嵌套: nested['alice']['math'] = 90
  嵌套缺失键: nested.get('bob', {}).get('math', '无记录') = 无记录
```

- `d1 | d2` 合并字典（Python 3.9+），同键以右边为准；等价的老写法是 `{**d1, **d2}` 或 `d1.copy(); d.update(d2)`。
- 嵌套取值要一层层取，中间任何一层缺键都会抛 `KeyError`；
- 链式 `get` 的写法 `d.get("bob", {}).get("math", "无记录")` 能安全穿两层，但再深就不该这么写了——那种情况通常说明数据结构需要重新设计。

取值会了，下一节用一张总表做选型。

## 8. 选型总表

| 需求 | 用哪个 | 关键理由 |
|---|---|---|
| 保持顺序、会增删、要排序 | 列表 | 有序、可改、`sort` 好用 |
| 固定结构、不修改、当键 | 元组 | 不可变、可哈希 |
| 按条件（键）直接取值 | 字典 | 均摊 O(1) 定位 |
| 只关心"在不在"、去重 | 集合 | 均摊 O(1) 判断、自带运算 |
| 计数 | 字典或 `Counter` | 键是元素，值是次数 |
| 频繁判断"在不在"的长序列 | 集合 | 列表线性 vs 集合常数 |

一句话：**要顺序用列表，要定位用字典，要"有没有"用集合。**

选型表定完，下一节把本讲收起来。

## 9. 这一讲留下的东西

- 字典按键定位：`[]` 缺键报错、`get` 给默认值；`in` 查的是键。
- 遍历用 `items()`；遍历时修改会抛 `RuntimeError`，绕法是遍历 `list(d)`。
- 四种默认值方案：`get` 最好懂、`setdefault` 少查一次、`defaultdict` 适合累加、`Counter` 专做计数。
- 集合去重、无序、支持并交差；`a - b` 与 `b - a` 不同。
- 字典与集合快在哈希定位；实测 10 万条时列表比集合慢约 3000 倍，但绝对数字会波动。
- 代价：占内存更多、无序、键必须可哈希。

下一讲进入控制流：`if` 与循环。你会看到"真值判断"的完整规则、`for` 为什么没有三段式、循环 `else` 到底什么时候执行、以及 `break` 与 `continue` 该用哪个。

## 本讲小结

- `scores['carol']` 抛 `KeyError`；`get('carol')` 得 `None`，`get('carol', 0)` 得 `0`。
- 赋值即新增或覆盖；`pop` 删除并返回；`update` 批量合并；`in` 只查键。
- 遍历顺序是插入序；遍历时删键抛实测的 `RuntimeError: dictionary changed size during iteration`，用 `list(d)` 绕开。
- 词频四种写法实测结果一致；选型：计数用 `Counter`、累加容器用 `defaultdict`、简单场合用 `get`。
- 集合自动去重、无序；实测交并差与对称差的结果；`issubset` 判断子集。
- 成员判断实测：列表 1000/10000/100000 条约 9.94/67.25/486.85 微秒；集合 0.046/0.035/0.150 微秒；字典同量级。
- 元组可以当键，列表不行（`TypeError: unhashable type: 'list'`）。
- `d1 | d2` 合并字典，右边覆盖左边；嵌套取值用链式 `get` 兜底。

## 作业

**Q1.** 统计一段文本里每个单词出现的次数，并输出出现最多的前三个。写出代码并说明为什么用字典。

**参考答案：** 用 `Counter` 最省事：

```python
from collections import Counter

text = "a b a c b a"
words = text.split()
counter = Counter(words)
print(counter.most_common(3))
```

输出 `[('a', 3), ('b', 2), ('c', 1)]`。

为什么用字典：词频的本质是"键 → 次数"的映射，按词直接定位，每遇到一个词只做一次查表与自增；用两个列表（词表 + 次数表）则每次都要线性查找词的位置，词一多就慢（本讲实测：列表判断在不在是线性增长，字典是常数）。

也可以用 `get` 手写计数，效果一样，只是多两行。

**Q2.** 下面代码为什么报错？给出两种修法。

```python
d = {"a": 1, "b": 2, "c": 3}
for key in d:
    if d[key] < 2:
        del d[key]
```

**参考答案：** 报 `RuntimeError: dictionary changed size during iteration`。遍历过程中删除键改变了字典大小，解释器不允许。

修法一：遍历键的副本。

```python
for key in list(d):
    if d[key] < 2:
        del d[key]
```

修法二：先收集要删的键，遍历结束后统一删。

```python
to_delete = [k for k, v in d.items() if v < 2]
for k in to_delete:
    del d[k]
```

第二种多一步，但"先判断、后修改"这个结构在处理复杂条件时更清楚。

**Q3.** `s.get("bob", {}).get("math", "无记录")` 这一行在做什么？为什么不能写成 `s["bob"]["math"]`？

**参考答案：** 它在安全地取"bob 的数学成绩"：第一层 `get` 若没有 `bob` 就返回空字典，第二层再取 `math`，还没有就返回 `"无记录"`。

不能写 `s["bob"]["math"]` 是因为：如果 `s` 里没有 `bob`，第一层就抛 `KeyError`；即使有 `bob`，若其字典里没有 `math`，第二层也会抛。链式 `get` 把两处缺失都变成了"给默认值"。

代价是可读性下降，所以只在确实允许缺失时用；如果这两个键本来就该存在，应该用 `[]` 让它早点报错。

**Q4.** 两个班报名名单分别是 `a = {"张三","李四","王五"}`、`b = {"李四","赵六"}`。写出：两个班都报的、只在 a 班报的、至少有一个班报的。

**参考答案：** 三种运算分别对应交、差、并：

```python
both = a & b            # {'李四'}
only_a = a - b          # {'张三', '王五'}
either = a | b          # {'张三', '李四', '王五', '赵六'}
```

`a - b` 与 `b - a` 不同：后者是"只在 b 班报的"，即 `{'赵六'}`。写反了很常见，读题时先确认"谁减谁"。

**Q5.** 你有 5 万条记录，每条都要检查"这个 ID 是否在已处理列表里"。现在用 `if id in processed_list:`，程序很慢。怎么改？改成什么之后需要注意什么？

**参考答案：** 把 `processed_list` 换成集合（或字典），并保持"处理过就加进去"：

```python
processed = set()
...
if id in processed:
    ...
processed.add(id)
```

理由：本讲实测成员判断中，列表在 10 万条时单次约 486 微秒，集合约 0.15 微秒，差三个数量级；而且列表随规模线性变慢，集合基本不变。

需要注意：集合无序，所以如果程序依赖"处理顺序"，就得另存一个列表记顺序，集合只用于判断；另外集合占内存比列表多。

**Q6.** 判断对错并说明理由：
(a) 字典的键可以是列表；(b) 集合可以当字典的键；(c) 字典的遍历顺序是按值排序的；(d) `d1 | d2` 中同键取 d1 的值。

**参考答案：** 四条逐一看：

- (a) 错。键必须可哈希，列表可变，实测抛 `TypeError: unhashable type: 'list'`。要"复合键"用元组。
- (b) 对，但要用 `frozenset`：普通 `set` 可变、不可哈希。
- (c) 错。字典按**插入顺序**遍历（3.7+ 的保证），不按值排序；要排序得自己 `sorted(...)`。
- (d) 错。`d1 | d2` 里同键以**右边**（d2）为准，实测 `{'a':1,'b':2} | {'b':20,'c':30}` 得 `{'a': 1, 'b': 20, 'c': 30}`。
