# 第 01 讲 程序是怎么在计算机里跑起来的

> 本讲是素养卷的第一讲，定位是**见面熟**。这一讲会让你亲手造一个文件、在黑窗口里让 Python 读它。机器上没装 Python 也不要紧：你会看到"不是内部或外部命令"，那本身就是一个需要认识的现象，第 02 讲再装。读不下去随时可以跳到第 04 讲开始写代码，卡住了再回来。

## 这一讲解决什么

你大概遇到过下面两件事里的一件。

第一件：同学发给你一个文件，双击它，什么都没发生。你以为是文件坏了，或者以为自己缺什么软件。

第二件：你问他"这个怎么运行"，他回你一句："打开命令行，cd 到那个目录，然后 python 跑一下。"每个字你都认识，连起来不知道在说什么。

这一讲就是把这两件事讲清楚：那个文件到底是什么、他那句话在说什么、你按他说的敲下去之后电脑里发生了什么。最后你会得到一张表——看到什么现象，大概坏在哪一步。

## 1. 同学发你的文件，为什么双击没反应

先看你已经会的事情。双击一份 `.docx`，Word 打开了；双击一张 `.jpg`，看图软件打开了；双击一个 `.mp3`，播放器开始放。

这些程序是谁替你找的？是 Windows。它看文件名最后那个点后面的部分——`.docx`、`.jpg`、`.mp3`——拿这个尾巴去查"该用哪个程序打开"，查到了就把文件交给那个程序。这个尾巴叫**扩展名**（extension）。它不是文件内容的一部分，只是一个标签。

同学发你的那个文件，尾巴是 `.py`。`.py` 的意思是"这是写给 Python 的文字"。问题是，Windows 默认没给 `.py` 安排"双击时用哪个程序打开"，所以双击它什么都不会发生。**文件没有坏，也不是缺软件**，只是没有人被叫来读它。

再补两件会立刻用到的：

- `.py` 文件的内容就是**纯文本**——和你在记事本里写的字是同一种东西，用记事本就能打开看。它不是 Word，也不是图片。
- Windows 默认**把扩展名藏起来**。所以你看到的可能只是 `hello`，不是 `hello.py`；更麻烦的是，一个实际叫 `hello.py.txt` 的文件，在藏起扩展名之后也会显示成 `hello.py`。这个坑第 3 节会正面撞上。

那怎么让它跑起来？得先叫醒一个叫 **Python** 的程序，把这个文件交给它读。这一步怎么写，要看下一节那句话。

## 2. 那句"cd 到目录，再 python 跑一下"，在说什么

同学那句话里有两个动作。先看他说这话时面对的是什么。

他让你打开的那个东西，叫**终端**（terminal），俗称"黑窗口"：一个黑底白字的窗口，里面有一行字在闪。你按 Win 键，输入 `cmd` 或 `powershell`，回车，就能看到一个。

窗口只是壳。真正读懂你敲的那行字、并去执行的，是窗口里运行的另一个程序，叫 **shell**。Windows 上常见两种 shell：

- **cmd**：老的那一个，命令少，简单；
- **PowerShell**：新的那一个，功能多，语法也更现代。

所以"终端 / 命令提示符 / cmd / PowerShell"这几个词经常被混着叫，说的其实是"一个黑窗口，加上里面那个 shell"。你在网上抄命令时，偶尔会遇到"这条只在 PowerShell 里能用"的情况，原因就在这里。本课程默认用 PowerShell；两种的差别会在用到时就地说。

为什么要用这么个东西，而不是右键、双击？因为你用鼠标做的事，本质上是一串操作：打开文件夹、找到文件、右键、运行。做一次很直观，做十次就要点十遍。黑窗口允许你把这些操作写成一行字，可以重复、可以复制给别人、可以写进脚本自动执行。它不是高手专用，它是给"同一件事要做很多遍"的人用的。

现在回到那句话的两个动作。

**"cd 到那个目录"**：`cd` 是 change directory 的缩写，意思是"切换当前目录"。**目录**就是文件夹；**当前目录**是黑窗口此刻站着的位置。你敲的所有相对名字，都是从这里开始找的。他说这句，是为了让黑窗口先站到你那个文件所在的文件夹里。

**"python 跑一下"**：`python` 是 Python 那个程序的名字。这句话的完整写法是 `python 文件名`，意思是"启动 Python，把后面这个文件交给它读"。`python` 和文件名之间用空格隔开，前者叫**命令**，后者叫**参数**。

这两件事合起来就是：先站对地方，再叫醒 Python 去读那个文件。下一节你自己做一遍。

## 3. 自己造一个能跑的文件：五步

**第 1 步：打开记事本，输入一行字。**

```python
print("你好")
```

这一行里三样东西：`print` 在英文里是"打印、显示"的意思，在 Python 里就是"把括号里的东西显示出来"；括号里放要显示的内容；引号表示"这是一段文字，原样显示，不要当成数学式子去算"。

完整的语法规则第 04 讲才讲，现在照着敲就行。注意括号和引号都必须用英文半角——写成 `print（"你好"）`（全角括号）会报错。

**第 2 步：另存为 `hello.py`。**

先在桌面建一个文件夹，叫 `py01`。然后在记事本里点"文件 → 另存为"，存到这个文件夹。

两个地方会坑人：

- **保存类型**要选"所有文件（\*.\*）"。如果留着默认的"文本文档（\*.txt）"，文件名会自动变成 `hello.py.txt`——它的扩展名是 `.txt`，Python 不会把它当代码。
- **编码**选 UTF-8（新版记事本默认就是）。

存好后，打开 `py01` 文件夹，点窗口上方的"查看"，勾上"显示 → 文件扩展名"。现在你应该能清楚看到文件名是 `hello.py`，而不是 `hello` 或 `hello.py.txt`。这一步是在防第 1 节说的那个"藏扩展名"的坑。

**第 3 步：在这个文件夹里打开黑窗口。**

不用背 `cd` 路径。直接打开 `py01` 文件夹的窗口，点一下顶部地址栏（显示 `此电脑 > 桌面 > py01` 的那一栏），把里面的字删掉，输入 `cmd`，回车。黑窗口会直接在 `py01` 里打开。

（更习惯 PowerShell 就输 `powershell`，两者都能用。）

**第 4 步：让 Python 读这个文件。**

在黑窗口里敲：

```text
python hello.py
```

按第 2 节拆过的结构：`python` 是命令，`hello.py` 是参数。

**第 5 步：看结果。**

如果屏幕上出现：

```text
你好
```

你刚刚完整地"运行了一个程序"。往下读第 4 节，你会看到这中间其实走了七站。

如果出现的是：

```text
'python' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

（PowerShell 里说法不同："无法将 python 项识别为 cmdlet、函数、脚本文件或可运行程序的名称"。）

说明这台机器上没装 Python，或者装了但系统不知道它在哪。**这不是你写错了。** 第 02 讲会装；你现在可以先读完这一讲，装好再回来做一遍。

如果出现的是：

```text
python: can't open file 'hello.py': [Errno 2] No such file or directory
```

说明 Python 已经启动了，但它在"当前目录"里没找到 `hello.py`。原因通常是第 3 步开黑窗口开错了文件夹，或者文件名其实叫 `hello.py.txt`。

## 4. 刚才那五步，机器里走了七站

你敲了 `python hello.py`，屏幕上出现 `你好`。中间走了七站：

1. **存盘**。记事本把内容写进磁盘。你点"保存"那一刻，`hello.py` 才真的存在于磁盘上。
2. **命令**。你敲的字进入黑窗口；shell（cmd 或 PowerShell）把它拆成两部分：命令 `python`，参数 `hello.py`。
3. **启动**。shell 去一张目录清单里，按顺序找名为 `python.exe` 的程序。找到就启动它；这个正在运行的程序叫**进程**（process）。找不到，就是第 3 节那句"不是内部或外部命令"。
4. **读入**。`python.exe` 打开 `hello.py`，把里面的文字读进来（按某种编码），编译成**字节码**（bytecode，Python 内部使用的中间指令）。
5. **执行**。Python 逐条执行字节码。`print("你好")` 把"你好"转成一串字节，写到**标准输出**（standard output，操作系统提供的一个输出通道）。
6. **显示**。黑窗口收到这串字节，按自己的**码页**（code page，它认为字节该按哪种编码来解）解成字符，再用字体把字形画出来。
7. **你看到 `你好`。**

这七站里，四个部件各管一段：

| 部件 | 负责哪几步 | 断电之后 | 量级 |
|---|---|---|---|
| 磁盘 | 1（存文件）、3（存 Python 程序） | 内容还在 | 几百 GB |
| 内存 | 3、4、5（进程和它处理的数据都在这里） | 内容全没 | 8–32 GB |
| CPU（中央处理器） | 5（逐条执行指令） | —— | 每秒几十亿条指令 |
| 终端与屏幕 | 2、6 | —— | —— |

这张表能顺手回答几个常被问到的问题：

- **为什么"文件还在"和"程序在跑"是两回事**：文件只是磁盘上的字节；只有被叫醒、进了内存，才有一个进程在跑。
- **为什么 20 GB 的文件不能一次读进来**：内存只有 8–32 GB，装不下。（即使用 `read()` 这样的写法把整个文件一次读进来，也一样装不下；第 13 讲给流式读法。）
- **为什么关掉窗口，程序就停了**：进程结束，内存回收。
- **为什么 `.py` 换台电脑通常能跑**：它只是文本，只要有 Python 就能读；真正执行的指令在 Python 里，不在你的文件里。
- **为什么 Python 不生成 `.exe`**：干活的是 Python 这个程序，你的文件只是它读的原料。要发给没装 Python 的人，得用打包工具把 Python 一起塞进去，那是另一个话题。

### 这一讲真正要交付的东西

把七站和三节里见过的现象对起来：

| 坏在第几步 | 你会看到什么 | 先查什么 |
|---|---|---|
| 1 存盘 | 输出是旧的 | 有没有点保存；文件名是不是 `.py.txt` |
| 2 命令 | 报"无法将 ... 项识别为 cmdlet"；或跑成了别的程序 | 命令拼写 |
| 3 启动 | 同上，但命令拼写没问题 | Python 是否安装、系统能不能找到它（02 讲） |
| 4 读入 | `can't open file`；`SyntaxError`；`Non-UTF-8`；`UnicodeDecodeError` | 当前目录、文件名、编码 |
| 5 执行 | 报错（屏幕上那一长串以 `Traceback` 开头的东西）；或死循环不结束 | 从最后一行往前读（11 讲） |
| 6 显示 | 乱码（`???`、`锟斤拷`）或方块 | 码页与编码，或字体 |

见面熟不等于全都不管，也不等于全部背下来。分两档：

| 今天要会 | 今天只认得名字 |
|---|---|
| 用记事本存出 `.py`；在文件所在文件夹打开黑窗口；敲 `python 文件名`；拿现象对表判断大概哪一站 | 字节码、标准输出、shell、进程、名字绑定、码页 |

"只认得名字"的意思是：别人提起它，你知道大概指什么、大概在哪一站；不要求你现在会用。

## 5. 七站里，哪几站最常坏

下面按"你看到什么"来分，不按站号排。每一段末尾标出它对应第几站。

### 5.1 改了没生效

记事本里改完内容，必须**保存**（或另存为）才会写回磁盘。不保存就切回黑窗口再跑一次，跑的还是磁盘上那一版。

这一站还有两个变种：

- 保存到了别处，跑的是旧目录里的同名文件；
- 文件名其实是 `hello.py.txt`，你以为在跑 `.py`，实际跑的是别的。

至于"是不是 Python 缓存了旧内容"——不是。5.4 节会讲缓存到底是什么，以及为什么它不背这个锅。

### 5.2 命令找不到

`python hello.py` 被 shell 拆成命令加参数。所以命令拼错一个字母，它找的就是另一个程序：

```text
> pythn hello.py
pythn : 无法将"pythn"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
```

注意这句话里**没有任何 Python 的信息**——Python 根本没被叫醒。从现象上看，拼错命令和第 3 站的"没装 Python"长得一模一样，区别只在：这次是你打字打错了，那次是你打对了但系统里确实没有它。

第 3 站依赖的是一个叫 `PATH` 的环境变量：一张目录清单。shell 收到 `python` 这个名字，就在清单里的目录中按顺序找 `python.exe`，找到第一个就用它。

```text
> where python
C:\Users\you\AppData\Local\Programs\Python\Python312\python.exe
> python -V
Python 3.12.13
```

（路径随安装位置不同。如果你的机器上 `python` 根本没进 PATH，`where python` 什么都不打印，`python -V` 会报"无法将 python 项识别"——那正是这一站出了问题。）

`where python` 列出几个，就说明你机器上装了几份。用哪个取决于 PATH 里的先后顺序，第 02 讲会讲透。

本课程的示例有时写成 `uv run python`。`uv` 是另一个工具，它自带一份 Python，`uv run python` 的意思是"用 uv 管的那份来跑"。它和 `python` 跑的是同一类东西，区别在 02 讲。你现在只需要知道：**换了一份 Python，已经装好的第三方包就可能完全找不到**，这是后面很多"明明装了却用不了"的根源。

黑窗口里最常用的四条命令：

| 想做什么 | PowerShell 写法 | 说明 |
|---|---|---|
| 看我在哪 | `pwd` | 打印当前目录 |
| 看这里有什么 | `dir` | 列出当前目录内容 |
| 进入某个目录 | `cd 路径` | 改当前目录；路径可绝对或相对 |
| 跑脚本 | `python 文件名.py` | 前提是 Python 在 PATH 里 |

再加一条：程序跑飞了按 `Ctrl+C` 中止。

两个细节：Windows 自带的 PowerShell 5.1 里，命令之间用分号 `;` 分隔，**不认 `&&`**（PowerShell 7 才支持），这是很多人从网上抄命令失败的原因；命令名不区分大小写，路径区分。

### 5.3 找不到文件

你在黑窗口里敲 `python hello.py`，这个 `hello.py` 是**相对路径**：它相对的不是文件所在的位置，而是黑窗口的**当前工作目录**（current working directory，cwd）。绝对路径则是从盘符写全，例如 `E:\hw\hello.py`；相对路径只写从当前目录出发的那一段。第 3 步用地址栏打开黑窗口，就是为了让 cwd 正好是 `py01`。

换个目录启动同一个脚本，相对路径就会指到别处：

```text
> cd E:\...\WHATIFICATCHUPFROMSCRATCH
> uv run python tutorials\python\scripts\lec01-01_demo_chain.py
cwd        : E:\...\WHATIFICATCHUPFROMSCRATCH
script dir : E:\...\WHATIFICATCHUPFROMSCRATCH\tutorials\python\scripts
same?      : False

> cd E:\...\WHATIFICATCHUPFROMSCRATCH\tutorials\python
> uv run python scripts\lec01-01_demo_chain.py
cwd        : E:\...\WHATIFICATCHUPFROMSCRATCH\tutorials\python
script dir : E:\...\WHATIFICATCHUPFROMSCRATCH\tutorials\python\scripts
same?      : False
```

`cwd` 跟着你敲命令的位置变，`script dir`（脚本所在目录）不变。所以脚本里写 `open("data/scores.csv")` 时，找的是"你敲命令的那个目录"下面的 `data`，不是脚本旁边的 `data`。这是"在编辑器里能读到数据，换个地方运行就报 `FileNotFoundError`"的全部原因。第 13 讲给不依赖 cwd 的标准写法。

（上面的路径中间用 `...` 省略了，你屏幕上会看到完整路径，关键在末段。）

Windows 路径还有两个坑：分隔符 `\` 在 Python 字符串里是转义符，所以写路径时常用 `r"C:\new\todo.txt"`（原始字符串）或改用 `/`，第 05 讲展开；路径带空格时，命令行里要用引号包起来，`cd "E:\my homework"`。

### 5.4 文件读不进来：编码与缓存

Python 读源代码时默认按 UTF-8 解释字节。UTF-8 是一种把字符变成字节的规则。如果文件不是 UTF-8，Python 连"你写的是什么"都不知道。

我实测过一个特别常见的坑：Windows 自带的 PowerShell 5.1 里，用 `>` 把输出写进文件（这个写法叫重定向）时，默认写的是 UTF-16。

```text
> "print('hello from demo')" > hello.py
> python hello.py
  File "hello.py", line 1
SyntaxError: Non-UTF-8 code starting with '\xff' in file ... but no encoding declared
```

`\xff` 是 UTF-16 在文件开头留下的字节序标记（几个字节，用来标明"这个文件是 UTF-16 写的"）的前半截。此时代码一个字符都没写错，错的是文件的编码。所以这条报错虽然长着 `SyntaxError` 的样子，却不该去改代码；正确的写法是 `"print('hello from demo')" | Set-Content -Encoding utf8 hello.py`，或者干脆用记事本另存为 UTF-8。

要记住的是：**报错的名字不等于出错的环节。** `SyntaxError` 出现在第 4 站，不等于你"语法没学好"。

另一件常被冤枉的是缓存。当你的程序引用了另一个 `.py` 文件里的代码（这个动作叫 `import`，意思是"导入"，被导入的那个文件叫**模块**），Python 会把编译好的字节码存到源码旁边的 `__pycache__` 目录里。它只是省时间：下次直接读字节码，跳过解析源码。删掉它不会让程序出错，只是下次重新编译；改了 `.py` 后 Python 会比对修改时间自动重编。所以"我改了没生效"不该怪它，真正的嫌疑人是没保存（5.1）和跑的是另一个文件（5.3）。

### 5.5 跑起来之后才出错

走到这里，Python 已经在跑你的代码了。先分清两个词。

**程序**（program）是磁盘上的文件；**进程**（process）是它的一次运行。你敲三次 `python hello.py`，就有三个进程，互不知道对方存在。

一次运行开始时，操作系统给这个进程划出一块内存；程序里出现的每个值，都是这块内存里的一个对象。变量名只是贴在对象上的标签。看一个实验：

```text
=== EXP4: 名字指向对象，id 观察（先只记现象）===
a is b (256)      : True;  id(a)==id(b): True
c is d ('257')    : False;  c == d: True;  id 相同: False
```

`id()` 给出对象在本次运行中的编号；`is` 问"是不是同一个对象"；`==` 问"值是否相等"。第一行说明 `a = 256` 和 `b = 256` 这两个名字贴到了同一个对象上；第二行说明用 `int("257")`（把文字 "257" 变成整数 257）分别造出来的两个 257 是两个对象，但值相等。

为什么 256 会共用、257 不会？因为 Python 预先缓存了 $-5$ 到 $256$ 这些小整数。这是实现细节，第 04 讲会讲清什么时候可以依赖、什么时候绝对不能。**本讲只要一个印象：名字不是盒子，两个名字可以指向同一个东西。**

另外，同一个 Python 还有交互式入口：只敲 `python` 不带文件名，会出现 `>>>` 提示符，输入一行执行一行。**`>>>` 是提示符，不是 Python 语法**，抄进 `.py` 文件会得到 `SyntaxError`。写程序用脚本方式，`>>>` 只适合试一小段。

最后一个要点：`print` 不是"显示"，它只是把字节写到标准输出。**写出去**是第 5 站，**看见**是第 6 站。这两件事分开，才能解释"程序算对了，但屏幕上是乱的"。

### 5.6 算对了，屏幕上是乱的

最后一段路是这样走的：

字符（"你"）→ 码点（一个编号）→ 字节（UTF-8 里是三个字节）→ 黑窗口按自己的码页解码 → 字体画出字形。

Windows 中文环境的历史默认码页是 936（GBK）。你可以自己看：

```text
> chcp
活动代码页: 936
```

码页和文件编码不匹配，就得到两类完全不同的现象：

| 你看到的 | 原因 | 该改哪一边 |
|---|---|---|
| `???`、`锟斤拷` | 窗口用错规则去解那串字节 | 终端码页或文件编码（02、05 讲） |
| 方块，但英文完全正常 | 字节解对了，字体没有这个字的字形 | 换字体 |

这条区分很实用：**乱码是"解错了字节"，方块是"解对了但没图可画"。** 搞反了方向，就会去改一个不该改的东西。

> 一处修正：这一节把最后一步说成了"终端按码页解码"，这是简化说法。更准确地说，Python 3.6+ 在真正的控制台窗口里输出时走的是 Windows 的 Unicode 接口，不受码页影响；只有被**重定向到文件或管道**时，才按 `sys.stdout.encoding` 编码（中文 Windows 常为 gbk）。第 02 讲第 7 节把这三条路分开讲了。

## 6. 拿这张表判断三件事

下面三件事，都按"现象 → 归到第几站 → 第一件事做什么"走。

**例 1**：你昨天用 `pip install numpy` 装过一个叫 numpy 的包（包就是把一堆现成代码打包成的工具，`pip` 是用来装它的命令，02 讲），今天运行脚本却报 `ModuleNotFoundError: No module named 'numpy'`。

**解**：归到第 3 站（叫醒的是哪一份 Python）。`pip install` 装进了某一个 Python 的目录，今天跑起来的可能是另一个。第一件事：对照两个命令的输出——`pip show numpy` 里的 `Location`，和 `python -c "import sys; print(sys.executable)"` 打印的解释器路径。对不上就是装到了别处，不是"没装"。

**例 2**：`FileNotFoundError: [Errno 2] No such file or directory: 'data.csv'`，而 `data.csv` 明明就在脚本旁边。

**解**：归到第 4 站（当前目录）。脚本旁边的文件不等于"当前目录"下的文件。第一件事：在脚本里打印 `Path.cwd()`（`pathlib` 是什么，第 13 讲讲），看你实际站在哪里。

**例 3**：黑窗口里中文显示成方块，英文完全正常。

**解**：归到第 6 站的下半段（字体），不是编码。第一件事：换一个字体或换一个窗口，把同一段输出再打一次。换了就好，问题在字体；还是方块，再回头查码页。

判断顺序固定为三步：**看现象 → 对表 → 只查那一站。** 跳过前两步直接动手，是最常见的浪费。

## 小结

- `.py` 只是扩展名，文件本身是纯文本；双击没反应不是文件坏了。
- 黑窗口、终端、cmd、PowerShell、shell 不是五个东西：终端是窗口，shell 是里面解析命令的程序，cmd 与 PowerShell 是两种 shell。
- "运行"不是一次双击，而是七站：存盘、命令、启动、读入、执行、显示、你看到。
- 最高频的三个坑：没保存、当前目录不对、叫醒的不是你以为的那份 Python。
- 报错的名字不等于出错的环节：`SyntaxError` 可能是编码问题，`ModuleNotFoundError` 可能是装错了解释器。
- 乱码与方块是两件事：前者改编码或码页，后者改字体。
- 下次见到没见过的报错，先对表定位，再动手；不要先重装。

## 作业

**Q1.** 用你自己的话说清：为什么 `hello.py.txt` 这个文件用 `python hello.py.txt` 也许能跑，但双击它或按 `.py` 的方式使用就不行？文件名和扩展名在这里各起什么作用？

**参考答案：**
文件里装的是纯文本内容，`python 文件名` 这个命令只是让 Python 去读这个文件，它并不挑扩展名——所以如果你明确把 `hello.py.txt` 交给它，它照样能读。但双击、以及大多数工具判断"这是什么文件、该用哪个程序打开"时，看的是扩展名；`.txt` 会被当成普通文本，不会交给 Python。所以扩展名是给人和工具看的标签，不是内容本身的属性。这也是"另存为时选错保存类型"会让人以为代码坏了的原因。

**Q2.** 用一句话说明：为什么"我的程序文件还在，但它没在运行"和"我关掉了程序，所以代码丢了"这两句话都是错的？

**参考答案：**
文件在磁盘上不会因为程序没跑而消失，所以"文件还在但没在运行"是正常状态；关掉程序丢的是内存里的运行状态（变量、执行到哪一步），磁盘上的 `.py` 不受影响，重新运行就能重建；只有忘记保存时，丢的才是"还没写回磁盘的编辑内容"。

**Q3.** 跑一次 `python -c "print(2**100)"`（或用 `uv run python -c "print(2**100)"`），抄下输出。为什么它没有溢出？

**参考答案：**
输出是 `1267650600228229401496703205376`。Python 的整数是任意精度的，位数由内存决定，不固定在 32 位或 64 位，所以不会溢出；代价是大数运算更慢、更占内存（第 04 讲实测）。C 的 `int` 是固定宽度的机器整数，超出范围会回绕或触发未定义行为。

**Q4.** 分别在项目根目录和 `tutorials\python` 目录下运行 `lec01-01_demo_chain.py`，记录 `cwd` 与 `script dir` 两行。哪一行变了？它解释了哪一类故障？

**参考答案：**
`cwd` 变了，`script dir` 两行相同。它解释"同样的代码，在编辑器里能读到数据文件，换个目录运行就报 `FileNotFoundError`"这一类故障：脚本里的相对路径按 cwd 解析，不按脚本所在目录。

**Q5.** 判断并说明理由：删掉 `__pycache__` 会不会让程序出错？什么情况下会？

**参考答案：**
正常不会。它只是字节码缓存，源码还在，Python 发现缓存缺失就重编一次；已经加载到内存的模块更不受影响。只有当你手里只有 `.pyc` 而没有对应的 `.py`（有人只发了缓存）时，删掉才真的没有东西可执行。正常项目不会这样发布。

**Q6.** 目录结构如下，当前目录是 `E:\hw`：

```
E:\hw\
├── main.py
├── data\
│   └── scores.csv
└── backup\
    └── old.csv
```

写出：① `main.py` 的相对路径；② `scores.csv` 的相对路径；③ `old.csv` 的相对路径；④ 先进入 `backup` 再回到 `hw` 的命令。

**参考答案：**
① `main.py`（或 `.\main.py`）；② `data\scores.csv`；③ `backup\old.csv`；④ `cd backup`，再 `cd ..`。

**Q7.** 你在黑窗口敲 `python hello.py`，屏幕上出现：

```text
python: can't open file 'E:\\hw\\hello.py': [Errno 2] No such file or directory
```

按第 4 节的表，这属于第几站的问题？写出前两条排查动作。

（提示：报错前缀可能是 `python:`，也可能是 Python 程序的完整路径，意思相同。）

**参考答案：**
属于第 4 站"读入"：Python 已经启动（否则会报"不是内部或外部命令"），但按给定路径打不开文件。

前两条动作：① 用 `dir` 看当前目录里有没有 `hello.py`，注意 Windows 默认隐藏扩展名，可能实际是 `hello.py.txt`；② 用 `pwd` 看 cwd 是不是你以为的那个，不是就用 `cd` 进去，或改用绝对路径。

**Q8.** 把七站用你自己的话重写一遍，每一站后面标出"这一站出问题会看到什么"。

**参考答案：**
① 存盘：不保存则跑旧文件，表现为"我改了没生效"；若存成 `.py.txt`，表现为找不到文件或报语法错。
② 命令：shell 拆"命令 + 参数"；拼错则报"无法将 ... 项识别为 cmdlet"。
③ 启动：在 PATH 里找 `python.exe`；找不到则报同样的"不是内部或外部命令"，但命令拼写是对的。
④ 读入：Python 读文件、编字节码；失败会报 `can't open file`、`SyntaxError`、`Non-UTF-8`、`UnicodeDecodeError`。
⑤ 执行：跑字节码；出错给 `Traceback`，死循环则既不输出也不结束。
⑥ 显示：窗口解码并用字体画字；错了是乱码或方块。
⑦ 你看到结果：这一步没有独立故障，但要分清"算错"与"显示错"。

**Q9.** 有人说"Python 是解释型语言，所以它比 C 慢，而且不编译"。这句话哪一半对、哪一半会误导人？

**参考答案：**
"通常比 C 慢"在多数场景成立；"不编译"错：Python 运行前会把源码编译成字节码（还缓存到 `.pyc`），只是不编译成 CPU 直接执行的机器码，也不生成独立可执行文件。

"慢"也要限定范围：第 17 讲会实测，同样的任务换个数据结构就差几个数量级——多数时候瓶颈在算法与容器选择，不在语言。把一切都归给语言，会在错误的地方优化。

**Q10.** 给出三个现象，分别判断坏在第几站，并写出第一件该做的事：① 程序跑完窗口一闪就没了；② 输出里中文是 `锟斤拷`；③ 脚本里 `import requests` 报 `ModuleNotFoundError`，但你确实装过。

**参考答案：**
① 不在这七站里出错：程序正常结束了，是黑窗口跟着关闭。这属于"怎么启动它"的问题（在已经打开的窗口里运行，或让程序末尾等一下再退出），不是代码错。
② 第 6 站：窗口用错规则反复解码/编码，属于乱码。第一件事：看 `chcp` 的码页，并确认窗口与文件编码是否一致。
③ 第 3 站：叫醒的 Python 不是装包的那一份。第一件事：`pip show requests` 的 `Location` 与 `python -c "import sys; print(sys.executable)"` 对照。
