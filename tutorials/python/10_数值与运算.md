## 0. 场景：三个都算错的地方

- 你写了一个算平均分的脚本，结果 `0.30000000000000004` 这种数字出现在屏幕上。
- 你把 19.99 元累加十次，得到一个比 199.9 小一点点的数，`== 199.9` 竟然是 `False`。
- 你写 `round(2.5)` 想得到 3，Python 给你 2。

这三个都不是 bug，是你对"数字在计算机里是什么"的默认假设不对。这一讲把假设改过来。

## 1. 四种数值类型

| 类型 | 是什么 | 精度 | 本课要求 |
|---|---|---|---|
| `int` | 整数，任意精度 | 精确，位数只受内存限制 | 要会用 |
| `float` | 浮点数（IEEE 754 双精度） | 约 15–17 位有效数字，有舍入误差 | 要会用，且要知道它的误差边界 |
| `bool` | 布尔值，只有 `True` / `False` | — | 要会用；它其实是 `int` 的子类 |
| `complex` | 复数，如 `1+2j` | 由两个 `float` 组成 | 知道存在 |

`bool` 是 `int` 的子类这件事有实测支撑：

```text
  True + True = 2   isinstance(True, int) = True
```

所以 `True + True` 等于 2，不报错。两个后果值得记住：

- `if x:` 与 `if x == True:` **不是一回事**：前者判断"真值"（非零、非空），后者只在 `x` 恰好等于 1 时为真。写条件判断时用前者。
- 布尔值可以当数字用（`sum([True, False, True])` 得到 2），统计"满足条件的个数"时很顺手。

`complex` 现在只需要知道"存在、写法是 `1+2j`、`.real` / `.imag` 取两部分、`abs()` 取模"。本课程后续不依赖它。

## 2. `int`：任意精度，没有溢出这回事

C 或 Java 里，整数有固定位宽（32 位、64 位），超出就溢出。Python 的 `int` 没有这个限制。实测：

```text
  2 ** 100 = 1267650600228229401496703205376
  它的十进制位数 = 31
  10 ** 1000 的位数 = 1001（照样算得出来）
```

代价是：大数运算比机器字长慢，位数越多越慢。学习阶段不用担心，第 23 讲比较 numpy 与纯 Python 时会看到"数值计算为什么慢"的另一半原因。

`int` 的字面量（直接写在代码里的数字）有几种写法，实测：

```text
  1_000_000 = 1000000   0b1010 = 10   0o17 = 15   0xFF = 255
  1e3 = 1000.0   1.5e-3 = 0.0015
```

- 下划线 `_` 只是给人看的分隔符，读大数不容易数错，值不变；
- `0b` 二进制、`0o` 八进制、`0x` 十六进制；
- `1e3` 这种科学计数法得到的是 **float**（`1000.0`），不是 `int`——这一点在判断类型时容易忽略。

## 3. `float`：误差从哪来

### 3.1 二进制存不下 0.1

`float` 用的是二进制科学计数法，和十进制的关系就像"1/3 写不成有限小数"一样：**0.1 在二进制里是无限循环的**，只能截断存储。实测它的真面目：

```text
  0.1 的精确值 = 0.1000000000000000055511151231257827021181583404541015625
```

你以为存的是 0.1，实际存的是比 0.1 稍大一点点的那个数。

单个 0.1 打印时仍然显示 `0.1`，因为打印只显示最少的必要位数。但一加就有机会露出马脚：

```text
  0.1 + 0.2        = 0.30000000000000004
  等于 0.3 吗     = False
  两者相差        = 5.551115123125783e-17
  用 isclose 判定  = True
```

读法：

- 误差在 `1e-17` 量级，也就是小数点后第 17 位。对于绝大多数工程计算，这个量级可以忽略；
- 但 `==` 是精确比较，所以它会说 `False`；
- `math.isclose(a, b)` 用"相对容差"判断"够不够近"，这才是比较浮点的正确姿势。

### 3.2 浮点比较的三种写法

| 写法 | 什么时候用 | 风险 |
|---|---|---|
| `a == b` | 只在两边都是由整数精确算出来的值（如 `2.0`）时用 | 有误差就判错 |
| `abs(a - b) < 1e-9` | 自己定容差，适合"我知道量级"的场合 | 容差选大了漏判、选小了误判 |
| `math.isclose(a, b)` | 默认选择 | 需要知道它默认用的是相对容差 |

日常结论一句话：**不要用 `==` 比较两个算出来的浮点数。**

### 3.3 `Decimal`：精确十进制（知道存在）

Python 标准库里有 `decimal.Decimal`，用十进制方式存储，`Decimal("0.1") + Decimal("0.2")` 正好等于 `Decimal("0.3")`。

代价是慢，而且必须用字符串构造（`Decimal(0.1)` 会把 float 的误差原样带进去，实测就是那串长数字）。本课程不要求用它，但你要知道"需要精确十进制时，有这个东西"。金额更常用的做法见第 7 节。

## 4. 五种运算

### 4.1 双除法：`/` 与 `//`

Python 有两个除法，这是很多语言没有的设计：

- `/` 永远给浮点结果：`7 / 2` 是 `3.5`，`4 / 2` 是 `2.0`；
- `//` 是**向下取整**（朝负无穷），不是"去掉小数部分"。

实测四种组合：

```text
算式                / 结果     // 结果         divmod 结果
7 / 2              3.5         3            (3, 1)
-7 / 2             -3.5        -4           (-4, 1)
7 / -2            -3.5        -4          (-4, -1)
-7 / -2             3.5         3           (3, -1)
```

看第二行：`-7 // 2` 是 `-4`，不是 `-3`。原因是 `-3.5` 向下（往更小的方向）取整得到 `-4`。如果你的直觉是"去掉小数"，那在负数上就会差 1。

同一个坑还有第二个入口：`int()` 是**朝零截断**，不是向下取整。实测：

```text
  int(-3.7) = -3   而  -3.7 // 1 = -4.0
```

一句话区分：**`int()` 朝零，`//` 朝负无穷。** 正数上两者一样，负数上差 1。

`divmod(a, b)` 一次返回"商与余数"的元组，等价于 `(a // b, a % b)`。第 12 讲讲元组，这里先知道它能省一次计算。

### 4.2 取余：符号跟着除数走

```text
  7 % 2 = 1
  -7 % 2 = 1
  7 % -2 = -1
  -7 % -2 = -1
```

在 Python 里，**余数的符号与除数相同**。这条和 C / Java 不同（它们的余数符号跟被除数），所以从别的语言转过来时最容易在这里出错。

有一个恒等式永远成立，可以用来验算：

```text
  -7 == (-7 // 2) * 2 + (-7 % 2) -> True
```

即 `a == (a // b) * b + (a % b)`。当你不确定某个负数取余的结果时，用这条式子反推。

### 4.3 幂与优先级

```text
  2 ** 10   = 1024
  2 ** -1   = 0.5（负指数得到小数）
  2 + 3 * 4 = 14； (2 + 3) * 4 = 20
  -2 ** 2   = -4； (-2) ** 2 = 4
```

`-2 ** 2` 是 `-4`，因为 `**` 的优先级高于一元负号，它先算 `2 ** 2` 再取负。这不是"设计缺陷"，是数学惯例（$-2^2$ 也写作 $-4$）。

优先级从高到低（只列本讲涉及的）：

| 顺序 | 运算符 | 例子 |
|---|---|---|
| 1 | `**` | `2 ** 3 ** 2` 是 `2 ** 9`（右结合） |
| 2 | 一元 `+` / `-` | `-x` |
| 3 | `*` `/` `//` `%` | `7 // 2 * 3` |
| 4 | `+` `-` | `1 + 2 * 3` |

不需要背表。规则只有一条：**拿不准就加括号**。括号不花钱，猜优先级会花时间。

## 5. `round`：不是四舍五入

```text
  round(0.5) = 0
  round(1.5) = 2
  round(2.5) = 2
  round(3.5) = 4
```

`round` 用的是**银行家舍入**（round half to even）：恰好 `.5` 时，往最近的**偶数**方向取整。所以 2.5 得 2、3.5 得 4。这样做的理由很实在：大量数据求和时，总是向上舍入会让结果系统性偏大，一上一下则互相抵消。

带小数位的舍入还有一层坑：

```text
  round(2.675, 2) = 2.67
  round(1.005, 2) = 1.0
```

直觉上 2.675 保留两位应该是 2.68，但 2.675 存成浮点后实际比 2.675 略小（约 2.674999…），舍入就落到 2.67。1.005 同理，实际是 1.00499…，得到 1.0。

结论：**`round` 不适合做金额结算**。它适合"打印时保留几位小数"这种展示场景。

## 6. 类型转换

| 表达式 | 结果 | 说明 |
|---|---|---|
| `int("12")` | `12` | 字符串转整数，内容必须是整数字面量 |
| `int("1.5")` | 报 `ValueError` | 不能直接转带小数点的字符串，先 `float` 再 `int` |
| `int(3.9)` | `3` | 朝零截断 |
| `int(-3.9)` | `-3` | 也是朝零，不是 `-4` |
| `float("1.5")` | `1.5` | 字符串转浮点 |
| `float(3)` | `3.0` | 整数转浮点 |
| `str(3.0)` | `"3.0"` | 转成字符串，注意带着 `.0` |
| `bool(0)` / `bool("")` / `bool([])` | `False` | 零、空字符串、空列表都是假 |
| `bool("0")` | `True` | 非空字符串就是真——这是最常被误判的一个 |

`bool("0")` 为 `True` 值得单独说：字符串 `"0"` 不是数字 0，它是一个长度 1 的字符串，非空即真。所以"判断用户有没有输入"和"判断用户输入的是不是 0"是两件事。

## 7. 金额：用整数分，别用浮点

实测两种累加方式，各加 10 次 0.1 元：

```text
  整数分累加 10 次：100 分 = 1.0 元
  float 累加 10 次：0.9999999999999999 元
  两者相等吗 = False
```

十次就已经不相等了。如果有十万笔流水，误差会累积到真实可见的程度。

工程做法只有一条：**金额一律用整数存最小单位（分），只在显示时除以 100。**

```python
price_cents = 1999          # 19.99 元
total_cents = price_cents * 10
print("合计", total_cents / 100, "元")
```

乘 10 次、加 10 万次都是精确的整数运算；显示时除以 100 得到 `199.9`。如果连"除以 100"都不放心（比如要格式化到两位小数），用整数拆分：`f"{total_cents // 100}.{total_cents % 100:02d}"`——这里的 `f"..."` 是第 11 讲的内容，先看个样子。

## 8. 这一讲留下的东西

- 四种数值类型的分工：`int` 精确且任意精度、`float` 有舍入误差、`bool` 是 `int` 子类、`complex` 知道存在。
- `float` 的误差来自"二进制存不下十进制小数"；比较用 `math.isclose`，别用 `==`。
- `/` 给浮点、`//` 向下取整、`int()` 朝零截断；负数上这三者会分道扬镳。
- `%` 的符号跟除数走，恒等式 `a == (a // b) * b + (a % b)` 永远成立。
- `round` 是银行家舍入；带小数位时还会被浮点表示坑；不适合金额。
- 金额用整数分存，显示时再换算。

下一讲处理另一种最常用的数据：字符串。你会看到"为什么字符串改不了""切片为什么越界不报错""一行日志怎么拆成三段"。

## 小结

- `int` 任意精度：实测 `2 ** 100` 有 31 位、`10 ** 1000` 有 1001 位，不会溢出。
- `float` 是 IEEE 754 双精度：实测 `0.1 + 0.2 = 0.30000000000000004`，`== 0.3` 为假，`math.isclose` 为真。
- `/` 永远给浮点；`//` 向下取整（`-7 // 2 = -4`）；`int()` 朝零截断（`int(-3.7) = -3`）。
- `%` 的符号与除数相同（`-7 % 2 = 1`、`7 % -2 = -1`），且 `a == (a // b) * b + (a % b)`。
- `-2 ** 2 = -4`，因为 `**` 优先于一元负号；`2 ** 3 ** 2` 是右结合。
- `round` 是银行家舍入：`round(2.5) = 2`、`round(3.5) = 4`；`round(2.675, 2) = 2.67`。
- `bool("0")` 是 `True`；`bool` 是 `int` 子类，`True + True = 2`。
- 金额用整数分：实测 float 累加十次得 `0.9999999999999999`，整数分得 100 分。

## 作业

**Q1.** 计算 `-9 // 4`、`-9 % 4`、`int(-9 / 4)`，并说明三者为什么不同。

**参考答案：** 三个结果分别是 `-3`、`3`、`-2`。

- `-9 // 4 = -3`：向下取整，`-2.25` 往负无穷方向取到 `-3`；
- `-9 % 4 = 3`：余数符号跟除数（正），由恒等式 `-9 == (-3) * 4 + 3` 验证；
- `int(-9 / 4) = -2`：`int()` 朝零截断，`-2.25` 朝零是 `-2`。

三者不同是因为"向下取整"与"朝零截断"在负数上是两个方向。正数时 `-9` 换成 `9`，三者分别是 `2`、`1`、`2`——`//` 与 `int()` 就一样了。

**Q2.** 下面这段判断为什么会出错？给出两种改法。

```python
x = 0.1 + 0.2
if x == 0.3:
    print("相等")
else:
    print("不等")
```

**参考答案：** 因为 `0.1 + 0.2` 的实际值是 `0.30000000000000004`，与 `0.3` 不相等（实测 `==` 为 `False`），所以永远走 `else`。

两种改法：

```python
import math
if math.isclose(x, 0.3):
    print("够近，算相等")
```

```python
if abs(x - 0.3) < 1e-9:
    print("差值小于容差，算相等")
```

如果这个量本身就该精确（比如钱），那正确做法不是改比较方式，而是**换类型**：用整数分。

**Q3.** 用整数分重写：一件商品 19.99 元，买 3 件，输出总价（元）。

**参考答案：** 全程用整数分：

```python
unit_cents = 1999
count = 3
total_cents = unit_cents * count
print("总价", total_cents // 100, "元", total_cents % 100, "分")
```

结果是 `5997` 分，即 `59` 元 `97` 分。全程整数运算，没有误差。

如果只想要"元"的数字，`total_cents / 100` 得到 `59.97`；注意这是 `float`，仅用于显示可以，别拿它继续做精确累加。

**Q4.** `round(2.5)` 与 `round(3.5)` 分别是多少？为什么？如果业务上确实要"四舍五入"，该怎么写？

**参考答案：** `round(2.5) = 2`、`round(3.5) = 4`。因为 `round` 用银行家舍入：恰好 `.5` 时往最近的偶数取整，2 是偶数、4 是偶数。

要严格"四舍五入"（.5 一律进位），用 `decimal`：

```python
from decimal import Decimal, ROUND_HALF_UP
print(Decimal("2.5").quantize(Decimal("1"), rounding=ROUND_HALF_UP))  # 3
```

或者自己写整数逻辑：`int(x + 0.5)` 对正数成立，但负数与浮点边界上仍要小心——所以金额场景还是回到整数分。

**Q5.** 下面四个表达式分别是什么类型？值是多少？

```python
a = 4 / 2
b = 2 ** 10
c = 2 ** -1
d = 1e3
```

**参考答案：** 逐个看类型与值：

- `a`：`float`，值 `2.0`（`/` 永远给浮点）；
- `b`：`int`，值 `1024`；
- `c`：`float`，值 `0.5`（负指数得到小数）；
- `d`：`float`，值 `1000.0`（科学计数法写法产生浮点，即使看起来是整数）。

验证方式：`type(x).__name__`。这一题的用意是：**"看起来像整数"不代表它是 `int`**。

**Q6.** 一个人说："Python 的 `%` 和 C 一样，`-7 % 2` 应该是 `-1`。" 指出错在哪里，并用恒等式验证你的答案。

**参考答案：** 错在把 C 的规则套到 Python 上。C 的余数符号跟被除数，`-7 % 2` 得 `-1`；Python 的余数符号跟**除数**，`-7 % 2` 得 `1`（实测）。

用恒等式验证：`a == (a // b) * b + (a % b)`，即 `-7 == (-4) * 2 + 1`，两边都是 `-7`，成立。

顺带修正说法：两侧语言在负数取余上不同，跨语言移植代码时这类差异最容易埋雷，凡是涉及负数的整除与取余，都要用具体数字验算一遍。
