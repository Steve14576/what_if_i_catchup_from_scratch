## 0. 场景：三段几乎一样的代码

你在三个地方写了几乎相同的逻辑：读入、判断、打印。改一个规则时，你要改三处，还漏了一处。这就是"需要函数"的信号。

函数解决三件事：**给一段逻辑起名字**（读代码的人知道它在干什么）、**把变化的部分变成参数**（同一段逻辑处理不同数据）、**把结果交回去**（而不是直接打印，让调用方决定怎么用）。

## 1. `def` 定义了什么

### 1.1 一个可调用的对象

```python
def add(a, b):
    """返回两个数的和。"""
    return a + b
```

实测：

```text
  add(1, 2) = 3
  add.__name__ = 'add'
  add.__doc__ = '返回两个数的和。'
```

三件事：

- `def` 把函数体包起来，并把这个"函数对象"绑到名字 `add` 上；
- `__name__` 是函数名，`__doc__` 是那行文档字符串（第 09 讲说过注释进不了 `__doc__`，三引号进得去）；
- 函数是对象，所以能赋值给别的名字：

```text
  函数也是对象，可以赋值给别的名字：f(2, 5) = 7
```

`f = add` 之后 `f` 和 `add` 指向同一个函数对象。这条为第 16 讲"函数当参数传"打底。

### 1.2 没写 `return` 就等于返回 `None`

```text
  没写 return 的函数：no_return(3) = None
```

`no_return` 里算了 `x * 2`，但没有 `return`，所以调用结果是 `None`——那个算出来的值直接丢了。

这条和第 10 讲讲过的"脚本里光写表达式，结果会被丢掉"是同一件事的两个层面：

- 脚本层面：表达式的结果不显示；
- 函数层面：表达式的结果不返回。

一句话记住：想让调用方拿到什么，就必须 `return` 什么。

`return` 还有两个行为要记住：

- 一旦执行到 `return`，函数立刻结束，后面的语句不执行；
- `return` 不带值（或干脆不写）都返回 `None`。

### 1.3 一个函数只做一件事

判断标准很实用：**能不能用一句不含"并且"的话说清它做什么。** "读文件并清洗并统计并打印"是四件事，应该拆四个函数。拆开之后每个函数都能单独测试（第 25 讲），也能被别处复用。

## 2. 参数绑定

### 2.1 三种传参方式

```text
  greet('小明')            = '你好，小明'
  greet('小明', '早上好')   = '早上好，小明'
  greet(greeting='hi', name='Bob') = 'hi，Bob'
```

函数定义是 `greet(name, greeting="你好")`，三种调用方式：

- **位置参数**：按顺序对上参数名；
- **关键字参数**：写 `名字=值`，顺序可以打乱；
- **默认值**：没传就用定义时写的那个。

### 2.2 少传、多传都会立刻报错

```text
  greet() -> TypeError: greet() missing 1 required positional argument: 'name'
  greet('a','b','c') -> TypeError: greet() takes from 1 to 2 positional arguments but 3 were given
```

两句话都很有用：第一句告诉你缺哪个参数，第二句告诉你这个函数能收几个。这类错误发生在调用那一刻，不用等到函数体跑一半。

### 2.3 参数名是给调用方看的文档

`greet(greeting="hi", name="Bob")` 这种写法看起来啰嗦，但它让调用处自解释：读代码的人不必回头查函数定义，就知道每个值是什么。

所以参数名要认真起：`f(a, b)` 这种签名，调用方永远得翻定义。`f(source, target)` 就好得多。

## 3. 可变默认参数：最经典的一个坑

### 3.1 实测

```python
def bad_default(x, acc=[]):
    acc.append(x)
    return acc
```

```text
  bad_default(1) = [1]
  bad_default(2) = [1, 2]
  bad_default(3) = [1, 2, 3]
```

每次调用都没传 `acc`，按理说每次都该从空列表开始，结果却一直在累积。

### 3.2 为什么

因为**默认值只在 `def` 执行那一刻算一次**，之后所有调用共享同一个列表对象。`acc=[]` 不是"每次调用新建一个空列表"，而是"定义时建一个空列表，以后默认就用它"。

这和"参数默认值是表达式"这一点直接相关。看下一节的时间戳实验：

```text
  两次调用 stamp() 的返回值相同吗 = True
```

`def stamp(when=time.time())` 里的 `time.time()` 在定义时就算完了，之后每次调用拿到的都是同一个时间戳。想"每次调用重新算"，就不能把它写在默认值里。

### 3.3 正确写法

```python
def good_default(x, acc=None):
    if acc is None:
        acc = []
    acc.append(x)
    return acc
```

```text
  换成好写法 good_default(1) = [1]
  good_default(2) = [2]
```

用 `None` 当占位符，进函数后判断"没传就新建"。这是 Python 里处理可变默认值的标准做法。

为什么必须用 `is None` 而不是 `if not acc`？因为空列表也是假——那样传进来一个空列表就会被当成"没传"，用户的意图被覆盖。`is None` 只认 `None` 这一种情况（第 14 讲讲过的"判真假"与"判 None"的区别）。

## 4. 作用域：LEGB

### 4.1 四层查找

Python 找名字有固定顺序，缩写 **LEGB**：

| 层 | 名字 | 是什么 |
|---|---|---|
| L | Local | 当前函数内部的局部变量 |
| E | Enclosing | 外层嵌套函数的变量（第 16 讲闭包） |
| G | Global | 模块级变量 |
| B | Built-in | 内置名字（`print`、`len` 等） |

从 L 往外找，找到就停。

### 4.2 函数里一赋值，这名字在整个函数内就是局部的

```text
  全局 x = 5
    函数内 x = 10（局部）
  unbound_demo() -> UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
```

`unbound_demo` 里先 `print(x)` 再 `x = 99`。直觉上 `print` 时该拿到全局的 5，实际却报错。

原因是 Python 在**编译函数时**就扫了一遍：函数体里出现过对 `x` 的赋值，所以 `x` 被判为局部变量；到了 `print(x)` 那一刻，局部变量还没有值，于是报 `UnboundLocalError`。

这条规则看起来反直觉，但好处是：**读函数时不必担心某个名字会不会悄悄指向外部**。只要函数里给它赋过值，它就是本地的。

### 4.3 `global` 与"别用 global"

真要在函数里改全局变量，得显式声明：

```python
count = 0

def bump():
    global count
    count += 1
```

能跑，但不建议。理由很实在：`global` 让"这个函数改了什么"变得不可从签名看出来——调用一次 `bump()`，外面某个你没注意的变量变了，调试时极难定位。

替代方案：**需要改状态，就把它作为参数传进来、用返回值交回去**，或者用类把状态收在一起（第 20 讲）。如果确实要多个函数共享状态，用可变对象（列表/字典）当参数传，也比 `global` 清楚。

### 4.4 内置名字可以被覆盖

`print = 3` 是合法的，之后 `print("x")` 会报 `'int' object is not callable`。所以不要用 `print`、`list`、`sum` 这类内置名当变量名——第 09 讲列的命名规则之外，这是另一条容易犯的。

## 5. 传参语义：传的是对象引用

### 5.1 先说结论

Python 传参不是"值传递"也不是"引用传递"这种二分。准确说法是：**把实参对象本身交给形参这个新名字**——就是第 09 讲的标签模型，函数调用时多贴一张标签而已。

由此推出两条：

- 如果形参指向的是**可变对象**，函数里改内容，外面看得见；
- 如果函数里只是**重新绑定**形参（`xs = 别的`），外面不受影响。

### 5.2 三种结果实测

```text
  函数里 append：调用后 xs = [1, 2, 99]
  函数里重新绑定：调用后 ys = [1, 2]
  传数字进去改：调用后 n = 10
```

对应三个函数：

```python
def mutate_list(xs):      # 改内容：外面跟着变
    xs.append(99)

def rebind_list(xs):      # 换标签：外面不变
    xs = xs + [99]

def try_change_number(v): # 数字不可变，"改"其实是新建
    v = v + 1
```

### 5.3 实践规则

| 你想做的事 | 写法 | 调用方会看到 |
|---|---|---|
| 就地修改传进来的容器 | `xs.append(x)` / `xs[k] = v` | 原对象变了 |
| 返回新结果、不改实参 | 新建一个容器再返回 | 原对象不变 |
| 传不可变值 | 必须用返回值 | 原值不变 |

一条纪律：**函数的文档字符串里要写清"会不会改实参"**。这比任何命名约定都直接。比如"返回排序后的新列表，不修改参数"——调用方立刻就知道能不能复用原列表。

## 6. `*args`、`**kwargs` 与仅关键字参数

### 6.1 `*args`：收多余的位置参数

```text
  describe(1, 2)                = args=(1, 2)  kwargs={}
  describe(1, k=2)              = args=(1,)  kwargs={'k': 2}
```

定义 `def describe(*args, **kwargs)` 之后：

- `*args` 把多余的位置参数收成一个**元组**；
- `**kwargs` 把多余的关键字参数收成一个**字典**。

名字 `args` / `kwargs` 只是习惯，`*things` / `**options` 一样能跑。决定行为的是星号，不是名字。

### 6.2 调用时反过来：解包传参

```text
  describe(*[1, 2], **{'k': 3}) = args=(1, 2)  kwargs={'k': 3}
```

调用时用 `*序列` 把列表拆成一个个位置参数，用 `**字典` 拆成关键字参数。常见用途：把一份配置字典直接传给函数，或者把参数原样转交给下一层函数（第 16 讲装饰器会用到）。

### 6.3 仅关键字参数：星号之后必须写名字

```python
def kw_only(a, *, b):
    return a + b
```

```text
  kw_only(1, b=2) = 3
  kw_only(1, 2) -> TypeError: kw_only() takes 1 positional argument but 2 were given
```

星号后面的参数只能按关键字传。好处是调用处必须写出 `b=...`，读代码的人一眼看出这个值是什么；同时以后加参数也不会影响已有调用。

### 6.4 参数顺序规则

一条固定的顺序，记住就不会写错：

```text
位置参数 → 默认参数 → *args → 仅关键字参数 → **kwargs
```

例如：

```python
def f(a, b=2, *args, c, d=4, **kwargs):
    ...
```

实际的函数签名很少这么复杂。日常遇到最多的是三种：普通参数、带默认值、`*args`/`**kwargs`（通常出现在包装函数里）。

## 7. 卫语句与拆函数

第 14 讲提过"把异常情况挡在前面"，函数里是它最自然的用武之地：

```text
    average([90, 80]) = 85.0
    average([]) = None
```

```python
def average(nums):
    if not nums:
        return None
    return sum(nums) / len(nums)
```

没有卫语句的话，空列表会在 `sum(nums) / len(nums)` 处除零报错。加了这一句，调用方拿到 `None`，可以自己决定怎么处理（提示、跳过、给默认分）。

空值返回 `None` 还是抛异常？两条都常见：

- **返回 `None`**：适合"没有结果是正常情况"，调用方会主动检查；
- **抛异常**：适合"没有结果说明调用方用错了"，让它早点暴露（第 18 讲）。

选哪个取决于语义，但**必须在文档字符串里写明**，否则调用方只能靠试。

## 8. 这一讲留下的东西

- `def` 定义一个可调用对象；不写 `return` 就返回 `None`；函数本身是对象，能赋值、能传参。
- 参数绑定：位置按序、关键字按名、默认值兜底；少传多传都在调用时立刻报 `TypeError`。
- 默认值只在定义时求值一次；可变默认参数会跨调用共享，用 `None` 占位解决。
- 作用域 LEGB；函数里一赋值，这名字在整个函数内就是局部；`UnboundLocalError` 由此而来。
- 传参传的是对象引用：改可变对象的内容会影响外部，重新绑定不会。
- `*args` 收成元组、`**kwargs` 收成字典；调用时 `*` / `**` 反向解包；星号后的参数只能按关键字传。

下一讲把函数当值来用：把函数传给 `sorted` 当排序规则、用 `lambda` 写短函数、用闭包保存状态、用装饰器给函数套一层、以及"生成器只能遍历一次"到底是怎么回事。

## 小结

- `add.__name__ = 'add'`、`add.__doc__` 是那行文档字符串；没写 `return` 的 `no_return(3)` 返回 `None`。
- `greet()` 抛 `missing 1 required positional argument`；`greet('a','b','c')` 抛 `takes from 1 to 2 positional arguments but 3 were given`。
- 可变默认参数实测累积：`bad_default(1)=[1]`、`(2)=[1,2]`、`(3)=[1,2,3]`；`None` 写法每次独立。
- 默认值在定义时求值：`stamp()` 两次调用返回值相同（实测 `True`）。
- `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`。
- 传参：`append` 后外部得 `[1, 2, 99]`；重新绑定后外部仍 `[1, 2]`；数字改不动。
- `describe(1, 2)` 得 `args=(1, 2) kwargs={}`；`describe(1, k=2)` 得 `args=(1,) kwargs={'k': 2}`；`*[1,2], **{'k':3}` 解包传参。
- 仅关键字参数 `a, *, b`：`kw_only(1, 2)` 抛 `takes 1 positional argument but 2 were given`。

## 作业

**Q1.** 下面函数每次调用都返回同一个列表，为什么？给出两种修改方式。

```python
def collect(x, bucket=[]):
    bucket.append(x)
    return bucket

print(collect(1))
print(collect(2))
```

**参考答案：** 输出 `[1]` 和 `[1, 2]`。因为默认值 `[]` 在 `def` 执行时就创建了一次，之后每次调用都用同一个列表，`append` 一直在往它里面加。

修法一：用 `None` 占位，进函数后新建。

```python
def collect(x, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(x)
    return bucket
```

修法二：让调用方负责传入容器。

```python
def collect(x, bucket):
    bucket.append(x)
    return bucket
```

修法二更"纯"，把"容器从哪来"的决定交给调用方；修法一保留"不传就能用"的便利，代价是多三行。

**Q2.** 下面代码报什么错？为什么？

```python
count = 0

def add_one():
    count = count + 1
    return count

add_one()
```

**参考答案：** 抛 `UnboundLocalError: cannot access local variable 'count' where it is not associated with a value`。

原因：函数体里对 `count` 有赋值，所以 `count` 在整个函数内被判为局部变量；执行 `count + 1` 时局部变量还没有值，于是报错。它不会去读全局那个 `count`。

修法二选一：把 `count` 作为参数传进来、用返回值交回去（推荐）；或者显式 `global count`（不推荐，理由见正文 4.3）。

**Q3.** 下面的函数调用后，`xs` 会变成什么？为什么？

```python
def clear(xs):
    xs = []
    return xs

data = [1, 2, 3]
clear(data)
print(data)
```

**参考答案：** 打印 `[1, 2, 3]`，不变。

函数里的 `xs = []` 是**重新绑定**：把形参 `xs` 从原来的列表上撕下来、贴到一个新列表上。外面 `data` 还贴着原来那个列表，所以不受影响。

对比：如果写 `xs.clear()`，那是**改内容**，`data` 会变成空列表。这两个动作的区别就是第 12 讲"别名 vs 重新绑定"在函数里的重演。

**Q4.** 写一个函数 `stats(nums)`，返回最小值、最大值、平均值三个值；要求空列表时返回 `None`。并说明调用方怎么接这三个返回值。

**参考答案：** 卫语句 + 元组返回：

```python
def stats(nums):
    if not nums:
        return None
    return min(nums), max(nums), sum(nums) / len(nums)

result = stats([3, 1, 7])
if result is None:
    print("没有数据")
else:
    low, high, avg = result
    print(low, high, avg)
```

`return min(...), max(...), ...` 用逗号分隔，实际返回的是一个元组（第 12 讲）。调用方可以用三个名字解包，也可以先接住整个元组再判断是不是 `None`。

卫语句 `if not nums: return None` 避免了空列表上的 `min()` 报错与除零。

**Q5.** 下面两个签名，哪个更好？为什么？

```python
def send(msg, to, urgent=False, copy=[]):
    ...

def send(msg, to, *, urgent=False, copy=None):
    ...
```

**参考答案：** 第二个更好，两个改动各解决一个问题：

- `*` 让 `urgent` / `copy` 只能按关键字传，调用处必须写 `copy=...`，读代码的人不用猜 `True` 是给谁的；
- `copy=None` 换掉了可变默认值 `[]`，避免"默认列表跨调用累积"的坑（本讲第 3 节）。

代价是调用方多打几个字，换来的是"调用处自解释 + 不会踩坑"。

**Q6.** 一个函数签名是 `def report(rows, *, title, decimals=2, **extra)`。解释每个部分的含义，并写一个合法调用与一个非法调用。

**参考答案：** 逐个部分看：

- `rows`：普通位置参数，必须传；
- `*` 之后的 `title`：仅关键字参数，必须写成 `title=...`；
- `decimals=2`：仅关键字参数，有默认值，可以不传；
- `**extra`：收集其余所有关键字参数成字典，可以为空。

合法调用：

```python
report(data, title="月度报告", decimals=1, author="me")
```

非法调用（`title` 用了位置参数）：

```python
report(data, "月度报告")     # TypeError: report() takes 1 positional argument but 2 were given
```

这个签名的用意是：`rows` 是"数据主体"，放第一位；其余都是"配置"，强迫调用方写名字，避免 `report(data, "标题", 2, True)` 这种没人看得懂的调用。
