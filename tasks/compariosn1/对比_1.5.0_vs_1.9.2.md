# WIICUFS 1.5.0 与 1.9.2 对比

> 取证方式：`git show d2d066b:wiicufs/SKILL.md` 与 `git show d2d066b:wiicufs/reference.md`（front matter 为 `version: 1.5.0`）。
> 当前版本取工作区 `wiicufs--tutorialgen/`（1.9.2）。
> 本目录文件：`1.5.0/`–`1.7.4/`（各自 `SKILL.md` + `reference.md`；另收 `1.7.4-late/`）；`SKILL_1.5.0.md`、`reference_1.5.0.md`、`SKILL_1.9.2.md`、`reference_1.9.2.md`。

## 0. 一条时间线（先纠正一个事实）

- **1.5.0**：`d2d066b`。SKILL 约 32 KB，18 条原则；PLAN 里**没有逐讲五槽施工图**。
- **1.6.0 / 1.7.x**：1.6.0（`18366d2`）第一次把“三”改成“骨架大纲（正文第一依据）”；1.7.0（`6cb9e62`）改名“逐讲施工图”并要求“细到能照写”；1.7.2（`ba07ff1`）加“开课每讲都写”“正文不新增结构”；1.7.4（`33db29e`）加“它自己是完整的”。
- **Python PLAN 的引入提交**：`02fb736`。在这个提交上，SKILL 的版本是 **1.9.0**，不是 1.5.0。
- **1.9.2**：当前工作区。SKILL 56 KB，20 条原则；PLAN 里有“三、逐讲施工图”，默认五问/五槽。

所以 Python 的五槽 PLAN 不是 1.5.0 的产物，是 1.9.0 的产物。1.5.0 是更早的基线，也是材料力学那一版的形态。

## 1. 体量

| | 1.5.0 | 1.9.2 |
|---|---|---|
| SKILL | 约 32 KB | 56 KB |
| reference | 约 16 KB | 32 KB |
| 顶层节 | 6（原则 / 流程 / 数值 / 文件 / 失败 / 格式） | 7（原则 / 格式契约 / 流程 / 数值 / 闸门 / 失败 / 并行） |
| 原则数 | 18 | 20 |

体量不是罪证，但 1.9.2 的增量主要落在“格式契约”和“闸门”，不是落在原则上。

## 2. PLAN 的形状（关键差异）

### 1.5.0 的 PLAN 模板

```markdown
## 一、目标与读者画像
## 二、骨架大纲
| # | 讲 | 任务/问题/案例（按讲次选择） | 回答什么 | 状态 |
## 三、地毯式覆盖清单
## 四、每讲认知思维链条（4–8 个卡点，6–14 行/讲）
## 五、两遍走状态
```

逐讲只有**骨架大纲的一行**：任务 / 回答什么 / 状态。没有“每条五问”的施工图。

### 1.9.2 的 PLAN 模板

```markdown
## 一、目标，读者画像与要求
## 二、地毯式覆盖清单
## 三、逐讲施工图（覆盖台账；五问可选）
## 四、每讲认知思维链条（巩固 6–14 + 自由 4–9）
## 五、两遍走状态
```

“三”是后来加的。1.9.2 已把它降为“覆盖台账、五问可选”，但 Python 的 PLAN 是在 1.9.0 的旧口径下写的：三 = 逐讲五槽、每讲 60 行左右。

## 3. 正文是怎么写出来的

### 1.5.0 的第 1 遍

> “在 PLAN 中确认本讲范围、六问决定和认知链；选择任务、现象或问题作为合适起点。”

> “预写连续正文：先让知识按因果顺序站住，不预填脉络图、下一站、态度表、自测等模块。”

**正文是第一稿，PLAN 只提供范围、六问决定和认知链。**

### 1.9.2 的第 1 遍（已修）

> “合上三，按读者顺序写正文……正文的标题、顺序、分节由讲述需要定，不必与三的条目一一对应。”

但 1.7.x–1.9.0 的旧流程是“以三为第一依据、正文只允许比三多”。Python 的 PLAN/正文是在旧流程下写的，所以 01/02 仍然带着“照三扩写”的痕迹。

## 4. 认知链

- 1.5.0：4–8 个卡点，6–14 行/讲；并明确写了一句：
  > “思维链条是写作前的预测和写完后的对账工具，**不是要求正文按读者脑中每个跳跃逐问展开的脚本**。”
- 1.9.2：巩固 6–14 + 自由 4–9；原则 14 仍说“不是大纲”，但五槽三和闸门增加了“按三填”的压力。

1.5.0 的这句防线，在后面的版本里被五槽和三的体量冲淡了。

## 5. 闸门与格式契约

- 1.5.0：没有 A–E 闸门，没有独立的“格式契约”节；回查 8 条，不含“节标题/顺序一致”。
- 1.9.2：新增格式契约（PLAN / 正文 / 文件 / AA / 模块）+ 闸门 A–E；回查已改为“只核覆盖与深度，不核标题/顺序”。

闸门不是坏东西，但它把“怎么写”的一部分变成了“怎么验”，而验的对象长期是 PLAN，不是正文。

## 6. 自相矛盾

1.5.0 的失败形态里已经写着：

> “让文件卫生、流程正义或作者表演盖过知识本身。”

1.5.0 的原则 17 也叫“台账陷阱”。

后来 1.7.x 引入的五槽施工图、1.9.x 的闸门/格式契约，正好是“流程正义/台账”的形态。**不是原则变坏，是流程层过度生长，长成了它自己警告的东西。**

## 7. 结论

**1.5.0 更健康的地方：**

- PLAN 薄：骨架大纲一行/讲 + 覆盖清单 + 认知链；
- 正文直接写：先让知识按因果顺序站住；
- 没有五槽、没有 1:1、没有闸门；
- 认知链明确“不替正文写剧本”。

**1.9.2 值得保留的增益：**

- 原则 19（例题题头就地完整、答案不跳步）；
- 原则 20（具体化与可视化审计）；
- 认知链的“巩固 / 自由”拆分；
- 教材骨架警报（E）——对傅里叶、拉普拉斯这类主题有用；
- 术语清单（C）和空白页测试（D）作为交付前抽查。

**回归的根源：**

- 五槽“三”被当成正文第一依据；
- “条名=节标题”“正文只允许比三多”“回查节标题/顺序一致”三条硬映射；
- 格式契约/闸门把流程做成了第二产品，PLAN 越完整越像认真。

**建议的工作顺序（恢复 1.5.0 的骨架，保留 1.9.2 的原则）：**

1. 二：骨架大纲，一行/讲（任务 / 回答什么 / 状态）。
2. 三：覆盖清单（关键词 + 深度 + 不写理由），不五槽、不预写 18 讲。
3. 四：只详写下一讲的 4–8 个卡点。
4. 正文：按卡点和材料直接写；写时合上三。
5. 写后：打开三做落点表（每条落在正文/作业/AA/后讲），只核覆盖，不核标题/顺序。
6. 闸门：交付前抽查 A/B/D，C/E 按需；不作为写作驱动。

一句话：**1.5.0 的 PLAN 是便签，1.9.2 的 PLAN 一度成了第二份讲义。** 该恢复的是便签，不是把便签做得更漂亮。

## 9. 逐版差异明细（1.5.0→1.5.1→1.5.2→1.5.3→1.9.2）

### 9.1 1.5.0 → 1.5.1（SKILL 8+/4-；reference 1+/1-）

- 版本号 1.5.0→1.5.1。
- 原则 3 标题：“即定义”→“即良好定义”。
- 把“what if 微扰”从原则 3 的第一段拆出来单独成段；中间插入 Fick 定律反例：“谁和谁扩散都没说……一定要留意，对谁用，有没有前提。”
- 熵的段落末尾补：“最讨厌所谓的‘点到为止’。”
- reference 只改标题版本号。

判断：纯质量修补，无结构变化。

### 9.2 1.5.1 → 1.5.2（SKILL 12+/3-；reference 8+/6-）

- 原则 3：补“有没有业内默认但是新手不知道的隐含前提默认假设”；补“公式定理的适用范围；超出范围怎么办（推广/失效/换工具）”。
- 原则 4：补“工科切忌不讲方法论”（莫尔圆：讲完没讲怎么用，读者不敢 SOP）。
- 原则 6：补“边界条件尽可能切干净……不要让读者不敢学进去”。
- PLAN 模板后：补“PLAN 可以一次写出，也可以逐步推进；默认偏向写全不能写漏”；“三、覆盖清单当场复核至少 1 次”。
- reference：
  - “生活化”→“所谓的生活化”；
  - 万能词问题补“信息熵极其可怜，观感恐怖谷”；
  - 补“定理全部、完整给出后，为了便于理解，才追加式地写……”；
  - 补“非任务图不代表拒绝小的例题场景”；
  - “什么不是 WIICUFS”加“不是空洞和无具体实现的，自我承诺，自我指述”。
  - **一个坏句子**：“就像筛掉了...的筛子”插在傅里叶正交性的正面示例末尾。它没有映射、没有结果、没有边界，违反原则 1；从 1.5.2 一直留到 1.9.2，没人发现。

判断：仍是质量修补；但 reference 开始出现“无人校验的示例层腐烂”。

### 9.3 1.5.2 → 1.5.3（SKILL 26+/4-；reference 96+/3-）

- 18 条原则 → 20 条：
  - 新增原则 19（例题题头就地完整、答案不跳步）；
  - 新增原则 20（具体化与可视化审计）。
- 第 1 遍第 5 步扩展：检查题头（搜索 `同上|见例|同例|§.*例`）、答案可复现、几何概念有图、抽象公式有具体算例。
- 失败形态加 3 条：例题用“同上/见例 X”；答案跳步；符号公式没有具体函数落点。
- reference：
  - 回查清单加 8/9（题头、答案可复现）；
  - 新增 §18 例题题头与答案步长、§19 具体化与可视化审计；
  - 环境坑加 4 行（mathtext 不支持 \le/\ge/\sqrt2、反斜杠二次解码、图号顺序、替换重复插入）。

判断：1.5.x 的增量全是“读者质量底线”（原则、例题、图、环境坑）；**仍无五槽/施工图/闸门**。1.5.3 是“薄 PLAN + 直接写正文”的高水位。

### 9.4 1.5.3 → 1.9.2（SKILL +278/-93；reference +226/-44）

- 体量：SKILL 36.5→56.4 KB；reference 19.9→31.9 KB。
- 结构新增：
  - “二、格式契约”：PLAN 五块 + 五问“三”模板 + 正文格式 + 文件树 + AA + 条件化模块；
  - “五、交付闸门”：A–E；
  - 原则 13/14 重写（PLAN 五块、认知链巩固/自由拆分）；
  - 第 1 遍从“预写连续正文”改为“以三为第一依据 / 正文只许比三多”（1.7.x–1.9.0），1.9.1 才改回“合上三”；
  - 回查从“覆盖”改为“节标题/顺序一致”（1.7.x–1.9.0），1.9.1 才改回“只核覆盖”。
- 关键断点：1.5.3 的 PLAN 是二骨架大纲、三覆盖清单；1.9.0 的 PLAN 是二覆盖、三逐讲五槽。五槽“三”在 1.6/1.7 出现，不在 1.5.x。
- Python PLAN 的引入提交 02fb736 对应 1.9.0，所以 1650 行/五槽是 1.9.0 的直接产物。

### 9.5 三个结论

1. **1.5.x 越改越健康，1.9.x 越改越重。** 1.5.x 的增量是原则/例子/环境坑；1.9.x 的增量是格式契约/闸门/五槽三。
2. **腐烂不是渐变，是断点。** 1.5.0→1.5.3 只涨 4.6 KB；1.5.3→1.9.2 涨 20 KB（SKILL）。断点处新增的正是“三=正文第一依据”的流程。
3. **示例层无人校验。** “就像筛掉了...的筛子”从 1.5.2 活到 1.9.2，说明 reference 的示例也会腐烂；闸门只查 PLAN，不查示例。

### 9.6 如果要恢复

- 以 **1.5.3** 为基线（20 原则、薄 PLAN、直接写正文），而不是 1.5.0（缺 19/20）。
- 保留 1.9.2 的：认知链巩固/自由拆分、教材骨架警报、术语/空白页抽查、1.9.1 的“三=覆盖台账”。
- 去掉/降级：五槽三作为主流程、1:1 映射、闸门作为写作驱动。
- Python：把 1650 行 PLAN 压回“骨架表 + 覆盖清单 + 下一讲认知链”；01/02 暂不动，03 试点。

## 10. 1.6/1.7 系：断点与硬化

### 10.1 版本与体量

| 版本 | 提交 | SKILL 字节 | reference 字节 | 三的定位 |
|---|---|---|---|---|
| 1.5.3 | 2b444d1 | 36538 | 19920 | 二是骨架大纲（一行/讲），三是覆盖清单 |
| 1.6.0 | 18366d2 | 40077 | 23289 | 二是覆盖，三是**骨架大纲（写正文的第一依据）**；条名=正文节标题 |
| 1.7.0 | 6cb9e62 | 40764 | 23625 | 改名**逐讲施工图**；“写正文前就要细到能照写” |
| 1.7.1 | 4f3e039 | 40929 | 24556 | 同 1.7.0（小修） |
| 1.7.2 | ba07ff1 | 41958 | 24566 | “开课时每讲都写、只怕漏不怕写”；“正文不新增结构” |
| 1.7.4 | 33db29e | 44008 | 25740 | “它自己是完整的”；其余同 1.7.2 |
| 1.7.4-late | 56a75cf | 43975 | 25740 | 仅 2 行小改，reference 未变 |

### 10.2 1.6.0 才是断点

1.5.3→1.6.0（SKILL 71+/47-；reference 78+/32-）做了四件事：

1. **PLAN 二/三互换**：二是覆盖清单，三是骨架大纲。
2. **三被定为“写正文的第一依据”**。
3. **条名=正文节标题**：“条名就是正文的节标题；正文改节标题时，同步改这里。”
4. **正文照骨架写，回查 1:1**：
   - 第 1 遍：“读本讲骨架大纲（第一依据）……照骨架顺序预写连续正文。遇到骨架没覆盖但正文必须讲的——先回改骨架，再写。”
   - 收尾：“把本讲正文的实际节标题与顺序同步回‘三、骨架大纲’。”
   - 第 2 遍：“骨架 vs 正文：节标题、顺序、每点‘讲到什么’是否一致？”

同时，认知链从“4–8 个卡点”改为“6–10 个，顺着骨架大纲预测，标骨架第几条；不规定正文顺序，也不是正文的第一依据”。**读者的疑问被降为骨架的核对项，骨架升为正文的第一依据。** 这就是断点。

### 10.3 1.7.0 把骨架硬化成施工图

1.6.0→1.7.0（29+/23-；31+/23-）：

- 三改名“逐讲施工图”。
- 定义补一句：“写正文的第一依据；**不是‘只留骨头’，写正文前就要细到能照写**。”
- 第 1 遍第 1 步从“读骨架大纲”改为“读本讲施工图（第一依据）”。

1.7.0 已经足以让正文变成“照图施工”；但它还把认知链写成“不是正文的第一依据”，说明当时仍知道要留一道防线。

### 10.4 1.7.2/1.7.4 把“正文不新增结构”写死

- 1.7.2（35+/21-）在三的定义里加“**开课时每讲都写、只怕漏不怕写**”；第 1 遍第 5 步改为“**以‘三’为第一依据开写正文：正文不新增结构；写中发现缺口，回改‘三’再写**”。
- 1.7.4（31+/25-）在定义里再加“**它自己是完整的**”；其余同 1.7.2。
- 1.7.4-late 只有 2 行小改，reference 未变。

到这里，“三=正文的唯一结构、正文不得新增结构”已经完全定型。1.9.0 只是继承这条线；Python 的 1650 行 PLAN 就是这条线的终点产物。

### 10.5 结论

1. **1.5.3 是最后干净版**：20 原则、薄 PLAN、正文直接写。
2. **1.6.0 是断点**：三变成正文第一依据、条名=节标题、回查 1:1。
3. **1.7.0 是硬化**：改名施工图，要求“细到能照写”。
4. **1.7.2/1.7.4 是锁死**：开课每讲都写、正文不新增结构、三自己是完整的。
5. **1.9.0 继承**；1.9.1/1.9.2 的“三=台账/合上三”是事后回退，但 Python 的 PLAN/正文仍是 1.9.0 的旧产物。

要恢复，基线应是 **1.5.3**（不是 1.5.0，也不是 1.7.x）：保留 20 原则和例题/具体化，删掉 1.6.0 引入的“三=正文第一依据/条名=节标题/回查 1:1”，以及 1.7.x 的“细到能照写/正文不新增结构”。
