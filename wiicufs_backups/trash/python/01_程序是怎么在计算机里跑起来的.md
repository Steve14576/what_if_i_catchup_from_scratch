# 第 01 讲 程序是怎么在计算机里跑起来的

> 本讲是开头三讲（计算机素养）的第一讲，定位是**见面熟**：读完这一讲，你亲手造过一个文件、让 Python 读过它（Python 是一个能读 `.py` 文件、照着里面的文字干活的程序，第 1 节会给完整说法）；以后再遇到"打不开、跑不了、显示乱"，你知道大概该往哪儿看。任何一条命令（你在黑窗口里敲的那行字）记不住都不要紧，后面用到时会整条重新给出。机器上没装 Python 也能读——你会看到一句"不是内部或外部命令"，那本身就是要认识的现象，第 02 讲再装。读完可以直接跳到第 04 讲写代码，卡住了再回来。

## 这一讲解决什么

你大概遇到过下面两件事里的一件。

第一件：同学发给你一个文件，双击它，什么都没发生。你以为文件坏了，或者以为自己缺什么软件。

第二件：你问他"这个怎么运行"，他回你一句："打开命令行，cd 到那个目录，然后 python 跑一下。"每个字你都认识，连起来不知道在说什么。

这句话里的 `cd`、目录、`python` 分别是什么，第 2 节会逐个拆开。现在只需要抓住他的意思：**先站到那个文件所在的文件夹里，再让 Python 去读它。**

这一讲就是把这两件事讲清楚：那个文件到底是什么、他那句话在说什么、你按他说的敲下去之后电脑里发生了什么。最后你会得到一张表：看到什么现象，大概坏在哪一步。

## 1. 同学发你的文件，为什么双击没反应

先从你天天在做的事说起。双击一份 Word 文档（文件名以 `.docx` 结尾），Word 打开了；双击一张照片（`.jpg`），看图软件打开了；双击一首歌（`.mp3`），播放器开始放。

是谁替你挑的程序？是 Windows。它看文件名最后那个点后面的部分——`.docx`、`.jpg`、`.mp3`——拿这个尾巴去查"该用哪个程序打开"，查到就把文件交给那个程序。这个尾巴叫**扩展名**（extension）。扩展名不是文件内容的一部分，它只是一个标签，告诉系统"该叫谁来读"。

同学发你的那个文件，尾巴是 `.py`。`.py` 的意思是"这是写给 Python 的文字"。这里先记住一句话：**Python 是一个程序**，它没有窗口界面，它的工作是读出 `.py` 文件里的文字，照着那些文字去干活。这门课要学的语言，就是写这种文件的写法。

那么问题来了：Windows 默认没给 `.py` 安排"双击时用哪个程序打开"，所以双击它什么都不会发生。**文件没有坏，也不是你缺软件**，只是没有人被叫来读它。

还有两件马上要用到的事：

- `.py` 文件里装的是**纯文本**——和你在记事本里打的字是同一种东西，用记事本就能打开看。它不是 Word 文档，也不是图片。
- Windows 默认**把扩展名藏起来**。所以你看到的可能只是 `hello`，不是 `hello.py`。更麻烦的是：一个实际叫 `hello.py.txt` 的文件，在藏起扩展名之后也会显示成 `hello.py`。这个坑第 3 节会正面撞上。

要让这个文件真的跑起来，需要两步：打开一个能敲命令的窗口，让 Python 去读它。先说那个窗口。

## 2. 那句"cd 到目录，再 python 跑一下"，在说什么

### 2.1 终端：那个黑窗口

同学让你打开的，叫**终端**（terminal），俗称黑窗口：一个黑底白字的窗口，里面有一行字在闪，等你敲东西。

怎么打开：按键盘上的 Windows 键，直接输入 `cmd`，回车；或者输入 `powershell`，回车。两个都能开，长得差不多。

窗口本身只是个壳，负责显示和接收你敲的字。真正读懂你敲的那行字、并照着去做的，是窗口里运行的另一个程序，叫 **shell**。Windows 上常见两种 shell：

- **cmd**：老的那一个，命令少，简单；
- **PowerShell**：新的那一个，功能多，语法也更现代。

所以"终端 / 命令提示符 / cmd / PowerShell"这几个词，日常经常被混着叫，说的其实是"一个黑窗口，加上里面那个 shell"。网上抄命令时偶尔会遇到"这条只在 PowerShell 里能用"，原因就在这里。本课程默认用 PowerShell；两者真有差别时，会当场说。

为什么非要用它，而不是右键、双击？因为用鼠标做一件事，实际上是一串动作：打开文件夹、找到文件、右键、选运行。做一次很直观，做十次就要点十遍。黑窗口允许你把这些动作写成一行字：可以重复、可以复制给别人、可以写进脚本让它自己跑。它不是高手专用，它是给"同一件事要做很多遍"的人用的。

### 2.2 cd：先站到文件所在的文件夹

`cd` 是 change directory 的缩写，意思是"切换当前目录"。**目录**就是文件夹；**当前目录**是黑窗口此刻站着的位置。

这句话很重要：你在黑窗口里敲一个文件名，如果没有把完整位置写全，它就从这个"当前目录"开始找。同学让你 `cd` 过去，就是为了让黑窗口先站到你那个文件所在的文件夹里，这样后面只写文件名就够。

"完整位置"和"只写文件名"的区别，第 5.3 节会展开。现在只要知道：**黑窗口站的位置，决定了它去哪儿找文件**。

### 2.3 python 文件名：叫醒 Python，把文件交给它

`python` 是那个程序的名字。完整写法是：

```text
python hello.py
```

意思是"启动 Python，把后面这个文件交给它读"。中间的空格是分隔符：空格前面是**命令**（要运行哪个程序），空格后面是**参数**（交给这个程序的东西）。

两件事合起来：先站对地方，再叫醒 Python 去读那个文件。下一节你自己做一遍。

## 3. 自己造一个能跑的文件：五步

### 3.1 第 1 步：打开记事本，输入一行字

按 Windows 键，输入"记事本"，回车。在空白页里原样输入这一行：

```python
print("你好")
```

这一行有三个部分：

- `print` 在英文里是"打印、显示"的意思。在 Python 里，它的作用是"把括号里的东西显示出来"。
- 括号 `()` 表示"这些是要交给 `print` 的东西"。
- 引号 `""` 表示"这里面是一段文字，原样显示，不要当成数学式子去算"。

完整的语法规则第 04 讲才讲，现在照着敲就行。只有一个地方必须注意：**括号和引号都要用英文半角**。如果你在中文输入法下打出 `print（"你好"）`（全角括号），Python 会报错。

### 3.2 第 2 步：另存为 hello.py

先在桌面建一个文件夹，名字叫 `py01`。然后在记事本里点"文件 → 另存为"，存到这个文件夹里，文件名填 `hello.py`。

这一步有两个地方会坑人：

- **保存类型**要选"所有文件"（显示为 `*.*`）。如果留着默认的"文本文档（`*.txt`）"，记事本会自动把名字补成 `hello.py.txt`。这个文件的扩展名是 `.txt`，不是 `.py`，Python 不会把它当代码。
- **编码**要选 UTF-8。这里先给一句定义：**编码是"把文字存成字节的规则"**。同一句"你好"，按不同规则存出来的字节不一样，读的时候也必须用同一条规则，否则就是乱码。UTF-8 是现在最通用的一条规则，新版记事本默认就是它。第 05 讲会把这件事讲透。

存好之后，打开 `py01` 文件夹，点窗口上方的"查看"，勾上"显示 → 文件扩展名"。现在你应该能清楚看到文件名是 `hello.py`，而不是 `hello` 或 `hello.py.txt`。这一步是在防第 1 节说的"藏扩展名"的坑。

### 3.3 第 3 步：在这个文件夹里打开黑窗口

不用背 `cd` 路径。直接打开 `py01` 文件夹的窗口，点一下顶部的地址栏（显示 `此电脑 > 桌面 > py01` 的那一栏），把里面的字删掉，输入 `cmd`，回车。黑窗口会直接在 `py01` 这个目录里打开。

想用 PowerShell 就输 `powershell`，两者都能用。

### 3.4 第 4 步：让 Python 读这个文件

在黑窗口里敲：

```text
python hello.py
```

按第 2.3 节拆过的结构：`python` 是命令，`hello.py` 是参数。

### 3.5 第 5 步：看结果

**情况一：成功。** 屏幕上出现：

```text
你好
```

你刚刚完整地"运行了一个程序"。往下读第 4 节，你会看到这中间其实走了七站。

**情况二：报"不是内部或外部命令"。** 屏幕上出现：

```text
'python' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

（PowerShell 里的说法不同："无法将 python 项识别为 cmdlet、函数、脚本文件或可运行程序的名称"。这里的 `cmdlet` 是 PowerShell 对"命令"的叫法，整句意思就是"没有叫 python 的命令"。）

这说明这台机器上没装 Python，或者装了但系统不知道它在哪。**这不是你写错了。** 第 02 讲会装；你可以先读完这一讲，装好再回来做一遍。

**情况三：报 can't open file。** 屏幕上出现：

```text
python: can't open file 'hello.py': [Errno 2] No such file or directory
```

这说明 Python 已经启动了，但它在"当前目录"里没找到 `hello.py`。原因通常是第 3 步开黑窗口开错了文件夹，或者文件名其实叫 `hello.py.txt`。

## 4. 刚才那五步，机器里走了七站

你敲了 `python hello.py`，屏幕上出现 `你好`。中间走了七站：

1. **存盘**。记事本把内容写进磁盘。你点"保存"那一刻，`hello.py` 才真的存在于磁盘上。
2. **命令**。你敲的字进入黑窗口；shell（cmd 或 PowerShell）把它拆成两部分：命令 `python`，参数 `hello.py`。
3. **启动**。shell 去一张目录清单里，按顺序找名为 `python.exe` 的程序。找到就启动它。`.exe` 是 Windows 上"可执行程序"的后缀，`python.exe` 就是 Python 这个程序的本体文件。这个正在运行的程序叫**进程**（process）。找不到，就是第 5.2 节那句"不是内部或外部命令"。
4. **读入**。`python.exe` 打开 `hello.py`，把里面的文字读进来（按某种编码），翻译成**字节码**（bytecode，Python 内部使用的一种中间指令）。它不是把译文交给别人去执行，而是自己翻译完、自己逐条执行。
5. **执行**。Python 逐条执行字节码。`print("你好")` 把"你好"转成一串字节，写到**标准输出**（standard output，操作系统提供的一个输出通道）。
6. **显示**。黑窗口收到这串字节，按自己的**码页**（code page，它认为这串字节该按哪条编码规则来解）解成字符，再用字体把字形画出来。
7. **你看到 `你好`。**

第 6 站的"码页"和第 2 步的"编码"是同一类东西：都是"文字和字节之间的换算规则"。区别只在：编码说的是文件，码页说的是这个窗口。

### 4.1 四个部件各管一段

先分清两样东西：**磁盘**（就是硬盘，长期存文件的地方，断电内容还在）和**内存**（程序运行时临时放数据的地方，断电就清空）。买电脑时看到的 8G / 16G，说的是内存；看到的 512G / 1T，说的是磁盘。CPU 是电脑里负责计算和判断的芯片。

| 部件 | 负责哪几步 | 断电之后 | 量级 |
|---|---|---|---|
| 磁盘 | 1（存文件）、3（存 Python 程序） | 内容还在 | 几百 GB |
| 内存 | 3、4、5（进程和它处理的数据都在这里） | 内容全没 | 8–32 GB |
| CPU（中央处理器） | 5（逐条执行指令） | —— | 每秒几十亿条指令 |
| 终端与屏幕 | 2、6 | —— | —— |

这张表能顺手回答几个常被问到的问题：

- **为什么"文件还在"和"程序在跑"是两回事**：文件只是磁盘上的字节；只有被叫醒、进了内存，才有一个进程在跑。
- **为什么 20 GB 的文件不能一次读进来**：内存只有 8–32 GB，装不下。第 13 讲会讲怎样一段一段地读。
- **为什么关掉窗口，程序就停了**：进程结束，内存回收。
- **为什么 `.py` 换台电脑通常能跑**：它只是文本，只要有 Python 就能读；真正执行的指令在 Python 里，不在你的文件里。
- **为什么 Python 不生成 `.exe`**：干活的是 Python 这个程序，你的文件只是它读的原料。要发给没装 Python 的人，得用打包工具（把 Python 和你写的文件捆成一个程序的东西）把 Python 一起塞进去，那是另一个话题。

### 4.2 把现象和七站对上

| 坏在第几步 | 你会看到什么 | 先查什么 |
|---|---|---|
| 1 存盘 | 输出是旧的 | 有没有点保存；文件名是不是 `.py.txt` |
| 2 命令 | 报"无法将 ... 项识别为 cmdlet"；或跑成了别的程序 | 命令拼写 |
| 3 启动 | 同上，但命令拼写没问题 | Python 是否安装、系统能不能找到它（02 讲） |
| 4 读入 | `can't open file`；`SyntaxError`；`Non-UTF-8`；`UnicodeDecodeError` | 当前目录、文件名、编码 |
| 5 执行 | 报错（屏幕上那一长串以 `Traceback` 开头的东西）；或死循环不结束 | 从最后一行往前读（11 讲） |
| 6 显示 | 乱码（`???`、`锟斤拷`）或方块 | 码页与编码，或字体 |

表里那些英文报错名（`SyntaxError`、`Non-UTF-8`、`Traceback`）现在不用记。它的用途是：将来屏幕上真的出现时，回来对一眼。

### 4.3 哪些现在要会，哪些只要认得

| 现在要会 | 现在只要认得名字 |
|---|---|
| 用记事本存出 `.py`；在文件所在文件夹打开黑窗口；敲 `python 文件名`；拿现象对表判断大概哪一站 | 字节码、标准输出、shell、进程、码页 |

"只要认得名字"的意思是：别人提起它，你知道大概指什么、大概在哪一站；不要求现在会用。

## 5. 七站里，哪几站最常坏

下面按"你看到什么"来分，不按站号排。每一段末尾标出它对应第几站。

### 5.1 改了没生效

记事本里改完内容，必须**保存**（或另存为）才会写回磁盘。不保存就切回黑窗口再跑一次，跑的还是磁盘上那一版。

这一站还有两个变种：

- 保存到了别处，跑的是旧目录里的同名文件；
- 文件名其实是 `hello.py.txt`，你以为在跑 `.py`，实际跑的是别的。

至于"是不是 Python 把旧内容缓存了"——不是。第 5.4 节会讲缓存到底是什么，以及为什么它不背这个锅。

### 5.2 命令找不到

`python hello.py` 被 shell 拆成命令加参数。所以命令拼错一个字母，它找的就是另一个程序：

```text
> pythn hello.py
pythn : 无法将"pythn"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
```

（`cmdlet` 是 PowerShell 对"命令"的叫法，这句话的意思就是"没有叫 `pythn` 的命令"。）

注意这句话里**没有任何 Python 的信息**——Python 根本没被叫醒。从现象上看，拼错命令和第 3 站的"没装 Python"长得一模一样，区别只在：这次是你打字打错了，那次是你打对了但系统里确实没有它。

第 3 站依赖的是一个叫 `PATH` 的东西。先给定义：**环境变量**是操作系统交给程序看的一组设置，每项是一个名字配一个值；`PATH` 是其中一项，它的值是一串目录。shell 收到 `python` 这个名字，就按顺序在 `PATH` 列出的目录里找 `python.exe`，找到第一个就用它。

```text
> where python
C:\Users\you\AppData\Local\Programs\Python\Python312\python.exe
> python -V
Python 3.12.13
```

（路径随安装位置不同。如果你的机器上 `python` 根本没进 `PATH`，`where python` 什么都不打印，`python -V` 会报"无法将 python 项识别"——那正是这一站出了问题。）

`where python` 列出几个，就说明你机器上装了几份。用哪个取决于 `PATH` 里的先后顺序，第 02 讲会讲透。

本课程的示例有时写成 `uv run python`。`uv` 是另一个工具，它自带一份 Python；`uv run python` 的意思是"用 uv 管的那份来跑"。它和 `python` 跑的是同一类东西，区别在 02 讲。你现在只需要知道：换了一份 Python，已经装好的第三方包就可能完全找不到，这是后面很多"明明装了却用不了"的根源。

黑窗口里最常用的四条命令：

| 想做什么 | PowerShell 写法 | 说明 |
|---|---|---|
| 看我在哪 | `pwd` | 打印当前目录 |
| 看这里有什么 | `dir` | 列出当前目录内容 |
| 进入某个目录 | `cd 路径` | 改当前目录；路径可以写全，也可以只写一段 |
| 跑脚本 | `python 文件名.py` | 前提是 Python 在 `PATH` 里 |

再加一条：程序跑飞了按 `Ctrl+C` 中止。

两个细节：Windows 自带的 PowerShell 5.1 里，命令之间用分号 `;` 分隔，不认 `&&`（PowerShell 7 才支持），这是很多人从网上抄命令失败的原因；命令名不区分大小写，路径区分。

### 5.3 找不到文件

你在黑窗口里敲 `python hello.py`，这个 `hello.py` 只写了文件名、没写完整位置，叫**相对路径**。它相对的不是文件所在的位置，而是黑窗口的**当前工作目录**（current working directory，cwd）。

与它相对的是**绝对路径**：从盘符写全，例如 `C:\Users\you\Desktop\py01\hello.py`。相对路径只写从当前目录出发的那一段。

第 3 步用地址栏打开黑窗口，就是为了让 cwd 正好是 `py01`。换个地方启动同一个脚本，相对路径就会指到别处。例如你把 `hello.py` 放在 `C:\Users\you\Desktop\py01`，却在 `C:\Users\you` 打开黑窗口：

```text
> cd C:\Users\you
> python hello.py
python: can't open file 'hello.py': [Errno 2] No such file or directory
> cd Desktop\py01
> python hello.py
你好
```

`cwd` 跟着你敲命令的位置变。所以脚本里写一个只到文件名或子目录的路径（比如"读同目录下 `data` 文件夹里的 `scores.csv`"）时，它找的是"你敲命令的那个目录"下面的那个文件；换个地方运行就找不到了。这是"在编辑器里能读到数据，一换地方就报 `FileNotFoundError`"的全部原因。第 13 讲会给不依赖 cwd 的标准写法。

（`FileNotFoundError` 是 Python 找不到文件时报的错误名，现在不用记。）

Windows 路径还有两个坑：分隔符 `\` 在 Python 字符串里是转义符（它会把后面的字符变成特殊含义），所以写路径时常用 `r"C:\new\todo.txt"` 这种写法——前面那个 `r` 表示"这段字符串里的反斜杠按原样算，不转义"；或者干脆改用 `/`，第 05 讲展开。路径带空格时，命令行里要用引号包起来，`cd "C:\my homework"`。

### 5.4 文件读不进来：编码与缓存

Python 读源码文件时，默认按 UTF-8 去解字节。如果文件不是 UTF-8 存的，Python 连"你写的是什么"都读不出来。

我实测过一个特别常见的坑：Windows 自带的 PowerShell 5.1 里，用 `>` 把输出写进文件（这个写法叫重定向）时，默认写的是 UTF-16。

```text
> "print('hello from demo')" > hello.py
> python hello.py
  File "hello.py", line 1
SyntaxError: Non-UTF-8 code starting with '\xff' in file ... but no encoding declared
```

`\xff` 是 UTF-16 在文件开头留下的字节序标记（几个字节，用来标明"这个文件是 UTF-16 写的"）的前半截。此时代码一个字符都没写错，错的是文件的编码。所以这条报错虽然长着 `SyntaxError` 的样子，却不该去改代码；正确的写法是 `"print('hello from demo')" | Set-Content -Encoding utf8 hello.py`，或者干脆用记事本另存为 UTF-8。

要记住的是：**报错的名字不等于出错的环节。** `SyntaxError` 出现在第 4 站，不等于你"语法没学好"。

另一件常被冤枉的是缓存。当你的程序引用了另一个 `.py` 文件里的代码（这个动作叫 `import`，意思是"导入"，被导入的那个文件叫**模块**），Python 会把翻译好的字节码存到源码旁边的 `__pycache__` 目录里，文件名以 `.pyc` 结尾。它只是省时间：下次直接读字节码，跳过翻译。删掉它不会让程序出错，只是下次重新翻译一次；改了 `.py` 后 Python 会比对修改时间自动重来。所以"我改了没生效"不该怪它，真正的嫌疑人是没保存（第 5.1 节）和跑的是另一个文件（第 5.3 节）。

### 5.5 跑起来之后才出错

走到这里，Python 已经在跑你的代码了。先分清两个词。

**程序**（program）是磁盘上的文件；**进程**（process）是它的一次运行。你敲三次 `python hello.py`，就有三个进程，互不知道对方存在。

一次运行开始时，操作系统给这个进程划出一块内存。程序里出现的每个值，都是这块内存里的一个**对象**：一块有类型、有值的数据。变量名（比如下面实验里的 `a`）只是贴在对象上的一张标签，不是装东西的盒子。

看一个实验：

```text
=== EXP4: 名字指向对象，id 观察（先只记现象）===
a is b (256)      : True;  id(a)==id(b): True
c is d ('257')    : False;  c == d: True;  id 相同: False
```

`id()` 给出对象在本次运行中的编号；`is` 问"是不是同一个对象"；`==` 问"值是否相等"。第一行说明 `a = 256` 和 `b = 256` 这两个名字贴到了同一个对象上；第二行说明用 `int("257")`（把文字 `"257"` 变成整数 257）分别造出来的两个 257 是两个对象，但值相等。

为什么 256 会共用、257 不会？因为 Python 预先缓存了 $-5$ 到 $256$ 这些小整数。这是实现细节，第 04 讲会讲清什么时候可以依赖、什么时候绝对不能。**本讲只要一个印象：名字不是盒子，两个名字可以指向同一个东西。**

另外，同一个 Python 还有交互式入口：只敲 `python` 不带文件名，会出现 `>>>` 提示符，输入一行执行一行。**`>>>` 是提示符，不是 Python 语法**，抄进 `.py` 文件会得到 `SyntaxError`。写程序用脚本方式，`>>>` 只适合试一小段。

最后一个要点：`print` 不是"显示"，它只是把字节写到标准输出。**写出去**是第 5 站，**看见**是第 6 站。这两件事分开，才能解释"程序算对了，但屏幕上是乱的"。

### 5.6 算对了，屏幕上是乱的

最后一段路是这样走的：

字符（"你"）→ 码点（一个编号）→ 字节（UTF-8 里是三个字节）→ 黑窗口按自己的码页解码 → 字体画出字形。

Windows 中文环境的历史默认码页是 936（GBK）。`chcp` 是查看当前码页的命令，你可以自己看：

```text
> chcp
活动代码页: 936
```

码页和文件编码不匹配，就得到两类完全不同的现象：

| 你看到的 | 原因 | 该改哪一边 |
|---|---|---|
| `???`、`锟斤拷` | 窗口用错规则去解那串字节 | 终端码页或文件编码（02、05 讲） |
| 方块，但英文完全正常 | 字节解对了，字体没有这个字的字形 | 换字体 |

这条区分很实用：**乱码是"解错了字节"，方块是"解对了但没图可画"。** 搞反了方向，就会去改一个不该改的东西。

> 一处修正：这一节把最后一步说成了"终端按码页解码"，这是简化说法。更准确地说，Python 3.6+ 在真正的控制台窗口里输出时走的是 Windows 自己的字符接口，不经过码页；只有被重定向到文件，或把输出接给另一个程序（这种接法叫管道）时，才按 `sys.stdout.encoding` 编码（中文 Windows 常为 gbk）。这里的 `sys` 是 Python 自带的一个模块，`stdout.encoding` 是它记录的"当前输出该用哪种编码"。第 02 讲第 7 节把这三条路分开讲。

## 6. 拿这张表判断三件事

下面三件事，都按"现象 → 归到第几站 → 第一件事做什么"走。

### 6.1 例 1：装过的包，运行时说找不到

现象：你昨天用 `pip install numpy` 装过一个叫 numpy 的包（包就是把一堆现成代码打包成的工具；`pip` 是用来装它的命令，第 02 讲），今天运行脚本却报 `ModuleNotFoundError: No module named 'numpy'`。

**解**：归到第 3 站（叫醒的是哪一份 Python）。`pip install` 装进了某一个 Python 的目录，今天跑起来的可能是另一个。第一件事：对照两个输出——`pip show numpy` 里的 `Location`，和 `python -c "import sys; print(sys.executable)"` 打印的 Python 程序位置（Python 这个程序也常被叫**解释器**）。`-c` 的意思是"后面这串引号里的内容，就是要执行的代码"。两个路径对不上，就是装到了别处，不是"没装"。

### 6.2 例 2：文件明明在旁边，却说找不到

现象：`FileNotFoundError: [Errno 2] No such file or directory: 'data.csv'`，而 `data.csv` 就在脚本旁边。

**解**：归到第 4 站（当前目录）。"脚本旁边的文件"不等于"当前目录下的文件"。第一件事：在脚本里打印 `Path.cwd()`，看实际站在哪里（`Path` 是 Python 里处理路径的工具，第 13 讲讲）。

### 6.3 例 3：中文显示成方块，英文正常

现象：黑窗口里中文显示成方块，英文完全正常。

**解**：归到第 6 站的下半段（字体），不是编码。第一件事：换一个字体或换一个窗口，把同一段输出再打一次。换了就好，问题在字体；还是方块，再回头查码页。

判断顺序固定为三步：**看现象 → 对表 → 只查那一站。** 跳过前两步直接动手，是最常见的浪费。

## 小结

- `.py` 只是扩展名，文件本身是纯文本；双击没反应不是文件坏了。
- 黑窗口、终端、cmd、PowerShell、shell 不是五个东西：终端是窗口，shell 是里面解析命令的程序，cmd 与 PowerShell 是两种 shell。
- "运行"不是一次双击，而是七站：存盘、命令、启动、读入、执行、显示、你看到。
- 最高频的三个坑：没保存、当前目录不对、叫醒的不是你以为的那份 Python。
- 报错的名字不等于出错的环节：`SyntaxError` 可能是编码问题，`ModuleNotFoundError` 可能是装错了解释器。
- 乱码与方块是两件事：前者改编码或码页，后者改字体。
- 下次见到没见过的报错，先对表定位，再动手；不要先重装。

## 作业

**Q1.** 用你自己的话说清：为什么 `hello.py.txt` 这个文件用 `python hello.py.txt` 也许能跑，但双击它或按 `.py` 的方式使用就不行？文件名和扩展名在这里各起什么作用？

**参考答案：**
文件里装的是纯文本内容，`python 文件名` 这个命令只是让 Python 去读这个文件，它并不挑扩展名——所以如果你明确把 `hello.py.txt` 交给它，它照样能读。但双击、以及大多数工具判断"这是什么文件、该用哪个程序打开"时，看的是扩展名；`.txt` 会被当成普通文本，不会交给 Python。所以扩展名是给人和工具看的标签，不是内容本身的属性。这也是"另存为时选错保存类型"会让人以为代码坏了的原因。

**Q2.** 用一句话说明：为什么"我的程序文件还在，但它没在运行"和"我关掉了程序，所以代码丢了"这两句话都是错的？

**参考答案：**
文件在磁盘上不会因为程序没跑而消失，所以"文件还在但没在运行"是正常状态；关掉程序丢的是内存里的运行状态（变量、执行到哪一步），磁盘上的 `.py` 不受影响，重新运行就能重建；只有忘记保存时，丢的才是"还没写回磁盘的编辑内容"。

**Q3.** 跑一次 `python -c "print(2**100)"`（或用 `uv run python -c "print(2**100)"`），抄下输出。为什么它没有溢出？

**参考答案：**
输出是 `1267650600228229401496703205376`。Python 的整数是任意精度的，位数由内存决定，不固定在 32 位或 64 位，所以不会溢出；代价是大数运算更慢、更占内存（第 04 讲实测）。C 的 `int` 是固定宽度的机器整数，超出范围会回绕或触发未定义行为。

**Q4.** 在 `py01` 文件夹里打开黑窗口，运行 `python hello.py`，记下结果；再进入它的上一级目录（`cd ..`），运行 `python hello.py`，记下结果。两次为什么不一样？

**参考答案：**
在 `py01` 里能跑出 `你好`；退到上一级会报 `can't open file 'hello.py'`。第一，上一级目录里没有 `hello.py`；第二，`python hello.py` 里的 `hello.py` 是相对路径，按当前目录解析。要修，要么先 `cd py01` 再跑，要么写完整路径。

**Q5.** 判断并说明理由：删掉 `__pycache__` 会不会让程序出错？什么情况下会？

**参考答案：**
正常不会。它只是字节码缓存，源码还在，Python 发现缓存缺失就重新翻译一次；已经加载到内存的模块更不受影响。只有当你手里只有 `.pyc` 而没有对应的 `.py`（有人只发了缓存文件）时，删掉才真的没有东西可执行。正常项目不会这样发布。

**Q6.** 目录结构如下，当前目录是 `E:\hw`：

写出：① `main.py` 的相对路径；② `scores.csv` 的相对路径；③ `old.csv` 的相对路径；④ 先进入 `backup` 再回到 `hw` 的命令。


按第 4 节的表，这属于第几站的问题？写出前两条排查动作。

（提示：报错前缀可能是 `python:`，也可能是 Python 程序的完整路径，意思相同。）

**参考答案：**
属于第 4 站"读入"：Python 已经启动（否则会报"不是内部或外部命令"），但按给定路径打不开文件。

前两条动作：① 用 `dir` 看当前目录里有没有 `hello.py`，注意 Windows 默认隐藏扩展名，可能实际是 `hello.py.txt`；② 用 `pwd` 看当前目录是不是你以为的那个，不是就用 `cd` 进去，或改用完整路径。

**Q8.** 把七站用你自己的话重写一遍，每一站后面标出"这一站出问题会看到什么"。

**参考答案：**
① 存盘：不保存则跑旧文件，表现为"我改了没生效"；若存成 `.py.txt`，表现为找不到文件或报语法错。
② 命令：shell 拆"命令 + 参数"；拼错则报"无法将 ... 项识别为 cmdlet"。
③ 启动：在 `PATH` 里找 `python.exe`；找不到则报同样的"不是内部或外部命令"，但命令拼写是对的。
④ 读入：Python 读文件、翻译成字节码；失败会报 `can't open file`、`SyntaxError`、`Non-UTF-8`、`UnicodeDecodeError`。
⑤ 执行：跑字节码；出错给 `Traceback`，死循环则既不输出也不结束。
⑥ 显示：窗口解码并用字体画字；错了是乱码或方块。
⑦ 你看到结果：这一步没有独立故障，但要分清"算错"与"显示错"。

**Q9.** 有人说"Python 是解释型语言，所以它比 C 慢，而且不编译"。这句话哪一半对、哪一半会误导人？

**参考答案：**
"通常比 C 慢"在多数场景成立；"不编译"错：Python 运行前会把源码翻译成字节码（还缓存到 `.pyc`），只是不翻译成 CPU 直接执行的机器码，也不生成独立可执行文件。

"慢"也要限定范围：第 17 讲会实测，同样的任务换个数据结构就差几个数量级——多数时候瓶颈在算法与容器选择，不在语言。把一切都归给语言，会在错误的地方优化。

③ 第 3 站：叫醒的 Python 不是装包的那一份。第一件事：`pip show requests` 的 `Location` 与 `python -c "import sys; print(sys.executable)"` 对照。
