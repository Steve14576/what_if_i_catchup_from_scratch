# 第 02 讲 把你的机器配成能干活的工位

> 本讲是开头三讲（计算机素养）的第二讲。第 01 讲把"运行"拆成了七站；这一讲处理其中最常坏的一段：**机器上不止一份 Python，而你不知道此刻用的是哪一份**。命令不用背，卡住时回来查。装环境要动你自己的电脑；如果机器是学校的、不让装，第 2 节的"写全路径"和第 3 节的"不激活也能用"就是给这种情况准备的。

## 这一讲解决什么

先把后面反复要用的四个词落地：

- **`python`**：那个程序的命令名。第 01 讲已经见过：它是一个能读 `.py` 文件、照着里面的文字干活的程序。
- **`pip`**：装第三方包的命令，跟着 Python 一起来。
- **`import`**：在代码里"引用另一个文件或包里现成代码"的写法。
- **第三方包**：别人写好、发布出来给你用的代码包，比如 `requests`（用来发网络请求的）。

三个真实发生过的场景。

**第一个。** 同一份代码，在机房能跑，在你的笔记本上报：

```text
'python' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

**第二个。** 你明明用 `pip install requests` 装过，脚本里写 `import requests`，还是报：

```text
ModuleNotFoundError: No module named 'requests'
```

（`ModuleNotFoundError` 是 Python 说"找不到你要引用的那个模块"时用的报错名。模块就是一个可以被引用的 `.py` 文件，或一组这样的文件。）

**第三个。** 别人电脑上好好的代码，到你这里中文变成问号或方块。

这三件事看着无关，根子是同一个：**你机器上不止一份 Python，包也不止一份，而你在每一步用的可能不是同一份。**

这一讲做四件事：**① 装好，并让系统找得到它；② 给项目一套独立环境；③ 把包装进那套环境；④ 让编辑器和黑窗口（终端：一个可以敲命令的字符窗口）指向同一份。** 最后给一张"卡住时按什么顺序查"的表。

## 1. 先确认：你机器上到底有没有 Python

### 1.1 三条命令，各回答一个问题

| 命令 | 回答什么 | 典型输出 |
|---|---|---|
| `python -V` | 现在敲 `python`，会用哪一份、什么版本 | `Python 3.12.13` |
| `where python` | 系统按 `PATH` 能找到几份 | 一行一个路径；找不到就什么都不打印 |
| `py -0` | 机器上装了哪些版本（靠 Windows 的 `py` 启动器） | `-V:3.12 *` 之类 |

两个新词先说清：

- **`PATH`**：操作系统给程序看的一张目录清单。你敲一个命令名，shell（黑窗口里解析并执行命令的那个程序）就去清单里的目录按顺序找同名程序。它是"命令能不能用"的总开关，第 2 节展开。
- **`py` 启动器**：Windows 装 Python 时附赠的一个小工具，专门用来"按版本挑解释器"（解释器就是 Python 那个程序，第 01 讲叫作 `python.exe`）。`py -0` 里的 `-0` 是"列出所有已装版本"，输出里带 `*` 的那一行是**默认版本**（不带版本号直接 `py` 时用它）。

### 1.2 三条结果互相矛盾，是正常的

这台机器上实测：

```text
> where python
信息: 用提供的模式无法找到文件。

> py -0
py : 无法将"py"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。

> python -V
python : 无法将"python"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
```

（`cmdlet` 是 PowerShell 对"命令"的叫法，整句意思就是"没有叫 python 的命令"。）

三条全失败。但 Python 其实装了——它在这个项目的 `.venv` 里（第 3 节会讲），只是没进系统 `PATH`，也没有 `py` 启动器。所以：

**"三条命令全红"不等于"没装"，只等于"按这个名字找不到它"。** 这两件事必须分开，否则你会一直在重装。

### 1.3 没有就装：四种来源，选一个

| 来源 | 怎么装 | 特点 |
|---|---|---|
| 官网安装包（python.org） | 下载安装器，下一步下一步 | 最接近机房环境，本课程主线 |
| Microsoft Store | 商店里搜 Python | 方便，但它装的是"别名"：有时你敲 `python` 打开的是商店页面，不是解释器 |
| uv 托管 | `uv python install 3.12` | uv 自己下一份放在它的目录，不碰系统 `PATH`；uv 是什么见第 5 节 |
| conda | 装 Anaconda / Miniconda | 管的是整个软件栈，科研数据方向常见；见第 5 节 |

安装器第一屏有一个勾选框 **"Add python.exe to PATH"**（把 Python 加进 `PATH`）。`PATH` 的具体含义第 2 节讲；现在只要知道：**勾上，之后在任意目录都能敲 `python`；不勾，也能用，但每次要写全路径，或者用 `py`。**

### 1.4 装到哪了

官网安装包默认装在类似这样的目录：

```text
C:\Users\你\AppData\Local\Programs\Python\Python312\
```

- `AppData` 是 Windows 给每个用户存程序数据的地方，默认是隐藏的，所以在资源管理器里不一定看得见。
- 末尾的 `Python312` 是版本号：3.12。
- `python.exe` 就在这个目录里。

记住这个路径有一个直接用途：**即使 `PATH` 没配好，写全路径也能跑。**

```text
> C:\Users\你\AppData\Local\Programs\Python\Python312\python.exe hello.py
```

"装没装"和"系统找不找得到"是两件事：装在 `AppData` 下面，但那个目录没进 `PATH`，你敲 `python` 照样找不到。

### 1.5 装了两个版本怎么办

`py` 启动器可以按版本挑：

```text
> py -0
 -V:3.12 *        Python 3.12 (64-bit)
 -V:3.8           Python 3.8 (64-bit)

> py -3.8 hello.py
```

`py -3.8 hello.py` 的意思是"用 3.8 那一份来跑这个文件"，和 `python hello.py` 走的不是同一条路。机房是 3.8、你本机是 3.12 时，交作业前用 `py -3.8` 跑一遍，能提前发现"用了 3.8 没有的语法"。

（macOS 和 Linux 没有 `py`，对应写法是 `python3.12`。）

## 2. 装完还是"找不到"：PATH 在替你做决定

### 2.1 PATH 是什么

`PATH` 是一个**环境变量**。环境变量是操作系统交给程序看的一组设置，每项是一个名字配一个值；`PATH` 是其中一项，它的值是一串目录，目录之间用分号隔开。

你敲一个命令名，shell 做的事是：**按顺序去 `PATH` 列出的目录里找同名程序，找到第一个就用它；一个都没找到，就报"不是内部或外部命令"。**

所以"命令能不能用"取决于两件事：那个程序在不在清单里的某个目录；以及清单里的顺序。

这台机器上实测：`PATH` 里一共 45 个目录，**没有一个是 Python 的**（逐条检查，名字里含 `python` 的条目数为 0）。这就是第 1.2 节三条命令全红的直接原因。

### 2.2 四种修法，挑一个

| 修法 | 怎么做 | 适用 |
|---|---|---|
| 安装时勾选 | 官网安装器第一屏勾 "Add python.exe to PATH" | 还没装，最省事 |
| 手动加 | 把 `...\Python312\` 和 `...\Python312\Scripts\` 加进用户 `PATH` | 已经装了 |
| 写全路径 | `C:\...\Python312\python.exe hello.py` | 只想跑一次；机房不让改环境变量 |
| 让工具代劳 | `py hello.py` 或 `uv run python hello.py` | 本课程示例常用 |

两个必须知道的细节：

- **改完 `PATH` 要重开终端。** 已经开着的黑窗口拿的是它启动时的那份旧清单，不会自动刷新。
- **手动加时，`Scripts` 目录也要一起加。** `pip` 这个命令就住在 `Scripts` 里；只加主目录，`python` 能用，`pip` 不能用。

### 2.3 清单里有好几个 Python 时，用哪个

`where python` 列出的第一个，就是 shell 会用的那个。想让某一份优先，就把它所在目录在 `PATH` 里往前挪。

这也是后面很多怪事的来源：你以为在用 A，实际在用的是 B。第 4 节会给三条命令，专门用来确认"此刻到底是哪一份"。

## 3. 为什么每个项目都要有自己的"环境"

### 3.1 全局装包为什么会打架

一份 Python 只有一份 **site-packages**——这是第三方包装在磁盘上的目录。你 `pip install` 的东西，默认都进这里。

假设你有两个项目：项目甲要求 `requests` 2.20，项目乙要求 `requests` 2.32。全局只有一份，后装的会把先装的覆盖掉。你今天跑甲，明天跑乙，就得来回卸载重装；更麻烦的是，你往往不知道是哪个包被谁改过。

### 3.2 虚拟环境造出了什么

**虚拟环境**（virtual environment，常简称 venv）就是"给一个项目单独造一份 site-packages"。建它的命令是：

```text
> python -m venv .venv
```

这里 `-m` 的意思是"把后面这个名字当成一个模块来运行"（模块就是一个可以被引用的 `.py` 文件，或一组这样的文件）。`venv` 是 Python 自带的一个模块，专门负责建环境。最后那个 `.venv` 是你要建的目录名；前面加一个点，表示"这是隐藏目录"，免得它混在你的代码里碍眼。

这条命令会造出：

- 一个目录（这里是 `.venv`）；
- 里面有一份指向原解释器的启动器（Windows 上是 `.venv\Scripts\python.exe`）；
- 一份独立的 `Lib\site-packages`；
- 几个激活脚本。

之后你用**这一份** `python` 装包，包就进这个项目的 `.venv`，与别的项目无关。

### 3.3 怎么确认自己在不在环境里

不用装任何东西，跑一行命令。这里 `-c` 的意思是"后面这串引号里的内容，就是要执行的代码"；`sys` 是 Python 自带的一个模块，`sys.prefix` 是它记录的一个值：

```text
> python -c "import sys; print(sys.prefix); print(sys.base_prefix); print(sys.prefix != sys.base_prefix)"
```

这台机器上实测：

```text
E:\...\WHATIFICATCHUPFROMSCRATCH\.venv
C:\Users\...\uv\python\cpython-3.12-windows-x86_64-none
True
```

（你的路径会不同，看关系就行。）

- `sys.prefix` 是**当前环境**的目录；
- `sys.base_prefix` 是**造出这个环境的那一份原始 Python** 的目录；
- 两者不同（最后一行 `True`），就说明你在一个虚拟环境里；相同就是没有。

再看包放在哪：

```text
> python -c "import sysconfig; print(sysconfig.get_paths()['purelib'])"
> python -c "import json; print(json.__file__)"
```

`sysconfig` 也是 Python 自带的模块，`get_paths()['purelib']` 就是"纯 Python 包该装的目录"，也就是 site-packages。`json` 是 Python 自带的一个**标准库**——装 Python 时一起装好的一批模块，不需要你 `pip install`。这句打印的是它的文件位置。

这台机器上实测：

```text
E:\...\WHATIFICATCHUPFROMSCRATCH\.venv\Lib\site-packages
C:\Users\...\cpython-3.12-windows-x86_64-none\Lib\json\__init__.py
```

两行值得对比：第三方包进 `.venv\Lib\site-packages`；而 `json` 这种标准库来自原始 Python 的 `Lib`。也就是说，**虚拟环境隔离的是"你装的包"，不是整个 Python**。

### 3.4 建、激活、退出、删

```text
> python -m venv .venv
> .\.venv\Scripts\Activate.ps1
(.venv) > python -V
(.venv) > deactivate
```

- **建**：`python -m venv .venv`。
- **激活**：PowerShell 用 `.\.venv\Scripts\Activate.ps1`；cmd 用 `.\.venv\Scripts\activate.bat`。激活成功后，提示符前面会出现 `(.venv)`。
- **退出**：`deactivate`。
- **删**：直接删掉整个目录。它不会弄坏系统 Python。

"激活"到底改了什么？只改了**当前这个终端**的环境变量，让 `python` 和 `pip` 指向 `.venv`。所以：

- 在 A 窗口激活，B 窗口不受影响；
- 关掉窗口，激活就没了；
- 删除 `.venv` 后，系统 Python 完好无损。

### 3.5 激活失败怎么办

PowerShell 可能报"无法加载文件 ... 因为在此系统上禁止运行脚本"。这是 Windows 的**执行策略**（execution policy）在拦脚本，不是 venv 坏了。给当前窗口临时放行：

```text
> Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

`-Scope Process` 表示"只对当前这个窗口生效"，关掉就恢复，不改系统设置。

### 3.6 不激活也能用

激活只是让命令变短。你完全可以绕过它，直接用 `.venv` 里的解释器：

```text
> .\.venv\Scripts\python.exe hello.py
```

路径长一点，但不会有"我以为激活了其实没有"的问题。第 6 节的编辑器、以及以后的任务计划，用的都是这种写法。

## 4. 装包：pip 到底把东西放哪了

### 4.1 一次 install 的完整过程

`pip` 是 Python 自带的包管理命令。`pip install requests` 大致做四件事：

1. 去**包索引**（默认是 PyPI，一个公开的包仓库）查这个名字与版本；
2. 解析依赖：`requests` 自己还依赖几个包，一并算进来；
3. 下载 **wheel**（预编译好的包文件，后缀 `.whl`）；
4. 解压到**当前这个解释器**的 site-packages。

关键在于第 4 步：**"当前这个解释器"是谁，包就装给谁。** 你在系统 Python 下装，就在全局；在 `.venv` 里装，就只进这个项目。

### 4.2 常用四条命令

```text
> python -m pip install requests
> python -m pip list
> python -m pip show requests
> python -m pip freeze
```

写成 `python -m pip` 而不是直接 `pip`，是为了保证"装包的这个 pip"和"跑代码的那个 python"是同一份。裸 `pip` 有时候指向另一个 Python 的 `Scripts` 目录，这是"装了却 `import` 不到"的第一大来源。

### 4.3 用 uv 建的环境里可能没有 pip

如果你是用 `uv venv` 建的环境，里面**可能没有 pip**（uv 默认不装）。uv 是什么第 5 节讲，这里先给出判断方法：

```text
> python -m pip -V
... No module named pip
```

这时用 `uv pip install 包名`（uv 自带的 pip 兼容命令），或者直接用 `uv add`。这不是环境坏了，只是建环境的工具不同。

### 4.4 国内网络装不上时

换一个镜像（把包的下载地址换到国内的站）：

```text
> python -m pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`-i` 只对这一次生效；要长期用，可以去配置 `pip.ini`，这里不展开。

### 4.5 三条命令定位"装到哪了"

出现 `ModuleNotFoundError` 时——这是 Python 找不到你要引用的模块时报的错——按顺序跑这三条：

```text
> python -c "import sys; print(sys.executable)"
> python -m pip show requests
> python -c "import requests; print(requests.__file__)"
```

`sys.executable` 是"此刻这个 Python 程序自己的路径"；`pip show` 输出里的 `Location` 是"pip 把包装到了哪"；`requests.__file__` 是这个包自己的文件位置。

三者对不上，就是"装到了别处"：常见的是用系统 `pip` 装了包，却在 `.venv` 里跑代码；或者反过来。

### 4.6 把环境记下来

```text
> python -m pip freeze > requirements.txt
> python -m pip install -r requirements.txt
```

`freeze` 把当前环境里所有包与版本写成清单，别人（或三个月后的你）照着装就能复现。它会把间接依赖也写进去，所以清单通常很长；这是正常现象，第 17 讲会讲怎么维护。

一个细节：PowerShell 的 `>` 默认写成 UTF-16（第 7.2 节实测）。`pip` 和 `uv` 一般能读这种文件，但 git diff、编辑器、别的工具看着会别扭。要 UTF-8（一种通用的文字编码，第 7 节展开），写成：

```text
> python -m pip freeze | Set-Content -Encoding utf8 requirements.txt
```

## 5. uv 和 conda：什么时候轮到它们

### 5.1 uv 是什么

`uv` 是一个管 Python 的工具：下解释器、建环境、装依赖、跑脚本，它都能做。它比 `pip` 快，并且自带**锁文件**（`uv.lock`，记录每个包的确切版本，保证别人装出同样的环境）。

本课程示例里常见这几种写法：

```text
> uv venv
> uv pip install requests
> uv run python hello.py
> uv run --with requests python hello.py
```

最后一种值得单独说：`uv run --with requests` 的意思是"临时给我一份带 `requests` 的环境，跑完这个脚本就行"，适合随手写的小脚本。它不等于"把 requests 装进了项目"——项目要长期用，还是应该建 `.venv` 并写依赖清单。

`uv` 不替代 Python 本身：它管的仍然是 Python，只是把"下载、建环境、装包"这几步打包了。

### 5.2 conda、poetry、pipx 各解决什么

| 工具 | 管什么 | 典型场景 |
|---|---|---|
| conda | 整个软件栈，包括非 Python 的二进制依赖 | 科学计算、需要 CUDA/MKL 的环境 |
| poetry | 项目依赖 + 打包发布 | 要发布成库 |
| pipx | 把命令行工具装成全局可执行 | 装 `black` 这类命令行工具 |

它们与 venv + pip 不是替代关系，而是不同粒度的封装。**默认先用 venv + pip**；想快、想要锁文件，用 uv；需要非 Python 依赖，再考虑 conda。

一个具体的坑：在 conda 环境里用系统的 `pip` 装包，会把 conda 环境搞乱。规则同第 4 节：用哪个解释器，就用它自己的 `pip`（`python -m pip`）。

## 6. 编辑器的"运行"按钮，背后是哪条命令

记事本只能编辑文本。**编辑器**（editor）多给你语法高亮；**IDE**（集成开发环境）再多给你三件事：选解释器、运行、调试。VS Code 装 Python 插件之后，就接近一个轻量 IDE。

关键的一句：**"运行"按钮不是程序的一部分，它只是替你拼一条命令**——用你选定的解释器，跑当前文件。所以"按钮跑不动"几乎总是"解释器选错了"。

验证方法：在编辑器里选一个解释器，跑

```text
> python -c "import sys; print(sys.executable)"
```

换一个解释器再跑，路径会变。变的就是"按钮背后那条命令"。

另一个常见差异是**当前目录**。IDE 可能把工作目录设成项目根，而你在黑窗口里是从别处启动的。所以同一份代码会出现"编辑器里能读到数据，终端里报 `FileNotFoundError`（Python 找不到文件时的报错）"——这是第 01 讲第 5.3 节的 cwd（当前工作目录）问题，不是编辑器额外做了什么。

## 7. 中文乱码：先分清是哪条路上的

第 01 讲把这一段简化成了"终端按码页解码"。这里补准确，因为三条路的规则并不一样。（`码页` 是窗口用来把字节解成字符的那条规则，跟文件的编码是同一类东西。）

### 7.1 三条路

- **控制台直接输出**：`print("你好")` 打到真正的黑窗口里。Python 在 Windows 控制台上走的是 Windows 自己的字符接口，不经过码页，通常不会乱码。
- **重定向到文件或管道**：`python a.py > out.txt`，或者被别的程序接走。这时 Python 按 `sys.stdout.encoding` 编码。中文 Windows 下这个值常常是 `gbk`。`encoding` 就是"文字按哪条规则变成字节"，第 01 讲给过定义。
- **自己读写文件**：`open(path, encoding=...)`。`open` 是打开文件的写法。编码由你指定；不指定则跟系统区域走。

实测这台机器（输出被工具接走，相当于"管道"）：

```text
stdout.encoding      : gbk
stdout.isatty()      : False
locale preferred     : cp936
filesystem encoding  : utf-8
```

`isatty()` 问的是"输出是不是接在真控制台上"，这里为 False，说明输出被接走了，所以走了 `gbk`。这解释了为什么"同样的 `print`，在窗口里好好的，重定向到文件就乱"。

### 7.2 PowerShell 的 `>` 还会再改一次

在 PowerShell 5.1 里，`>` 不只是"把程序的输出写进文件"，它还会把整段输出**重新编码**成 UTF-16。实测同一个文件的开头字节：

```text
ff fe 60 4f 7d 59 0d 00 0a 00
```

`ff fe` 是 UTF-16 的字节序标记。所以用 `>` 写出来的 `.py` 文件，Python 读的时候会报 `Non-UTF-8`（第 01 讲第 5.4 节那个例子）。

要写 UTF-8 文本，用 `Set-Content -Encoding utf8`，或者用编辑器存盘。

### 7.3 怎么改

| 现象 | 改哪边 |
|---|---|
| 读文件报 `UnicodeDecodeError` | `open()` 里写对 `encoding`（UTF-8 文件写 `encoding="utf-8"`） |
| 中文 Windows 上重定向的文件想在别的系统读 | 设一个环境变量 `PYTHONIOENCODING=utf-8`（它专门告诉 Python"输出该用哪种编码"），或写文件时指定编码 |
| 控制台里别的程序输出乱码 | `chcp`（查看当前码页的命令）看码页；必要时 `chcp 65001` 切到 UTF-8 |
| 文件里有 `\ufeff` 打头的怪字符 | `\ufeff` 是 UTF-8 文件开头可能带的"字节序标记"，有时会被当成正文读进来；用 `encoding="utf-8-sig"` 读，这个写法会让 Python 把它丢掉 |
| 方块，英文正常 | 字体缺字形，换字体，不是编码 |

最后一行要记住：**乱码是"字节被解错"，方块是"解对了但没图可画"。** 两者改的不是同一处。

## 8. 卡住时按什么顺序查

环境问题千奇百怪，但入口只有四类。按顺序对号，每类给一条最短的定位命令：

| 你看到的 | 属于哪类 | 第一条命令 | 常见原因 |
|---|---|---|---|
| 不是内部或外部命令 | 命令找不到 | `where python` | `PATH` 没配、没重开终端、装的是 Store 别名 |
| `ModuleNotFoundError` | 模块找不到 | `python -c "import sys; print(sys.executable)"` | 装到了另一个解释器或环境 |
| `FileNotFoundError` | 文件打不开 | `python -c "import os; print(os.getcwd())"` | cwd 不对、相对路径 |
| 乱码或方块 | 编码 / 显示 | `chcp`（查看当前码页的命令） | 文件编码、重定向编码、字体 |

（`os` 也是 Python 自带的一个模块；`os.getcwd()` 返回当前工作目录。表里最后一行说的"相对路径"是只写一段、从当前目录算起的路径，第 01 讲第 5.3 节有例子。）

判断顺序固定：**看现象 → 归到四类之一 → 只查那一类。** 不要一上来就重装；重装只解决"真的没装"这一种情况，而它恰恰最少见。

## 小结

- `python -V`、`where python`、`py -0` 三条命令各回答一个问题，结果可以互相矛盾；矛盾本身就是线索。
- `PATH` 是一张目录清单，决定"命令能不能用"；改完要重开终端，`Scripts` 目录也要加。
- 虚拟环境给项目一份独立的 site-packages；`sys.prefix` 与 `sys.base_prefix` 不同，就说明在 venv 里。
- 激活只改当前终端；不激活也能用 `.venv\Scripts\python.exe`。
- `python -m pip` 比裸 `pip` 稳；装完 `import` 不到，先跑 `sys.executable`、`pip show`、`包.__file__` 三条命令。
- uv 是工具链（快、有锁文件），conda 管非 Python 依赖；默认仍是 venv + pip。
- 编辑器的运行按钮 = 选定解释器 + 脚本；按钮跑不动，先看解释器和 cwd。
- 乱码要分三条路：控制台、重定向、文件读写；方块是字体。

## 作业

**Q1.** 你在自己电脑上敲 `python -V` 说"不是内部或外部命令"，但 `py -0` 能列出 3.12。这说明什么？给出两种让 `python` 能用的办法。

**参考答案：**
说明 Python 装了（`py` 启动器能找到它），但它的目录没进 `PATH`，所以按 `python` 这个名字找不到。两种办法：① 把 `...\Python312\` 与 `...\Python312\Scripts\` 加进用户 `PATH`，然后**重开终端**；② 不改 `PATH`，改用 `py hello.py` 或写全路径 `C:\...\Python312\python.exe hello.py`。

**Q2.** `where python` 列出两行，分别在不同目录。你敲 `python hello.py` 时用的是哪一个？怎么确认？

**参考答案：**
用第一行那个——shell 按 `PATH` 顺序找，找到第一个就用。确认方法：`python -c "import sys; print(sys.executable)"`，打印出的路径与 `where` 的第一行一致；或者对比两行的 `python -V` 版本。

**Q3.** 用一句话解释：为什么"全局装包"会让两个项目打架？虚拟环境是怎么解决的？

**参考答案：**
全局只有一份 site-packages，两个项目要同一个包的不同版本时，后装的会覆盖先装的；虚拟环境给每个项目一份独立的 site-packages，各装各的，互不覆盖。

**Q4.** 在一个项目目录里跑：

```text
python -c "import sys; print(sys.prefix); print(sys.base_prefix); print(sys.prefix != sys.base_prefix)"
```

抄下三行。如果你不在任何虚拟环境里，这三行会变成什么？

**参考答案：**
在项目的 `.venv` 里跑，第一行是项目里的 `.venv` 路径，第二行是造出它的原始 Python 路径，第三行是 `True`。不在虚拟环境里时，前两行相同，第三行是 `False`——因为没有"外层环境"，它就是原始那份。

**Q5.** 激活虚拟环境时报"因为在此系统上禁止运行脚本"。这是 venv 坏了吗？写出解决办法，并说明它的作用范围。

**参考答案：**
不是。是 Windows 执行策略禁止运行 `.ps1` 脚本。用 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 给当前窗口临时放行；`-Scope Process` 表示只对当前窗口生效，关掉就恢复，不改系统设置。

**Q6.** 你确定自己 `pip install requests` 过，但脚本里 `import requests` 报 `ModuleNotFoundError`。写出三条排查命令，并说明每条告诉你什么。

**参考答案：**
① `python -c "import sys; print(sys.executable)"`——此刻用的是哪个 python；② `python -m pip show requests`——pip 把包装到了哪个 `Location`；③ `python -c "import requests; print(requests.__file__)"`——如果这条能跑，说明包在另一份解释器里能看到。三者对不上，就是"用 A 装、用 B 跑"。

**Q7.** `python -m pip freeze > requirements.txt` 生成的清单为什么常常有几十行，而你只装了两三个包？

**参考答案：**
因为你装的包自己还依赖别的包，`freeze` 把**当前环境里所有**已安装包都写进去，包括间接依赖。这正常，也正因为如此，别人照着清单才能装出一样的环境；代价是清单里混着你不直接使用的包。

**Q8.** 什么时候该用 uv，什么时候该用 conda？各说一个具体场景。

**参考答案：**
uv：想要快、想要锁文件保证可复现，例如一个新项目要固定依赖版本；或者随手跑一个带第三方包的小脚本（`uv run --with`）。conda：需要非 Python 的二进制依赖，例如要装带 CUDA 的深度学习环境，pip 管不了那些系统库。

**Q9.** 判断并说明理由：`python a.py > out.txt` 写出来的文件，用记事本打开可能乱码；而同样的 `print` 直接显示在黑窗口里却正常。问题出在哪？

**参考答案：**
出在"输出走哪条路"。直接显示在黑窗口时，Python 走 Windows 控制台自己的字符接口；重定向到文件时，Python 按 `sys.stdout.encoding`（中文 Windows 常为 gbk）编码，而 PowerShell 的 `>` 还会再把它写成 UTF-16。文件因此不是 UTF-8，用默认按 UTF-8 打开的工具看就会乱码。要写 UTF-8，用 `Set-Content -Encoding utf8`，或在程序里写文件时指定 `encoding="utf-8"`。

**Q10.** 给出四个现象，分别归到第 8 节的哪一类，并写出第一条命令：① `'python' 不是内部或外部命令`；② `ModuleNotFoundError: No module named 'numpy'`；③ `FileNotFoundError: 'data.csv'`；④ 窗口里中文是方块，英文正常。

**参考答案：**
① 命令找不到 → `where python`；② 模块找不到 → `python -c "import sys; print(sys.executable)"`；③ 文件打不开 → `python -c "import os; print(os.getcwd())"`；④ 编码/显示 → `chcp`（且方块更可能是字体，先换字体验证）。
