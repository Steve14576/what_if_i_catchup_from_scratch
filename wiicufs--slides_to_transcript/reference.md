> 本文件是 skill `courseware-transcript` 的细节层，按需查阅。更完整的论证与来龙去脉见母本 `personal/课件扒取方法论.md`。

## 0. 先探测、后假设（对抗"格式地狱"）

课件版式不统一，动手前先**探测事实**，再决定走哪条通路。要探测的东西：

| 探测什么 | 怎么探 | 决定什么 |
|---|---|---|
| 源文件类型 | 扩展名 / 文件头 | `.pdf` 走 PyMuPDF；`.pptx` 走 python-pptx；`.ppt` 优先转 PDF/pptx |
| 有没有文本层 | `page.get_text()` 是否为空 | 空 → 该页纯图，只能靠渲染（必要时 OCR） |
| 有没有嵌入位图 | 旧 `.ppt` 里 `Pictures` 流是否存在 | 有 → 可魔数切片取干净原图；无 → 只能渲染 |
| 每页文本密度 | 逐页字符数 | < 50 字 → 疑似纯图/表格截图，重点看图 |
| 图是位图还是矢量 | 能否从 `Pictures` 流取到 | 取不到（矢量绘制）→ 渲染兜底 |
| 图上有没有标注 | 直接看渲染图 | 有标注 → 一律用整页渲染 |

**红线**：任何"这一步一定是 X / 一定有 Y"的假设，都先验证再用。

**格式难度（开工前向用户声明）**：PDF 最省事（文本层完整、编码无歧义）→ PPTX 中等（须递归组合形状、公式为 OLE）→ 旧 `.ppt` 最麻烦（OLE record 解析、编码易乱）。**主动鼓励用户把 `.ppt` / `.pptx`「另存为 PDF」再交给我们**——最省事、最稳的入口。注意「另存为 PDF」要保留文本层，导出后仍要探测文本层是否为空。

## 1. 第 1 步：逐页文本提取（原始稿）

目标：得到按 `## 第 N 页` 分节的 Markdown，每页文字尽量完整。这一步**不管公式和图**，先把文本层能拿的都拿到。

### （A）PDF → PyMuPDF（首选）

PDF 文本层最完整、编码最无歧义，是主通路。

```python
import pymupdf
doc = pymupdf.open(str(pdf))
for i, page in enumerate(doc, start=1):
    text = page.get_text("text").strip()
    # 输出 "## 第 i 页"；text 为空则标 "（本页无可提取文本，可能为纯图页）"
```

公式在 PDF 文本层里会碎成逐字符碎片（如把 $\rho_A$ 拆成 `ρ`、`A`、下标），所以这步拿到的公式是坏的，留给第 3 步。

### （B）PPTX → python-pptx（无 PDF 时用）

**关键：必须递归遍历组合形状（group）。** `slide.shapes` 只返回顶层形状，被"组合"包起来的文本框、表格拿不到——会**静默漏字**，且不报错。

```python
from pptx import Presentation
from pptx.enum.shapes import MSO_SHAPE_TYPE

def walk(shapes, out):
    for shape in shapes:
        st = shape.shape_type
        if st == MSO_SHAPE_TYPE.GROUP:
            walk(shape.shapes, out); continue          # 深入组合内部
        if st == MSO_SHAPE_TYPE.EMBEDDED_OLE_OBJECT:
            out.append("[公式对象]"); continue          # 公式多是 OLE 嵌入对象，无文本
        if st == MSO_SHAPE_TYPE.PICTURE:
            out.append("[图片]"); continue
        if getattr(shape, "has_chart", False):
            out.append("[图表]"); continue
        if getattr(shape, "has_table", False):
            for row in shape.table.rows:
                out.append(" | ".join(c.text.strip() for c in row.cells))
            continue
        if shape.has_text_frame:
            for para in shape.text_frame.paragraphs:
                t = para.text.strip()
                if t: out.append(t)
```

遇到 `[公式对象]` 落一个**占位符**，第 3 步再替换成 LaTeX。幻灯片备注（`notes_slide`）也一并提取，常有老师补充。

### （C）老格式 `.ppt`（OLE 复合文档）→ olefile 手工解析（下策）

老 `.ppt` 不是 zip，是 OLE 复合文档，文本藏在 `PowerPoint Document` 流的 record 里，编码不可靠。**优先另存为 PDF/pptx**，实在不行才走这条路。

若必须解析：

- record 头 8 字节：`version/instance`(u16) + `type`(u16) + `len`(u32)。
- `instance & 0x0F == 0x0F` 是容器 record，进入子记录（`pos += 8`，不跳过 body）。
- `TextCharsAtom`（type `0x0FA0`）= UTF-16LE 文本。
- `TextBytesAtom`（type `0x0FA8`）= 单字节文本。**有些工具会把 UTF-16LE 数据塞进 TextBytesAtom**，需探测——按每两字节看、高字节为 0 的比例超过 1/4，就按 UTF-16LE 解；否则按 GBK 解；再退回 latin-1。
- 过滤母版噪音：`单击此处编辑母版…`、`第二级/第三级…`、纯标点行。

### 收尾

- **挑"字少讲图页"**：扫一遍原始稿，把每页有效文本 < 50 字的页列出来——多半是纯图页或表格截图，第 4 步重点看。
- **讲次清单**：批量脚本里的"源文件名列表"会随目录重组而过期，跑前先列目录核实。

### 禁用

- **不要用 markitdown** 转 PDF/Word/PPT：输出稀碎。
- **不要用 pandoc 做 md→tex**：产出大量不干净的中间标记。

## 2. 第 2 步：全页渲染（读图 + 兜底）

```python
pix = doc[p - 1].get_pixmap(dpi=200)                  # 200 起；字小的调到 300
pix.save(str(out_dir / f"{pdf.stem}_p{p:02d}.png"))   # 命名：讲次名_p两位页码.png
```

- **命名固定 `<源文件名>_pNN.png`**，后续引用与脚本都按此找图，不随意改名。
- 渲染图干两件事：① 第 3、4 步"读图"；② 兜底目录，任何页都能翻回原图。
- 只渲染需要的页：页码参数从 `all` 换成 `"2,6,8"`；但兜底要求每页都有，通常直接 `all`。

---

## 3. 第 3 步：公式视觉还原

课件公式常常既不在文本层（PPTX 里是 OLE 对象），从 PDF 文本层拿到的又是碎字符。**唯一权威来源是"看"渲染图。**

流程：

1. **读含公式页的渲染图**。
2. 把 `[公式对象]` / 碎片**替换成干净 LaTeX**，注入原始稿对应位置。
3. **校验**：占位符清零；纯图页已加图表标注。

**定界符约定**（务必统一）：行内 `$...$`；块级 `$$...$$`；**不用** `\(...\)` / `\[...\]`。

**易空降的公式细节**（顺手补）：符号首次出现要注明它代表什么（如 $c^Tx$ 里的 $c$、$x$）；记号要能读（如 $\lfloor v\rfloor$ 注明"向下取整"）。

## 4. 第 4 步：图片归档

### 4.1 图源三条通路（按优先级）

1. **从源文件提取"插入的位图"**：旧 `.ppt` 用 olefile 打开，若存在 `Pictures` 流，在流内按**完整格式魔数**定位每张图起点、切片写出 → **干净白底原图**，质量优于渲染。局限：只有"插入的图片"能拿到；**矢量形状绘制**的图（及叠加层）不在流里。
2. **渲染整页**：任何页可取，产物**带页面背景**。
3. **决定性判据**：图上带**教学标注**（箭头、分段名、公式注记）时一律用整页渲染图——干净原图会丢标注，而标注是教学主体。判据：**"去掉标注后这张图还完整吗？"** 不完整 → 渲染。此类页常成群出现，可整批处理。

> 判断走哪条通路前**先核实源文件内部结构**，不要凭印象断言"只能截图"。

### 4.2 提取嵌入位图：只认可靠魔数，且按结束标记截断

**只按可靠魔数提取**，宁可少提不可误报：

| 格式 | 魔数 | 是否提取 |
|---|---|---|
| PNG | `89 50 4E 47 0D 0A 1A 0A` | 是（长签名，误报低） |
| JPEG | `FF D8 FF` | 是 |
| GIF | `GIF87a` / `GIF89a` | 是 |
| BMP | `BM` | **否**（2 字节短签名，误报极高） |
| WMF/EMF | — | 否（短签名误报高） |

**按结束标记截断切片**：从起始魔数切到"下一张起点"的片段会带大段尾部垃圾字节（实测单图膨胀十余倍）。定位该格式的结束块标记截断——PNG 找 `IEND`，切到 `IEND + 8`（4 字节 `IEND` + 4 字节 CRC）：

```python
i = chunk.find(b"IEND")
if i >= 0 and i + 8 <= len(chunk):
    chunk = chunk[: i + 8]
```

截断后**逐张读图核验**，确认完好才归档。

### 4.3 归档范围怎么判（哪些页出图）

**判据：这张图的信息量，是否超出文字层？**

- **超出 → 归档**：示意图、流程图、构造剖面图、位置地图、装置/仪表实物照、思维导图、事故现场照等。
- **未超出 → 不归档**：文字层已完整覆盖的表格；纯装饰性照片（证书、合影、教材封面）；本身就是可提取文本的表格。

一句话：**"这张图不看行不行？"** 不看就漏信息 → 归档。

### 4.4 高效通览：接触表法（大批量页面时）

逐页读渲染图会把上下文吃光。把逐页渲染图**拼成带页码标签的接触表（contact sheet）**——网格排列，如 4 列 × 3 行 = 一张图覆盖 12 页，页脚标 `pN`。

```python
# 用 PIL：按页码排序 → 每 N 张拼一格 → 缩略图贴进网格 → 画页码标签
# 一讲 84 页 → 7 张接触表，7 次读图就能通览全部
```

先看接触表扫出"哪些页有图、是什么图"，再对候选页精读渲染图做 4.3 的判断。辅助线索：按文件大小排序（大文件 = 照片或复杂图）可快速定位含图页。

### 4.5 命名与目录

- 提取出的原图默认是机器名 → **重命名为 `p页码_中文描述.png`**（如 `p12_实验室位置及安全出入口.png`）。
- 归档图放 `<讲次>-images/`；渲染兜底图在 `<讲次>-render/`。二者分开，都按讲次划分，便于相对路径引用。
- 归档脚本（拷贝 + 重命名）写成可复跑小脚本，把"页码 → 目标名"映射写清楚；**执行后核验源↔目标一一对应**。

## 5. 第 5 步：嵌入成品

在 `## 第 N 页` 之后、正文之前插入：

```markdown
![P12 实验室位置及安全出入口](<讲次>-images/p12_实验室位置及安全出入口.png)

（图中：D03/D04 实验楼总平面示意图——标注东门、西门、楼梯口与连廊位置。）
```

- 图片走**相对路径**（相对文字稿所在目录）。
- 配一行 `（图中：…）` 说明，把图里对文字层不可见的信息用文字补齐——不看图也知道那张图在讲什么。

**头部说明行**：

```markdown
> 来源: `<源文件名>.pdf` | 共 N 页
> 说明: 文字来自 PDF 文本层（原样保留）；公式按页面渲染图逐页还原为 LaTeX；关键图从页面渲染提取（完整保留图上标注，见 `<讲次>-images/`），已嵌入对应页。
```

**同一讲次只保留成品一份**：以成品覆盖原始稿，避免两份并存导致引用错乱。

## 6. 第 6 步：交付前校验（每次必做）

| 校验项 | 判据 |
|---|---|
| 页数对齐 | 文字稿的 `## 第 N 页` 段数 = 源文件页数 |
| 公式计数 | `$$` 块数量符合预期 |
| 图片路径可解析 | 每个 `![...](路径)` 的路径全部存在 |
| 占位符清零 | `grep` `TODO` / `待补` / `{{` 等残留为 0 |
| 纯图页有标注 | 每个纯图页都补了 `（图中：…）` |

**汇报进度用实测计数**：说"某讲做完了"，附"页数 / `$$` 块数 / 图片数"，不凭主观描述。

## 7. 工具坑全表

| 坑 | 症状 | 规避 |
|---|---|---|
| PowerShell 执行含中文的 `.ps1` | 无 BOM 的 UTF-8 被按 ANSI 读 → 乱码、语法报错 | 不要直接 `.\x.ps1`；改用 `$c = Get-Content -LiteralPath "x.ps1" -Raw -Encoding UTF8; Invoke-Expression $c` |
| 命令行向 python 传中文路径 | 参数乱码，文件找不到 | 命令行保持纯 ASCII；中文路径硬编码进脚本源码（python 默认按 UTF-8 读源码） |
| Python 打印中文/特殊符号到 Windows 控制台 | `UnicodeEncodeError: 'gbk' codec` | 开头 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`；或 print 里避免 `✓` `²` `³`，改 `[OK]` `^2` `^3` |
| 批量"源→目标名"映射拷完不核验 | 键值一旦错位，源会被写成别的目标名，末段目标名为空时还会互相覆盖，且不报错 | 映射无论用哈希表还是数组，**拷完必核验源↔目标一一对应** |
| 写文件的工具报"创建失败" | 其实文件已生成 | 先 `ls` / 读一下再说，别急着重试 |
| 删除工具报成功但文件没删（shell 创建的二进制文件） | 文件仍在 | 换删除途径并核实结果，别只看"成功"回执 |
| `grep` 模式假阴性 | 搜某种编码形式得 0 匹配，误判"全缺失"并批量误改 | 用字面量模式；批量改前两种模式双向验证，改完再 grep 确认 |
| 文件快照失效 | 别人重排过文件，凭记忆改会匹配失败或改错 | 改前必读当前版本 |
| 脚本内置路径过期 | 目录重组后脚本找不到源文件 | 跑前先列目录核实 |

## 8. 与下游"写教程"的接口

本通路产出的是**文字稿 + 图**，不是教程。文字稿定位是"可检索、可引用、保真的原料"。下游写作（如 WIICUFS 那类）在此基础上做讲解、例题、作业——**那是另一件事，不要混进来**。

判据别互相污染：扒取阶段判"保不保真、全不全"；写作阶段判"读者看不看得懂"。

## 9. 未来脚本方向（本 skill 暂不含 scripts）

若将来要给本 skill 配可复跑脚本，候选与要点：

| 脚本 | 职责 | 关键点 |
|---|---|---|
| 逐页提取 | 文本 → 原始稿 | PDF 走 PyMuPDF；PPTX 递归 group；OLE 落占位符 |
| 全页渲染 | PDF 逐页渲染 PNG | `get_pixmap(dpi=200)`；命名 `讲次名_pNN.png` |
| 提取嵌入位图 | 从 `.ppt` 的 `Pictures` 流抠图 | 只认可靠魔数；PNG 按 `IEND` 截断 |
| 老 `.ppt` 文本 | 下策 | OLE record 解析；`TextBytesAtom` 编码探测 |
| 找纯图页 | 扫原始稿 | 每页有效字符 < 50 即报 |
| 归档图 | 拷贝 + 重命名 | "源文件名 → 目标名"映射；执行后核验 |

**落地前提**：这些脚本在项目里都带硬编码路径与讲次清单。做成通用脚本前必须**去项目化**——改成接命令行参数、不写死路径，否则换个课件就崩（正是"格式地狱"的坑）。
