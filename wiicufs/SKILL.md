# WIICUFS 1.4：自然、完整、可验证的技术教程

> WIICUFS = What If I Catch Up From Scratch。
>
> 目标不是把教材改成“亲切的流程图”，也不是让作者显得很会带课；目标是让没学过的人读完一份讲义后，能自然地理解、做题、动手，并知道结论在什么条件下成立。

## 0. 先分清两件事：正文与作者工具

教程有两层，绝不能互相夺舍：

- **读者正文**：解释知识本身。它应按对象、问题、条件、因果、例子和结论自然推进。读者不需要知道作者检查了多少项、PLAN 写了多少行。
- **作者工具**：PLAN、知识覆盖清单、学习者卡点预测、验证脚本、回查表。这些用来防漏、验证和恢复上下文；默认不出现在正文里。

一句话：**PLAN 强，正文松；验证严，行文自然。**

## 1. 第一原则：直接说清，不拿修辞代替信息

“说人话”不是把技术关系换成生活化口号，而是用完整自然的句子，直接说清：

1. 现在讨论的对象是什么；
2. 它在什么条件下成立；
3. 为什么会这样；
4. 能从中推出什么，或怎样验证。

优先级固定如下：

1. 对象、条件、方程、因果关系；
2. 数值例子、图、反例；
3. 必要时的低频类比。

不能颠倒。公式能说清时就说公式；数值例子能说清时就给数值；不要为了“生动”再包一层日常词。

### 1.1 类比的极窄许可

类比只有同时满足三条才可保留：

- **映射明确**：明确说出源概念的哪个结构对应技术概念的哪个结构；
- **后果可验证**：它能帮助读者推出一个具体结果，而非只是制造气氛；
- **立即退出**：紧接着回到正式定义、公式或适用边界。

同一喻体全文最多出现两次。若把它换成平实技术语言，意思没有损失，就必须换。

以下词默认不得出现在读者正文的标题、步骤名、结论名、跨讲引用名或验算动词中：`账/账本/旧账/核账`、`武器`、`面孔`、`宪法`、`金律`、`舞台`、`地基`、`镜子`、`门票`、`魔法`等。

| 不要写 | 直接写 |
|---|---|
| “旧账”“一笔悬着的账” | 换路前的初始值、此前已求出的量、一个待解释的现象 |
| “核账”“对账” | 验算、独立核对、残差检查、两种结果吻合 |
| “三笔账”“两本账” | 三个结论、两类功率、两套约束 |
| “舞台”“魔法” | 本节要解决的问题、由哪些关系推出的结果 |
| “全部武器” | 已学的方法，或结点法、相量法等具体方法名 |
| “两副面孔” | 取不同输出端口得到不同网络函数 |

作者工具里可以使用简写和内部记号，但写正文时必须重新翻译为技术语言。

## 2. 不空降：术语、符号和前提在第一次出现处落地

重要术语第一次出现时，至少给出：中文名、英文全称或缩写、它是什么、为什么现在需要它。公式第一次出现时说清每个新符号是什么、单位或量纲是什么、公式在什么条件下可用。

可使用三种处理：

1. 当场完整解释；
2. 给最小解释，并明确“现在只需知道什么、后面哪里细讲”；
3. 明确标为认识层，说明现在可跳过。

不要因为后面会讲就故意留白。解释必须放在读者第一次自然会问的位置之前或当场，而不是两页之后统一补课。

## 3. 正文如何自然推进

一段正文的首要任务是接住上一段自然留下的问题，不是展示作者的组织能力。

常见的自然推进是：

```text
定义或现象
→ 为什么需要这个量/关系
→ 公式与符号
→ 一个具体例子或反例
→ 条件、边界或下一件由内容本身必然引出的事
```

这不是固定段落模板。概念简单时可以两段讲完；推导复杂时可以多段展开。标题应说明知识对象或问题，例如“为什么温度不变仍然吸热”“怎样确定同名端”，而不是“下一站”“关键武器”“三件套”。

自然过渡直接写因果即可：

- “这解释了为什么……”；
- “要计算它，还缺……”；
- “这个结论只在……条件下成立”；
- “现在把上式代入……”。

除非读者面对真正的分支或长篇多模块内容，否则不需要脉络图、流程箭头或“下一站”广播。

## 4. 完整不等于把作者检查表塞进正文

读者确实会问“只有这一种吗”“什么时候不能用”“容易错在哪里”。作者应在 PLAN 中检查这些问题；但正文只在它们对当前概念的理解、使用或防错真正必要时展开。

对一个机制，作者可私下检查：标准形态、组合、外部条件、重复/共存、规范、相邻边界。最终正文只保留其中与本讲读者任务有关的部分；其他部分可放到后讲，或在 PLAN 中写明不讲的理由。

**覆盖清单是防漏工具，不是正文版式蓝图。**

## 5. 例子、图与验证：用事实建立直觉

抽象结论优先用可观察的东西坐实：具体输入输出、数值量级、极端情形、反例、图或可运行程序。

- 能用物理或公式准确说明的地方，用物理或公式；
- 能用小数值例子说明的地方，不必额外发明生活化比喻；
- 数值结论必须有可复跑来源；
- 预想与实测不一致时，要如实写出预想、数据和根因，不能偷偷改掉。

验证脚本应有规模纪律、实验标题、预期与实测、结论一句话；跑完归档，不删。复杂度结论至少测三个规模点；随机结论要重复实验。

## 6. 读者需要知道学到什么程度

对关键概念，应明确它是：

- **工具**：要会算、会用；
- **判定条件**：遇到时会检查；
- **直觉或认识层**：知道它存在、知道什么时候找它即可。

不要把“理解深度”机械做成每讲一张态度表。复杂、容易混或考试重点多的讲可以用短表；其余讲在定义后用一句话说明即可。

## 7. 作业与答案

每讲应有作业，题型和数量按内容自然设计，不按“基础/提高/综合”凑档位。

- 数值题给答案与验算方法；
- 代码题给可运行验证；
- 概念题给判断和理由；
- 答案只能使用已经教过的概念；
- 答案一律平铺为“**参考答案：**”，禁用 `<details>`。

例题负责教学，作业负责练习；不要把正文没有系统讲过的知识塞进答案。

## 8. PLAN：私有防漏工具，不是读者文本

PLAN 放在课程目录中，作者自用。它至少回答：

- 读者已有知识和课程目标；
- 每讲的知识归属与范围；
- 容易漏掉的边界、规范和前提；
- 可能的读者卡点；
- 验证与回查状态。

学习者视角、完整形态检查、两遍走都可记录在 PLAN 中，但不强制固定五段、六问或问题数量。真实的卡点比凑够四到八个问题重要。

PLAN 中的“钩子、链条、台账、地基、武器”等内部词不得直接复制到正文。

## 9. 两遍走

### 第一遍：先写内容，再做检查

1. 写出连续正文：先让知识按因果顺序站住，不预填脉络图、下一站、态度表、自测等模块。
2. 写例子、图和验证脚本，实跑后回填数据。
3. 按读者第一次遇到的顺序检查空降、符号、条件与边界。
4. 只在确有价值时补导航、短总结、学习提示或自测。
5. 做读者文本卫生检查：思考片段、工具标记、旧术语、内部 PLAN 行话、牵强类比、自造动词均不得残留。

### 第二遍：防漏回查，不重写成清单

1. 对 PLAN 覆盖清单逐项确认：正文已自然讲清、后讲处理，或明确不讲；
2. 对验证数字、图、作业答案与正文交叉核对；
3. 通读标题、开头、段落交接、小结、作业，删除只是在提醒读者“作者正在组织内容”的句子；
4. 搜索喻体词族与自造动词。默认计数为 0；保留例外必须逐处说明映射、后果和边界；
5. 做错别字、编号、表格、引号和 Markdown 渲染检查。

## 10. 最小文件结构

```text
课程目录/
├── PLAN.md                 作者自用：范围、覆盖、卡点、验证状态
├── 00_导览.md              读者导览
├── 01_主题.md              正文
├── scripts/                验证脚本
├── figures/                图形（如需要）
└── AA_一览.md              读者可查的概念/公式字典
```

AA 是读者文件：定义应直接、完整、无内部行话；它不是作者台账。

## 11. 最小每讲形态

```markdown
# 第 N 讲：主题

> 前置：……
> 这讲解决：……

## 1. 从问题或对象开始
## 2. 机制、公式与例子
## 3. 必要的边界或应用

## 小结
## 作业
```

以下全是**按需**添加，不是默认义务：脉络图、任务成品、图、常见误区、学习深度提示、掌握度自测、作业分层、跨讲预告。添加它们前问：删掉后读者会在具体哪里迷失？回答不出，就不加。

## 12. 常见失败形态

- 空降术语、公式符号或适用条件；
- 正文只给结论，不给对象、因果、例子或边界；
- 为了防漏，把 PLAN、检查清单和作者行话搬进读者正文；
- 比喻通胀：用“账、舞台、魔法、武器、面孔”等词替代技术对象；
- 自造动词：用“核账”等词替代验算或残差检查；
- 模板通胀：每讲强行塞脉络图、下一站、态度表、自测、分层作业，打断内容；
- 只靠“我觉得正确”交付，跳过实测；
- 跑完删除脚本，断掉数字来源；
- 偷偷改掉预写偏差；
- 让答疑或作业替代正文教学；
- 过度删减，留下只有作者能读懂的命令式短语。

## 13. 格式约定

- 行内公式用 `$...$`，块级公式用 `$$...$$`；
- 表格单元格内的绝对值不要写 `$|H|$`，`|` 会被 Markdown 当作列分隔符；写 `$\lvert H\rvert$`；
- 修改旧术语、标题或编号后，全文搜索旧词，确认引用没有漂移；
- 多课程并行时，只改当前课程文件，不改全局 README 或其他课程。
