# WIICUFS 1.4.1：自然、完整、可验证的技术教程

> WIICUFS = What If I Catch Up From Scratch。
>
> 它服务于多讲次技术教程：让没学过的人能看懂、练手、相信结论，并拿去应对考试、考核、科研或实际应用。

## 这两份文件分别干什么

- **SKILL.md**：把写作思想、判断依据、作者流程和文件契约完整讲清；读完应知道课程怎么设计、每讲怎么写、PLAN 怎么填、怎样回查。SKILL.md需要全量读取，并在此之后，要去看reference.md。
- **reference.md**：把这些要求做给你看，放正反例、已填 PLAN、真实事故、验证脚本和环境坑。它不替代本文件，也不把本文件只换词复述。

同一根因在两份文件出现并不构成重复：这里负责说清，reference 负责示范。不要把任一文件砍成指针。

## 0. 三层架构：后台强，正文自然

教程有三层，不能互相夺舍：

| 层           | 内容                                           | 强度     | 是否默认出现在正文               |
| ------------ | ---------------------------------------------- | -------- | -------------------------------- |
| 读者质量底线 | 定义、因果、例子、边界、作业、验证结论         | 硬规则   | 是，按知识需要自然出现           |
| 作者后台协议 | PLAN、覆盖清单、六问、认知链、脚本、两遍走     | 硬规则   | 否                               |
| 读者呈现模块 | 脉络图、任务成品、导航、自测、态度表、作业分层 | 按需工具 | 只有删掉后读者会具体迷失时才出现 |

一句话：**PLAN 强，正文松；验证严，行文自然；防漏在幕后，解释在台前。**

# 一、十六条原则（违反即 bug）

## 1. 说人话：直接说清，不拿修辞代替信息

“说人话”不是把技术关系全部强行换成生活化喻体--那样有一种恐怖谷的牵强和怪异，也不是全部抽象成行军一样缩略的单字口号--因为读者不会自动解读通用省略和话外之音。而是用完整自然的句子，直接说明：讨论对象、成立条件、因果关系、可推出的结果或验证方式。更不是把技术术语换成生活化口号(比如把“伏安特性”换成“伏安性格”，把具体的有名字的物理定律说成“我们上次记的账”)

优先级固定：

1. 对象、条件、方程、因果；
2. 数值例子、图、反例；
3. 必要时的低频类比。

类比只有同时满足三条才可保留：映射明确、能推出可验证后果、立即回到正式定义与边界。且必须在平实的技术语言已经完整完备之后，在此之上为了便于理解，在不影响严谨的技术层之上，加花一层更好理解的抽象，才做。

`账/账本/旧账/核账`、`武器`、`面孔`、`宪法`、`金律`、`舞台`、`地基`、`镜子`、`门票`、`魔法`等，不应作为读者正文的标题、步骤名、结论名、跨讲引用名或验算动词。它们能泛指任何东西，读者反而不知道当前说的是变量、前提、方法、结论还是验证。它们绝对不能渗透，侵犯，随意指代专有名词以及本身不是专有名词的解释性关系，尤其是那种“什么特么的叫‘这种魔法’，具体是什么你倒是说啊你早干什么去了特么“戴维南等效”一共五个字说出来会死吗”的专有名词。读者是读书来的，不是看你记账来的。

| 不要写                   | 直接写                                                   |
| ------------------------ | -------------------------------------------------------- |
| “旧账”“一笔悬着的账” | 换路前的初始值、此前已求出的量、待解释的现象             |
| “核账”“对账”         | 验算、独立核对、残差检查、两种结果吻合                   |
| “三笔账”“两本账”     | 三个结论、两类功率、两套约束                             |
| “舞台”“魔法”         | 本节要解决的问题、由哪些关系推出的结果                   |
| “全部武器”             | 对谁的什么武器，已学的方法，或结点法、相量法等具体方法名 |
| “两副面孔”             | 取不同输出端口得到不同网络函数                           |

PLAN、检查清单、会话中的内部行话同样不得直接搬入正文；先翻译为技术语言。

“说人话”不等于不正式，也不等于只讲感觉。正式文本仍须完备、自包含、边界清楚；只是要把读者真正会问的“它到底是什么”“我为什么现在要学它”说出来，而不是用一句标题式的学术话把问题盖过去。

不是说你用了比喻或者”你以为的意思到了“就是安全地”说人话了“，有时候那种极限失真浓缩动词名词的，人类压根不这么说的黑话比喻，仿佛只会说单字词，仿佛只会说口令的情况，更让人晕眩和反胃。你的听众是个活人，大概率还是个天真但认真的大学生乃至高中生，不是另一个agent或者某个执行器，更不是象征性接受信息的社畜，信息理解不到位吃亏和难受的是自己。那种极限浓缩黑话，像作战一样单字成词约定省略的口令式文章，春秋笔法的吟游诗人，是反面教材，很多时候即使是真正的论文都不敢这么写，更何况我们这个的语言柔顺度和完备度几乎是要远高于论文，因为我们是教程。你想想那些天真但认真的高中生和大学生，他们看到这些黑话不会感激，只会困惑和害怕。

## 2. 严禁空降概念

新术语第一次出现，当场做到以下三者之一：

1. 完整解释；
2. 说明“它是干什么的、现在只需知道什么、后面哪里细讲”；
3. 明确标注为认识层，现在可以跳过。

重要术语、专有名词和缩写首次出现要给中英文全称；公式里每个新符号要说是什么、单位或量纲是什么、何时可用；术语不能只有名字，还要说明为什么现在需要它。

跨讲引用要回追根：后讲使用的缩写若前讲未定义，应回到首次自然出现处补定义。解释必须在读者第一次自然会问的位置之前或当场，而不是两页之后统一补课。

## 3. 不藏着掖着，也不要无慈悲陈述

每个重要机制，作者必须确保读者得到四类信息：

- **它长这样**：标准形态、对象、最小例子或可观察形式；
- **这意味着什么**：把形式翻译成行为或后果；
- **怎么对待它**：它是工具、判定清单还是直觉，要会用、会推导还是先知道存在；
- **现在怎么办**：现在记住、动手，还是暂留到后讲。

这是作者后台检查项，不要求正文机械写成四个小标题。正文要让读者自然得到这些信息。

不要把正文没教的知识塞进作业答案。例题负责教学，作业负责练习；如果概念只能靠例子讲清，就多给例子，不要藏起来。作业过饱和是正常的，正文负责讲全，饱和，作业负责过饱和强化。

## 4. 防止退化成字典：给知识方向感

定义不等于会用。读者还需要知道：什么时候调用、和相邻概念怎么区分、怎样判断做法是否合适。否则会退化成让人无所适从的字典。

一个典型例子是 Python 这类语义基础：很多时候在变量、循环、函数都已经“明明理论上已经”教给学生了以后，学生写起来还是瞎试拼凑，组合爆炸，不知道哪种写法好、标准在哪里。教程要帮助读者建立这种对知识的方向感，而不是只让他认识词条。

## 5. 丰富具体例子

优先用工程、数值或可观察例子坐实抽象结论。读者看到具体输入、输出、误差、量级和反例，通常比看到一句抽象断言更能理解。

能用物理或公式准确说明的地方，用物理或公式；能用数值例子说明的地方，不必额外发明生活化喻体。

## 6. 每讲结尾留作业，而且必须可自验证

每讲应有作业，题型和数量按内容自然设计：

- 数值题给答案与验算方法；
- 代码题给可运行验证；
- 概念题给判断与解释；
- 综合题给参考思路，并尽量说明真实用途。

硬约束：答案只能使用已教概念；答案一律平铺为“**参考答案：**”，禁用 `<details>`。作业可按基础、提高、综合分层，但不是每讲必须凑齐档位。

## 7. 标明理解角度与深度

每个关键概念不只说“是什么”，还要告诉读者：从什么角度理解、理解到什么程度就够。

- **工具**：要会算、会用；
- **清单**：遇到时会检查；
- **直觉/认识层**：知道它存在、知道什么时候找它即可。

复杂、易混或考试重点多的讲可以用态度表；其余讲在定义后用一句话交代即可。不要让读者看完仍在问“这要背吗”。

## 8. 鼓励任务驱动、应用出发

每讲可以但不强求围绕一个能跑的小任务展开。适合任务驱动时，让概念在任务卡住的地方出现。这个小任务可以有一些人为构造来有意探照知识点，或者干脆展开多个小任务，否则单个天然的小任务可能涵盖不全所有知识点；不适合时，可以从一个真实问题、反例、实验现象或公式矛盾开始，或者乃至直接顺着知识点陈列梳理也是可以的-只要不是硬背字典，只要串讲的水平和方向感够，因为很多时候知识点内部的逻辑可以看出来，而agent只需自然地直白地点出而不是绕弯子。

反面症状是读者说：“先入为主背概念”“不知道学的哪里是哪里”“连要干啥都不知道就糊一脸概念”。
另一个反面症状是全面退化为“小任务冒险故事书”而完全丧失手册性质， 读者想要什么还得自己总结自己抓。这就是教程本身不到位，因为明明可以写清楚。

## 9. 解释的位置和解释本身同样重要

解释放在读者产生疑问之后，效果等于空降。审查时按读者第一次遇到的顺序走，不按作者知识组织顺序走。

读者看见 `main`、分号、某个符号、某个图例时自然会问什么，最低限度的答案必须在当页或前一页。完整原理可以后讲深入，但基本疑问不能悬着。

## 10. 地毯式覆盖优先于组织优雅

作者不能把“主线任务跑通”误当作“这一讲已经完整”。读者还会问：只能这样吗、能否组合、什么会打断、重复了怎样、好习惯是什么、与相邻概念差在哪。

每个新机制第一次教时，作者在 PLAN 中逐项过完整形态六问：

| 问               | 要检查什么                           |
| ---------------- | ------------------------------------ |
| 标准形态与自由度 | 标准写法是什么；哪些位置能换、能空   |
| 嵌套与组合       | 能否嵌套、与什么组合、什么不能组合   |
| 被控与外部打断   | 谁控制它、谁让它停止、特殊形态是什么 |
| 重复与共存       | 重复写会怎样、改名复用怎样、听谁的   |
| 规范             | 什么是好习惯、什么会埋坑             |
| 相邻边界         | 与相邻概念如何区分、旧直觉哪里会错   |

作者最容易犯的错是“主线任务 = 本讲内容”：任务跑通需要的才写，规范/边界/习惯被自动归为“讲外”；专家也会默认过滤“显然的东西”。但读者恰恰会问“就这些吗？只能这样吗？”。而且读者不知道自己不知道什么，没写出来的地方他问不出来，只能靠地毯式覆盖兜底。很可能还会问“没有概念的”“天马行空的”“额话其实不是这么讲的”问题，这很正常，要做好准备。

六问必须在 PLAN 中做出决定：进本讲正文、标认识层、留到后讲，或不讲并说明理由。六问答案不要求逐项显形为正文段落。

既然都有PLAN对照兜底，那么正文就放心自然地写，不忘记核对PLAN就行，而不是正文又扭捏又紧张。

## 11. 先定读者心智模型再动笔

写作前先明确假想读者是谁：要简明手册的、完全踏入陌生领域且不知道自己不知道什么的、需要基本覆盖的技术入门读者、还是带旧语言经验来的读者。

每一讲都写一条该讲假想学生的**认知思维链条**。它是学习者第一人称的自我梳理（“我以为……等等，那岂不是……”），不是作者用第三人称替他做总结。统一五段：

1. **我带着什么来**：旧心智模型 + 已有工具，写成“我以为 X 是……”式旧直觉，不是能力清单；
2. **第一反应**：看到任务时的期待/误判/抗拒，常含一个会错的直觉；正文要有对应的破误段；
3. **我会依次卡住的疑问**：4–8 个，按遇到顺序，每个具体可答；必须覆盖元问题迷失（“我该往哪想”）、旧直觉冲突（“加法逐元素，乘法凭什么不是”）、边界（“只能这样吗”）、防错（“我会不会栽在 X”）；每问标出正文哪一部分回答；
4. **学完后我的新心智模型**：学习者自己能说出口的一句话；
5. **还悬着的钩子**：通往下讲。

每问一行，全条约 6–14 行，具体而不嘴碎。思维链条是写作前的预测和写完后的对账工具，**不是要求正文按读者脑中每个跳跃逐问展开的脚本**。正文仍要系统地组织知识；任务主线决定读者先看到什么，完整形态六问决定一个机制该讲全什么。迁就混乱会制造更多混乱，但不照顾读者的认知链条又会空降。

对带旧语言经验的读者，PLAN 还要列“误会清单”：例如 Python 背景可能以为“参数能把值还回去”“同名函数后写覆盖前写”“for 是遍历不是三段式”。每条误会都应在课程正文有对应的打破误会段，不默认读者会自己纠正。

再次注意，这是兜底的参照，默认不把这些碎碎念口水话本身，或者对这些口水话的回应，像心理医生一样滔滔不绝地写进正文。特别要求除外。

可以有适当的对读者的第一人称揣测，但是仅用于引入，拦漏，常见点预先答疑，知识点细节定向展开的指导。绝对不能代替正文正式知识点本体，也不能直接不加精简不加布局地第作为全篇缠绵的排版散乱各处的抓都抓不到的主线(14. 口水话陷阱)

## 12. PLAN 是防漏的兜底

没有 PLAN 不动笔。PLAN 是作者工具，不给读者；它不是写完就扔的草稿。

PLAN 至少包含：目标与读者画像、骨架大纲、地毯式覆盖清单、每讲认知思维链条、两遍走状态。具体模板见“作者流程”一节。

PLAN严谨写，正文自信大方轻松写，正文有PLAN兜着，不怕了。正文不要很紧张很口令一样地短促黑话吞字，那样人类看不懂。

## 13. 问答/破误段不是教学容器

任何新知识必须先由正文系统节完整教过。常见问法、想当然归纳、误区卡片只做对答案和校准：首句声明“本节零新知识”，并逐条对应正文系统小节。

就地破误应守在疑问自然发生的位置附近；不要把一堆新定理、新记号塞进问答段，也不要为了满足问题配额机械凑“三连击”。

## 14. 口水话陷阱

不要写成博物馆导游，也不要念字典。读者讨厌铺垫：每一句铺垫都收注意力税，必须换来后面理解所必需的对象、问题或条件。

不一定要强行编一个故事来入戏，这让翻手册的时候很痛苦，但是也不能字典式地不符合认知规律地直接强硬陈列。尝试做到简明扼要且系统全面(优先偏向系统全面)，这个内部 trade off 按以及用户画像来拿捏。但不能走极端念字典念经或者极端口水稿。在这个内部trade off之上，文章质量的上线是，PLAN和后台脚本和流程正义 ，以及agent的头脑清醒定位明确，以及agent活人感说人话。

“删句子”不是目标。该列公式就列公式，该给表格就给表格，该系统展开就展开；不要把正文压缩成ai作者能懂、人类读者解码不了的号令式短语。判断标准是：这句话删掉后，读者会不会失去一个具体的因果、条件、例子或方向？

永远不要把正式定义，正式知识点和SOP，以所“讲故事”的，不经严谨排版所整合的形式呈现给读者。永远不要过度铺垫或者过度引入。你应直入重点。永远不要把娓娓道来的引入当成正式定义。

默认文风直白，不绕弯子。说人话讲给读者听。如若读者没有特殊要求，则默认读者是要在一个刚好时间不长不短但以及有点小急的情况下进行有把握的知识点全面的期末速通。知识点直观且深刻体现第一性，最好一句话说清楚谁是干什么的。

知识点的排版应当：简明，统一，尤其是统一，不要擅自非对称地花哨(除非有必要)，不要擅自开深层(除非挖到有很必要当面讲清楚的)，否则在找知识点上面还有额外注意力开销。鼓励"> "，"- 分点"，"1. 序号分点"，尽可能浅层(尽量不超过3层)且统一的"#"层级。说人话就是插入图片和表格照常插，但是别把一个个知识点散落的像沙子一样，用户还得自己抓，最绝望的是排版乱的话用户每次抓的姿势还不一样，累死了。(重点)

## 15. 台账陷阱

读者关心的是知识本身，不关心作者如何完成检查。PLAN、状态表、引用索引、验证过程不应淹没正文。

这不禁止必要引用、验算或前后呼应；要求是每次出现都当场说清它对当前知识意味着什么。不要让“作者做了多少对照”替代对象、关系和结论。

## 16. 读者默认画像

读者不是“按理应当理解”的机器。知识即使实质完整，也极其可能或者几乎天天都因形式混乱、解释位置错误、铺垫过多、术语无落点而真实地读不懂。这个skill就是解决这个来的。

读者不在乎 agent 用了几个流程、PLAN 有多少项、脚本跑了几次；他们只在乎：我现在在学什么、为什么需要它、这句话是什么意思、接下来能做什么。

人类平等地讨厌铺垫。其实从本质上来说人类讨厌学习，因为这一定意味着额外注意力开销。但是学都学了，恳请你不要和读者对着干。但是很多时候铺垫是客观上不得不为之的，这就见agent的功底了，不强制要求每一次都引人入胜，但起码也要不说废话。如果铺垫冗长，或者是短促的失真压缩黑话，或者不知所云的牵强比喻和ai slop，那么这个铺垫的注意力税将完全没有意义。

对了，读者看到“台账”两个字就想吐。

读者永远是一个天真但认真的高中生或大学生。像Elon Musk一样清醒地平时忙自己的项目，讨厌形式主义绕弯子和念ppt，但是期末又不能不通过考试，并且希望在通过考试时真正学到东西。信条是“如果我在一个已经明知是讲义和教材的文档里，已经看了一个知识点或者技能点，5分钟后却依然看不懂它想干什么，25分钟后却依然没有找到一个统一的基线并进入哪怕最最基础的第0步的推导， 那么我有权对其提出质问，哪怕这个知识点是量子力学，哪怕这个技能点是造宇宙飞船，因为真正的体力发生在进入知识点之后的精彩，发生在对技能点的磨合，而不是把人拒之门外并让其捶门白费力气，哪怕我只是一个高中生，甚至是初中生。”

如若读者没有特殊要求，则默认读者是要在一个刚好时间不长不短但有点小急的情况下进行不狼狈的有把握的系统性的期末速通。

# 二、作者流程：先 PLAN 后逐讲（两遍走）

## 第 0 步：先建 PLAN.md

```markdown
# [课程名] PLAN（作者自用，不给读者）

## 一、目标与读者画像
- 课程目标：学完能做什么（行为化）
- 读者：简明手册 / 完全陌生 / 技术入门 / 带旧经验
- 旧经验误会清单：每条对应未来正文中的破误位置

## 二、骨架大纲
| # | 讲 | 任务/问题/案例（按讲次选择） | 回答什么 | 状态 |
|---|---|---|---|---|

## 三、地毯式覆盖清单
- 领域知识逐项归属讲次，宁多勿少
- 不写的项写“不写 + 理由”
- 每个新机制记录完整形态六问的决定

## 四、每讲认知思维链条
- 第一人称五段：我带着什么来 / 第一反应 / 4–8 个具体卡点[→正文位置] / 学完后 / 钩子
- 每讲至少一个“不知道自己不知道”问题和一个“想当然归纳”问题

## 五、两遍走状态
- 第一遍：预写 / 实测 / 空降检查 / 格式与修辞卫生
- 第二遍：覆盖清单 / 读者顺序 / 链条问题 / 问答段 / AA 对账
```

## 第 1 遍：逐讲写作

1. 在 PLAN 中确认本讲范围、六问决定和认知链；选择任务、现象或问题作为合适起点。
2. 预写连续正文：先让知识按因果顺序站住，不预填脉络图、下一站、态度表、自测等模块。
3. 写验证脚本并实跑；C/C++ 可走“生成源码 → 编译 → 运行 → 对照预期”。
4. 对照预想与实测：一致则嵌入数据；偏差则在讲义写清预想、实测、根因。
5. 按读者顺序检查术语、符号、解释位置、条件与边界；检查作业答案不使用未教内容。
6. 做格式与卫生自检：`<details>` 为 0、引号一致、编号一致、无思考片段/工具标记/旧术语/PLAN 行话/牵强类比。
7. 数据维护：总表、图、正文、小结、自测引用的数值同步核对。
8. 归档脚本、更新 AA、PLAN、导览和确有的系列总览。

## 第 2 遍：交付前全课程回查

1. 对 PLAN 地毯清单逐项确认：已在正文自然讲清、留到后讲、或明确不写；
2. 按读者顺序通读，重点查规范、边界、习惯、被控形态等主线外内容；
3. 对照每讲认知链：每个卡点是否在恰当位置得到系统回答；
4. 回查问答/破误段：是否零新知识，是否出现机械凑数；
5. AA 批量对账：首次出现讲次、定义、公式条件和正文交叉核对；
6. 脚本、图、讲义实测数字互相可回溯；
7. 搜索喻体词族、自造动词、旧标题/编号、错别字和渲染问题；
8. 删除只是在提醒读者“作者正在组织内容”的句子，但不删除必要解释、因果和例子。

# 三、数值验证闭环

每讲含数值实验时必须跑脚本。验证不只验证最初代码：补漏、重写、作业答案中新加的代码也要实测。

脚本应：

- 开头写规模纪律（目标 < X 秒）；
- 尽量纯 numpy/scipy，不依赖重型框架；
- 每个实验打印标题、实测数据、预期与结论；
- 让“预期 vs 实测”直观看得出；
- 按 `lec03-01_verify_name.py` 归档到课程 `scripts/`，不删；
- 讲义每个实测数字可回到脚本；
- 删除 `__pycache__`、编译产物、临时日志等中间物。

复杂度结论至少三个规模点；随机实验重复多次看稳定性；使用 `uv run --with numpy python` 或相应隔离环境运行。

预写结论与实测不一致时，在讲义如实写：预想什么、实测什么、为什么不同。透明化偏差比伪装永远正确更可信。

# 四、课程文件契约与读者模块

```text
课程目录/
├── PLAN.md                 作者自用：目标、覆盖、链条、验证状态
├── 00_导览.md              读者导览
├── 01_xxx.md               正文
├── scripts/                验证脚本
├── figures/                图（如需要）
├── NN_与X的接口.md         最后一讲：与后续/应用的接口
└── AA_一览.md              概念、公式、中英对照字典
```

## 00_导览.md 必含内容

课程是什么、前置知识、学完能做什么、讲次大纲、达标判据、当前状态。读者与后来的维护者都应能从文件本身看到进度。

## AA_一览.md 必含内容

AA 是附录和字典，不是速查口令。每条概念写：中文名、英文/缩写、完整定义、首次出现讲次、理解层次；每条公式写：公式、符号各指什么、适用条件、出处讲次。正文不退化成 AA 条目，AA 也不只甩名字。

## 每讲的核心读者合同

每讲默认至少有：前置、这一讲解决什么、连续正文、小结、作业。正文可采用任务、现象、问题、反例或直接定义作为起点。

以下是**条件化模块**，不是默认仪式：

| 模块              | 什么时候加                                   | 不该加的情形             |
| ----------------- | -------------------------------------------- | ------------------------ |
| 脉络图            | 多分支、长篇、多方法选择，读者会在路径上迷失 | 单一线性因果链           |
| 任务成品          | 一个成品能自然牵引多数概念                   | 为凑任务而扭曲课程覆盖   |
| “下一站”/导航句 | 章节确有分岔、读者需要定位                   | 仅能重复“接下来讲……” |
| 态度表/自测       | 多公式易混、考试要求分层明显                 | 小结已足以说明深度       |
| 作业分层          | 基础与综合练习确有不同学习目标               | 只为凑基础/提高/综合标签 |
| 常见误区段        | 正文系统节已教完，存在高频误解需校准         | 借误区首次塞进新知识     |
| 跨讲预告          | 能说明下一讲为什么必然需要                   | 只是卖关子或串故事       |

# 五、常见失败形态

- 只靠“我觉得对”就交付，跳过验证；
- 跑完删脚本，断掉数字来源；
- 偷偷改掉预写偏差；
- 空降术语、符号、条件或缩写；
- 只写主线、挤牙膏，遗漏规范、边界、习惯和被控形态；
- 没有 PLAN 就动笔，或 PLAN 写完不再对照；
- 让答疑、作业或卡片替代正文教学；
- 把认知链写成笼统愿望或机械凑题；
- 把 PLAN、检查清单、会话行话搬进正文；
- 比喻通胀：用“账、舞台、魔法、武器、面孔”等替代技术对象；
- 自造动词：用“核账”等替代验算、独立核对或残差检查；
- 模板通胀：每讲强行塞脉络图、下一站、态度表、自测、分层作业，打断内容；
- 过度删减，留下只有作者能读懂的命令式短语；
- 改标题、术语或编号后不全文搜索，留下旧引用；
- 让文件卫生、流程正义或作者表演盖过知识本身。

# 六、格式与并行边界

- 行内公式用 `$...$`，块级公式用 `$$...$$`；
- 表格内绝对值写 `$\lvert H\rvert$`，不要写 `$|H|$`，避免 `|` 被 Markdown 当列分隔符；
- 新增文本前采样当前文件引号与编号风格；
- 多课程并行时，只改当前课程目录、必要系列总览；不改全局 README/JOURNAL 或其他课程；
- 运行环境、Markdown、PowerShell/WSL 的具体症状与修复见 reference.md，不要凭记忆乱猜。
