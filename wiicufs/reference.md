## 1. 说人话不是降精度

### 反面：官话把读者挡在门外

> “本节阐述凸优化理论中拉格朗日对偶的数学基础及其在约束优化中的应用。”

这句话的问题不是词难，而是读者不知道它在回答什么问题，也不知道“对偶”是一个什么东西。

### 正面：先让人看到问题，再给正式名字

> “每个优化问题都有个‘影子’——对偶问题。原问题问‘用这些资源最多赚多少’；对偶问题问‘这些资源每单位值多少钱’。两个问题看似不同，但最优值相等。”

这不是要替代正式定义。后面仍可给拉格朗日函数、对偶函数和强对偶条件；只是读者在看公式前已经知道：自己在比较“做事本身”和“资源价格”两种看法。

判断标准是：读出来像不像一个懂行的人在跟朋友解释，而不是教材在念稿。正式文本要完备自包含，边界清楚；说人话文本也要完整，没有歧义，不是铺垫很久卖关子，最后却讲漏了。

## 2. 空降概念：LP 标准形的正反例

### 反面

```markdown
## 一、LP 标准形
线性规划的标准形：max c^Tx s.t. Ax ≤ b, x ≥ 0
```

读者第一次见“LP”“标准形”“$c^Tx$”“$Ax\le b$”，四样都没有落脚点。

### 正面

```markdown
## 一、线性规划的标准形

先说清“线性规划”是什么：目标函数和约束**都是线性的**（变量只出现一次式，
没有 $x^2$、$xy$、$\sin(x)$ 这种）的优化问题。缩写 **LP**（Linear Programming），
后面反复用这个缩写。

**标准形**是一种统一写法：$\max c^Tx\ \mathrm{s.t.}\ Ax\le b,\ x\ge0$。
先说清每个符号：$x$ 是**决策变量**向量；$c$ 是**目标系数**；
$b$ 是**约束右端项**；$A$ 是**约束矩阵**。

**为什么要有标准形？** 实际 LP 写法千差万别，但求解器只认一种统一形式——
有了标准形接口，一套算法能解所有 LP。
```

这个例子同时完成了：缩写展开、符号说明、概念定义、动机说明。不是只在术语旁边塞一个英文括号。

### 跨讲空降的真实修复

第 03 讲标题“线性规划 I——标准形”直接用了 LP，但第 01、02 讲从未定义。修复不是在第 03 讲加一个脚注，而是回到第 01 讲第一次出现问题模型的位置，插入：

```markdown
> **这叫线性规划**（Linear Programming，缩写 **LP**）：目标函数和约束
> **都是线性**的优化问题。本例是 LP。后面反复用这个缩写。
```

### 写完后怎样找高危空降

下面不是第二份规则清单，而是实际审稿时可按类型搜索的“症状—修法”对照：

| 症状 | 读者会卡在哪里 | 修法 |
| --- | --- | --- |
| 只写 LP、BFS、DAG、DFS、RMSE、NP-hard | “缩写到底代替了什么？” | 首次出现给全称 + 一句话定义 |
| 写 $c^Tx$、$Ax\le b$ 却不说 $c,x,A,b$ | “我该把这些字母当什么？” | 逐个符号说“是什么” |
| 只说“转成标准形”“引入松弛变量” | “为什么要这么折腾？” | 补“为什么需要它”的动机 |
| 出现地面集、独立集族、超平面支撑 | “它长什么样？” | 给一个具体对象或小图景 |
| 出现 $\lfloor v\rfloor$、$\epsilon$ | “这个怎么读、怎么用？” | 给读音与最小例子 |
| 作业答案冒出数组、三元运算符 | “我还没学，答案怎么会？” | 改成只用已教语法的写法 |

## 3. 不甩清单：把“为什么”放在条目旁边

### 反面

```markdown
线性规划的转换技巧：
- 最小化 → 取负
- 等式约束 → 拆成两个不等式
- ≥ 约束 → 取负
- 自由变量 → 拆成两个非负变量之差
```

读者可以机械地照抄，但不知道为什么能这么变，也无法在新题里判断该不该用。

### 正面

```markdown
| 情况 | 转换 | 为什么 |
|---|---|---|
| 最小化 $\min c^Tx$ | 取负为 $\max -c^Tx$ | 求解器只认最大化；最小化 = 最大化负值 |
| 等式约束 $Ax=b$ | 拆成 $Ax\le b$ 和 $-Ax\le-b$ | 求解器只认 $\le$；“等于” = “既≤又≥” |
```

表格没有替读者做完所有推导，但每条都能对上理由。读者之后看到“自由变量拆成两个非负变量之差”，也会知道要问的是“限制为什么消失了”，而不是把它当口诀。

## 4. 字典陷阱：同一个语法，何时该用

下面是解释性示范，不是假装来自某一门已经交付的 Python 课。

| 读者已经知道的东西 | 还缺的方向感 | 就地该补的一句话 |
| --- | --- | --- |
| `for` 与 `while` 都能循环 | 不知道任务来了怎么选 | “已知大概循环几次、或在遍历一个序列时先想 `for`；停止时刻取决于运行中条件时先想 `while`。” |
| 推导式与普通 `for` 都能生成列表 | 不知道什么是可读、什么是炫技 | “只是在把一个序列映射成另一个列表，推导式通常更紧；循环体有多步判断、日志或副作用，就别硬塞推导式。” |
| 默认参数能写成 `[]` | 不知道为什么有坑 | “它能跑，但这个列表会在多次调用之间共用；需要新列表时用 `None` 作哨兵再在函数内创建。” |

这三句不是完整 Python 教程；它们做的是把“认识语法”接到“面对任务时怎样选”的方向感上。

## 5. 抽象概念用数值坐实

偏差—方差分解的一个实测样子：真实规律 $y=\sin(x)$，在测试点 $x_0=1.5$ 上，重复 50 次采样训练集。

| 模型复杂度 | 偏差$^2$ | 方差 | 能看到什么 |
| --- | ---: | ---: | --- |
| 1 次多项式 | 0.2343 | 0.0328 | 高偏差、低方差：欠拟合 |
| 3 次多项式 | 0.0002 | 0.0137 | 两者都低：这次实验中刚好 |
| 9 次多项式 | 6.3720 | 390.50 | 方差爆炸：对训练集极敏感 |

读者看到具体数字，比看到“复杂模型方差大”更容易抓到量级。这里也保留了一个诚实点：9 次项的偏差并不低，不能硬把数据涂成教科书的经典曲线；其原因和修正写在第 16 节。

## 6. 作业要让人能自己对照

### 一个最小的数值题形态

```markdown
**A. 温度传感器的平均读数**

设备连续读到 $20,22,21,23,24$（单位：℃）。
1. 算平均读数；
2. 若报警阈值是 $23$，平均读数是否触发报警？

**参考答案：**
平均值是 $(20+22+21+23+24)/5=22$。$22<23$，所以平均读数不触发报警。
验算：五个数的总和是 $110$，$110/5=22$。
```

这个例子不使用任何额外语法或尚未教过的技巧；答案紧跟题目、可手算复查。真实课程可把题换成矩阵、流体、概率或代码，但“题目—答案—验算”的闭环不变。

### `<details>` 事故为什么不能再碰

线代课程 01–08 曾有 70 个答案块折叠在 `<details>` 里。部分渲染环境会整体报错，漏一个闭合标签还会吞掉后面所有内容。后来全部改成平铺“**参考答案：**”。所以这不是审美偏好，是确实发生过的渲染事故。

## 7. 给读者标理解深度

### 反面：只给八条公理

```markdown
向量空间是一个集合 $V$，配上加法和数乘，满足八条公理：
1. 交换律  2. 结合律  3. 有零元  4. 有负元
5. $1v=v$  6. $(ab)v=a(bv)$  7. $a(u+v)=au+av$  8. $(a+b)v=av+bv$
```

读者自然会问：“八条要背吗？背了干嘛？遇到什么情况要用？”

### 正面：定义之后告诉他怎样对待

```markdown
别被八条吓到。说人话版本：向量空间 = 一个“能加、能缩放，
而且加完缩放完还在里面”的集合。

八条里没有任何反直觉的东西——它们全是你在数字上早就习惯的规则。
列出来的意义不是让你背，而是为了以后遇到一个新集合时，
有一份可以逐条打勾的清单。
```

这就是把“八条公理”从背诵对象变成验证清单。不同课程可再明确写“本讲只需建立直觉”或“这一条需要手算”，别让读者自己猜。

## 8. 任务驱动的 C++ 重写案例

读者反馈过：“先入为主背概念”“连要干啥都不知道就糊一脸概念”“全是罗列原理，实例很分散或没有”“我怎么知道哪里哪个意义是什么，看漏了怎么办”。

问题不是内容都错，而是组织错：概念按知识分类出场，不按读者需要的时刻出场；分号和 `main` 的解释排在后面；没有显式脉络。

C++ 课程 03–05 的重写做了四件事：

| 改造 | 实际做法 |
| --- | --- |
| 任务驱动 | 03 写设备开机自检报告，04 存传感器读数，05 做超温报警；概念在任务卡壳处引入 |
| 显式脉络 | 每讲开头“本讲怎么走”图，每节末尾“下一站” |
| 实例密度 | 每个概念 2–4 个微例子，加删分号看报错、把 `==` 改成 `=` 看逻辑坑等破坏性实验 |
| 瘦身 | 删元注释与重复铺垫，每节不超一屏，直接说人话 |

重写后行数从 397 到 218，读感反而更好。多讲还串成同一台“温度装置”，读者一直在给同一个东西加功能。重写版新增的代码也重新编译验证；这一步发现过作业答案误用了未教数组/三元运算符，后来改成纯 `if` 写法。

## 9. 解释放错位置，等于没解释

下面是“解释存在却仍然空降”的典型形态：

```markdown
第 2 行：int main() {
第 3 行：    cout << "hello";

……两页之后……
## 程序结构
main 是程序入口；分号表示一条语句结束。
```

读者在第 2、3 行已经会问 `main`、花括号、分号是什么。两页后再统一解释，作者觉得“我写过”，读者体验仍是“我前面根本看不懂”。

修法是把最低限度的解释放在第一次用到的当页：完整原理可以后面再深讲，但不能让读者带着无答案的基本疑问走两页。

## 10. 地毯式覆盖不是凭空加料

C++ 课程曾连续收到 A36–A42 七轮补问：声明是什么；程序不等于 `main`、定义次序和嵌套出路；声明/定义/赋值三件套、遮蔽、重载；循环与函数的规范；条件被控/标志驱动；`if/for/while` 可嵌套；忙等。

这些内容都不难，问题在于它们都不影响“主线程序先跑起来”。作者按任务需要写，读者按完整形态问，二者错位。

写完一个机制后，拿六问过一遍，再问一句：**“读者会问：只有这一种形态吗？只能这样吗？”**。例如只教 `for (int i=0; i<n; i++)` 时，不要误以为读者自然知道三段都能变化、能多条件、能写 `for(;;)`；是否此讲讲到什么程度可以决定，但“没想到这些问题”不行。

## 11. 思维链条的好坏对照

### 被退回的许愿式写法

> 来——会解小方程组、会数组。疑问——“为什么矩阵乘法要行乘列这么怪？干嘛不逐元素乘？”。学完——矩阵乘法=变换复合，顺序不可交换。

问题：第三人称；只有一问，问的还是讲题；没有旧直觉冲突、边界、防错；回查时没有可对的位置。

### 具体的第一人称链条

> 我带着什么来：会解小方程组；“矩阵”在我印象里就是“数摆成方格”，看不出跟我有啥关系。  
> 第一反应：矩阵乘法大概跟数字乘法差不多吧——我多半会一路默认 $AB=BA$。  
> 我会依次卡住：  
> - “矩阵到底是个啥？只是数表的话我为什么要学它？我该把它当成什么来想？” [→五副面孔]  
> - “矩阵加法居然是对应格子相加，那乘法凭什么搞特殊、不逐元素？” [→加法 vs 乘法脾气]  
> - “‘行乘列’算的时候手往哪放？怎么一眼记住结果多大、不串行？” [→怎么算/尺寸口诀]  
> - “为什么 $R(30)\cdot R(60)$ 就该等于 $R(90)$？这是定义还是巧合？” [→复合原理]  
> - “看到 $AB$ 我就想交换顺序，行不行？什么时候才可以？” [→不交换]  
> - “$AB=0$ 但 $A,B$ 都不是 0？那我从 $AB=AC$ 还能不能约掉 $A$？我会不会栽在这？” [→坑]  
> 学完后：矩阵在我心里不再是数表，而是“一列列向量打包 / 一台变换机器”；乘法行×列是为了让它=变换复合，$AB$ 要从右往左读、不能乱交换。  
> 钩子：变换能“撤销”吗（逆）？$Ax=b$ 到底怎么解？——去下一讲。

这条链条不是要求正文写成问答串。它的作用是预测读者会在哪里卡住，并让写作者核对：正文是否已经在合适位置回答了每个问题。

## 12. PLAN 的一个填法片段

下面只示范“矩阵与矩阵乘法”这一讲怎样把要求落到 PLAN；不是要替任何现有课程捏造正式 PLAN。

```markdown
## 二、骨架大纲（节选）
| # | 讲 | 任务（能跑的成品） | 回答什么 | 状态 |
|---|---|---|---|---|
| 02 | 矩阵与矩阵乘法 | 用两个二维变换连续作用于一个点 | 矩阵为何不是数表；为何行乘列；为何不交换 | 待写 |

## 三、地毯式覆盖清单（节选）
- 矩阵乘法：标准形态、尺寸匹配、结果尺寸、行×列计算 —— 第 02 讲
- 矩阵乘法：与逐元素乘的边界 —— 第 02 讲
- 矩阵乘法：不交换、零因子、消去法陷阱 —— 第 02 讲
- 逆矩阵：决定何时可“撤销” —— 第 06 讲；第 02 讲只留下钩子

## 四、每讲认知思维链条（第 02 讲，节选）
- 我带着什么来：会解小方程组；我把矩阵当成数摆成方格，还看不出它为什么重要。
- 第一反应：矩阵乘法大概和数字乘法差不多，我会默认 $AB=BA$。
- 我会依次卡住：矩阵只是数表吗？乘法为什么不逐元素？结果尺寸怎么一眼判断？$AB$ 能交换吗？$AB=AC$ 时能约掉 $A$ 吗？
- 学完后：矩阵是变换机器；行×列使乘法对应变换复合，顺序不能乱换。
- 钩子：变换能不能撤销？去逆矩阵一讲。
```

它显示的是：知识项归哪一讲、这一讲明确不讲什么、为什么不讲、下讲钩子通向哪里。写 PLAN 时“决定不写”必须留下理由，不能事后把“没想到”伪装成教学取舍。

## 13. 问答段装新知识的真实事故

线性代数第 05/06 讲曾为了满足“想当然式归纳至少 1 条”的要求，把新知识首讲塞进“想当然三连击”：

- $(AB)^{-1}=B^{-1}A^{-1}$ 的反序律；
- $A^{-k}$ 的幂定义；
- 矩阵除法不存在。

正文没有系统教，读者只能从问答里捡结论；同时每讲机械凑“三个”问法，变成仪式。

### 错误写法

> “想当然三连击：(b-1) $(AB)^{-1}$ 是不是 $A^{-1}B^{-1}$？”……

### 重写后

> 正文系统节给出定理 $(AB)^{-1}=B^{-1}A^{-1}$ + 证明 + 数值。定理后就地补：“如果你想当然认为顺序无所谓——”。末尾如果需要索引问答，首句写“本节只对答案，零新知识”，并逐条标出对应系统小节。

两类要求要同时满足：PLAN 里可以预测读者会有“想当然归纳”问题；正文仍必须先系统教新知识。前者不能误读成“应该建一个问答节并把知识塞进去”。

## 14. 念字典与口水稿分别长什么样

**念字典念经**：按“变量 → 运算符 → 控制流 → 函数”列知识点，顺序是知识分类，不是读者认知顺序；每条看似自足，读者却不知道自己在哪、为什么现在学它、下一站去哪里。

**口水稿**：铺垫冗长，卖关子（“这个我们后面就知道了”），故事/隐喻套隐喻；讲了三段温度计，读者还没看见一行代码，也记不住任何能动手的东西。

中间不是折中地各来一点，而是：任务牵引、概念在卡壳处引入、每节有下一站、讲末给心智模型总结。既不念经，也不说书。

## 15. 一个完整验证脚本的形态

以下是已有的梯度下降小规模验证脚本。它展示的不是“唯一标准代码”，而是一个可复跑实验怎样同时写出规模纪律、实验标题、实测数据、预期与结论。

```python
import time
import numpy as np

T0 = time.perf_counter()
# 规模纪律：小规模演示，目标 < 8 秒。

np.random.seed(42)
N = 50
x = np.random.uniform(-3, 3, N)
true_w, true_b = 2.0, 3.0
y = true_w * x + true_b + np.random.normal(0, 0.5, N)

print("=== EXP1: gradient descent — loss decreases ===")
w, b = 0.0, 0.0
lr = 0.05
losses = []
for epoch in range(100):
    y_pred = w * x + b
    loss = np.mean((y_pred - y) ** 2)
    losses.append(loss)
    grad_w = 2 / N * np.sum((y_pred - y) * x)
    grad_b = 2 / N * np.sum(y_pred - y)
    w -= lr * grad_w
    b -= lr * grad_b

print(f"  learned: w={w:.4f} (true {true_w}), b={b:.4f} (true {true_b})")
print(f"  loss: epoch 0={losses[0]:.4f}, epoch 99={losses[-1]:.4f}")
print("  -> loss DECREASES; w,b converge toward true values.")

print(f"\n=== EXP2: learning rate effect (t={time.perf_counter() - T0:.1f}s) ===")
for lr in [0.001, 0.05, 0.5]:
    w, b = 0.0, 0.0
    for _ in range(100):
        y_pred = w * x + b
        grad_w = 2 / N * np.sum((y_pred - y) * x)
        grad_b = 2 / N * np.sum(y_pred - y)
        w -= lr * grad_w
        b -= lr * grad_b
    final_loss = np.mean((w * x + b - y) ** 2)
    print(f"  lr={lr}: final loss={final_loss:.4f}")

print(f"\nTOTAL runtime: {time.perf_counter() - T0:.2f}s")
```

    result = algorithm(n)

## 16. 预写偏差怎样诚实写进讲义

### 案例一：偏差—方差分解

预写：“9 次多项式偏差低、方差高。”

实测：

```text
degree=9: bias^2=6.3720, variance=390.5019
```

这次实测中偏差不低。讲义里的诚实修正是：

```markdown
> **一个诚实记录**：9 次的 bias^2 也高（6.37，不是经典图里“低偏差”）。
> 因为 15 点拟合 9 次（参数 10 个接近样本数）数值极不稳定，某些采样的
> 预测剧烈偏离，连均值都偏了。**但最突出的是方差爆炸到 390**——过拟合
> 的核心标志是“对训练数据敏感”，方差爆炸才是关键，bias 偏高是附带现象。
```

这里三样都在：原来预想什么、真实数据是什么、为什么偏了。

### 案例二：测试集污染

预写：“用测试集选超参会导致乐观偏差。”第一次实测，两种流程选出同一超参，误差一样，没显示出偏差。改成重复 50 次后：

```text
WRONG (pick on test): mean err=0.1066
RIGHT (pick on val):  mean err=0.1126
```

50 次里 29 次选出不同超参。教训不是“原结论错了”，而是：单次实验可能看不出系统趋势，重复才把偏差露出来。

## 18. 已发生的环境与文档维护坑

### Python 验证脚本

| 坑 | 症状 | 修复 |
| --- | --- | --- |
| GBK 编码 | 控制台报 `UnicodeEncodeError: 'gbk' codec can't encode ✓` | print 用 `[OK]` 代替 ✓、`^2` 代替 ² |
| `np.trapz` 变动 | `AttributeError` | 改用 `np.trapezoid` 或手动梯形积分 |
| 数据太容易 | 浅模型就 100%，看不出过拟合 | 换更难的数据，例如重叠高斯团 |
| 网络太小 | 2-2-1 MLP 解 XOR 只到 75% | 加宽到 2-4-1 |
| 卷积核选错 | 输出全 0，虽正确但没有教学效果 | 换匹配图像特征的核 |
| 单次实验看不出趋势 | 测试集污染等结论不稳定 | 重复多次取平均 |
| K-means 计数 | `len(g1)` 数的是数组长度，不是 True 个数 | 用 `g1.sum()` |
| 特征归一化 | 归一化后 loss 更高 | 加截距列，只归一化特征列 |

### Markdown 与长文维护

| 坑 | 症状 | 修复 |
| --- | --- | --- |
| `<details>` 答案块 | 渲染报错或吞后文 | 改成平铺“参考答案”，交付前查残留 |
