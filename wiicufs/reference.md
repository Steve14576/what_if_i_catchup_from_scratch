## 一、核心原则的展开

### 1.1 "说人话"具体怎么做

**反面**（官话）："本节阐述凸优化理论中拉格朗日对偶的数学基础及其在约束优化中的应用。"

**正面**（说人话）："每个优化问题都有个'影子'——对偶问题。原问题问'用这些资源最多赚多少'；对偶问题问'这些资源每单位值多少钱'。两个问题看似不同，但最优值相等。"

**判断标准**：读出来像不像"一个懂行的人在跟朋友解释"，而不是"教材在念稿"。但是正式文本的也要有，看你水平了。正式本文要完备自包含，不用翻书东拼西凑引用，且清晰到能一眼抓到；说人话文本要完整，没有歧义，边界清晰，很顺的思维链条。标准就是，要直观讲述，而不是铺垫很久地卖关子。

### 1.2 "严禁空降概念"具体怎么做

**反面**（空降）：

```
## 一、LP 标准形
线性规划的标准形：max c^Tx s.t. Ax ≤ b, x ≥ 0
```

读者第一次见"LP""标准形""c^Tx""Ax≤b"——全空降。

**正面**（首次定义）：

```
## 一、线性规划的标准形

> 先说清"线性规划"是什么：目标函数和约束**都是线性的**（变量只出现一次式，
> 没有 x^2、xy、sin(x) 这种）的优化问题。缩写 **LP**（Linear Programming）。
> 后面反复用这个缩写。

> **标准形**是一种统一写法：max c^Tx s.t. Ax ≤ b, x ≥ 0。
> 先说清每个符号：x 是**决策变量**向量；c 是**目标系数**；
> b 是**约束右端项**；A 是**约束矩阵**。

> **为什么要有标准形？** 实际 LP 写法千差万别，但求解器只认一种统一形式——
> 有了标准形接口，一套算法能解所有 LP。
```

### 1.3 "不甩清单"具体怎么做

**反面**（甩清单）：

```
线性规划的转换技巧：
- 最小化 → 取负
- 等式约束 → 拆成两个不等式
- ≥ 约束 → 取负
- 自由变量 → 拆成两个非负变量之差
```

读者不知道"为什么要取负""为什么要拆"。

**正面**（每条配解释）：

```
| 情况 | 转换 | 为什么 |
|---|---|---|
| 最小化 min c^Tx | 取负 max -c^Tx | 求解器只认最大化；最小化 = 最大化负值 |
| 等式约束 Ax=b | 拆成 Ax≤b 和 -Ax≤-b | 求解器只认 ≤；"等于" = "既≤又≥" |
```

### 1.4 "丰富具体例子"具体怎么做

**每个抽象概念配一个能跑的数值例子**：

```
概念：偏差-方差分解
实测：真实规律 y=sin(x)，在测试点 x0=1.5 上，重复 50 次采样训练集：
  | 模型复杂度 | 偏差^2 | 方差   |
  |---|---|---|
  | 1次多项式  | 0.2343 | 0.0328 | ← 高偏差低方差（欠拟合）
  | 3次多项式  | 0.0002 | 0.0137 | ← 都低（刚好）
  | 9次多项式  | 6.3720 | 390.50 | ← 方差爆炸（过拟合）
```

读者看到具体数字，比看到"高复杂度方差大"更理解。

### 1.5 "每讲结尾留作业"具体怎么做

**数值题**：附答案 + 验算方法（用 `<details>` 折叠）。
**代码题**：附能跑的代码片段 + 预期输出。
**概念题**：判断对错 + 参考答案（折叠）。
**综合题**：开放性，附参考思路。
注重实际生产实践。

### 1.6 "标明理解角度与深度"具体怎么做

**问题**：读者看完一个概念后，不知道"我该怎么对待这个知识"——要背吗？要能推导吗？知道有这回事就行吗？

**反面**（只给定义不给角度）：

```
向量空间是一个集合 V，配上加法和数乘，满足八条公理：
1. 交换律  2. 结合律  3. 有零元  4. 有负元
5. 1v=v   6. (ab)v=a(bv)  7. a(u+v)=au+av  8. (a+b)v=av+bv
```

读者看完："八条要背吗？背了干嘛？遇到什么情况要用？"

**正面**（给定义 + 理解角度 + 理解深度）：

```
向量空间八条公理：
[列出八条]

别被八条吓到。说人话版本：
向量空间 = 一个"能加、能缩放，而且加完缩放完还在里面"的集合。

八条里没有任何反直觉的东西——它们全是你在数字上早就习惯的规则。
列出来的意义不是让你背，是为了以后遇到一个新集合时，
有一份可以逐条打勾的清单。
```

**三个层次**：

| 层次                                    | 含义                       | 案例                                           |
| --------------------------------------- | -------------------------- | ---------------------------------------------- |
| **要能推导/手算**                 | 核心技能，作业要练         | 线性回归的梯度下降手算一步                     |
| **要知道有这回事 + 什么时候找它** | 不用背，遇到知道去查       | 向量空间八条公理（打勾清单）、SVD 公式         |
| **要建立直觉**                    | 理解"它在干什么"，不背细节 | 单纯形法="顶点之间跳"、注意力="每个词看所有词" |

**写作时问自己**：读者学完这个概念，应该达到哪个层次？然后在讲义里**明确标注**。

### 1.7 “任务驱动、应用出发”具体怎么做（C++ 课程全量重写案例）

**症状**（读者原话类反馈）：“先入为主背概念”“连要干啥都不知道就糊一脸概念”“全是罗列原理，实例很分散或没有”“我怎么知道哪里哪个意义是什么，看漏了怎么办”。

**诊断**：内容本身往往不是错的（都实测过），问题在**组织方式**：

1. 概念按“知识分类”顺序出场，而不是按“读者需要的时刻”出场；
2. 读者自然产生的疑问（分号干啥的、main 干啥的）的答案被排在后面某节——**解释在错误位置，效果等于空降**；
3. 没有显式脉络，读者不知道自己在哪、看漏了找不回。

**重写四件套**（C++ 课程 03–05 讲实践，行数 397→218 的同时读感反而更好）：

| 改造     | 做法                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| 任务驱动 | 每讲围绕一个能跑的小任务（03=写设备开机自检报告、04=存传感器读数、05=超温报警），概念只在任务卡壳的那一刻引入 |
| 显式脉络 | 每讲开头一张“本讲怎么走”图 + 每节末尾一句“下一站”                                                         |
| 实例密度 | 每个概念配 2–4 个微实例 + 可亲手跑的破坏性实验（删分号看报错、把 == 改成 = 看逻辑坑）                        |
| 瘦身     | 删掉元注释与重复铺垫，每节不超一屏，直接说人话                                                                |

**多讲串故事线**：C++ 课程 03–05 串成“温度装置”（自检报告→存读数→超温报警），每讲的成品是上一讲的升级——读者始终在“给同一个东西加功能”，不是孤立地学知识点。

**重要经验：重写前重写后都要实测**。重写时新写的代码（累加 5050、值/引用传递差异、整除 7/2=3 等）全部重新编译运行验证，零偏差才交付；重写中还会暴露新的空降（自查发现重写版作业答案误用了未教的数组/三元运算符，当场改为纯 if 写法）。

### 1.8 “地毯式覆盖”具体怎么做（C++ 课程 A36–A42 实录）

**症状**：读者连环追问，每一问都补出一块正文漏掉的内容——七连问补出七块：声明是什么（A36）、程序≠main/定义次序/嵌套出路（A38）、声明/定义/赋值三件套/遮蔽/重载（A39）、循环与函数的规范习惯（规范轮）、条件被控/标志驱动（A40）、if/for/while 可嵌套（A41）、忙等（A42）。内容本身都不难，难的是**全是读者问出来的，不是写出来的**。

**诊断**：这些被漏项有共同特征——都是“主线任务跑通不需要”的内容：规范、边界、自由度、被控形态、与相邻概念的对比。作者按“任务需要”写，读者按“完整形态”问——两者错位。

**修法：完整形态六问**（见 SKILL.md 对应章节的表）。写作时对每个新机制逐问过：① 每部分的自由度；② 嵌套与组合；③ 被控与外部打断；④ 重复与共存；⑤ 好习惯/坏习惯；⑥ 相邻边界与旧语言对比。**关键不是六问答案都进正文，而是逐问过并做出决定**——“决定不写（理由：XX 讲再展开）”记进 PLAN.md；“没想到”才是漏。

**反面自检题**：写完一个机制后问自己“读者会问：只有这一种形态吗？只能这样吗？”——若答不出完整形态，就是漏了。

### 1.9 “先定读者心智模型”具体怎么做

写作前先回答三个问题：

1. **读者是谁**：要简明手册的（已懂概念要速查）/ 完全踏入陌生领域、不知道自己不知道什么的（需地毯兜底）/ 基本覆盖的技术入门（要体系）/ 带旧语言经验来的（需专门破误会）。不同画像决定覆盖策略：不知道自己不知道什么的读者**问不出没写的东西**，只能靠作者地毯式覆盖兜底。
2. **每讲一条认知思维链条**——写法见下方专节（这是 PLAN 里最容易写废的一项）。
3. **旧语言经验画像要列“误会清单”**：如 Python 背景读者会以为“参数能把值还回去”“同名函数后写覆盖前写”“for 是遍历不是三段式”——每条误会都要有对应的“打破误会”段，不默认读者会自己纠正。

**C++ 课程实例**：读者画像是“带 Python 经验、目标嵌入式、不知道自己不知道什么”——所以每一讲都要兼顾：破 Python 误会（A37 参数误解、A39 覆盖 vs 共存）+ 地毯兜底（A36–A42 全是兜底补的）。

#### 认知思维链条：统一五段骨架（学习者第一人称）

思维链条是**学习者写给自己的思路梳理**，不是作者替他做的总结。写废了的样子：每讲只有“来→一个笼统疑问→学完”三拍，疑问约等于把讲题复读一遍（“疑问：为什么矩阵乘法要行乘列？”——这不是读者会问的话，这是标题换个句式）。读者真实的心理活动是**一连串具体的小卡壳**，链条必须把它们按遇到顺序摆出来。线性代数课程 PLAN 曾按三拍写，被读者退回：“像许愿一样笼统，而不是具体面对问题”。

每讲固定五段（全条约 6–14 行，每问一行，**具体而不嘴碎**）：

| 段                    | 写什么                            | 写法要点                                                                                                                                                                                                                        |
| --------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 我带着什么来       | 旧心智模型 + 已有工具             | 写成“我以为 X 是……”式的旧直觉，不是作者视角的能力清单                                                                                                                                                                       |
| ② 第一反应           | 看到本讲任务时的期待/误判/抗拒    | 常含一个**会错的直觉**（如“矩阵乘法大概和数字乘法差不多”），正文要有对应的破误段                                                                                                                                        |
| ③ 我会依次卡住的疑问 | **4–8 个**，按遇到顺序排列 | 每个是具体可答的问题，后标 [→正文哪部分回答]；四类必含：**元问题迷失**（“我该往哪想”）、**旧直觉冲突**（“加法逐元素，乘法凭什么不是”）、**边界**（“只能这样吗”）、**防错**（“我会不会栽在 X”） |
| ④ 学完后             | 新心智模型                        | 学习者自己能说出口的一句话，不是作者结论的搬运                                                                                                                                                                                  |
| ⑤ 钩子               | 还悬着什么，通往下讲              | 一句话                                                                                                                                                                                                                          |

PLAN 阶段的 [→] 可标“计划中的小节名”，交付该讲时校正为真实小节。

**写法（代入法）**：把自己清零成目标读者（忘掉你会这件事），按正文顺序在脑内把本讲任务“读”一遍，每到一个会卡住的地方，用大白话记下那句真实心理活动（“等等，那岂不是……”“这跟我想的不一样啊”），最后压缩成一行一问。**写不出来的讲 = 你对读者在这条链上会卡在哪没有想象——先去补想象，再动笔写正文**。

**好坏对照（以“矩阵与矩阵乘法”一讲为例）**：

❌ 许愿式/题设复读式（真实被退过的写法）：

> 来——会解小方程组、会数组。疑问——“为什么矩阵乘法要行乘列这么怪？干嘛不逐元素乘？”。学完——矩阵乘法=变换复合，顺序不可交换。

毛病：第三人称；只有一问、问的还是讲题；没有过程、没有旧直觉冲突、没有防错；回查时根本无处可对。

✅ 具体的第一人称链条：

> 我带着什么来：会解小方程组；“矩阵”在我印象里就是“数摆成方格”，看不出跟我有啥关系。
> 第一反应：矩阵乘法大概跟数字乘法差不多吧——我多半会一路默认 AB=BA。
> 我会依次卡住：
>
> - “矩阵到底是个啥？只是数表的话我为什么要学它？我该把它当成什么来想？” [→五副面孔]
> - “矩阵加法居然是对应格子相加，那乘法凭什么搞特殊、不逐元素？” [→加法 vs 乘法脾气]
> - “‘行乘列’算的时候手往哪放？怎么一眼记住结果多大、不串行？” [→怎么算/尺寸口诀]
> - “为什么 R(30)·R(60) 就该等于 R(90)？这是定义还是巧合？” [→复合原理]
> - “看到 AB 我就想交换顺序，行不行？什么时候才可以？” [→不交换]
> - “AB=0 但 A、B 都不是 0？那我从 AB=AC 还能不能约掉 A？我会不会栽在这？” [→坑]
>   学完后：矩阵在我心里不再是数表，而是“一列列向量打包 / 一台变换机器”；乘法行×列是为了让它=变换复合，AB 要从右往左读、不能乱交换。
>   钩子：变换能“撤销”吗（逆）？Ax=b 到底怎么解？——去下一讲。

**第 2 遍回查时对账**：链条上**每一个**疑问都能在正文找到答题位置，且答题位置不晚于该疑问自然产生处。找不到的疑问 = 正文有漏，回填正文（或登记“决定不讲+理由”）；正文有但链条没预测的 = 链条漏了真实卡壳点，补进链条。

```markdown
|---|---|---|---|---|

- 强制出现至少1条的“想当然地可以这么说吗”，“我可以这么归纳吗”的，“可以但没必要”，“你直接记住...就行”，“对，你这个见解很独到但是要小心哪些边界不能用”，“太小众了，我们不这么说”，“你能记住就好”，“别这么记，会绕晕的”

## 五、两遍走状态
- 第 1 遍逐讲：每讲的预写/实测/空降检查/格式自检状态
- 第 2 遍回查：地毯清单逐项打勾结果、读者顺序通读发现的漏、思维链条疑问答案核对结果
```

**纪律**：第三节的覆盖清单是防漏的根——没有它，漏是必然不是意外；“决定不写”必须带理由写在清单里，与“没想到”区分开。

## 二、数值验证闭环的完整案例

### 2.1 一个完整的验证脚本范例

```python
import time, math
import numpy as np
T0 = time.perf_counter()
# 规模纪律：小规模演示，目标 < 8 秒。

np.random.seed(42)

# ---- 数据 ----
N = 50
x = np.random.uniform(-3, 3, N)
true_w, true_b = 2.0, 3.0
y = true_w * x + true_b + np.random.normal(0, 0.5, N)

# ============ 实验 1：梯度下降 loss 下降 ============
print("=== EXP1: gradient descent — loss decreases ===")
w, b = 0.0, 0.0
lr = 0.05
losses = []
for epoch in range(100):
    y_pred = w * x + b
    loss = np.mean((y_pred - y)**2)
    losses.append(loss)
    grad_w = 2/N * np.sum((y_pred - y) * x)
    grad_b = 2/N * np.sum(y_pred - y)
    w -= lr * grad_w
    b -= lr * grad_b
print(f"  learned: w={w:.4f} (true {true_w}), b={b:.4f} (true {true_b})")
print(f"  loss: epoch 0={losses[0]:.4f}, epoch 99={losses[-1]:.4f}")
print(f"  -> loss DECREASES; w,b converge toward true values.")

# ============ 实验 2：学习率影响 ============
print(f"\n=== EXP2: learning rate effect (t={time.perf_counter()-T0:.1f}s) ===")
for lr in [0.001, 0.05, 0.5]:
    w, b = 0.0, 0.0
    for _ in range(100):
        y_pred = w * x + b
        grad_w = 2/N * np.sum((y_pred - y) * x)
        grad_b = 2/N * np.sum(y_pred - y)
        w -= lr * grad_w; b -= lr * grad_b
    final_loss = np.mean((w*x+b - y)**2)
    print(f"  lr={lr}: final loss={final_loss:.4f}")

print(f"\n  TOTAL runtime: {time.perf_counter()-T0:.2f}s")
```

## 三、预写偏差修正的完整案例

### 3.1 案例：偏差-方差分解

**预写**："9 次多项式偏差低、方差高（经典偏差-方差权衡图）。"

**实测**：

```
degree=9: bias^2=6.3720, variance=390.5019
```

**偏差**：预写"偏差低"，实测 bias^2=6.37（偏高，不是经典图的"低偏差"）。

**讲义里的修正**：

```markdown
> **一个诚实记录**：9 次的 bias^2 也高（6.37，不是经典图里"低偏差"）。
> 因为 15 点拟合 9 次（参数 10 个接近样本数）数值极不稳定，某些采样的
> 预测剧烈偏离，连均值都偏了。**但最突出的是方差爆炸到 390**——过拟合
> 的核心标志是"对训练数据敏感"，方差爆炸才是关键，bias 偏高是附带现象。
```

**三要素**：偏差描述（预想低实际高）+ 实测数据（6.37/390）+ 根因（小样本+高次=数值不稳）。

### 3.2 案例：测试集污染

**预写**："用测试集选超参会导致乐观偏差。"

**第一次实测**：两种流程选出相同超参，报出误差相同——**没显示出偏差**。

**修正**：改成重复 50 次看平均：

```
WRONG (pick on test): mean err=0.1066
RIGHT (pick on val):  mean err=0.1126
```

50 次里 29 次选出不同超参——**重复才暴露系统性偏差**。

**教训**：单次实验可能看不出趋势，**重复多次取平均**才能暴露系统性偏差。

## 五、多尺度实测范式

**含算法复杂度的教学材料，必须设至少三个规模点**——单点无法暴露规模敏感性。

```python
# 错误：只测 n=100
n = 100; result = algorithm(n)

# 正确：测 n=10, 100, 1000
for n in [10, 100, 1000]:
    result = algorithm(n)
```

**原则**：涉及"随规模变化"的结论（如"算法 X 比 Y 快"），必须多尺度实测，不能只凭一个点下结论。

## 六、抽样波动实测

**涉及随机性的实验，必须重复多次看稳定性**——单次结果可能是幸运/不幸。

```python
# 错误：只跑一次
result = random_experiment()

# 正确：重复 50-5000 次看分布
results = [random_experiment() for _ in range(1000)]
print(f"mean={np.mean(results):.4f}, std={np.std(results):.4f}")
```

**适用场景**：训练-测试划分的随机性、K-means 初始化敏感性、统计检验的 power 分析等。
