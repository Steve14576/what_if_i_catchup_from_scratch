## R1 "说人话"具体怎么做（←P1）

**反面**（官话）："本节阐述凸优化理论中拉格朗日对偶的数学基础及其在约束优化中的应用。"

**正面**（说人话）："每个优化问题都有个'影子'——对偶问题。原问题问'用这些资源最多赚多少'；对偶问题问'这些资源每单位值多少钱'。两个问题看似不同，但最优值相等。"

**判断标准**：读出来像不像"一个懂行的人在跟朋友解释"，而不是"教材在念稿"。但是正式文本也要有，看你水平了。正式文本要完备自包含，不用翻书东拼西凑引用，且清晰到能一眼抓到；说人话文本要完整，没有歧义，边界清晰，很顺的思维链条。标准就是，要直观讲述，而不是铺垫很久地卖关子最后讲漏了都不知道。

## R2 "严禁空降概念"具体怎么做（←P2）

**反面**（空降）：

```
## 一、LP 标准形
线性规划的标准形：max c^Tx s.t. Ax ≤ b, x ≥ 0
```

读者第一次见"LP""标准形""c^Tx""Ax≤b"——全空降。

**正面**（首次定义）：

```
## 一、线性规划的标准形

> 先说清"线性规划"是什么：目标函数和约束**都是线性的**（变量只出现一次式，
> 没有 x^2、xy、sin(x) 这种）的优化问题。缩写 **LP**（Linear Programming）。
> 后面反复用这个缩写。

> **标准形**是一种统一写法：max c^Tx s.t. Ax ≤ b, x ≥ 0。
> 先说清每个符号：x 是**决策变量**向量；c 是**目标系数**；
> b 是**约束右端项**；A 是**约束矩阵**。

> **为什么要有标准形？** 实际 LP 写法千差万别，但求解器只认一种统一形式——
> 有了标准形接口，一套算法能解所有 LP。
```

**空降高危类型全表**（写完务必回查，唯一权威版本）：

| 类型 | 例子 | 修复方式 |
| --- | --- | --- |
| 缩写没展开 | LP、BFS、DAG、DFS、RMSE、NP-hard | 首次出现给全称 + 一句话定义 |
| 公式符号没说 | $c^Tx$ 里的 $c/x$、$Ax\le b$ 里的 $A/b$ | 逐个符号说"是什么" |
| 术语没给动机 | "为什么要标准形""为什么要松弛变量" | 补"为什么要有"的动机段 |
| 抽象概念没类比 | "地面集""独立集族""超平面支撑" | 补"它长什么样"的具体例子 |
| 记号没注音 | $\lfloor v\rfloor$（向下取整）、$\epsilon$（读 epsilon） | 补读音 + 解释 |
| 解释在错误位置 | 解释存在但排在读者产生疑问的位置之后 | 按读者第一次遇到的顺序重排，疑问当页或前一页必须有答案（←P9） |
| 作业答案用未教概念 | 答案代码用了后面讲才教的语法（数组、三元运算符） | 对照"已教清单"逐句检查答案；必须提前用时改为只用已教语法的写法（←P6） |
| 读者带旧语言经验来的误会 | Python 背景读者以为"必须先声明变量" | 显式写"打破常见误会"段，不默认读者会自己纠正 |

**跨讲空降案例（LP 缩写）**：第 03 讲标题"线性规划 I——标准形"直接用"LP"缩写，但第 01、02 讲从没定义过"LP = 线性规划"。修复：回第 01 讲，在写出 $\max 3A+5B$ 后插入——

```markdown
> **这叫线性规划**（Linear Programming，缩写 **LP**）：目标函数和约束
> **都是线性**的优化问题。本例是 LP。后面反复用这个缩写。
```

## R3 "配全四件套、不甩清单"具体怎么做（←P3）

**反面**（甩清单）：

```
线性规划的转换技巧：
- 最小化 → 取负
- 等式约束 → 拆成两个不等式
- ≥ 约束 → 取负
- 自由变量 → 拆成两个非负变量之差
```

读者不知道"为什么要取负""为什么要拆"。

**正面**（每条配"为什么"）：

```
| 情况 | 转换 | 为什么 |
|---|---|---|
| 最小化 min c^Tx | 取负 max -c^Tx | 求解器只认最大化；最小化 = 最大化负值 |
| 等式约束 Ax=b | 拆成 Ax≤b 和 -Ax≤-b | 求解器只认 ≤；"等于" = "既≤又≥" |
```

**讲内心智模型总结的示例**（P3 后半段的落地）：一讲讲完矩阵乘法，小结处给"矩阵在我心里不再是数表，而是一台变换机器：行×列是为了让乘法=变换复合，AB 从右往左读、不能乱交换"——这是比 AA_一览条目更细的全讲浓缩：AA 只写"矩阵乘法：$C=AB$，$C_{ij}=$ 行 $i$ 点列 $j$……"，讲内总结写整条认知线。前文讲得再全，最后缺这一段，读者的收获是散的。

## R4 "字典陷阱（方向感）"具体怎么做（←P4）

**症状**：语法语义全教了（变量、循环、函数、推导式……），读者拿到任务还是瞎试拼凑——把学过的语法当零件随机组合，组合爆炸，不知道哪种写法是对的、好的、地道的。这就是字典化：每个词条都查得到，拼起来不会用。

**缺的就是三样**：

| 方向感三问 | 长什么样 | 例子 |
| --- | --- | --- |
| 什么时候会用到它 | 触发场景一句话，接到"任务→工具"的映射 | "已知循环次数用 for，不知道什么时候停用 while" |
| 和同类怎么选 | 同类工具摆在一起给选择判据 | "要新列表用推导式，只要副作用用普通 for" |
| 好坏的判断标准 | 什么算地道、什么算坑 | "可变默认参数能跑但是坑，标准写法是 None 哨兵" |

**落地写法**：每个工具性概念教完，补一小段"什么时候轮到它"——三五行，接住"读者知道它是什么但不知道何时用"的断层。没有这三样，就不是教了 Python，是编了本 Python 词典。

## R5 "丰富具体例子"具体怎么做（←P5）

**每个抽象概念配一个能跑的数值例子**：

```
概念：偏差-方差分解
实测：真实规律 y=sin(x)，在测试点 x0=1.5 上，重复 50 次采样训练集：
  | 模型复杂度 | 偏差^2 | 方差   |
  |---|---|---|
  | 1次多项式  | 0.2343 | 0.0328 | ← 高偏差低方差（欠拟合）
  | 3次多项式  | 0.0002 | 0.0137 | ← 都低（刚好）
  | 9次多项式  | 6.3720 | 390.50 | ← 方差爆炸（过拟合）
```

读者看到具体数字，比看到"高复杂度方差大"更理解。

**已知公式别用 ML 的案例**：教程里要演示"用数据验证两点确定一条直线"，用线性回归去"学"这个结论——能跑通，但白费力气还带拟合误差；直接由两点式 $y-y_1 = \frac{y_2-y_1}{x_2-x_1}(x-x_1)$ 推出来，精确且更短。规则已知的问题，公式就是最短路径，ML 只在规则未知时才值得上。

## R6 "每讲结尾留作业"具体怎么做（←P6）

**数值题**：附答案 + 验算方法（参考答案平铺在题下，`<details>` 禁用判据见 P6）。
**代码题**：附能跑的代码片段 + 预期输出。

## R7 "标明理解角度与深度"具体怎么做（←P7）

**问题**：读者看完一个概念后，不知道"我该怎么对待这个知识"——要背吗？要能推导吗？知道有这回事就行吗？

**反面**（只给定义不给角度）：

```
向量空间是一个集合 V，配上加法和数乘，满足八条公理：
1. 交换律  2. 结合律  3. 有零元  4. 有负元
5. 1v=v   6. (ab)v=a(bv)  7. a(u+v)=au+av  8. (a+b)v=av+bv
```

读者看完："八条要背吗？背了干嘛？遇到什么情况要用？"

**正面**（给定义 + 理解角度 + 理解深度）：

```
向量空间八条公理：
[列出八条]

别被八条吓到。说人话版本：
向量空间 = 一个"能加、能缩放，而且加完缩放完还在里面"的集合。

八条里没有任何反直觉的东西——它们全是你在数字上早就习惯的规则。
列出来的意义不是让你背，是为了以后遇到一个新集合时，
有一份可以逐条打勾的清单。
```

**四档枚举**（与 P7、AA_一览共用，唯一权威版本）：

| 档次 | 含义 | 案例 |
| --- | --- | --- |
| 要会用 | 拿到任务能正确使用 | LP 建模；线性回归写代码跑通 |
| 要能推导/手算 | 核心技能，作业要练 | 线性回归的梯度下降手算一步 |
| 知道有这回事 + 什么时候找它 | 不用背，遇到知道去查 | 向量空间八条公理（打勾清单）、SVD 公式 |
| 要建立直觉 | 理解"它在干什么"，不背细节 | 单纯形法="顶点之间跳"、注意力="每个词看所有词" |

**写作时问自己**：读者学完这个概念，应该落在四档的哪一档？然后在讲义里**明确标注**，AA_一览的层次列用同一套枚举。

## R8 "任务驱动、应用出发"具体怎么做（←P8，C++ 课程全量重写案例）

**症状**（读者原话类反馈）："先入为主背概念""连要干啥都不知道就糊一脸概念""全是罗列原理，实例很分散或没有""我怎么知道哪里哪个意义是什么，看漏了怎么办"。

**诊断**：内容本身往往不是错的（都实测过），问题在**组织方式**：

1. 概念按"知识分类"顺序出场，而不是按"读者需要的时刻"出场；
2. 读者自然产生的疑问（分号干啥的、main 干啥的）的答案被排在后面某节——解释在错误位置，效果等于空降（←P9）；
3. 没有显式脉络，读者不知道自己在哪、看漏了找不回。

**重写四件套**（C++ 课程 03–05 讲实践，行数 397→218 的同时读感反而更好）：

| 改造 | 做法 |
| --- | --- |
| 任务驱动 | 每讲围绕一个能跑的小任务（03=写设备开机自检报告、04=存传感器读数、05=超温报警），概念只在任务卡壳的那一刻引入 |
| 显式脉络 | 每讲开头一张"本讲怎么走"图 + 每节末尾一句"下一站" |
| 实例密度 | 每个概念配 2–4 个微实例 + 可亲手跑的破坏性实验（删分号看报错、把 == 改成 = 看逻辑坑） |
| 瘦身 | 删掉元注释与重复铺垫，每节不超一屏，直接说人话 |

**多讲串故事线**：C++ 课程 03–05 串成"温度装置"（自检报告→存读数→超温报警），每讲的成品是上一讲的升级——读者始终在"给同一个东西加功能"，不是孤立地学知识点。

**重要经验：重写前重写后都要实测**。重写时新写的代码（累加 5050、值/引用传递差异、整除 7/2=3 等）全部重新编译运行验证，零偏差才交付；重写中还会暴露新的空降（自查发现重写版作业答案误用了未教的数组/三元运算符，当场改为纯 if 写法）。

## R9 "解释的位置"具体怎么做（←P9）

R8 诊断里的第 2 条单独展开——这是最隐蔽的一类空降：**解释存在，但在错误的位置**。

检查法：把讲义按"读者第一次遇到的顺序"走一遍（不是按作者知识组织顺序），每到一处自问"读者走到这里，脑子里已经攒下了哪些没被回答的问题"——凡是攒了超过一节的，就是解释位置错了。典型：分号、main、return 的解释被统一放在"程序结构"一节，但读者在第 2 行代码就产生了这些疑问——这中间的每一页，读感都等于空降。

修复：把答案搬到疑问产生的当页或前一页；实在搬不动（需要后续知识才能解释全），就地给 P2 的缓期三选一，并在后续位置兑现。

## R10 "地毯式覆盖"具体怎么做（←P10，C++ 课程 A36–A42 实录）

**症状**：读者连环追问，每一问都补出一块正文漏掉的内容——七连问补出七块：声明是什么（A36）、程序≠main/定义次序/嵌套出路（A38）、声明/定义/赋值三件套/遮蔽/重载（A39）、循环与函数的规范习惯（规范轮）、条件被控/标志驱动（A40）、if/for/while 可嵌套（A41）、忙等（A42）。内容本身都不难，难的是**全是读者问出来的，不是写出来的**。

**诊断**：这些被漏项有共同特征——都是"主线任务跑通不需要"的内容：规范、边界、自由度、被控形态、与相邻概念的对比。作者按"任务需要"写，读者按"完整形态"问——两者错位。

**修法**：完整形态六问（表在 SKILL.md P10，逐问过、做决定、记 PLAN）。关键不是六问答案都进正文，而是逐问过并做出决定——"决定不写（理由：XX 讲再展开）"记进 PLAN.md；"没想到"才是漏。

**反面自检题**：写完一个机制后问自己"读者会问：只有这一种形态吗？只能这样吗？"——若答不出完整形态，就是漏了。

## R11 认知思维链条：统一五段骨架（←P11，学习者第一人称）

思维链条是**学习者写给自己的思路梳理**，不是作者替他做的总结。写废了的样子：每讲只有"来→一个笼统疑问→学完"三拍，疑问约等于把讲题复读一遍（"疑问：为什么矩阵乘法要行乘列？"——这不是读者会问的话，这是标题换个句式）。读者真实的心理活动是**一连串具体的小卡壳**，链条必须把它们按遇到顺序摆出来。线性代数课程 PLAN 曾按三拍写，被读者退回："像许愿一样笼统，而不是具体面对问题"。

每讲固定五段（全条约 6–14 行，每问一行，**具体而不嘴碎**）：

| 段 | 写什么 | 写法要点 |
| --- | --- | --- |
| ① 我带着什么来 | 旧心智模型 + 已有工具 | 写成"我以为 X 是……"式的旧直觉，不是作者视角的能力清单 |
| ② 第一反应 | 看到本讲任务时的期待/误判/抗拒 | 常含一个**会错的直觉**（如"矩阵乘法大概和数字乘法差不多"），正文要有对应的破误段 |
| ③ 我会依次卡住的疑问 | **4–8 个**，按遇到顺序排列 | 每个是具体可答的问题，后标 [→正文哪部分回答]；四类必含：**元问题迷失**（"我该往哪想"）、**旧直觉冲突**（"加法逐元素，乘法凭什么不是"）、**边界**（"只能这样吗"）、**防错**（"我会不会栽在 X"） |
| ④ 学完后 | 新心智模型 | 学习者自己能说出口的一句话，不是作者结论的搬运 |
| ⑤ 钩子 | 还悬着什么，通往下讲 | 一句话 |

PLAN 阶段的 [→] 可标"计划中的小节名"，交付该讲时校正为真实小节。

**写法（代入法）**：把自己清零成目标读者（忘掉你会这件事），按正文顺序在脑内把本讲任务"读"一遍，每到一个会卡住的地方，用大白话记下那句真实心理活动（"等等，那岂不是……""这跟我想的不一样啊"），最后压缩成一行一问。**写不出来的讲 = 你对读者在这条链上会卡在哪没有想象——先去补想象，再动笔写正文**。

**好坏对照（以"矩阵与矩阵乘法"一讲为例）**：

❌ 许愿式/题设复读式（真实被退过的写法）：

> 来——会解小方程组、会数组。疑问——"为什么矩阵乘法要行乘列这么怪？干嘛不逐元素乘？"。学完——矩阵乘法=变换复合，顺序不可交换。

毛病：第三人称；只有一问、问的还是讲题；没有过程、没有旧直觉冲突、没有防错；回查时根本无处可对。

✅ 具体的第一人称链条：

> 我带着什么来：会解小方程组；"矩阵"在我印象里就是"数摆成方格"，看不出跟我有啥关系。
> 第一反应：矩阵乘法大概跟数字乘法差不多吧——我多半会一路默认 AB=BA。
> 我会依次卡住：
>
> - "矩阵到底是个啥？只是数表的话我为什么要学它？我该把它当成什么来想？" [→五副面孔]
> - "矩阵加法居然是对应格子相加，那乘法凭什么搞特殊、不逐元素？" [→加法 vs 乘法脾气]
> - "'行乘列'算的时候手往哪放？怎么一眼记住结果多大、不串行？" [→怎么算/尺寸口诀]
> - "为什么 R(30)·R(60) 就该等于 R(90)？这是定义还是巧合？" [→复合原理]
> - "看到 AB 我就想交换顺序，行不行？什么时候才可以？" [→不交换]
> - "AB=0 但 A、B 都不是 0？那我从 AB=AC 还能不能约掉 A？我会不会栽在这？" [→坑]
>   学完后：矩阵在我心里不再是数表，而是"一列列向量打包 / 一台变换机器"；乘法行×列是为了让它=变换复合，AB 要从右往左读、不能乱交换。
>   钩子：变换能"撤销"吗（逆）？Ax=b 到底怎么解？——去下一讲。

**第 2 遍回查时对账**：链条上**每一个**疑问都能在正文找到答题位置，且答题位置不晚于该疑问自然产生处。找不到的疑问 = 正文有漏，回填正文（或登记"决定不讲+理由"）；正文有但链条没预测的 = 链条漏了真实卡壳点，补进链条。

**PLAN 里读者画像的三问**（写链条前的准备）：

1. **读者是谁**：要简明手册的（已懂概念要速查）/ 完全踏入陌生领域、不知道自己不知道什么的（需地毯兜底）/ 基本覆盖的技术入门（要体系）/ 带旧语言经验来的（需专门破误会）。不同画像决定覆盖策略：不知道自己不知道什么的读者**问不出没写的东西**，只能靠作者地毯式覆盖兜底。

## R13 问答/破误段红线（←P13：零新知识 + 数量由内容定）

**症状**（线性代数课程第 05/06 讲实录，均被读者退回）：为了满足 PLAN 思维链条里"想当然归纳至少 1 条"的要求，agent 把**新知识首讲塞进"想当然三连击"节**——$(AB)^{-1}=B^{-1}A^{-1}$ 的反序律、$A^{-k}$ 幂定义、矩阵除法不存在等本应在正文系统节正式教的东西，只在问答段用几句话带过，正文反而没教全；并且每讲机械地固定"三个"问法，变成套路仪式。"三连击"式命名本身就是信号：数量不是长出来的，是凑的。

> 根因注记：事故源头正是"链条要求"被误读成"正文要设问答节"。R12 的两条只管链条预测；本节红线管正文响应。两条规则管辖范围不同，混读就是事故。

**红线四条**：

1. **新知识零例外先进正文系统节**：定义、定理、记号、结论，一律先在正文系统节完整教过（"系统教过"= 该讲正文本体完整讲授；"问法段里补一句"不算教过）。
2. **问答段只对答案**：首句声明"本节只对答案 / 零新知识"，逐条锚定系统小节（如 [→6.1]），本体都在前文。若写不出来锚点，说明那处知识还没系统教——先回去补正文。
3. **数量由内容决定**：该几条几条，禁止固定数字，禁止"三连击/三大误区/最常犯的三个"这类凑数命名。
4. **就地破误优先**：按 P9，破误守在疑问自然产生的位置附近（如定理后紧跟"如果你以为顺序无所谓——"），不要攒成一节逃避。集中问答段只做"复习/对答案"用。

**好坏对照**：

❌（被退回的做法）：新知识只出现在问答段——

> "想当然三连击：(b-1) $(AB)^{-1}$ 是不是 $A^{-1}B^{-1}$？"……（正文无对应定理节，读者只能从问答里捡结论）

✅（重写后）：

> 正文系统节给出定理 $(AB)^{-1}=B^{-1}A^{-1}$ + 证明 + 数值，定理后就地破误解"如果你想当然认为顺序无所谓——"；（末尾可选）问法索引节首句"本节只对答案，零新知识"，逐条标 [→6.1] 等。

**执行检查**：交付前回查"问法/破误段出现的每个结论，正文系统节是否已完整教过"；搜全文确认没有"三连击"式固定数量命名残留。

### 15.2 一个完整的验证脚本范例

```python
import time, math
import numpy as np
T0 = time.perf_counter()
# 规模纪律：小规模演示，目标 < 8 秒。

np.random.seed(42)

# ---- 数据 ----
N = 50
x = np.random.uniform(-3, 3, N)
true_w, true_b = 2.0, 3.0
y = true_w * x + true_b + np.random.normal(0, 0.5, N)

# ============ 实验 1：梯度下降 loss 下降 ============
print("=== EXP1: gradient descent — loss decreases ===")
w, b = 0.0, 0.0
lr = 0.05
losses = []
for epoch in range(100):
    y_pred = w * x + b
    loss = np.mean((y_pred - y)**2)
    losses.append(loss)
    grad_w = 2/N * np.sum((y_pred - y) * x)
    grad_b = 2/N * np.sum(y_pred - y)
    w -= lr * grad_w
    b -= lr * grad_b
print(f"  learned: w={w:.4f} (true {true_w}), b={b:.4f} (true {true_b})")
print(f"  loss: epoch 0={losses[0]:.4f}, epoch 99={losses[-1]:.4f}")
print(f"  -> loss DECREASES; w,b converge toward true values.")

# ============ 实验 2：学习率影响 ============
print(f"\n=== EXP2: learning rate effect (t={time.perf_counter()-T0:.1f}s) ===")
for lr in [0.001, 0.05, 0.5]:
    w, b = 0.0, 0.0
    for _ in range(100):
        y_pred = w * x + b
        grad_w = 2/N * np.sum((y_pred - y) * x)
        grad_b = 2/N * np.sum(y_pred - y)
        w -= lr * grad_w; b -= lr * grad_b
    final_loss = np.mean((w*x+b - y)**2)
    print(f"  lr={lr}: final loss={final_loss:.4f}")

print(f"\n  TOTAL runtime: {time.perf_counter()-T0:.2f}s")
```

### 15.3 多尺度实测（判据在 SKILL.md"数值验证闭环"）

含算法复杂度的教学材料，必须设至少三个规模点——单点无法暴露规模敏感性：

```python
# 错误：只测 n=100
n = 100; result = algorithm(n)

# 正确：测 n=10, 100, 1000
for n in [10, 100, 1000]:
    result = algorithm(n)
```

原则：涉及"随规模变化"的结论（如"算法 X 比 Y 快"），必须多尺度实测，不能只凭一个点下结论。

### 15.4 抽样波动实测（判据在 SKILL.md"数值验证闭环"）

涉及随机性的实验，必须重复多次看稳定性——单次结果可能是幸运/不幸：

```python
# 错误：只跑一次
result = random_experiment()

# 正确：重复 50-5000 次看分布
results = [random_experiment() for _ in range(1000)]
print(f"mean={np.mean(results):.4f}, std={np.std(results):.4f}")
```

适用场景：训练-测试划分的随机性、K-means 初始化敏感性、统计检验的 power 分析等。

## R16 预写偏差修正的完整案例（←预写偏差修正）

### 案例 1：偏差-方差分解

**预写**："9 次多项式偏差低、方差高（经典偏差-方差权衡图）。"

**实测**：

```
degree=9: bias^2=6.3720, variance=390.5019
```

**偏差**：预写"偏差低"，实测 bias^2=6.37（偏高，不是经典图的"低偏差"）。

**讲义里的修正**：

```markdown
> **一个诚实记录**：9 次的 bias^2 也高（6.37，不是经典图里"低偏差"）。
> 因为 15 点拟合 9 次（参数 10 个接近样本数）数值极不稳定，某些采样的
> 预测剧烈偏离，连均值都偏了。**但最突出的是方差爆炸到 390**——过拟合
> 的核心标志是"对训练数据敏感"，方差爆炸才是关键，bias 偏高是附带现象。
```

三要素齐：偏差描述（预想低实际高）+ 实测数据（6.37/390）+ 根因（小样本+高次=数值不稳）。

### 案例 2：测试集污染

**预写**："用测试集选超参会导致乐观偏差。"

**第一次实测**：两种流程选出相同超参，报出误差相同——**没显示出偏差**。

**修正**：改成重复 50 次看平均：

```
WRONG (pick on test): mean err=0.1066
RIGHT (pick on val):  mean err=0.1126
```

50 次里 29 次选出不同超参——**重复才暴露系统性偏差**。

**教训**：单次实验可能看不出趋势，**重复多次取平均**才能暴露系统性偏差。

### 18.1 Python 验证脚本坑

| 坑 | 症状 | 修复 |
| --- | --- | --- |
| GBK 编码 | 控制台报 `UnicodeEncodeError: 'gbk' codec can't encode ✓` | print 里用 `[OK]` 代替 ✓、`^2` 代替 ² |
| numpy API 变动 | `np.trapz` 报 `AttributeError` | 改用 `np.trapezoid` 或手动梯形积分 `np.sum(np.diff(x) * (y[1:]+y[:-1])/2)` |
| 数据太容易 | 实验看不出效果（如过拟合没复现、浅模型就 100% 准确率） | 换更难的数据（如两类重叠的高斯团） |
| 网络太小 | MLP 训练后准确率不够（2-2-1 解 XOR 只到 75%） | 加宽隐藏层（如 2-4-1 达 100%） |
| 卷积核选错 | 输出全 0（正确但教学效果差） | 换匹配图像特征的核（竖线用竖直边缘核） |
| 单次实验看不出趋势 | 结论不稳定（测试集污染单次不显现） | 重复多次（如 50 次）取平均看趋势 |
| K-means 计数 | `len(g1)` 返回数组长度，报 50+50=100 但只有 50 点 | 改 `g1.sum()` 数 True 的个数 |
| 特征归一化 | 归一化后 loss 反而更高 | 加截距列、只对特征列归一化 |

### 18.2 Markdown 格式与文档维护坑

## R19 什么不是 WIICUFS

- **不是"怎么写学术论文"**：学术写作有不同规范（引用、严格证明、被动语态）
- **不是"怎么做技术博客"**：博客更随意、更短、不需系统
- **不是"怎么写代码文档"**：代码文档面向 API 使用者，不是"从零学"
- **不是"怎么做视频教程"**：视频有不同媒介特性（口语化、演示）
- **不绑定任何具体项目**：方法通用，可用于数学/物理/编程/工程任何领域
