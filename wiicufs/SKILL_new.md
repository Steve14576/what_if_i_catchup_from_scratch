# WIICUFS — 写"说人话"的技术课程文档

> **WIICUFS** = What If I Catch Up From Scratch
> 一套让"没学过的人"也能看懂的技术教程写作方法。

## 什么时候用

当你需要写一套**多讲次的技术教程**（如"从零学 X"系列），面向**没学过这个领域**的读者，要求他们能看懂、能练手、能信任内容正确性、能单纯凭借它通过诸如考试、考核、科研等实际考验时。

典型场景：

- 给自己补一门没上过的课
- 给团队写技术入门系列
- 从零恶补一门"不知道自己不知道什么"但对当前极其重要的领域
- 给社区写开源教程
- 期末考试（绝对不能想当然，绝对不能漏或跳知识点）（不能口语和散装到完全用不了）（要前因后果但不要卖关子讲口水话）（要系统地组织）

## 核心原则（违反即 bug）

1. **说人话**：不用官话、不堆砌不知所云的术语。能用大白话说清的概念不用学术黑话。但说人话 ≠ 口水话——系统、完整、不卖关子、不漏知识点、不像博物馆导游一样啰嗦。读出来像"一个懂行的人在跟朋友解释"，而不是"教材在念稿"。

2. **严禁空降概念**：新术语第一次出现，当场给三样之一——① 完整解释；② 一句话"它是干啥的 + 现在只需知道这么多 + 第 N 讲细讲"；③ 明确标注"这个词现在可以跳过"。**写作时作者脑里有上下文会无意识跳过定义，读者第一次见没有这个上下文**——这是长篇教程最易违反的一条。（曾出现：直接写 C 语言的 `float` 的一堆性质但从来不说它是个什么。）

3. **不藏着掖着、无慈悲陈述**：列出的每样东西至少配"它长什么样、这意味着什么、完整方法论心智模型、是否先记下来后面再说"。不要因为后面会细讲就在前面故意藏着不说。前面的知识点要完备，作业过饱和了是正常的。**不吝啬心智模型和总结**：能提炼干货就做，不因为前文讲过就不给；在讲内写，比 AA_一览更细更全。

4. **丰富具体例子**：倾向工程/数值计算方向，能跑的代码优先。抽象概念用数值实验坐实。**在教程里用 ML 学已知公式是白费力气还加误差——用物理/公式更精确。**

5. **每讲结尾留作业**：可自验证——数值题附答案和验算方法，代码题附能跑的验证。**两条硬约束**：① 答案只能用**已教过的概念**（曾犯：第 05 讲答案用了第 07 讲才教的数组）；② 答案块**一律平铺**为"**参考答案：**"段写在题下，**禁用 `<details>`/HTML 折叠**——折叠答案在部分渲染环境会整体报错，未闭合会吞后续内容。

6. **标明理解角度与深度**：每个概念不只说"是什么"，还要告诉读者"从什么角度理解"和"理解到什么程度"。
   - **理解角度**：是"工具"（要会用）、"清单"（遇到时打勾验证）、还是"直觉"（建立感觉就行）？
   - **理解深度**：要能推导？要能复述？只要知道"有这回事 + 什么时候找它"？
   - **字典陷阱**：概念出现时要给方法论或心智模型（什么时候怎么用），否则退化成让人无所适从的字典——学生瞎试拼凑就会组合爆炸，且不知道好坏与标准。
   - **案例**：向量空间八条公理——不背，是"打勾清单"，理解到"能加能缩放还在里面"的直觉就够；SVD——知道"旋转-缩放-旋转"的几何直觉，不背公式。

7. **任务驱动、应用出发**：每讲围绕一个**能跑的小任务**展开，概念只在"任务卡壳"的那一刻引入，**不上来罗列原理**。三个配套：① 开头一张"本讲怎么走"脉络图 + 每节末尾一句"下一站"（读者看漏了随时能定位）；② 一个可立即运行的成品程序开场（先看到"我能做出什么"再拆零件）；③ 多讲串成故事线。（C++ 课程曾因"罗列原理开场"被读者投诉后全量重写三讲，行数 397→218 的同时读感反而更好。）

8. **解释的位置和解释本身同样重要**：解释如果放在读者产生疑问的位置**之后**，效果等于空降。审查时按"读者第一次遇到的顺序"走，不按作者知识组织顺序。读者自然产生的疑问（"分号干啥的""main 干啥的"）必须在疑问产生的当页或前一页就有答案。

9. **地毯式覆盖优先于组织优雅**：写一个概念时，主线任务只决定"必须讲什么"，但读者要的是"完整形态"——标准形式之外能不能换、能不能嵌套、能不能被外部控制、重复了会怎样、好习惯坏习惯、和相邻概念的边界。**先地毯式列出完整形态再组织**。判断"这里先理解即可后面会讲"的时机是写到那一讲的时候，不是现在——现在只有"写全"和"不写"两个选项。也要注意不能钻特性细节而忽视主干和全面性。**格外留意不能漏掉知识点**——说人话不等于可以漏。要有前置 PLAN 疯狂穷举发散，留下的作为兜底，后文反复对照。

10. **先定读者心智模型再动笔**：写作前先明确假想读者是谁（简明手册型 / 完全陌生型 / 技术入门型 / 带旧语言经验型），每一讲写一条认知思维链条。详细骨架和写法见下方"认知思维链条"专节。

11. **问答/破误段不是教学容器**：任何新知识（定义、定理、记号、结论）必须**先由正文系统节完整教过**；"想当然/常见问法"类段落只做**对答案与校准表态**，首句须声明"本节零新知识"，逐条锚定正文系统小节；问法数量**由内容决定**，禁止固定套路数字。就地破误按原则 8 守在疑问自然产生的位置附近。答疑卡片（如 QnAnExperience）是索引不是正文替身——卡片里解释过的内容如果正文有漏，必须回填正文。详细红线见"问答/破误段红线"专节。

## 写作流程：先 PLAN 后逐讲（两遍走）

```
第 0 步：建 PLAN.md（课程目录最前面，agent 自用，不给读者）
  → 明确目标 + 读者画像（原则 10）
  → 骨架大纲（每讲的任务/回答什么/成品）
  → 对照领域完整知识清单做地毯式覆盖检查（见"地毯式覆盖检查"）
  → 每讲的认知思维链条（见"认知思维链条"）

第 1 遍：逐讲写作
  1. 预写讲义初稿（每讲先定"本讲的任务"再定内容；每个新机制按"完整形态六问"展开）
  2. 写验证脚本，实跑验证预写结论（不限 Python：C/C++ 课程用"生成源码→编译→运行→对照预期输出"）
  3. 对照预想 vs 实测：一致 → 嵌入实测数据；偏差 → 插入"我说过头了"段（偏差 + 实测 + 根因）
  4. 空降检查：逐段回查新术语首次出现处是否给了定义；按读者顺序查解释位置；检查作业答案是否用了未教概念
  5. 格式自检：`<details>` 计数为 0；引号风格一致；编号体系单一
  6. 重复内容检查：同一数据只允许一个权威出处，其他处指向它
  7. 归档验证脚本、补 AA_一览、回填 PLAN.md 状态、同步导览页

第 2 遍：交付前全课程回查
  1. 对照 PLAN.md 地毯清单逐项打勾，没写的要么补、要么给出"不写"的理由
  2. 按读者顺序从头走一遍，查漏（尤其"规范/边界/习惯/被控形态"这类主线外内容）
  3. 对照每讲思维链条：每一个疑问是否都能在正文找到答题小节、且位置不晚于疑问产生处；AA_一览批量对账去重
```

## PLAN.md 模板

```markdown
# [课程名] PLAN（agent 自用，不给读者）

## 一、目标与读者画像
- 课程目标：学完能做什么（行为化）
- 读者是哪一种：简明手册 / 完全陌生领域 / 技术入门 / 带旧语言经验
- 旧语言误会清单：[逐条列出，每条对应未来某一讲的"破误会"段]

## 二、骨架大纲（每讲）
| # | 讲 | 任务（能跑的成品） | 回答什么 | 状态 |
|---|---|---|---|---|

## 三、地毯式覆盖清单
- 领域完整知识清单（对照权威大纲/目录逐项列，宁多勿少）
- 每项标注归属讲次；不属于本课程的标"不写+理由"
- 每个机制的"完整形态六问"决定记录：哪几问进正文、哪几问"认识即可"、哪几问留到第 X 讲
- 已教清单（作业答案只用这些，逐讲更新）

## 四、每讲认知思维链条
- 每讲一条：学习者第一人称、五段骨架（见"认知思维链条"）
- 强制出现至少 1 条"不知道自己不知道"的问题
- 强制出现至少 1 条"想当然地可以这么归纳吗"的问题

## 五、两遍走状态
- 第 1 遍逐讲：每讲的预写/实测/空降检查/格式自检状态
- 第 2 遍回查：地毯清单逐项打勾、读者顺序通读发现的漏、思维链条疑问答案核对结果
```

**纪律**：第三节的覆盖清单是防漏的根——没有它，漏是必然不是意外；"决定不写"必须带理由写在清单里，与"没想到"区分开。

## 地毯式覆盖检查（完整形态六问）

每个新机制（语法/概念/工具）第一次教时，按"完整形态六问"逐项回答——每个问对应一类真实被漏的内容：

| 问 | 内容 | 被漏的实例 |
|---|---|---|
| ① 标准形态 + 每一部分的自由度 | 标准写法；每一段/每个位置能不能换成别的、空着 | for 三段全是自由位（`i+=2`/多条件/`for(;;)`） |
| ② 嵌套与组合 | 能不能嵌套自己；能不能和别的结构混着套；什么绝对不能嵌套 | 函数定义不能嵌套，控制流可以 |
| ③ 被控与外部打断 | 能不能被外部逻辑控制；谁让它变假/停；被控形态叫什么 | while 的标志驱动/忙等，循环体不自己前进 |
| ④ 重复与共存 | 重复写会怎样；能不能改名复用；听谁的 | 声明/定义/赋值三件套、遮蔽、重载、ODR |
| ⑤ 规范：好习惯/坏习惯 | 怎么用是对的；怎么用会埋坑 | 循环/函数的习惯表、垃圾值纪律 |
| ⑥ 相邻边界与对比 | 和相邻概念的区分；和读者旧语言（如 Python）的行为差异 | 函数不能嵌套 vs 控制流可嵌套；Python 参数也改不动外面 |

**执行纪律**：六问的答案不一定都进正文（有些可以标"认识即可"），但**必须逐问过并做出决定**——"决定不写"和"没想到"是两回事。决定记录在 PLAN.md。

**心智模型对账**：作者易犯"主线任务＝本讲内容"，专家视角自动过滤"显然的东西"；但读者问的恰恰是"就这些吗？只有这一种形态吗？"——凡回答不了"它的完整形态是什么"的机制，就是漏了。读者不知道边界，且**不知道自己不知道什么**——没写出来的地方他问不出来，只能靠地毯式覆盖兜底。

## 认知思维链条（五段骨架）

思维链条是**学习者写给自己的思路梳理**，不是作者替他做的总结。写废了的样子：每讲只有"来→一个笼统疑问→学完"三拍，疑问约等于把讲题复读一遍。读者真实的心理活动是一连串具体的小卡壳，链条必须按遇到顺序摆出来。

每讲固定五段（全条约 6–14 行，每问一行，**具体而不嘴碎**）：

| 段 | 写什么 | 写法要点 |
|---|---|---|
| ① 我带着什么来 | 旧心智模型 + 已有工具 | 写成"我以为 X 是……"式的旧直觉，不是作者视角的能力清单 |
| ② 第一反应 | 看到本讲任务时的期待/误判/抗拒 | 常含一个**会错的直觉**（如"矩阵乘法大概和数字乘法差不多"），正文要有对应的破误段 |
| ③ 我会依次卡住的疑问 | **4–8 个**，按遇到顺序排列 | 每个具体可答，后标 [→正文哪部分回答]；四类必含：**元问题迷失**（"我该往哪想"）、**旧直觉冲突**（"加法逐元素，乘法凭什么不是"）、**边界**（"只能这样吗"）、**防错**（"我会不会栽在 X"） |
| ④ 学完后 | 新心智模型 | 学习者自己能说出口的一句话，不是作者结论的搬运 |
| ⑤ 钩子 | 还悬着什么，通往下讲 | 一句话 |

**写法（代入法）**：把自己清零成目标读者，按正文顺序在脑内把本讲任务"读"一遍，每到一个会卡住的地方，用大白话记下那句真实心理活动（"等等，那岂不是……""这跟我想的不一样啊"），最后压缩成一行一问。**写不出来的讲 = 你对读者在这条链上会卡在哪没有想象——先去补想象，再动笔写正文**。

PLAN 阶段的 [→] 可标"计划中的小节名"，交付该讲时校正为真实小节。

**好坏对照（以"矩阵与矩阵乘法"为例）**：

❌ 许愿式/题设复读式（真实被退过的写法）：

> 来——会解小方程组、会数组。疑问——"为什么矩阵乘法要行乘列这么怪？干嘛不逐元素乘？"。学完——矩阵乘法=变换复合，顺序不可交换。

毛病：第三人称；只有一问、问的还是讲题；没有过程、没有旧直觉冲突、没有防错；回查时根本无处可对。

✅ 具体的第一人称链条：

> 我带着什么来：会解小方程组；"矩阵"在我印象里就是"数摆成方格"，看不出跟我有啥关系。
> 第一反应：矩阵乘法大概跟数字乘法差不多吧——我多半会一路默认 AB=BA。
> 我会依次卡住：
> - "矩阵到底是个啥？只是数表的话我为什么要学它？我该把它当成什么来想？" [→五副面孔]
> - "矩阵加法居然是对应格子相加，那乘法凭什么搞特殊、不逐元素？" [→加法 vs 乘法脾气]
> - "'行乘列'算的时候手往哪放？怎么一眼记住结果多大、不串行？" [→怎么算/尺寸口诀]
> - "为什么 R(30)·R(60) 就该等于 R(90)？这是定义还是巧合？" [→复合原理]
> - "看到 AB 我就想交换顺序，行不行？什么时候才可以？" [→不交换]
> - "AB=0 但 A、B 都不是 0？那我从 AB=AC 还能不能约掉 A？我会不会栽在这？" [→坑]
>   学完后：矩阵在我心里不再是数表，而是"一列列向量打包 / 一台变换机器"；乘法行×列是为了让它=变换复合，AB 要从右往左读、不能乱交换。
>   钩子：变换能"撤销"吗（逆）？Ax=b 到底怎么解？——去下一讲。

**第 2 遍回查时对账**：链条上**每一个**疑问都能在正文找到答题位置，且答题位置不晚于该疑问自然产生处。找不到的疑问 = 正文有漏，回填正文（或登记"决定不讲+理由"）；正文有但链条没预测的 = 链条漏了真实卡壳点，补进链条。它们是参考，不因为迁就读者发散的思维就放弃系统化知识组织讲解——迁就混乱的结果是更多的混乱。但是也要照顾读者的思维，顺着一个健康的认知链条。

## 问答/破误段红线

**事故**（线性代数课程实录，被读者退回）：为满足"想当然式归纳至少 1 条"的清单要求，把**新知识首讲塞进"想当然三连击"节**——反序律 $(AB)^{-1}=B^{-1}A^{-1}$、幂定义、矩阵除法不存在等本应在正文系统节正式教的东西，只在问答段用几句话带过，正文反而没教全。并且每讲机械地固定"三个"问法，变成套路仪式。"三连击"式命名本身就是信号：数量不是长出来的，是凑的。

**红线四条**：

1. **新知识零例外先进正文系统节**：定义、定理、记号、结论，一律先在正文系统节完整教过（"系统教过"= 该讲正文本体完整讲授；"问法段里补一句"不算教过）。
2. **问答段只对答案**：首句声明"本节只对答案 / 零新知识"，逐条锚定系统小节（如 [→6.1]）。若写不出锚点，说明那处知识还没系统教——先回去补正文。
3. **数量由内容决定**：该几条几条，禁止固定数字，禁止"三连击/三大误区/最常犯的三个"这类凑数命名。
4. **就地破误优先**：按原则 8，破误守在疑问自然产生的位置附近（如定理后紧跟"如果你以为顺序无所谓——"），不要攒成一节逃避。集中问答段只做"复习/对答案"用。

**好坏对照**：

❌（被退回）：新知识只出现在问答段——读者只能从问答里捡结论，正文无对应定理节。

✅（重写后）：正文系统节给出定理 + 证明 + 数值，定理后就地破误解"如果你想当然认为顺序无所谓——"；末尾可选问法索引节，首句"本节零新知识"，逐条标 [→6.1] 等。

**检查**：交付前回查"问法/破误段出现的每个结论，正文系统节是否已完整教过"；搜全文确认没有"三连击"式固定数量命名残留。

## 数值验证闭环

每一讲含数值实验的，必须跑脚本验证——不能只靠"我觉得这个结论对"。

```
写验证脚本（建在课程目录内）
  → uv run --with numpy python 脚本.py（或 --with scipy）
  → 实测数据回填讲义
  → 归档脚本：移入课程 scripts/，重命名为"讲次-序号_原名"
    （如 lec03-01_verify_gd_loss.py），不删
  → 清理中间产物（__pycache__、编译输出等）
  → 同步进度文件（导览页 + AA_一览）
```

**脚本规范**：

- 开头写"规模纪律"注释（目标 < X 秒）
- 纯 numpy/scipy，不依赖重型框架
- 每个实验有 print 标题 + 实测数据 + "→ 结论"一句话
- **跑完不删，编号归档**：移入课程 `scripts/`，文件名加"讲次-序号"编号前缀、原名完整保留在前缀之后，同一讲内按编写顺序编号，保证按序排列、可回溯复跑——讲义里每个实测数字都对应一个归档脚本
- **中间产物照旧清理**：`__pycache__`、编译输出、临时日志不算脚本，跑完即删

**非 Python 课程**（如 C/C++）：在课程目录建临时目录 `_lecXX_check/`，用 Write 工具生成测试源文件（不用 shell 内联 heredoc），编译运行，逐项对照讲义预写——连报错信息都算验证对象（讲义里引用的报错必须是真实原文）。测试源文件按编号规则归档，编译产物删除，临时目录清理。正文里出现的每一段新代码都要实测，包括重写/补漏时新写的。

**多尺度实测**：涉及算法复杂度的结论，必须设至少三个规模点（如 $n=10, 100, 1000$），单点无法暴露规模敏感性。涉及"随规模变化"的结论（如"算法 X 比 Y 快"），不能只凭一个点下结论。

**抽样波动实测**：涉及随机性的实验，必须重复多次（如 50–5000 次）取平均看稳定性——单次结果可能是幸运/不幸。适用场景：训练-测试划分的随机性、K-means 初始化敏感性、统计检验的 power 分析等。

## 预写偏差修正

预写结论 ≠ 实测结果时，不要偷偷改掉——**诚实记录**。在讲义中插入"我说过头了"或"一个诚实的修正"段落，包含三要素：

1. **偏差描述**：预想什么、实测什么
2. **实测数据**：具体数字
3. **根本原因**：为什么预想错了

**透明化偏差是教学可信度的核心**——读者看到"作者也会错、错了会纠正"，比看到"永远正确"更可信。

**案例 1**：预写"9 次多项式偏差低、方差高"（经典偏差-方差图），实测 $bias^2=6.37$（偏高，不是"低偏差"）。根因：15 点拟合 9 次（参数 10 个接近样本数）数值极不稳定。修正记录：方差爆炸到 390 才是过拟合核心标志，bias 偏高是附带现象。

**案例 2**：预写"用测试集选超参导致乐观偏差"，第一次实测没显示出来（两种流程选出相同超参）。改成重复 50 次取平均，才暴露系统性偏差（50 次里 29 次选出不同超参）。教训：单次实验可能看不出趋势，重复多次取平均才能暴露系统性偏差。

## 概念首次出现即定义

写的时候每个新术语首次出现就给定义，以及括号内英文专有名词，不要等"后面再补"。

**易空降的高危类型**（写完务必回查）：

| 类型 | 例子 | 修复方式 |
|---|---|---|
| 缩写没展开 | LP、BFS、DAG、DFS、RMSE | 首次出现给全称 + 一句话定义 |
| 公式符号没说 | $c^Tx$ 里的 $c/x$ | 逐个符号说"是什么" |
| 术语没给动机 | "为什么要标准形""为什么要松弛变量" | 补"为什么要有"的动机段 |
| 抽象概念没类比 | "地面集""独立集族""超平面支撑" | 补"它长什么样"的具体例子 |
| 记号没注音 | $\lfloor v\rfloor$、$\epsilon$ | 补读音 + 解释 |
| 解释在错误位置 | 解释存在但排在疑问之后 | 按读者第一次遇到的顺序重排，疑问当页或前一页必须有答案 |
| 作业答案用未教概念 | 答案代码用了后面才教的语法 | 对照"已教清单"逐句检查答案 |
| 读者带旧语言经验的误会 | Python 背景读者以为"必须先声明变量" | 显式写"打破常见误会"段，不默认读者会自己纠正 |

**跨讲引用要回追根**：第 03 讲用了第 01 讲没定义的缩写 → 回第 01 讲补定义。**不要因为它解释起来复杂就直接避开不讲，不然会漏知识点。**

### AA_一览——附录字典

它是**附录、字典，不是速查清单**——不必像正文那样循循善诱从头讲（不重复铺垫、动机、推导过程），但**必须和正文同样严谨：每条都要说清"是什么"**——完整的、自足的定义，读者忘了翻回来能重新明白这东西到底是什么。**只说"怎么样/怎么用"不说"是什么"是禁止的**。

收两类东西：① 关键概念/术语/缩写：中文名 + 英文名/缩写 + **说清"是什么"的定义**（不是用法提示） + 首次出现讲次 + 理解层次（对应原则 6 的三档）；② 关键公式：符号各指什么 + 适用条件 + 出处讲次。

**编号固定用 `AA_` 不用数字**——无论后续加多少讲，永不需要重排编号或换位置。**与正文的分工**：首次出现的叙述性教学（动机、例子、推导）仍在对应讲正文里（原则 2 不空降），AA 提供措辞严谨的字典形态。**维护**：每讲交付后补入本讲新条目；第 2 遍回查时批量对账去重（每条"首次出现讲次"与正文交叉核对）。

> 怎么学这一讲：成品→拆解→实验→作业→自测的固定循环

正文（任务驱动的成品开场，说人话，概念不空降，例子偏工程/数值）
（每节末尾一句"下一站"，指向下一节解决什么）
（可选"常见问法索引"节：首句声明"本节零新知识、只对答案"，逐条锚定系统小节，数量由内容定）

## 常见踩坑

| 坑 | 症状 | 解法 |
|---|---|---|
| GBK 编码 | `UnicodeEncodeError: 'gbk' codec` | print 里不用 ✓、²、³ 等 Unicode 符号，用 `[OK]`、`^2`、`^3` |
| numpy API 变动 | `np.trapz` 报 `AttributeError` | 改用 `np.trapezoid` 或手动梯形积分 |
| 答案用 `<details>` 折叠 | 渲染环境整体报错；未闭合吞后续内容 | 一律平铺为"**参考答案：**"块；交付前 grep `<details>` 计数 = 0 |
| grep 模式假阴性 | 搜编码形式（如 `&lt;/details&gt;`）得 0 匹配，误判全缺失并批量误改 | 用字面量模式；批量改前双向验证，改完再 grep 确认无重复 |
| 文件快照失效 | 凭记忆 SearchReplace 匹配失败或改错 | **改前必 Read 当前版本**，不信任会话内旧印象 |
| 解释在错误位置 | 解释存在但在读者需要它的位置之后，读感等同空降 | 按"读者第一次遇到的顺序"审查 |
| 作业答案用未教概念 | 答案代码用了后面讲才教的语法 | 对照"已教清单"逐句检查答案代码 |
| 同一数据多处重复 | 改一处漏其他 | 收拢到唯一权威出处，其余处指向 |
| PowerShell 剥引号 | `wsl -e bash -lc "..."` 嵌套引号被毁，`unexpected EOF` | 复杂命令写成脚本文件再执行；测试源文件用 Write 工具生成 |
| `$?` 被外层 shell 截胡 | 跨层取退出码输出错误值 | 含 `$?` 的整条命令用单引号包进 bash |
| Windows linter 误报 | `'iostream' file not found` | IntelliSense 找不到 Linux 头文件，以 WSL 编译为准，忽略 |
| 批量长文错别字 | "佳在""铺垂""甪"等同音/形近字 | 大量写作后专项自查一轮；diff 里扫新增文本 |
| 只写主线、漏周边 | 读者连环追问补漏 | 每个新机制过"完整形态六问"；先有 PLAN 地毯清单再动笔 |
| 数据太容易 | 实验看不出效果（如过拟合没复现） | 换更难的数据（如两类重叠的高斯团） |
| 网络太小 | MLP 训练后准确率不够 | 加宽隐藏层（如 2-2-1 → 2-4-1） |
| 卷积核选错 | 输出全 0（正确但教学效果差） | 换匹配图像特征的核 |
| 单次实验看不出趋势 | 结论不稳定 | 重复多次（如 50 次）取平均看趋势 |
| 预写结论与实测不符 | loss 不降/准确率不够/反常 | 诚实记录"我说过头了"，分析根因 |
| 文件写入截断 | `open(p,'wb')` 先截断再求值，曾把 12 个 md 全部写空 | 批量写文件前先 git 提交；写完立刻核验（大小 >0、行数合理）；IO 操作写成完整脚本 |
| K-means 计数 | `len(g1)` 返回数组长度而非 True 个数 | 改 `g1.sum()` 数 True 的个数 |
| 特征归一化 | 归一化后 loss 反而更高 | 加截距列、只对特征列归一化 |

## 什么不是 WIICUFS

- **不是"怎么写学术论文"**：学术写作有不同规范（引用、严格证明、被动语态）
- **不是"怎么做技术博客"**：博客更随意、更短、不需系统
- **不是"怎么写代码文档"**：代码文档面向 API 使用者，不是"从零学"
- **不是"怎么做视频教程"**：视频有不同媒介特性（口语化、演示）
- **不绑定任何具体项目**：方法通用，可用于数学/物理/编程/工程任何领域
